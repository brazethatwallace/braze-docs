# Publication du 27 mai 2025 {#may-27-2025-release}

## Flexibilité des données {#data-flexibility}

### Copier des Canvas entre les espaces de travail {#copying-canvases-across-workspaces}

{% multi_lang_include release_type.md release="General availability" %}

Vous pouvez désormais copier des Canvas entre les espaces de travail. Cela vous permet de démarrer rapidement la composition de vos messages en partant d'une copie d'un Canvas dans un autre espace de travail. Pour plus d'informations sur ce qui est copié, consultez [Copier des Campaigns et des Canvas entre les espaces de travail]({{site.baseurl}}/copying_to_workspaces).

### Règles de messagerie pour le workflow d'approbation {#messaging-rules-for-approval-workflow}

{% multi_lang_include release_type.md release="General availability" %}

Utilisez les [règles de messagerie]({{site.baseurl}}/user_guide/messaging/governance/approvals/messaging_rules) dans votre workflow d'approbation pour limiter le nombre d'utilisateurs joignables avant qu'une approbation supplémentaire ne soit requise. Vous pouvez ainsi vérifier vos Campaigns et Canvas avant de cibler une audience plus large.

### Diagrammes entité-relation pour Snowflake et Braze {#entity-relationship-diagrams-for-snowflake-and-braze}

Plus tôt cette année, nous avons créé des tableaux de relations entre entités pour les données partagées entre Snowflake et Braze. Ce mois-ci, nous avons ajouté de [nouveaux diagrammes interactifs]({{site.baseurl}}/partners/data_and_analytics/data_warehouses/snowflake/entity_relationships) dans lesquels vous pouvez naviguer, déplacer et zoomer sur les détails de chaque tableau, ce qui vous donne une meilleure idée de la façon dont vos données interagissent avec Braze.

## Libérer la créativité {#unlocking-creativity}

### Événements recommandés {#recommended-events}

{% multi_lang_include release_type.md release="Early access" %}

Les [événements recommandés]({{site.baseurl}}/user_guide/data/activation/events/recommended_events) correspondent aux cas d'usage eCommerce les plus courants. En utilisant les événements recommandés, vous pouvez accéder à des modèles Canvas prêts à l'emploi, à des tableaux de bord de reporting alignés sur le cycle de vie client, et bien plus encore.

## Canaux robustes {#robust-channels}

### Canal Banners {#banners-channel}

{% multi_lang_include release_type.md release="General availability" %}

Avec les [Banners]({{site.baseurl}}/user_guide/channels/banners), vous pouvez créer des messages personnalisés pour vos utilisateurs, tout en étendant la portée de vos autres canaux, tels que l'e-mail ou les notifications push. Vous pouvez intégrer les Banners directement dans votre application ou votre site web, ce qui vous permet d'interagir avec les utilisateurs à travers une expérience qui semble naturelle.

### Canal Rich Communication Services (RCS) {#rich-communication-services-rcs-channel}

{% multi_lang_include release_type.md release="General availability" %}

[Rich Communication Services (RCS)]({{site.baseurl}}/user_guide/channels/sms_mms_and_rcs) améliore les SMS traditionnels en permettant aux marques de diffuser des messages qui ne sont pas seulement informatifs, mais aussi bien plus engageants. Désormais pris en charge sur Android et iOS, le RCS apporte des fonctionnalités telles que des médias de haute qualité, des boutons interactifs et des profils d'expéditeur personnalisés directement dans les applications de messagerie préinstallées des utilisateurs, éliminant ainsi le besoin de télécharger une application distincte.

### Page de configuration Push {#push-settings-page}

{% multi_lang_include release_type.md release="General availability" %}

Utilisez la page [**Push Settings**]({{site.baseurl}}/user_guide/administer/global/workspace_settings/push_settings) pour configurer les paramètres clés de vos notifications push, notamment la durée de vie des notifications push (TTL) et la priorité FCM par défaut pour les Campaigns Android. Ces paramètres permettent d'optimiser la distribution et l'efficacité de vos notifications push, garantissant une meilleure expérience pour vos utilisateurs.

### Codes de promotion pour les Campaigns de messages in-app {#promotion-codes-for-in-app-message-campaigns}

{% multi_lang_include release_type.md release="Early access" %}

Vous pouvez utiliser des [codes de promotion]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/sources/promotion_codes) dans les Campaigns de messages in-app en insérant un [extrait de code de liste de promotions]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/sources/promotion_codes/create#create) dans le corps du message de votre Campaign de message in-app.

### Gestion des erreurs de webhook et limitation du débit {#handling-webhook-errors-and-rate-limiting}

[À propos des webhooks]({{site.baseurl}}/user_guide/message_building_by_channel/webhooks/understanding_webhooks#webhook-error-handling-and-rate-limiting) dispose d'une nouvelle section décrivant comment Braze gère les erreurs de webhook et la limitation du débit.

### Langues locales pour les messages in-app {#in-app-message-locales}

Après avoir [ajouté des langues locales]({{site.baseurl}}/locales_in_messages) à votre espace de travail, vous pouvez cibler des utilisateurs dans différentes langues, le tout au sein d'un seul message in-app.

### Amazon SES en tant que fournisseur d'envoi d'e-mails (ESP) {#amazon-ses-as-an-email-sending-provider-esp}

Vous pouvez désormais utiliser Amazon SES en tant qu'ESP, de la même manière que vous utiliseriez SendGrid et SparkPost. Consultez [SSL chez Braze]({{site.baseurl}}/user_guide/channels/email/email_setup/ssl#what-is-a-cdn-and-why-do-i-need-it) et [Liens universels et App Links]({{site.baseurl}}/user_guide/channels/email/customize/universal_links_and_app_links#turning-off-click-tracking-on-a-link-to-link-basis) pour les nuances concernant la configuration SSL et le suivi des clics lien par lien.

## Nouveaux partenariats Braze {#new-braze-partnerships}

### Eagle Eye - Fidélité {#eagle-eye-loyalty}

L'intégration bidirectionnelle entre Braze et [Eagle Eye]({{site.baseurl}}/partners/eagle_eye) vous permet d'activer les données de fidélité et promotionnelles directement dans Braze, permettant aux marketeurs de personnaliser l'engagement client à l'aide de données en temps réel telles que les soldes de points, les promotions et les activités de récompense.

### Eppo - Test A/B {#eppo-ab-testing}

L'intégration entre Braze et [Eppo]({{site.baseurl}}/partners/eppo) vous permet de configurer des tests A/B dans Braze et d'analyser les résultats dans Eppo afin de découvrir des informations et de relier les performances des messages à des indicateurs commerciaux à long terme comme le chiffre d'affaires ou la rétention.

### Mention Me - Recommandation {#mention-me-referrals}

Ensemble, [Mention Me](https://www.mention-me.com/) et Braze peuvent être votre passerelle pour attirer des clients premium et favoriser une fidélité indéfectible à votre marque. En intégrant de façon fluide des données de recommandation first-party dans Braze, vous pouvez offrir des expériences omnicanales hautement personnalisées ciblant les ambassadeurs de votre marque. Pour commencer, consultez [Partenaires technologiques : Mention Me]({{site.baseurl}}/partners/mention_me).

### Shopify - eCommerce

[Connectez plusieurs domaines de boutiques Shopify]({{site.baseurl}}/shopify_connecting_multiple_stores) à un seul espace de travail pour obtenir une vue globale de vos clients sur tous les marchés. Créez et lancez des programmes d'automatisation et des parcours dans un seul espace de travail sans dupliquer les efforts entre les boutiques régionales.

## Mises à jour du SDK {#sdk-updates}

Les dernières mises à jour du SDK ont été publiées. Les mises à jour majeures sont répertoriées dans la section des mises à jour du SDK ; toutes les autres mises à jour sont disponibles dans les journaux des modifications des SDK correspondants.

- [Android SDK 36.0.0](https://pub.dev/packages/braze_plugin/changelog)
    - Cette version annule l'augmentation de la version minimale du SDK Android du SDK Braze Android, passée de l'API 21 à l'API 25 dans la version 34.0.0. Cela permet au SDK d'être à nouveau compilé dans des applications prenant en charge dès l'API 21. Notez que bien que nous réintroduisions la possibilité de compiler, nous ne réintroduisons pas le support formel pour les versions < API 25, et nous ne pouvons pas garantir que le SDK fonctionnera comme prévu sur les appareils exécutant ces versions.
    - Si votre application prend en charge ces versions, vous devriez :
        - Valider que votre intégration du SDK fonctionne comme prévu sur des appareils physiques (et pas uniquement des émulateurs) pour ces versions d'API.
        - Si vous ne pouvez pas valider le comportement attendu, vous devez soit appeler [disableSDK](https://braze-inc.github.io/braze-android-sdk/kdoc/braze-android-sdk/com.braze/-braze/-companion/disable-sdk.html), soit ne pas initialiser le SDK sur ces versions. Sinon, vous risquez de provoquer des effets secondaires indésirables ou des performances dégradées sur les appareils de vos utilisateurs finaux.
    - Correction d'un problème où les messages in-app provoquaient une lecture sur le thread principal.
    `BrazeInAppMessageManager.displayInAppMessage` est désormais une fonction Kotlin suspend.
        - Si vous n'appelez pas cette fonction directement, vous n'avez pas besoin d'effectuer de modifications.
    - Le BOM AndroidX Compose a été mis à jour vers la version 2025.04.01 pour gérer les changements dans les API Jetpack Compose.
- [React Native SDK 15.0.0](https://github.com/braze-inc/braze-react-native-sdk/blob/master/CHANGELOG.md)
    - Mise à jour du pont Android natif du SDK Braze Android 35.0.0 vers 36.0.0.
    - Mise à jour des liaisons de version iOS natives du SDK Braze Swift 11.9.0 vers 12.0.0.
    - Mise à jour de la représentation de l'unité de PushNotificationEvent.timestamp en millisecondes sur iOS.
        - Auparavant, cette valeur était représentée en secondes sur iOS. Elle correspond désormais à l'implémentation Android existante.
- [Web SDK 5.9.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [Flutter SDK 14.0.0 5.9.0](https://pub.dev/packages/braze_plugin/changelog)
    - Cette version annule l'augmentation de la version minimale du SDK Android du SDK Braze Android, passée de l'API 21 à l'API 25 dans la version 34.0.0. Cela permet au SDK d'être à nouveau compilé dans des applications prenant en charge dès l'API 21. Cependant, nous ne réintroduisons pas le support formel pour les versions < API 25. Consultez l'[entrée du journal des modifications du SDK Braze Android](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#3600).
    - Mise à jour du pont Android natif du SDK Braze Android 35.0.0 vers 36.0.0.
    - Mise à jour du pont iOS natif du SDK Braze Swift 11.9.0 vers 12.0.0.
