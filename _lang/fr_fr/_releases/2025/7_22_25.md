# Version du 22 juillet 2025 {#july-22-2025-release}

## Exportation des événements de sécurité avec Amazon S3 {#security-events-export-with-amazon-s3}

Vous pouvez [exporter automatiquement les événements de sécurité vers Amazon S3]({{site.baseurl}}/user_guide/administer/global/admin_settings/security_settings/security_export_s3/), un fournisseur de stockage cloud, grâce à une tâche quotidienne qui s'exécute à minuit UTC. Une fois configuré, vous n'avez plus besoin d'exporter manuellement les événements de sécurité depuis le tableau de bord.

## Flexibilité des données {#data-flexibility}

### Importation CSV {#csv-import}

{% multi_lang_include release_type.md release="General availability" %}

Vous pouvez utiliser l'importation CSV pour enregistrer et mettre à jour les attributs utilisateur et les événements personnalisés dans Braze, comme `first_name`, `last_destination_searched` et `trip_booked`. Pour commencer, consultez [Importation CSV]({{site.baseurl}}/user_guide/audience/manage_audience/import_users/csv_import/).

### Alertes d'utilisation de l'API {#api-usage-alerts}

{% multi_lang_include release_type.md release="General availability" %}

Les alertes d'utilisation de l'API offrent une visibilité essentielle sur votre utilisation de l'API, vous permettant de détecter de manière proactive un trafic inattendu. En configurant ces alertes pour suivre les volumes de requêtes API clés, vous pouvez recevoir des notifications en temps réel et résoudre les problèmes avant qu'ils n'aient un impact sur vos campagnes marketing.

### Limites de débit de l'API de l'espace de travail {#workspace-api-rate-limits}

Avec les limites de débit de l'API de l'espace de travail, vous pouvez définir un nombre maximum de requêtes API qu'un espace de travail peut effectuer vers un endpoint d'ingestion spécifique, tel que `/users/track` ou les données SDK. Vous pouvez également appliquer des limites de débit à un groupe d'espaces de travail, ce qui signifie que la limite est partagée entre tous les espaces de travail de ce groupe.

### Période par défaut pour l'analytique des Campaigns {#default-time-range-for-campaign-analytics}

Par défaut, la période pour [**Campaign Analytics**]({{site.baseurl}}/user_guide/analytics/reports/campaign_analytics/) affiche les 90 derniers jours à partir de l'heure actuelle. Cela signifie que si la Campaign a été lancée il y a plus de 90 jours, l'analytique affichera « 0 » pour la période donnée. Pour afficher toutes les données analytiques des Campaigns plus anciennes, ajustez la période de rapport.

### Mise à jour du comportement de l'étape des chemins d'expérience Canvas {#updated-behavior-for-canvas-experiment-paths-step}

Si votre Canvas comporte une [expérience]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/experiment_step/) de chemin gagnant ou de chemin personnalisé active ou en cours et que vous mettez à jour le Canvas actif, que vous mettiez ou non à jour l'étape des chemins d'expérience elle-même, l'expérience en cours prendra fin et l'étape d'expérience ne déterminera pas de chemin gagnant ni de chemins personnalisés. Pour redémarrer l'expérience, vous pouvez déconnecter le chemin d'expérience existant et en lancer un nouveau, ou dupliquer le Canvas et en lancer un nouveau. Dans le cas contraire, les utilisateurs suivront le chemin d'expérience comme si aucune méthode d'optimisation n'avait été sélectionnée.

Pour plus d'informations, consultez [Modification des Canvas après le lancement]({{site.baseurl}}/post-launch_edits/).

### Limite de débit plus rapide disponible pour l'endpoint `/users/export/ids` {#faster-rate-limit-available-for-usersexportids-endpoint}

Vous pouvez également augmenter la [limite de débit pour l'endpoint /users/export/ids]({{site.baseurl}}/api/endpoints/export/user_data/post_users_identifier/#rate-limit) à 40 requêtes par seconde en remplissant les conditions suivantes :

- La limite de débit par défaut (250 requêtes par minute) est activée dans votre espace de travail. Contactez votre gestionnaire de compte Braze pour obtenir de l'aide afin de supprimer toute limite de débit préexistante.
- Votre requête inclut le paramètre fields_to_export pour lister tous les champs que vous souhaitez recevoir.

## Libérer la créativité {#unlocking-creativity}

### Pages d'accueil {#landing-pages}

Vous pouvez rendre votre page d'accueil [réactive à la taille de l'appareil de l'utilisateur]({{site.baseurl}}/user_guide/engagement_tools/landing_pages/creating_pages/#step-3-customize-the-page) en empilant verticalement les colonnes sur les écrans plus petits. ## Canaux robustes {#robust-channels}

### Filtrage des bots pour les e-mails {#bot-filtering-for-emails}

{% multi_lang_include release_type.md release="General availability" %}

Configurez le filtrage des bots dans vos [préférences d'e-mail]({{site.baseurl}}/user_guide/administer/global/workspace_settings/email_preferences/) pour exclure tous les clics suspectés d'être générés par des machines ou des bots. Un « clic de bot » dans un e-mail désigne un clic sur des liens hypertextes dans un e-mail généré par un programme automatisé. En filtrant ces clics de bots, vous pouvez déclencher et envoyer intentionnellement des messages aux destinataires qui sont engagés.

### Blocs de produits par glisser-déposer {#drag-and-drop-product-blocks}

{% multi_lang_include release_type.md release="Early access" %}

L'[éditeur par glisser-déposer]({{site.baseurl}}/dnd_product_blocks/) vous permet d'ajouter et de configurer rapidement des blocs de produits dans vos messages pour une mise en valeur fluide des produits, sans avoir besoin de créer du code Liquid personnalisé. La fonctionnalité de blocs de produits par glisser-déposer n'est actuellement disponible que pour les e-mails.

### Texte span pour les pages d'accueil et les messages in-app {#span-text-for-landing-pages-and-in-app-messages}

Le texte span vous permet d'appliquer un style spécifique à des blocs de texte sans code personnalisé pour vos [pages d'accueil]({{site.baseurl}}/user_guide/engagement_tools/landing_pages/creating_pages/#step-3-customize-the-page) et vos [messages in-app]({{site.baseurl}}/user_guide/channels/in_app_messages/customize/style_settings/#blocks). Pour ce faire, mettez en surbrillance le texte que vous souhaitez styliser, puis sélectionnez **Wrap with span for style**.

### Publicités « cliquer vers WhatsApp » {#ad-click-to-whatsapp}

Les [publicités qui redirigent vers WhatsApp]({{site.baseurl}}/whatsapp_use_cases/) sont un moyen efficace d'attirer des clients nouveaux et existants depuis les publicités Meta sur Facebook, Instagram ou d'autres plateformes. Utilisez ces publicités pour promouvoir vos produits et services tout en sensibilisant les utilisateurs à votre présence sur WhatsApp.

## Nouveaux partenariats Braze {#new-braze-partnerships}

### Shopify Visitory API — eCommerce

Braze collecte les informations des visiteurs, telles que les adresses e-mail et les numéros de téléphone, par le biais de messages dans le navigateur. Ces informations sont ensuite envoyées à Shopify. Ces données aident les commerçants à reconnaître les visiteurs de leur boutique et à créer une expérience d'achat plus personnalisée.

### Okendo — eCommerce

L'intégration entre Braze et [Okendo]({{site.baseurl}}/partners/okendo/) fonctionne sur plusieurs produits de la plateforme d'Okendo, notamment les avis, la fidélité, les recommandations, les enquêtes et les quiz. Okendo envoie des événements personnalisés et des attributs utilisateur à Braze, qui peuvent être utilisés pour personnaliser et déclencher des messages.

### Lemnisk — Plateforme de données client {#lemnisk-customer-data-platform}

L'intégration entre Braze et [Lemnisk]({{site.baseurl}}/partners/lemnisk/) permet aux marques et aux entreprises de libérer tout le potentiel de Braze en agissant comme une couche d'intelligence pilotée par la CDP qui unifie les données utilisateur à travers les plateformes en temps réel, et en envoyant les informations et les comportements collectés de l'utilisateur à Braze en temps réel.

## Mises à jour SDK {#sdk-updates}

Les mises à jour SDK suivantes ont été publiées. Les mises à jour majeures sont répertoriées ci-dessous ; vous pouvez trouver toutes les autres mises à jour en consultant les journaux de modifications SDK correspondants.

- [SDK Web 6.0.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
    - Suppression de la propriété `Banner.html`, des méthodes `logBannerClick` et `logBannerImpressions`. Utilisez plutôt [`insertBanner`](https://js.appboycdn.com/web-sdk/latest/doc/modules/braze.html#insertbanner) qui gère automatiquement le suivi des impressions et des clics.
    - Suppression de la prise en charge de l'ancienne fonctionnalité News Feed. Cela inclut la suppression de la classe Feed et de ses méthodes associées.
    - Les champs created et categories qui étaient utilisés par les anciennes cartes News Feed ont été supprimés des sous-classes [`Card`](https://js.appboycdn.com/web-sdk/latest/doc/classes/braze.card.html).
    - Le champ linkText a également été supprimé de la sous-classe [`ImageOnly`](https://js.appboycdn.com/web-sdk/latest/doc/classes/braze.imageonly.html) Card et de son constructeur.
    - Clarification des définitions et mise à jour des types pour indiquer que certaines méthodes du SDK renvoient explicitement undefined lorsque le SDK n'est pas initialisé, alignant les typages sur le comportement réel à l'exécution. Cela pourrait introduire de nouvelles erreurs TypeScript dans les projets qui s'appuyaient sur les typages précédents (incomplets).
    - Les images des messages in-app avec `cropType` de `CENTER_CROP` (comme `FullScreenMessage` par défaut) sont désormais rendues via une balise `<img>` au lieu de `<span>` pour une meilleure accessibilité. Cela peut casser les personnalisations CSS existantes pour la classe `.ab-center-cropped-img` ou ses enfants.
- [Cordova SDK 13.0.0](https://github.com/braze-inc/braze-cordova-sdk/blob/master/CHANGELOG.md#1300)
    - Mise à jour de l'implémentation interne iOS de la méthode `enableSdk` pour utiliser setEnabled: au lieu de `_requestEnableSDKOnNextAppRun`, qui a été dépréciée dans le SDK Swift.
        - L'appel de cette méthode ne nécessite plus le redémarrage de l'application pour prendre effet. Le SDK sera activé dès que cette méthode sera exécutée.
    - Mise à jour du pont natif Android [du SDK Android de Braze 36.0.0 vers 37.0.0](https://github.com/braze-inc/braze-android-sdk/compare/v36.0.0...v37.0.0#diff-06572a96a58dc510037d5efa622f9bec8519bc1beab13c9f251e97e657a9d4ed).
- [SDK Android 37.0.0](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md)
- [SDK Swift 12.0.1-12.1.0](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md)
