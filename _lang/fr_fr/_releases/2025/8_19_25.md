# Version du 19 août 2025 {#august-19-2025-release}

## Normalisation de la cohérence des fuseaux horaires pour Canvas Context {#time-zone-consistency-standardization-to-canvas-context}

{% multi_lang_include release_type.md release="Early access" %}

Si vous participez à l'[accès anticipé de l'étape Canvas Context]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/context), tous les horodatages de type datetime provenant des propriétés d'événement déclencheur dans les Canvas basés sur une action seront toujours normalisés en [UTC](https://en.wikipedia.org/wiki/Coordinated_Universal_Time). Pour en savoir plus, consultez [Normalisation de la cohérence des fuseaux horaires]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/context#time-zone-consistency-standardization).

## Flexibilité des données {#data-flexibility}

### Domaines personnalisés en libre-service {#self-serve-custom-domains}

{% multi_lang_include release_type.md release="General access" %}

Les [domaines personnalisés en libre-service]({{site.baseurl}}/user_guide/channels/sms_mms_and_rcs/message_features_and_optimization/custom_domains) vous permettent de configurer et de gérer vos propres domaines personnalisés pour les SMS, le RCS et WhatsApp, directement depuis votre tableau de bord de Braze. Vous pouvez facilement ajouter, surveiller et gérer jusqu'à 10 domaines personnalisés au même endroit.

### Statistiques d'entonnoir de Segment {#segment-funnel-statistics}

Sélectionnez [Afficher les statistiques d'entonnoir]({{site.baseurl}}/user_guide/engagement_tools/segments/creating_a_segment#viewing-funnel-statistics) pour afficher les statistiques de ce groupe de filtres et voir comment chaque filtre ajouté impacte les statistiques de votre Segment. Vous verrez un nombre estimé et un pourcentage d'utilisateurs ciblés par l'ensemble des filtres jusqu'à ce point. Une fois les statistiques affichées pour un groupe de filtres, elles se mettent à jour automatiquement chaque fois que vous modifiez les filtres.

### Nouveaux champs de réponse pour l'endpoint `/campaigns/details` pour les notifications push {#new-response-fields-for-campaignsdetails-endpoint-for-push-notifications}

La réponse `messages` pour les notifications push inclut désormais deux nouveaux champs :

- `image_url` : une URL d'image pour une image de notification Android, une image de notification iOS ou une icône de notification push Web.
- `large_image_url` : une URL d'image de notification Web pour les actions de notification push Web Android Chrome et Windows.

### Définition des champs de données d'identification {#defining-pii-fields}

La sélection et la [définition de certains champs comme champs de données d'identification]({{site.baseurl}}/user_guide/administer/global/admin_settings/security_settings#view-pii) n'affectent que ce que les utilisateurs peuvent voir sur le tableau de bord de Braze et n'impactent pas la manière dont les données de l'utilisateur final dans ces champs de données d'identification sont traitées.

Consultez votre équipe juridique pour aligner les paramètres de votre tableau de bord sur les réglementations et politiques de confidentialité applicables à votre entreprise, y compris celles liées à la [conservation des données]({{site.baseurl}}/api/data_retention).

### Partage d'un lien de téléchargement du générateur de rapports {#sharing-a-report-builder-download-link}

Vous pouvez [partager un lien vers le tableau de bord]({{site.baseurl}}/user_guide/analytics/reporting/report_builder#sharing-a-report) du rapport en sélectionnant **Partager**, puis **Partager un lien** ou **Envoyer ou planifier un e-mail**.

## Libérer la créativité {#unlocking-creativity}

### Balises head personnalisées pour les e-mails par glisser-déposer {#custom-head-tags-for-drag-and-drop-emails}

Utilisez les balises `<head>` pour ajouter du CSS et des métadonnées dans votre e-mail. Par exemple, vous pouvez utiliser ces balises pour ajouter une feuille de style ou un favicon. Liquid est pris en charge dans les balises `<head>`.

### WhatsApp Flows

{% multi_lang_include release_type.md release="Early access" %}

[WhatsApp Flows]({{site.baseurl}}/whatsapp_flows) est une amélioration du canal WhatsApp existant, vous permettant de créer des expériences de communication interactives et dynamiques.

### Questions entrantes sur les produits WhatsApp {#whatsapp-inbound-product-questions}

Les utilisateurs peuvent répondre à votre message de produit ou de catalogue avec des [questions sur les produits]({{site.baseurl}}/user_guide/message_building_by_channel/whatsapp/whatsapp_campaign/product_messages#receiving-inbound-product-questions). Celles-ci arrivent sous forme de messages entrants, qui peuvent ensuite être triés à l'aide d'un parcours d'action.

De plus, Braze extrait l'ID du produit et l'ID du catalogue à partir de ces questions. Ainsi, si vous souhaitez automatiser les réponses ou transmettre les questions à une autre équipe (comme le support client), vous pouvez inclure ces détails.

## Mises à jour du SDK {#sdk-updates}

Les dernières mises à jour du SDK ont été publiées. Les modifications importantes sont répertoriées dans la section des mises à jour du SDK ; toutes les autres mises à jour sont disponibles dans les journaux des modifications correspondants de chaque SDK.

- [Swift SDK 13.0.0](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md)
    - Étend la fonctionnalité de `BrazeSDKAuthDelegate.braze(_:sdkAuthenticationFailedWithError:)` pour qu'elle se déclenche également en cas d'erreurs d'authentification « Optional ».
        - La méthode déléguée `BrazeSDKAuthDelegate.braze(_:sdkAuthenticationFailedWithError:)` sera désormais déclenchée à la fois pour les erreurs d'authentification « Required » et « Optional ».
        - Si vous souhaitez gérer uniquement les erreurs d'authentification SDK « Required », ajoutez une vérification garantissant que `BrazeSDKAuthError.optional` est false dans votre implémentation de cette méthode déléguée.
    - Corrige l'utilisation de `Braze.Configuration.sdkAuthentication` afin qu'elle soit prise en compte lorsqu'elle est activée.
        - Auparavant, la valeur de cette configuration n'était pas consommée par le SDK et le jeton était systématiquement attaché aux requêtes s'il était présent.
        - Désormais, le SDK n'attachera le jeton d'authentification SDK aux requêtes réseau sortantes que lorsque cette configuration est activée.
    - Les setters de toutes les propriétés de `Braze.FeatureFlag` et de toutes les propriétés de `Braze.Banner` sont désormais `private`. Les propriétés de ces classes sont maintenant en lecture seule.
    - Supprime la propriété `Braze.Banner.id`, qui avait été dépréciée dans la version `11.4.0`.
        - Utilisez plutôt `Braze.Banner.trackingId` pour lire l'ID de suivi de campagne d'un banner.
- [React Native SDK 16.0.0](https://github.com/braze-inc/braze-react-native-sdk/blob/master/CHANGELOG.md)
    - Met à jour les liaisons de version du SDK Android natif de [Braze Android SDK 36.0.0 vers 37.0.0](https://github.com/braze-inc/braze-android-sdk/compare/v36.0.0...v37.0.0#diff-06572a96a58dc510037d5efa622f9bec8519bc1beab13c9f251e97e657a9d4ed).
    - Met à jour les liaisons de version du SDK Swift natif de [Braze Swift SDK 12.0.0 vers 13.0.0](https://github.com/braze-inc/braze-swift-sdk/compare/12.0.0...13.0.0#diff-06572a96a58dc510037d5efa622f9bec8519bc1beab13c9f251e97e657a9d4ed).
        - L'événement `sdkAuthenticationError` se déclenchera désormais pour les erreurs d'authentification « Required » et « Optional ».
- [Xamarin SDK 7.0.0](https://github.com/braze-inc/braze-xamarin-sdk/blob/7.0.0/CHANGELOG.md)
    - Ajout de la prise en charge de .NET 9.0 pour les liaisons iOS et Android.
        - Cela supprime la prise en charge de .NET 8.0.
        - Cela nécessite une [version minimale d'iOS 12.2](https://learn.microsoft.com/en-us/dotnet/maui/whats-new/dotnet-9?view=net-maui-9.0).
    - Mise à jour de la liaison Android de [Braze Android 32.0.0 vers 37.0.0](https://github.com/braze-inc/braze-android-sdk/compare/v32.0.0...v37.0.0#diff-06572a96a58dc510037d5efa622f9bec8519bc1beab13c9f251e97e657a9d4ed).
    - Mise à jour de la liaison iOS de [Braze Swift SDK 10.0.0 vers 12.1.0](https://github.com/braze-inc/braze-swift-sdk/compare/10.0.0...12.1.0#diff-06572a96a58dc510037d5efa622f9bec8519bc1beab13c9f251e97e657a9d4ed).
    - Cette version contient des API pour la fonctionnalité Banners mais n'est pas encore entièrement prise en charge par ce SDK. Si vous souhaitez utiliser les Banners dans votre application .NET MAUI, contactez votre gestionnaire de support client avant de procéder à l'intégration dans votre application.
- [Cordova SDK 13.0.0](https://github.com/braze-inc/braze-cordova-sdk/blob/master/CHANGELOG.md#1300)
    - Mise à jour de l'implémentation iOS interne de la méthode `enableSdk` pour utiliser `setEnabled`: au lieu de `_requestEnableSDKOnNextAppRun`, qui avait été dépréciée dans le SDK Swift.
    - L'appel de cette méthode ne nécessite plus le redémarrage de l'application pour prendre effet. Le SDK sera désormais activé dès l'exécution de cette méthode.
    - Mise à jour du bridge Android natif de [Braze Android SDK `36.0.0` vers `37.0.0`](https://github.com/braze-inc/braze-android-sdk/compare/v36.0.0...v37.0.0#diff-06572a96a58dc510037d5efa622f9bec8519bc1beab13c9f251e97e657a9d4ed).
