# Version du 17 octobre 2023 {#october-17-2023-release}

## Copie vers des espaces de travail {#copying-to-workspaces}

[Copier des Campaigns d'un espace de travail à un autre]({{site.baseurl}}/user_guide/messaging/governance/copy_across_workspaces) vous permet de prendre une longueur d'avance dans la composition de vos messages en partant d'une copie d'une Campaign dans un autre espace de travail. Cette copie restera à l'état de brouillon jusqu'à ce que vous la modifiiez et la lanciez, ce qui vous aide à conserver et à développer vos stratégies de communication efficaces.

## Tester les connecteurs Currents {#test-currents-connectors}

Les [connecteurs Currents de test]({{site.baseurl}}/user_guide/data_and_analytics/braze_currents/setting_up_currents#test-currents-connectors) sont des versions gratuites de nos connecteurs existants qui peuvent être utilisées pour tester et essayer différentes destinations. Les Currents de test présentent les caractéristiques suivantes :

- Aucune limite au nombre de connecteurs Currents de test que vous pouvez créer.
- Un maximum cumulé de 10 000 événements par période glissante de 30 jours. Ce total d'événements est mis à jour toutes les heures sur le tableau de bord.

## Feature flags

Les [feature flags]({{site.baseurl}}/developer_guide/feature_flags) vous permettent d'activer ou de désactiver à distance des fonctionnalités pour une sélection spécifique ou aléatoire d'utilisateurs. Ils vous permettent notamment d'activer et de désactiver une fonctionnalité en production sans déploiement de code supplémentaire ni mise à jour de la boutique d'applications. Vous pouvez ainsi déployer de nouvelles fonctionnalités en toute sécurité et en toute confiance.

## Expériences de feature flags {#feature-flag-experiments}

Les [expériences de feature flags]({{site.baseurl}}/developer_guide/feature_flags/experiments) vous permettent de réaliser des tests A/B sur les modifications apportées à vos applications afin d'optimiser les taux de conversion. Les marketeurs peuvent utiliser les feature flags pour déterminer si une nouvelle fonctionnalité a un impact positif ou négatif sur les taux de conversion, ou quel ensemble de propriétés de feature flag est le plus optimal.

## Fusion des profils utilisateur {#merging-user-profiles}

Si votre recherche sur la page **Rechercher des utilisateurs** renvoie plusieurs profils utilisateur, vous pouvez [fusionner les profils utilisateur]({{site.baseurl}}/user_guide/audience/manage_audience/merge_duplicate_users) en cliquant sur le bouton **Fusionner les doublons**. Vous pouvez sélectionner le profil utilisateur à conserver, ce qui signifie que ce profil sera conservé et héritera des attributs du profil fusionné.

## Données de performance par segment {#performance-data-by-segment}

Vous pouvez désormais utiliser les modèles de rapports du générateur de requêtes pour [ventiler les données de performance]({{site.baseurl}}/user_guide/data_and_analytics/reporting/viewing_and_understanding_segment_data#performance-data-by-segment) par Segments pour les Campaigns, Canvas, variantes et étapes.

## Mise à jour des profils utilisateur {#updating-user-profiles}

Vous pouvez désormais utiliser l'[endpoint `/users/track`]({{site.baseurl}}/api/endpoints/user_data/post_user_track) pour mettre à jour un profil utilisateur par numéro de téléphone ou par e-mail.

## Mises à jour du SDK {#sdk-updates}

Les dernières mises à jour du SDK ont été publiées. Les modifications importantes sont répertoriées dans la section des mises à jour du SDK ; toutes les autres mises à jour sont disponibles dans les journaux des modifications correspondants de chaque SDK.

- [Braze Segment Swift Plugin v2.1.0](https://github.com/braze-inc/braze-segment-swift/blob/main/CHANGELOG.md)
- [SDK Web v4.10.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [SDK Web v5.0.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
    - Le rappel [`subscribeToFeatureFlagsUpdates()`](https://js.appboycdn.com/web-sdk/latest/doc/modules/braze.html#subscribetofeatureflagsupdates) sera désormais toujours appelé, indépendamment du succès ou de l'échec de l'actualisation. En cas d'échec de la réception des mises à jour, le rappel sera appelé avec les feature flags actuellement en cache.
    - La méthode [`getFeatureFlag()`](https://js.appboycdn.com/web-sdk/latest/doc/modules/braze.html#getfeatureflag) renvoie désormais null si le feature flag n'existe pas ou si les feature flags sont désactivés.
    - Suppression de la méthode `logContentCardsDisplayed()` qui avait été précédemment dépréciée dans la version 4.0.4.
    - Suppression de l'option d'initialisation dépréciée `enableHtmlInAppMessages`. Elle doit être remplacée par l'option `allowUserSuppliedJavascript`.
    - Suppression de la classe Banner qui avait été précédemment dépréciée dans la version 4.9.0 au profit de [`ImageOnly`](https://js.appboycdn.com/web-sdk/latest/doc/classes/braze.imageonly.html).
    - Suppression du nom de classe CSS `ab-banner` dans le cadre de la suppression de la classe `Banner`. Les personnalisations CSS doivent désormais cibler la classe `ab-image-only`.
    - Le SDK ne génère plus d'erreurs d'exécution. Si des méthodes Braze sont appelées avant l'initialisation, un avertissement sera enregistré dans la console à la place.
    - Le SDK n'ajoute plus les styles par défaut des messages in-app de Braze aux messages in-app HTML personnalisés. Ces styles étaient auparavant utilisés par les anciens types de messages in-app.
- [SDK Android 29.0.0](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md)
    - Renommage de `BannerImageCard`, `BannerImageCardView` et `BannerImageContentCardView` en `ImageOnlyCard`, `ImageOnlyCardView` et `ImageOnlyContentCardView`.
    - Tous les styles utilisés pour les Banner Cards ont été mis à jour pour les Image Only Cards. Toutes les clés contenant le mot `banner` doivent être remplacées par `image_only`.
    - Les informations sur la marque de l'appareil sont désormais envoyées. Si vous souhaitez bloquer cela, consultez la section Blocage de la collecte de données.
- [SDK Flutter 7.0.0](https://pub.dev/packages/braze_plugin/changelog)
    - Mise à jour du pont Android natif [de Braze Android SDK 26.1.1 à 27.0.1](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#2701).
    - Ajout de la prise en charge de Gradle 8.
- [SDK Swift 7.0.0](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md)
    - La configuration `useUUIDAsDeviceId` est désormais activée par défaut.
        - Pour plus de détails sur les impacts, consultez [Collecte de l'IDFV - Swift]({{site.baseurl}}/developer_guide/analytics/managing_data_collection/?sdktab=swift).
    - Le type de Content Card Banner et les éléments d'interface correspondants ont été renommés en `ImageOnly`. Toutes les méthodes et propriétés des membres restent identiques.
        - `Braze.ContentCard.Banner` → `Braze.ContentCard.ImageOnly`
        - `BrazeContentCardUI.BannerCell` → `BrazeContentCardUI.ImageOnlyCell`
    - Refactorisation de certaines logiques de mise en page de texte dans BrazeUI vers une nouvelle classe Braze.ModalTextView.
    - Mise à jour du comportement des méthodes Feature Flags.
        - `FeatureFlags.featureFlag(id:)` renvoie désormais nil pour un ID qui n'existe pas.
        - `FeatureFlags.subscribeToUpdates(:)` déclenchera le rappel lorsqu'une demande d'actualisation se termine avec un succès ou un échec.
            - Le rappel se déclenchera également immédiatement lors de l'abonnement initial si des données précédemment mises en cache existent.
- [AppboyKit iOS SDK 4.6.0](https://github.com/Appboy/appboy-ios-sdk/releases/tag/4.6.0)
    - Cette version nécessite Xcode `14.x`.
    - Abandon de la prise en charge d'iOS 9 et d'iOS 10.
    - Suppression de la prise en charge des anciens éléments `.framework` lors de l'importation via Carthage au profit des éléments modernes `.xcframework`.
        - Utilisez la commande `carthage update --use-xcframeworks` pour importer la ressource Braze appropriée.
        - Suppression de la prise en charge de `appboy_ios_sdk_full.json` au profit de `appboy_ios_sdk.json`.
