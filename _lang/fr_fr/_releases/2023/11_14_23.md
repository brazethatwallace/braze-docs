# Version du 14 novembre 2023 {#november-14-2023-release}

## Premiers pas avec Braze {#getting-started-with-braze}

Bonne nouvelle ! Nous vous présentons deux sections Premiers pas conçues spécifiquement pour nos [marketeurs]({{site.baseurl}}/user_guide/get_started) et [développeurs]({{site.baseurl}}/developer_guide/getting_started) Braze. Ces sections sont pensées pour vous aider à démarrer rapidement avec Braze, en vous fournissant tous les outils et conseils nécessaires. Plongez-y et commencez à explorer.

## Nouvelle instance du tableau de bord de Braze {#new-braze-dashboard-instance}

Braze gère un certain nombre d'instances différentes pour notre tableau de bord et nos endpoints REST. Nous avons ajouté une nouvelle instance de tableau de bord `US-07`. Pour plus d'informations, consultez l'[aperçu de l'API]({{site.baseurl}}/api/basics).

## Canaux robustes {#robust-channels}

### Modèles personnalisés par glisser-déposer pour les messages in-app {#custom-drag-and-drop-templates-for-in-app-messages}

{% multi_lang_include release_type.md release="General availability" %}

Vous pouvez désormais utiliser des [modèles personnalisés par glisser-déposer pour les messages in-app]({{site.baseurl}}/user_guide/channels/in_app_messages/drag_and_drop) pour commencer à concevoir votre message in-app dans l'éditeur par glisser-déposer.

### Double opt-in SMS {#sms-double-opt-in}

{% multi_lang_include release_type.md release="General availability" %}

Le [double opt-in SMS]({{site.baseurl}}/user_guide/channels/sms_mms_and_rcs/message_features_and_optimization/keyword_processing/double_opt_in) vous permet d'exiger que les utilisateurs confirment explicitement leur intention d'abonnement avant de pouvoir recevoir des messages SMS. Cela vous aide à concentrer vos efforts sur les utilisateurs qui sont susceptibles d'être engagés ou qui interagissent déjà avec le SMS.

### Taux d'ouverture réel estimé pour le reporting e-mail {#estimated-real-open-rate-for-email-reporting}

{% multi_lang_include release_type.md release="General availability" %}

Le [taux d'ouverture réel estimé]({{site.baseurl}}/user_guide/channels/email/reporting#estimated-real-open-rate) utilise un modèle analytique propriétaire créé par Braze pour reconstituer une estimation du taux d'ouverture unique de la Campaign comme si les ouvertures automatiques n'existaient pas. Braze utilise les données de clics de chaque Campaign pour déduire le taux auquel de véritables utilisateurs ont ouvert le message. Cela compense les divers mécanismes d'ouverture automatique, y compris la protection de la confidentialité dans Mail d'Apple.

### Chemins personnalisés pour Canvas {#personalized-paths-for-canvas}

{% multi_lang_include release_type.md release="Beta" %}

Avec les [chemins personnalisés]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/experiment_step/personalized_paths), vous pouvez personnaliser des parcours Canvas entiers pour chaque utilisateur en fonction de la probabilité de conversion, de manière similaire aux variantes personnalisées dans les Campaigns. Utilisez les chemins personnalisés avec une étape de chemin d'expérience pour maintenir une partie des utilisateurs dans un groupe de délai pendant que Braze teste les autres chemins les uns par rapport aux autres.

## Flexibilité des données {#data-flexibility}

### Recherche dans votre tableau de bord de Braze {#searching-your-braze-dashboard}

{% multi_lang_include release_type.md release="General availability" %}

Vous pouvez utiliser la [barre de recherche]({{site.baseurl}}/user_guide/administer/personal/the_braze_dashboard) pour trouver votre travail et d'autres informations dans votre tableau de bord de Braze. La barre de recherche se trouve en haut de votre tableau de bord de Braze.

### Blocage d'attributs personnalisés et d'événements personnalisés {#blocklisting-custom-attributes-and-events}

{% multi_lang_include release_type.md release="General availability" %}

Vous pouvez désormais bloquer jusqu'à 10 attributs personnalisés ou événements personnalisés à la fois. Pour en savoir plus, consultez la section [Gestion des événements personnalisés et des attributs personnalisés]({{site.baseurl}}/user_guide/data/activation/custom_data/managing_custom_data).

### Nouvel article d'aide : liens universels et App Links {#new-help-article-universal-links-and-app-links}

Les liens universels Apple et les Android App Links sont des mécanismes conçus pour assurer une transition fluide entre le contenu web et les applications mobiles. Alors que les liens universels sont spécifiques à iOS, les Android App Links remplissent la même fonction pour les applications Android.

Pour en savoir plus sur ce sujet, consultez notre article dédié [Liens universels et App Links]({{site.baseurl}}/user_guide/channels/email/customize/universal_links_and_app_links).

## Nouveaux partenariats Braze {#new-braze-partnerships}

### Olo – Extensions de canaux {#olo-channel-extensions}

L'intégration de Braze et [Olo]({{site.baseurl}}/partners/ecommerce/ordering_payments_subscription/olo) vous permet de mettre à jour les profils utilisateur dans Braze afin de les maintenir en cohérence avec les profils utilisateur Olo. Vous pouvez également envoyer les messages appropriés depuis Braze en fonction des événements Olo.

### Typeform – Plateforme de données client {#typeform-customer-data-platform}

L'intégration de Braze et [Typeform]({{site.baseurl}}/partners/additional_channels_and_extensions/extensions/surveys/typeform) vous permet de mettre à jour les profils utilisateur dans Braze avec les données collectées à partir de leurs réponses Typeform, de déclencher des messages dans Braze en fonction de l'interaction d'un utilisateur avec un formulaire Typeform, et de personnaliser les messages Braze en fonction des réponses Typeform d'un utilisateur.

## Mises à jour du SDK {#sdk-updates}

Les dernières mises à jour du SDK ont été publiées. Les mises à jour majeures sont répertoriées dans la section des mises à jour du SDK ; toutes les autres mises à jour se trouvent dans les journaux des modifications correspondants de chaque SDK.

- [SDK Web v4.10.1](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [SDK Web v5.0.1](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [SDK Android 29.0.1](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md)
- [SDK Swift 7.1.0-7.2.0](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md)
    - `Braze.Configuration.DeviceProperty.pushDisplayOptions` est obsolète. Fournir cette valeur n'a plus aucun effet.
- [SDK React Native 8.0.0-8.1.0](https://github.com/braze-inc/braze-react-native-sdk/blob/master/CHANGELOG.md)
    - Met à jour le pont Android natif du SDK Android de Braze 27.0.1 vers 29.0.0.
    - Met à jour le pont iOS natif du SDK Swift de Braze 6.6.0 vers 7.0.0.
    - Renomme le type de Content Card `Banner` en ImageOnly :
        - `BannerContentCard` en `ImageOnlyContentCard`
        - `ContentCardTypes.BANNER` en `ContentCardTypes.IMAGE_ONLY`
    - Sur Android, si les fichiers XML de votre projet contiennent le mot `banner` pour les Content Cards, il doit être remplacé par `image_only`.
    - `Braze.getFeatureFlag(id)` renverra désormais `null` si le feature flag n'existe pas.
    - `Braze.Events.FEATURE_FLAGS_UPDATED` ne se déclenchera que lorsqu'une requête d'actualisation se termine avec succès ou en échec, et lors de l'abonnement initial s'il existait des données en cache de la session en cours.
