# Version du 19 septembre 2023 {#september-19-2023-release}

## BigQuery pour l'ingestion de données cloud {#bigquery-for-cloud-data-ingestion}

Vous pouvez désormais créer des intégrations d'ingestion de données cloud avec [BigQuery](https://cloud.google.com/bigquery), un entrepôt de données d'entreprise serverless. Pour plus d'informations, consultez la section [Intégrations d'ingestion de données cloud]({{site.baseurl}}/user_guide/data_and_analytics/cloud_ingestion/integrations/?tab=bigquery).

## Braze Data Transformation

[Braze Data Transformation]({{site.baseurl}}/user_guide/data/unification/data_transformation) vous permet de créer et de gérer des intégrations webhook pour automatiser le flux de données depuis des plateformes externes vers les profils utilisateur Braze. Ces données utilisateur nouvellement intégrées peuvent ensuite alimenter des cas d'usage marketing encore plus sophistiqués.

## Commenter dans Canvas {#commenting-in-canvas}

[Les commentaires dans les Canvas]({{site.baseurl}}/user_guide/messaging/canvas/create_a_canvas/canvas_comments) peuvent constituer un excellent espace collaboratif pour votre équipe marketing afin d'identifier, discuter et examiner les détails de vos Canvas. Lors de la création d'un Canvas, vous pouvez rédiger et gérer des commentaires pour identifier les points qui pourraient nécessiter des retours supplémentaires de la part de vos collègues.

## Centre de livrabilité {#deliverability-center}

Le [Centre de livrabilité]({{site.baseurl}}/user_guide/analytics/dashboards/deliverability_center) fournit des informations plus détaillées sur les performances de vos e-mails en prenant en charge l'utilisation de Gmail Postmaster Tools pour suivre les données relatives aux e-mails envoyés et recueillir des données sur votre domaine d'envoi.

La livrabilité des e-mails est au cœur du succès d'une campagne. En utilisant le Centre de livrabilité dans le tableau de bord de Braze, vous pouvez consulter vos domaines par réputation IP ou par erreurs de distribution afin de découvrir et résoudre tout problème potentiel lié à la livrabilité des e-mails.

## Éditeur par glisser-déposer pour les messages in-app {#drag-and-drop-editor-for-in-app-messages}

Ces fonctionnalités supplémentaires ont été ajoutées à l'[éditeur par glisser-déposer pour les messages in-app]({{site.baseurl}}/user_guide/channels/in_app_messages/drag_and_drop) :

- Liens textuels qui ne ferment pas le message
- Action de bouton pour demander l'amorce de notification push
- Bloc éditeur de code personnalisé

Pour profiter de toutes les fonctionnalités disponibles dans l'éditeur par glisser-déposer, mettez à jour vos SDK vers les versions de SDK recommandées.

### Enregistrer des modèles personnalisés (accès anticipé) {#save-custom-templates-early-access}

Dans l'éditeur par glisser-déposer pour les messages in-app, les participants à l'accès anticipé peuvent créer et enregistrer des modèles de messages in-app personnalisés à l'aide du bouton **Enregistrer comme modèle**, disponible après avoir quitté l'éditeur. Avant de pouvoir l'enregistrer comme modèle, vous devez d'abord lancer la campagne OU l'enregistrer comme brouillon.

Vous pouvez également créer et enregistrer des modèles de messages in-app en accédant à **Modèles** > **Modèles de messages in-app**.

## Désactivation du mode sombre pour les messages in-app {#disabling-dark-mode-for-in-app-messages}

Les développeurs peuvent empêcher les messages in-app d'adopter le style du mode sombre lorsque l'appareil de l'utilisateur a le mode sombre activé. Pour connaître les étapes de mise en œuvre, consultez la documentation suivante par plateforme :

- [Swift]({{site.baseurl}}/developer_guide/platform_integration_guides/swift/in-app_messaging/customization/setting_delegates#disabling-dark-mode)
- [Objective-C]({{site.baseurl}}/developer_guide/platform_integration_guides/ios/in-app_messaging/customization/handling_in_app_display#disabling-dark-mode)

## Nouveaux champs pour l'archivage des messages {#new-fields-for-message-archiving}

L'[archivage des messages]({{site.baseurl}}/user_guide/data/distribution/export_braze_data/message_archiving) vous permet d'enregistrer une copie des messages envoyés aux utilisateurs à des fins d'archivage ou de conformité dans votre compartiment S3. Les champs suivants ont été ajoutés au payload JSON livré à votre compartiment S3 chaque fois qu'un message est envoyé :

- `user_id`
- `campaign_name`
- `canvas_name`
- `canvas_step_name`

## Nouvelles balises de personnalisation Liquid {#new-liquid-personalization-tags}

Pour les messages in-app, vous pouvez utiliser les attributs d'application suivants dans Liquid. Les valeurs sont basées sur la clé API du SDK que vos applications utilisent pour demander la communication :

- {% raw %}`{{app.${api_id}}}`{% endraw %}
- {% raw %}`{{app.${name}}}`{% endraw %}

Pour en savoir plus, consultez [Balises de personnalisation prises en charge]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/liquid/supported_personalization_tags#targeted-app-information).

## Nouveaux partenariats Braze {#new-braze-partnerships}

### Antavo Loyalty Cloud – Extensions de canaux {#antavo-loyalty-cloud-channel-extensions}

L'intégration d'[Antavo]({{site.baseurl}}/partners/data_and_analytics/loyalty/antavo) et de Braze vous permet d'utiliser les données liées aux programmes de fidélité pour créer des campagnes personnalisées et améliorer l'expérience client. Antavo prend en charge la synchronisation des données de fidélité entre les deux plateformes — il s'agit d'une synchronisation de données unidirectionnelle, uniquement d'Antavo vers Braze.

### Ketch – Plateforme de données client {#ketch-customer-data-platform}

L'intégration de Braze et de [Ketch]({{site.baseurl}}/partners/data_and_analytics/data_privacy/ketch) vous permet de contrôler les préférences de communication des clients au sein du centre de préférences Ketch et de propager automatiquement ces modifications vers Braze.

### Redpoint – Plateforme de données client {#redpoint-customer-data-platform}

Redpoint est une plateforme technologique qui offre aux marketeurs une plateforme d'orchestration de campagnes entièrement intégrée. L'intégration de Braze et de [Redpoint]({{site.baseurl}}/partners/data_and_analytics/customer_data_platform/redpoint) vous permet de créer des Segments Braze à partir des données de votre CDP Redpoint.

### Simon Data – Plateforme de données client {#simon-data-customer-data-platform}

Utilisez l'intégration de Braze et de [Simon Data]({{site.baseurl}}/partners/data_and_analytics/customer_data_platform/simonai) pour créer et synchroniser des audiences sophistiquées vers Braze afin de les orchestrer en temps réel et sans code. Grâce à cette intégration, vous pouvez tirer parti des fonctionnalités avancées de Simon en matière de priorisation des campagnes et de correspondance d'identités, de la prise en charge d'agrégats complexes, et bien plus encore, pour optimiser vos Campaigns Braze en aval.

## Mises à jour du SDK {#sdk-updates}

Les dernières mises à jour du SDK ont été publiées. Les mises à jour majeures sont répertoriées dans la section des mises à jour du SDK ; toutes les autres mises à jour sont disponibles dans les journaux des modifications correspondants de chaque SDK.

- [SDK Swift 6.6.1](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md#661)
- [SDK Web 4.9.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md#490)
- [SDK Android 28.0.0](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#2800)
    - Version minimale du SDK mise à jour à 21 (Lollipop).
    - Les fonctions des Feature Flags ont été modifiées.
    - `Braze.getFeatureFlag(id)` retournera désormais null si le Feature Flag n'existe pas.
    - `Braze.subscribeToFeatureFlagsUpdates()` ne déclenchera un rappel que lorsqu'une demande d'actualisation sera terminée, et initialement si des données mises en cache existent. Il sera également appelé avec les Feature Flags mis en cache en cas d'échec de l'actualisation.
        - Si vous souhaitez obtenir la valeur mise en cache immédiatement au démarrage de l'application, utilisez `Braze.getFeatureFlag(id)`.
    - Refactorisation de `DefaultInAppMessageViewWrapper.createButtonClickListener()` en `DefaultInAppMessageViewWrapper.createButtonClickListeners()`.
- [SDK React Native 7.0.0](https://github.com/braze-inc/braze-react-native-sdk/blob/master/CHANGELOG.md#700)
    - Met à jour le pont Android natif du [SDK Android de Braze 26.3.2 vers 27.0.1](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#2701).
- [SDK Cordova 7.0.0](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#2800)
    - Met à jour le pont Android natif du [SDK Android de Braze 26.3.2 vers 27.0.1](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#2701).
- [SDK Roku 2.0.0](https://github.com/braze-inc/braze-roku-sdk/blob/main/CHANGELOG.md#200)
    - `getFeatureFlag` retournera une valeur invalide lorsque le flag n'existe pas.
    - `BrazeTask` observe désormais `BrazeFeatureFlagsUpdated` pour savoir quand les actualisations des Feature Flags réussissent ou échouent. Les valeurs des données peuvent ne pas toujours être différentes.
