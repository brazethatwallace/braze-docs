## Flexibilité des données {#data-flexibility}

### Notifications de retour en stock pour les catalogues {#back-in-stock-notifications-for-catalogs}

{% multi_lang_include release_type.md release="Early access" %}

En combinant les [notifications de retour en stock]({{site.baseurl}}/user_guide/data/activation/catalogs/catalog_triggers/back_in_stock_notifications/) via les catalogues et un Canvas, vous pouvez informer les clients lorsqu'un article est de nouveau disponible. Chaque fois qu'un client effectue un événement personnalisé sélectionné, il peut être automatiquement abonné pour être notifié lorsque l'article est réapprovisionné.

### Segments de catalogue {#catalog-segments}

{% multi_lang_include release_type.md release="Early access" %}

Les [segments de catalogue]({{site.baseurl}}/user_guide/audience/segments/segment_extension/sql_segments/catalog_segments/) sont des audiences d'utilisateurs basées sur les données de catalogue dans les extensions de segments SQL. Ces extensions de segments SQL peuvent être référencées dans un Segment, puis ciblées par des Campaigns et des Canvas. Les segments de catalogue utilisent SQL pour joindre des données provenant des catalogues avec des données issues d'événements personnalisés ou d'achats. Pour ce faire, vous devez disposer d'un champ d'identifiant commun entre vos catalogues et vos événements personnalisés ou achats.

### Migration vers l'API Firebase Cloud Messaging {#migrating-to-the-firebase-cloud-messaging-api}

{% multi_lang_include release_type.md release="Early access" %}

Découvrez [comment migrer]({{site.baseurl}}/developer_guide/push_notifications/?sdktab=android) depuis l'API Cloud Messaging obsolète de Google vers l'API Firebase Cloud Messaging (FCM), entièrement prise en charge.

## Mises à jour du SDK {#sdk-updates}

Les mises à jour suivantes du SDK ont été publiées. Les mises à jour majeures sont répertoriées ci-dessous ; vous pouvez consulter les journaux des modifications des SDK correspondants pour retrouver toutes les autres mises à jour.

- [SDK Swift 7.5.0](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md)
    - Ajoute des manifestes de confidentialité pour `BrazeKit` et `BrazeLocation` afin de décrire les politiques de collecte de données de Braze. Pour plus de détails, consultez la [documentation](https://developer.apple.com/documentation/bundleresources/privacy_manifest_files/describing_data_use_in_privacy_manifests) d'Apple sur les manifestes de confidentialité. Des configurations supplémentaires pour gérer vos pratiques de collecte de données seront disponibles dans une prochaine version.
    - Corrige un problème lié aux signatures de code des XCFrameworks introduit dans la version 7.1.0.
- [SDK Web v5.1.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [SDK Unity 5.0.0](https://github.com/braze-inc/braze-unity-sdk/blob/master/CHANGELOG.md)
    - Mise à jour du pont iOS natif du SDK Braze Swift de la version 6.1.0 à 7.4.0.
        - Le lien du dépôt iOS pointe désormais vers les XCFrameworks dynamiques préconfigurés de ce [dépôt](https://github.com/braze-inc/braze-swift-sdk-prebuilt-dynamic).
    - Mise à jour du pont Android natif du SDK Android Braze de la version 27.0.1 à 29.0.1.
    - `AppboyBinding.GetFeatureFlag(string id)` renverra désormais `null` si l'indicateur de fonctionnalité n'existe pas.
    - `FEATURE_FLAGS_UPDATED` ne se déclenchera que lorsqu'une demande d'actualisation se sera soldée par un succès ou un échec, et lors de l'abonnement initial si des données de la session en cours avaient été mises en cache précédemment.
