# 사용자 아카이브 {#user-archival}

> 매주 일요일 미국 동부 표준시(EST) 오전 5시 30분에 Braze는 비활성 사용자와 휴면 사용자를 Braze 서비스에서 제거하는 프로세스를 실행합니다. Braze는 워크스페이스의 사용자 수가 250,000명에 도달하지 않는 한 사용자를 아카이브하지 않습니다.

이 프로세스는 Braze가 Campaign 도달 가능 오디언스에 대한 정확한 통계를 제공하는 데 도움이 됩니다. 또한 [GDPR][1]의 두 가지 주요 개념에 따라 운영됩니다:

1. 저장 제한 원칙 — 처리 및 저장된 개인 데이터는 필요한 기간을 초과하여 보관하지 않아야 합니다
2. 개인 데이터를 처리할 정당한 비즈니스 목적을 가져야 합니다.

즉, 처리 및 저장되는 개인 데이터는 필요 이상으로 오래 보관하지 않아야 하며, 개인 데이터는 정당한 비즈니스 목적으로만 처리되어야 합니다. 아카이브된 사용자는 GDPR을 준수하여 탈퇴 상태도 삭제됩니다.

{% alert important %}
아카이브된 사용자는 영구 삭제됩니다. <br><br>Canvas를 사용하여 [사용자 아카이브 정책을 커스텀할](#customizing-your-user-archival-policy) 수 있습니다. 고객은 사용자의 비활성 또는 휴면 여부를 완전히 제어할 수 있습니다. Canvas에서는 이 작업을 자동으로 수행할 수 있는 기능을 제공하므로 비활성 또는 휴면 사용자의 일부 또는 전체에 대해 이 기능을 효과적으로 해제할 수 있습니다.
{% endalert %}

## 사용자 아카이브 정의 {#user-archival-definitions}

### 활성 사용자 {#active-users}

Braze는 특정 기간 동안의 "활성 사용자"를 모바일 앱이나 웹사이트에서 세션을 기록했거나, 업데이트되었거나, 메시지를 수신했거나, 메시지와 상호작용한 사용자로 정의합니다.

새 사용자가 로그인할 때 사용자를 식별하기 위해 사용자 ID를 설정하면, 해당 사용자는 별도의 활성 사용자로 집계됩니다. API를 통해 업데이트된 사용자도 업데이트된 기간 동안 활성 사용자로 집계됩니다.

{% alert important %}
비활성 사용자와 휴면 사용자는 아래에 나열된 사유로 아카이브에서 제외되지 않는 한 모두 아카이브됩니다.
{% endalert %}

### 비활성 사용자 {#inactive-users}

"비활성 사용자"는 도달할 수 없으며 고객이탈 가능성이 높은 사용자입니다. 비활성 사용자는 다음 기준을 모두 충족하는 사용자입니다:

- 이메일을 수신할 수 없습니다. 예를 들어, 이메일 주소가 없거나 모든 이메일 목록에서 탈퇴한 경우입니다.
- 단문 메시지 서비스를 수신할 수 없습니다. 예를 들어, 유효한 전화번호가 없거나 모든 단문 메시지 서비스 구독 그룹에서 탈퇴한 경우입니다.
- 푸시를 수신할 수 없습니다. 예를 들어, 앱을 삭제했거나 푸시 권한을 비활성화한 경우입니다.
- WhatsApp 메시지를 수신할 수 없습니다. 예를 들어, 유효한 전화번호가 없거나 모든 WhatsApp 구독 그룹에서 탈퇴한 경우입니다.
- LINE 메시지를 수신할 수 없습니다. 예를 들어, LINE ID가 없거나 모든 LINE 구독 그룹에서 탈퇴한 경우입니다.
- 6개월 이상 워크스페이스 내 모바일 앱을 사용하거나 웹사이트를 방문하지 않았습니다.
- 6개월 이상 워크스페이스에서 메시지를 수신하지 않았습니다.
- 6개월 이상 업데이트되지 않았습니다.

이 경우 해당 사용자에게는 메시지를 보낼 수 없으며, 브랜드와 상호작용하지 않고 있습니다. 이러한 사용자는 사실상 고객이탈한 것입니다.

### 휴면 사용자 {#dormant-users}

"휴면 사용자"는 지난 12개월 동안 활동이 없었으며 다음 조건을 충족하는 사용자입니다:

- 12개월 이상 워크스페이스 내 모바일 앱을 사용하거나 웹사이트를 방문하지 않았습니다.
- 12개월 이상 워크스페이스에서 메시지를 수신하지 않았습니다.
- 12개월 이상 업데이트되지 않았습니다.

## 글로벌 컨트롤 그룹 사용자 {#global-control-group-users}

글로벌 컨트롤 그룹에 속한 사용자는 비활성 또는 휴면 사용자의 정의에 해당하더라도 절대 아카이브되지 않습니다.

### 트리트먼트 샘플 그룹 {#treatment-sample-group}

글로벌 컨트롤 그룹 보고서의 트리트먼트 샘플 그룹 사용자는 아카이브 대상에서 제외됩니다.

## 테스트 사용자 {#test-users}

테스트 사용자는 비활성 또는 휴면 사용자의 정의에 해당하더라도 절대 아카이브되지 않습니다.

## 스팸 차단 {#spam-blocking}

Braze는 비정상적으로 커진 개별 고객 프로필("더미 사용자")을 차단합니다. 이러한 프로필은 대부분 잘못된 통합의 결과입니다. 프로필이 다음 임계값 중 하나를 초과하면 차단됩니다.

| 임계값 | 설명 |
| --- | --- |
| 5,000,000회 이상의 세션 | 일반적으로 하나의 `external_id`를 여러 사용자에게 재사용할 때 발생합니다. |
| 20,000개 이상의 고유 커스텀 이벤트 이름 | 일반적으로 고정된 이름 집합을 재사용하지 않고 매 이벤트마다 새로운 이벤트 이름을 생성할 때 발생합니다. |
| 구매 시 20,000개 이상의 고유 제품 이름 | 일반적으로 고정된 제품 ID 집합을 재사용하지 않고 매 구매마다 새로운 `product_id`를 생성할 때 발생합니다. |
{: .reset-td-br-1 .reset-td-br-2 aria-label="더미 사용자 차단 임계값" }

프로필이 차단되면 Braze는 SDK와 REST API 모두에서 해당 프로필에 대한 모든 수신 데이터 수집을 중단합니다. 차단된 식별자를 참조하는 [`/users/track`]({{site.baseurl}}/api/endpoints/user_data/post_user_track) 요청은 `"provided external_id is blacklisted and disallowed"` 오류를 반환합니다. 이 문구는 API 응답에서 그대로 가져온 것입니다. Braze는 또한 계정 매니저에게 알려 통합 문제를 제기할 수 있도록 합니다.

정상적인 사용자에게 이 문제가 발생한 경우, Braze [지원팀]({{site.baseurl}}/braze_support)에 티켓을 제출하세요.

대시보드에서 더미 사용자를 찾으려면 다음 단계를 수행하세요.

1. [Segment]({{site.baseurl}}/user_guide/audience/segments/creating_a_segment)를 생성합니다.
2. `Session Count` 필터를 선택하고 `more than 5,000,000`으로 설정합니다.
3. CSV를 통해 Segment를 내보냅니다.

**Session Count** 필터는 세션 기반 더미 사용자만 찾습니다. 프로필의 고유 커스텀 이벤트 이름 수나 제품 이름 수에 대한 세분화 필터는 없으므로, 해당 이유로 차단된 프로필을 확인하려면 Braze 계정 매니저에게 문의하세요.

필요한 경우 [`/users/delete` 엔드포인트]({{site.baseurl}}/api/endpoints/user_data/post_user_delete)를 통해 사용자를 삭제할 수 있습니다.

## 사용자 아카이브 정책 커스터마이징 {#customizing-your-user-archival-policy}

Braze는 사용자 아카이브 정책을 커스터마이징할 수 있는 데이터 오케스트레이션 기능을 제공합니다. Canvas [사용자 업데이트]({{site.baseurl}}/user_update) 컴포넌트를 사용하여 두 가지 장점을 모두 갖춘 사용자 아카이브 정책을 만들어 보세요.

이를 통해 다음을 수행할 수 있습니다:

- 더 이상 가치가 없는 고객 프로필을 삭제하여 GDPR 및 개인정보 보호 모범 사례를 준수합니다.
- 정당한 비즈니스 필요가 있는 고객 프로필을 유지합니다.

### 단계 {#steps}

1. 브랜드의 아카이브 기준에 해당하면서 유지하고 싶은 사용자를 타겟팅합니다. 예를 들어, 다음과 같은 사용자를 유지할 수 있습니다:
    - 마지막으로 메시지를 받은 지 23주 이상 경과했거나 메시지를 받은 적이 없는 사용자<br>AND<br>
    - 마지막으로 앱을 사용한 지 23주 이상 경과했거나 앱에서 세션이 0회인 사용자<br><br>
      ![마지막으로 메시지를 받은 지 23주 이상 경과했거나, Campaign 또는 캔버스 단계에서 메시지를 받은 적이 없으며, 마지막으로 앱을 사용한 지 23주 이상 경과했고, 앱 사용 횟수가 정확히 0회인 사용자를 타겟팅합니다.][2]<br><br>
2. 재자격 기간을 6개월보다 약간 짧게 설정합니다.<br><br>
      ![재자격이 활성화되어 있고 재자격 기간이 23주로 설정된 진입 제어.][3]<br><br>
3. 사용자 업데이트 단계를 구성하여 각 프로필에 이벤트를 추가합니다.<br><br>
      ![사용자 프로필에 "do_not_archive" 이벤트를 추가하는 사용자 업데이트 단계.][4]
