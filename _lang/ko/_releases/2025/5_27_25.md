# 2025년 5월 27일 릴리스 {#may-27-2025-release}

## 데이터 유연성 {#data-flexibility}

### 워크스페이스 간 Canvases 복사 {#copying-canvases-across-workspaces}

{% multi_lang_include release_type.md release="General availability" %}

이제 워크스페이스 간에 Canvases를 복사할 수 있습니다. 다른 워크스페이스에 있는 Canvas 사본으로 시작하여 메시지 작성을 빠르게 시작할 수 있습니다. 복사되는 항목에 대한 자세한 내용은 [워크스페이스 간 Campaigns 및 Canvases 복사]({{site.baseurl}}/copying_to_workspaces)를 참조하세요.

### 승인 워크플로를 위한 메시징 규칙 {#messaging-rules-for-approval-workflow}

{% multi_lang_include release_type.md release="General availability" %}

승인 워크플로에서 [메시징 규칙]({{site.baseurl}}/user_guide/messaging/governance/approvals/messaging_rules)을 사용하여 추가 승인이 필요하기 전에 도달 가능한 사용자 수를 제한할 수 있습니다. 이를 통해 더 큰 오디언스를 타겟팅하기 전에 Campaigns와 Canvases를 검토할 수 있습니다.

### Snowflake 및 Braze 엔터티 관계 다이어그램 {#entity-relationship-diagrams-for-snowflake-and-braze}

올해 초, Snowflake와 Braze 간에 공유되는 데이터에 대한 엔터티 관계 테이블을 만들었습니다. 이번 달에는 각 테이블의 세부 정보를 이동, 잡기, 확대할 수 있는 [새로운 인터랙티브 다이어그램]({{site.baseurl}}/partners/data_and_analytics/data_warehouses/snowflake/entity_relationships)을 추가하여 데이터가 Braze와 어떻게 상호작용하는지 더 잘 이해할 수 있습니다.

## 창의력 발휘 {#unlocking-creativity}

### 추천 이벤트 {#recommended-events}

{% multi_lang_include release_type.md release="Early access" %}

[추천 이벤트]({{site.baseurl}}/user_guide/data/activation/events/recommended_events)는 가장 일반적인 이커머스 사용 사례에 매핑됩니다. 추천 이벤트를 사용하면 고객 생애주기에 매핑된 사전 구축 Canvas 템플릿, 보고 대시보드 등을 활용할 수 있습니다.

## 강력한 채널 {#robust-channels}

### 배너 채널 {#banners-channel}

{% multi_lang_include release_type.md release="General availability" %}

[배너]({{site.baseurl}}/user_guide/channels/banners)를 사용하면 사용자에게 개인화된 메시지를 생성하면서 이메일이나 푸시 알림과 같은 다른 채널의 도달 범위를 확장할 수 있습니다. 배너를 앱이나 웹사이트에 직접 삽입할 수 있어 사용자가 자연스럽게 느끼는 경험을 통해 참여할 수 있습니다.

### 리치 커뮤니케이션 서비스(RCS) 채널 {#rich-communication-services-rcs-channel}

{% multi_lang_include release_type.md release="General availability" %}

[리치 커뮤니케이션 서비스(RCS)]({{site.baseurl}}/user_guide/channels/sms_mms_and_rcs)는 브랜드가 정보 제공뿐만 아니라 훨씬 더 매력적인 메시지를 전달할 수 있도록 기존 SMS를 향상시킵니다. 이제 Android와 iOS 모두에서 지원되는 RCS는 고품질 미디어, 인터랙티브 버튼, 브랜드 발신자 프로필과 같은 기능을 사용자의 사전 설치된 메시징 앱에 직접 제공하여 별도의 앱을 다운로드할 필요가 없습니다.

### 푸시 설정 페이지 {#push-settings-page}

{% multi_lang_include release_type.md release="General availability" %}

[**푸시 설정** 페이지]({{site.baseurl}}/user_guide/administer/global/workspace_settings/push_settings)를 사용하여 푸시 알림의 주요 설정을 구성할 수 있습니다. 여기에는 푸시 TTL 및 Android Campaigns의 기본 FCM 우선순위가 포함됩니다. 이러한 설정은 푸시 알림의 전달 및 효과를 최적화하여 사용자에게 더 나은 경험을 보장합니다.

### 인앱 메시지 Campaign을 위한 프로모션 코드 {#promotion-codes-for-in-app-message-campaigns}

{% multi_lang_include release_type.md release="Early access" %}

인앱 메시지 Campaign에서 [프로모션 코드]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/sources/promotion_codes)를 사용하려면 인앱 메시지 Campaign의 메시지 본문에 [프로모션 코드 목록 스니펫]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/sources/promotion_codes/create#create)을 삽입하면 됩니다.

### 웹훅 오류 처리 및 사용량 제한 {#handling-webhook-errors-and-rate-limiting}

[웹훅 정보]({{site.baseurl}}/user_guide/message_building_by_channel/webhooks/understanding_webhooks#webhook-error-handling-and-rate-limiting)에 Braze가 웹훅 오류 및 사용량 제한을 처리하는 방법을 설명하는 새로운 섹션이 추가되었습니다.

### 인앱 메시지 로케일 {#in-app-message-locales}

워크스페이스에 [로케일을 추가]({{site.baseurl}}/locales_in_messages)한 후, 단일 인앱 메시지 내에서 다양한 언어로 사용자를 타겟팅할 수 있습니다.

### Amazon SES를 이메일 서비스 공급자(ESP)로 사용 {#amazon-ses-as-an-email-sending-provider-esp}

이제 SendGrid 및 SparkPost를 사용하는 것과 유사하게 Amazon SES를 ESP로 사용할 수 있습니다. SSL 설정 및 링크별 클릭 추적의 세부 사항에 대해서는 [Braze의 SSL]({{site.baseurl}}/user_guide/message_building_by_channel/email/email_setup/ssl#what-is-a-cdn-and-why-do-i-need-it) 및 [유니버설 링크 및 앱 링크]({{site.baseurl}}/user_guide/message_building_by_channel/email/universal_links#turning-off-click-tracking-on-a-link-to-link-basis)를 참조하세요.

## 새로운 Braze 파트너십 {#new-braze-partnerships}

### Eagle Eye - 로열티 {#eagle-eye-loyalty}

Braze와 [Eagle Eye]({{site.baseurl}}/partners/eagle_eye)의 양방향 통합을 통해 로열티 및 프로모션 데이터를 Braze에서 직접 활성화할 수 있으며, 마케터는 포인트 잔액, 프로모션, 보상 활동과 같은 실시간 데이터를 사용하여 고객 참여를 개인화할 수 있습니다.

### Eppo - A/B 테스트 {#eppo-ab-testing}

Braze와 [Eppo]({{site.baseurl}}/partners/eppo)의 통합을 통해 Braze에서 A/B 테스트를 설정하고 Eppo에서 결과를 분석하여 인사이트를 발견하고 메시지 성능을 매출 또는 유지와 같은 장기 비즈니스 측정기준에 연결할 수 있습니다.

### Mention Me - 추천 {#mention-me-referrals}

[Mention Me](https://www.mention-me.com/)와 Braze를 함께 사용하면 프리미엄 고객을 유치하고 변함없는 브랜드 로열티를 조성하는 관문이 될 수 있습니다. 퍼스트파티 추천 데이터를 Braze에 원활하게 통합함으로써 브랜드 팬을 대상으로 한 고도로 개인화된 옴니채널 경험을 제공할 수 있습니다. 시작하려면 [기술 파트너: Mention Me]({{site.baseurl}}/partners/mention_me)를 참조하세요.

### Shopify - 이커머스 {#shopify-ecommerce}

[여러 Shopify 스토어 도메인을 단일 워크스페이스에 연결]({{site.baseurl}}/shopify_connecting_multiple_stores)하여 모든 시장에서 고객을 포괄적으로 볼 수 있습니다. 지역 매장 간의 노력을 중복하지 않고 단일 워크스페이스에서 자동화 프로그램과 여정을 구축하고 시작하세요.

## 기타 {#other}

### Braze에서 접근 가능한 메시지 구축 업데이트 {#update-to-building-accessible-messages-in-braze}

[Braze에서 접근 가능한 메시지 구축]({{site.baseurl}}/user_guide/messaging/messaging_fundamentals/accessibility) 문서를 더 명확하고 구체적인 접근 가능한 메시지 생성 지침으로 업데이트했습니다. 이 문서에는 이제 콘텐츠 구조, 대체 텍스트, 버튼, 색상 대비에 대한 확장된 모범 사례와 커스텀 HTML 메시지에 대한 ARIA 처리에 관한 새로운 섹션이 포함되어 있습니다.

이 업데이트는 Braze에서 더 접근 가능한 메시징 경험을 지원하기 위한 광범위한 노력의 일환입니다. 접근성은 계속 발전하는 분야이며, 배우는 내용을 지속적으로 공유하겠습니다.

## SDK 업데이트 {#sdk-updates}

다음 SDK 업데이트가 릴리스되었습니다. 주요 변경 사항은 아래에 나열되어 있으며, 그 외의 모든 업데이트는 해당 SDK 체인지로그를 확인하시면 됩니다.

- [Android SDK 36.0.0](https://pub.dev/packages/braze_plugin/changelog)
    - 이 릴리스는 34.0.0에서 도입된 Braze Android SDK의 최소 Android SDK 버전을 API 21에서 API 25로 올린 변경 사항을 되돌립니다. 이를 통해 SDK는 다시 API 21까지 지원하는 앱에 컴파일될 수 있습니다. 컴파일 기능을 다시 도입하고 있지만, API 25 미만에 대한 공식 지원을 재도입하는 것은 아니며, 해당 버전을 실행하는 기기에서 SDK가 의도한 대로 작동할 것이라고 보장할 수 없습니다.
    - 앱이 해당 버전을 지원하는 경우 다음을 수행해야 합니다:
        - 해당 API 버전의 실제 기기(에뮬레이터가 아님)에서 SDK 통합이 의도한 대로 작동하는지 확인하세요.
        - 예상되는 동작을 검증할 수 없는 경우 [disableSDK](https://braze-inc.github.io/braze-android-sdk/kdoc/braze-android-sdk/com.braze/-braze/-companion/disable-sdk.html)를 호출하거나 해당 버전에서 SDK를 초기화하지 않아야 합니다. 그렇지 않으면 최종사용자의 기기에서 의도하지 않은 부작용이나 성능 저하를 초래할 수 있습니다.
    - 인앱 메시지가 메인 스레드에서 읽기를 유발하는 문제를 수정했습니다.
    `BrazeInAppMessageManager.displayInAppMessage`는 이제 Kotlin 서스펜드 함수입니다.
        - 이 함수를 직접 호출하지 않는 경우 변경할 필요가 없습니다.
    - AndroidX Compose BOM이 Jetpack Compose API의 업데이트를 처리하기 위해 2025.04.01로 업데이트되었습니다.
- [React Native SDK 15.0.0](https://github.com/braze-inc/braze-react-native-sdk/blob/master/CHANGELOG.md)
    - Braze Android SDK 35.0.0에서 36.0.0으로 네이티브 Android 브리지를 업데이트합니다.
    - Braze Swift SDK 11.9.0에서 12.0.0으로 네이티브 iOS 버전 바인딩을 업데이트합니다.
    - iOS에서 PushNotificationEvent.timestamp의 단위 표현을 밀리초로 업데이트합니다.
        - 이전에는 이 값이 iOS에서 초 단위로 표현되었습니다. 이제 기존 Android 구현과 일치합니다.
- [Web SDK 5.9.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [Flutter SDK 14.0.0 5.9.0](https://pub.dev/packages/braze_plugin/changelog)
    - 이 릴리스는 34.0.0에서 도입된 Braze Android SDK의 최소 Android SDK 버전을 API 21에서 API 25로 올린 변경 사항을 되돌립니다. 이를 통해 SDK는 다시 API 21까지 지원하는 앱에 컴파일될 수 있습니다. 그러나 API 25 미만에 대한 공식 지원을 재도입하는 것은 아닙니다. 자세한 내용은 [Braze Android SDK 체인지로그 항목](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#3600)을 참조하세요.
    - Braze Android SDK 35.0.0에서 36.0.0으로 네이티브 Android 브리지를 업데이트합니다.
    - Braze Swift SDK 11.9.0에서 12.0.0으로 네이티브 iOS 브리지를 업데이트합니다.
