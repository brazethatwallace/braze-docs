# 2025년 5월 27일 릴리스 {#may-27-2025-release}

## 데이터 유연성 {#data-flexibility}

### 워크스페이스 간 Canvases 복사 {#copying-canvases-across-workspaces}

{% multi_lang_include release_type.md release="General availability" %}

이제 워크스페이스 간에 Canvases를 복사할 수 있습니다. 다른 워크스페이스에 있는 Canvas의 사본으로 시작하여 메시지 구성을 빠르게 시작할 수 있습니다. 복사되는 항목에 대한 자세한 내용은 [워크스페이스 간 Campaigns 및 Canvases 복사]({{site.baseurl}}/copying_to_workspaces)를 참조하세요.

### 승인 워크플로를 위한 메시징 규칙 {#messaging-rules-for-approval-workflow}

{% multi_lang_include release_type.md release="General availability" %}

승인 워크플로에서 [메시징 규칙]({{site.baseurl}}/user_guide/messaging/governance/approvals/messaging_rules)을 사용하여 추가 승인이 필요하기 전에 도달 가능한 사용자 수를 제한하세요. 이를 통해 더 큰 오디언스를 타겟팅하기 전에 Campaigns와 Canvases를 검토할 수 있습니다.

### Snowflake 및 Braze의 엔터티 관계 다이어그램 {#entity-relationship-diagrams-for-snowflake-and-braze}

올해 초, Snowflake와 Braze 간에 공유되는 데이터에 대한 엔터티 관계 테이블을 만들었습니다. 이번 달에는 각 테이블의 세부 사항을 이동, 드래그, 확대/축소할 수 있는 [새로운 인터랙티브 다이어그램]({{site.baseurl}}/partners/data_and_analytics/data_warehouses/snowflake/entity_relationships)을 추가하여 데이터가 Braze와 어떻게 상호작용하는지 더 잘 파악할 수 있도록 했습니다.

## 창의성 잠금 해제 {#unlocking-creativity}

### 추천 이벤트 {#recommended-events}

{% multi_lang_include release_type.md release="Early access" %}

[추천 이벤트]({{site.baseurl}}/user_guide/data/activation/events/recommended_events)는 가장 일반적인 이커머스 사용 사례에 매핑됩니다. 추천 이벤트를 사용하면 사전 구축된 Canvas 템플릿, 고객 생애주기에 매핑되는 리포팅 대시보드 등을 활용할 수 있습니다.

## 강력한 채널 {#robust-channels}

### 배너 채널 {#banners-channel}

{% multi_lang_include release_type.md release="General availability" %}

[배너]({{site.baseurl}}/user_guide/channels/banners)를 사용하면 사용자에게 개인화된 메시지를 생성하는 동시에, 이메일이나 푸시 알림과 같은 다른 채널의 도달 범위를 확장할 수 있습니다. 배너를 앱이나 웹사이트에 직접 임베드할 수 있어 자연스러운 경험을 통해 사용자와 소통할 수 있습니다.

### 리치 커뮤니케이션 서비스(RCS) 채널 {#rich-communication-services-rcs-channel}

{% multi_lang_include release_type.md release="General availability" %}

[리치 커뮤니케이션 서비스(RCS)]({{site.baseurl}}/user_guide/channels/sms_mms_and_rcs)는 기존 단문 메시지 서비스를 강화하여 브랜드가 유익할 뿐만 아니라 훨씬 더 매력적인 메시지를 전달할 수 있도록 합니다. 이제 Android와 iOS 모두에서 지원되는 RCS는 고품질 미디어, 인터랙티브 버튼, 브랜드 발신자 프로필과 같은 기능을 사용자의 기본 설치된 메시징 앱에 직접 제공하여 별도의 앱을 다운로드할 필요가 없습니다.

### 푸시 설정 페이지 {#push-settings-page}

{% multi_lang_include release_type.md release="General availability" %}

[**푸시 설정** 페이지]({{site.baseurl}}/user_guide/administer/global/workspace_settings/push_settings)를 사용하여 푸시 TTL(Push Time to Live) 및 Android Campaigns의 기본 FCM 우선순위를 포함한 푸시 알림의 주요 설정을 구성할 수 있습니다. 이러한 설정은 푸시 알림의 전달 및 효과를 최적화하여 사용자에게 더 나은 경험을 보장합니다.

### 인앱 메시지 Campaigns를 위한 프로모션 코드 {#promotion-codes-for-in-app-message-campaigns}

{% multi_lang_include release_type.md release="Early access" %}

인앱 메시지 Campaigns에서 메시지 본문에 [프로모션 코드 목록 스니펫]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/sources/promotion_codes/create#create)을 삽입하여 [프로모션 코드]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/sources/promotion_codes)를 사용할 수 있습니다.

### 웹훅 오류 처리 및 사용량 제한조치 {#handling-webhook-errors-and-rate-limiting}

[웹훅 이해하기]({{site.baseurl}}/user_guide/message_building_by_channel/webhooks/understanding_webhooks#webhook-error-handling-and-rate-limiting)에 Braze가 웹훅 오류와 사용량 제한조치를 처리하는 방법을 설명하는 새로운 섹션이 추가되었습니다.

### 인앱 메시지 로캘 {#in-app-message-locales}

워크스페이스에 [로캘을 추가]({{site.baseurl}}/locales_in_messages)하면 단일 인앱 메시지 내에서 다양한 언어의 사용자를 타겟팅할 수 있습니다.

### 이메일 서비스 공급자(ESP)로서의 Amazon SES {#amazon-ses-as-an-email-sending-provider-esp}

이제 SendGrid 및 SparkPost를 사용하는 것과 유사하게 Amazon SES를 ESP로 사용할 수 있습니다. SSL 설정 및 링크별 클릭 추적의 세부 사항은 [Braze의 SSL]({{site.baseurl}}/user_guide/channels/email/email_setup/ssl#what-is-a-cdn-and-why-do-i-need-it) 및 [유니버설 링크 및 앱 링크]({{site.baseurl}}/user_guide/channels/email/customize/universal_links_and_app_links#turning-off-click-tracking-on-a-link-to-link-basis)를 참조하세요.

## 새로운 Braze 파트너십 {#new-braze-partnerships}

### Eagle Eye - 로열티 {#eagle-eye-loyalty}

Braze와 [Eagle Eye]({{site.baseurl}}/partners/eagle_eye)의 양방향 통합을 통해 로열티 및 프로모션 데이터를 Braze에서 직접 활성화할 수 있으며, 마케터는 포인트 잔액, 프로모션, 리워드 활동 등의 실시간 데이터를 활용하여 고객 참여를 개인화할 수 있습니다.

### Eppo - A/B 테스트 {#eppo-ab-testing}

Braze와 [Eppo]({{site.baseurl}}/partners/eppo)의 통합을 통해 Braze에서 A/B 테스트를 설정하고 Eppo에서 결과를 분석하여 인사이트를 발견하고 메시지 성능을 매출이나 유지와 같은 장기적인 비즈니스 측정기준에 연결할 수 있습니다.

### Mention Me - 추천 {#mention-me-referrals}

[Mention Me](https://www.mention-me.com/)와 Braze를 함께 활용하면 프리미엄 고객을 유치하고 확고한 브랜드 로열티를 구축할 수 있습니다. 퍼스트파티 추천 데이터를 Braze에 원활하게 통합하여 브랜드 팬을 타겟으로 한 고도로 개인화된 옴니채널 경험을 제공할 수 있습니다. 시작하려면 [기술 파트너: Mention Me]({{site.baseurl}}/partners/mention_me)를 참조하세요.

### Shopify - 이커머스 {#shopify-ecommerce}

[여러 Shopify 스토어 도메인을 연결]({{site.baseurl}}/shopify_connecting_multiple_stores)하여 단일 워크스페이스에서 모든 시장의 고객을 종합적으로 파악하세요. 지역별 스토어에서 작업을 중복하지 않고도 단일 워크스페이스에서 자동화 프로그램과 여정을 구축하고 실행할 수 있습니다.

## 기타 {#other}

### Braze에서 접근성 높은 메시지 작성하기 업데이트 {#update-to-building-accessible-messages-in-braze}

[Braze에서 접근성 높은 메시지 작성하기]({{site.baseurl}}/user_guide/messaging/messaging_fundamentals/accessibility) 문서를 더 명확하고 실용적인 가이드로 업데이트했습니다. 이 문서에는 콘텐츠 구조, 대체 텍스트, 버튼, 색상 대비에 대한 확장된 모범 사례와 함께 커스텀 HTML 메시지의 ARIA 처리에 대한 새로운 섹션이 포함되어 있습니다.

이번 업데이트는 Braze에서 더 접근성 높은 메시징 경험을 지원하기 위한 광범위한 노력의 일환입니다. 접근성은 계속 발전하는 분야이며, 저희가 배운 내용을 지속적으로 공유하겠습니다.

## SDK 업데이트 {#sdk-updates}

최신 SDK 업데이트가 릴리스되었습니다. 주요 변경 사항은 SDK 업데이트 섹션에 나열되어 있으며, 그 외 모든 업데이트는 해당 SDK 체인지로그에서 확인할 수 있습니다.

- [Android SDK 36.0.0](https://pub.dev/packages/braze_plugin/changelog)
    - 이 릴리스에서는 34.0.0에서 도입된 Braze Android SDK의 최소 Android SDK 버전을 API 21에서 API 25로 올렸던 변경 사항을 되돌렸습니다. 이를 통해 SDK를 다시 API 21까지 지원하는 앱에 컴파일할 수 있습니다. 컴파일 가능성을 다시 제공하지만, API 25 미만에 대한 공식 지원을 다시 도입하는 것은 아니며, 해당 버전을 실행하는 기기에서 SDK가 의도한 대로 작동할 것이라고 보장할 수 없습니다.
    - 앱이 해당 버전을 지원하는 경우 다음을 수행해야 합니다:
        - 해당 API 버전에서 SDK 통합이 의도한 대로 작동하는지 실제 기기(에뮬레이터가 아닌)에서 검증합니다.
        - 예상되는 동작을 검증할 수 없는 경우, 해당 버전에서 [disableSDK](https://braze-inc.github.io/braze-android-sdk/kdoc/braze-android-sdk/com.braze/-braze/-companion/disable-sdk.html)를 호출하거나 SDK를 초기화하지 않아야 합니다. 그렇지 않으면 최종사용자 기기에서 의도하지 않은 부작용이나 성능 저하가 발생할 수 있습니다.
    - 인앱 메시지가 메인 스레드에서 읽기를 유발하던 문제를 수정했습니다.
    `BrazeInAppMessageManager.displayInAppMessage`가 이제 Kotlin suspend 함수입니다.
        - 이 함수를 직접 호출하지 않는 경우 변경할 필요가 없습니다.
    - Jetpack Compose API의 업데이트를 처리하기 위해 AndroidX Compose BOM이 2025.04.01로 업데이트되었습니다.
- [React Native SDK 15.0.0](https://github.com/braze-inc/braze-react-native-sdk/blob/master/CHANGELOG.md)
    - 네이티브 Android 브릿지를 Braze Android SDK 35.0.0에서 36.0.0으로 업데이트했습니다.
    - 네이티브 iOS 버전 바인딩을 Braze Swift SDK 11.9.0에서 12.0.0으로 업데이트했습니다.
    - iOS에서 PushNotificationEvent.timestamp의 단위 표현을 밀리초로 업데이트했습니다.
        - 이전에는 iOS에서 이 값이 초 단위로 표현되었습니다. 이제 기존 Android 구현과 일치하게 됩니다.
- [Web SDK 5.9.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [Flutter SDK 14.0.0 5.9.0](https://pub.dev/packages/braze_plugin/changelog)
    - 이 릴리스에서는 34.0.0에서 도입된 Braze Android SDK의 최소 Android SDK 버전을 API 21에서 API 25로 올렸던 변경 사항을 되돌렸습니다. 이를 통해 SDK를 다시 API 21까지 지원하는 앱에 컴파일할 수 있습니다. 다만, API 25 미만에 대한 공식 지원을 다시 도입하는 것은 아닙니다. [Braze Android SDK 체인지로그 항목](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#3600)을 참고하세요.
    - 네이티브 Android 브릿지를 Braze Android SDK 35.0.0에서 36.0.0으로 업데이트했습니다.
    - 네이티브 iOS 브릿지를 Braze Swift SDK 11.9.0에서 12.0.0으로 업데이트했습니다.
