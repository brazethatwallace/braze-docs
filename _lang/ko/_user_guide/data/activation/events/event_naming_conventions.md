# 이벤트 명명 규칙

> 이 페이지에서는 올바른 이벤트 명명 규칙과 모범 사례를 다룹니다. 이벤트 및 속성 분류 체계의 일관성을 유지하면 데이터를 깔끔하고 사용하기 쉽게 관리할 수 있어 Braze 플랫폼의 신규 및 기존 사용자 모두에게 도움이 됩니다. 이를 통해 잘못된 오디언스에 캠페인을 트리거하거나 잘못된 이벤트를 사용하여 잘못된 결과를 생성하는 등의 문제를 사전에 방지할 수 있습니다.

## 모범 사례

- 명명 규칙을 명확하게 유지하세요.
- 이벤트 이름의 대소문자와 형식을 일관되게 사용하세요.
- 유사한 이름의 이벤트를 만들지 마세요.
- 긴 이벤트 속성 문자열은 Braze 대시보드에서 잘리거나 생략될 수 있으므로 피하세요.

## 명명 규칙

### 이벤트 그룹 사용

제품의 각 부분을 구분하기 위해 그룹을 사용하여 이벤트 이름을 지정하세요. 제품을 그룹으로 분류하면 누구나 해당 이벤트가 무엇을 가리키고 어떤 역할을 하는지 명확하게 이해할 수 있습니다.

### 이벤트 명명 구조

가장 일반적인 명명 구조는 `group_noun_action`입니다. 이벤트는 대소문자 계측 오류를 방지하고 등록정보를 식별하기 위해 모두 소문자로 작성해야 합니다.

### 등록정보

하나의 이벤트에 태그를 지정한 다음 등록정보를 사용하여 차이점을 구분하세요. 이 방법은 본질적으로 동일하지만 캠페인의 채널과 같이 사소한 차이가 있는 이벤트에 유용합니다. 또한 사용자가 이벤트를 통해 어떻게 이동하는지 쉽게 확인할 수 있습니다. 예시 및 추가 컨텍스트는 [이벤트 등록정보 오브젝트]({{site.baseurl}}/api/objects_filters/event_object/#event-properties-object)를 참조하세요.

## 예시

이커머스 회사에서 고객이 앱에 가입한 시점과 뉴스레터를 구독한 시점을 추적하려는 경우를 가정해 보겠습니다. 다음은 효과적인 이벤트 이름의 예시입니다:

- `user_signup`
- `newsletter_subscribed`

이 두 이벤트 이름은 추적하는 이벤트를 명확하게 나타냅니다. 더 많은 커스텀 이벤트를 생성할 때 명명 규칙을 이해하기 쉽게 유지하세요. 예를 들어, `signup_event_1`과 같은 이벤트 이름은 명확성이 부족하고 `user_signup`에 비해 이벤트가 무엇을 추적하는지 전달하지 못하므로 사용을 피하세요.
