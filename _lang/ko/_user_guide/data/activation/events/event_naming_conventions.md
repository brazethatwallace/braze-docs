# 이벤트 명명 규칙 {#event-naming-conventions}

> 이 페이지에서는 적절한 이벤트 명명 규칙과 모범 사례에 대해 설명합니다. 이벤트 및 속성 분류의 일관성을 유지하면 데이터를 깔끔하게 유지하여 신규 및 기존 Braze 플랫폼 사용자 모두가 활용할 수 있습니다. 이렇게 하면 나중에 잘못된 오디언스에게 Campaign을 트리거하거나 잘못된 이벤트를 사용하여 잘못된 결과를 생성하는 등의 문제를 방지할 수 있습니다.

## 모범 사례 {#best-practices}

- 명명 규칙을 명확하게 유지하세요.
- 이벤트 이름의 대소문자 및 형식을 일관되게 사용하세요.
- 이벤트에 유사한 이름을 부여하지 마세요.
- Braze 대시보드에서 잘리거나 잘릴 수 있는 긴 이벤트 속성 문자열은 피하세요.

## 명명 규칙 {#naming-conventions}

### 이벤트 그룹 사용 {#use-event-groups}

그룹을 사용하여 제품의 각 부분을 구분하고 이벤트를 명명하세요. 제품을 그룹으로 분류하면 모든 사용자가 해당 이벤트가 무엇을 의미하는지, 어떤 동작을 하는지 명확하게 이해할 수 있습니다.

### 이벤트 명명 구조 {#event-naming-structure}

가장 일반적인 명명 구조는 `group_noun_action`입니다. 이벤트는 모두 소문자로 작성하여 대소문자 계측 오류를 방지하고 속성을 식별할 수 있도록 해야 합니다.

### 등록정보 {#properties}

하나의 이벤트에 태그를 지정한 다음 등록정보를 사용하여 차이점을 식별하세요. 이 방법은 Campaign의 채널처럼 본질적으로 동일하지만 약간의 차이가 있는 이벤트에 유용합니다. 이를 통해 사용자가 이벤트를 통해 어떻게 흐르는지도 쉽게 확인할 수 있습니다. 예시와 추가 컨텍스트는 [이벤트 등록정보 오브젝트]({{site.baseurl}}/api/objects_filters/event_object#event-properties-object)를 참조하세요.

## 예시 {#examples}

전자상거래 회사에 소속되어 있으며 고객이 언제 앱에 가입했는지, 언제 뉴스레터를 구독했는지 추적하고 싶다고 가정해 보겠습니다. 다음은 효과적인 이벤트 이름의 예입니다.

- `user_signup`
- `newsletter_subscribed`

이 두 이벤트 이름은 추적 중인 이벤트를 명확하게 나타냅니다. 더 많은 커스텀 이벤트를 생성할 때 명명 규칙을 이해하기 쉽게 유지해야 합니다. 예를 들어 `signup_event_1`과 같은 이벤트 이름은 `user_signup`과 비교했을 때 명확성이 부족하고 이벤트가 추적하는 내용을 전달하지 못하므로 사용하지 않는 것이 좋습니다.
