# 클라우드 데이터 수집: 비주얼 매퍼 {#cloud-data-ingestion-visual-mapper}

> 이 페이지에서는 SQL을 작성하거나 데이터를 재구성하지 않고 비주얼 매퍼를 사용하여 데이터 웨어하우스의 테이블 또는 뷰를 Braze에 동기화하는 방법을 다룹니다.

{% alert important %}
비주얼 매퍼는 현재 베타 버전입니다. 비주얼 매퍼는 모든 클라우드 데이터 수집 데이터 웨어하우스 소스에서 사용자 속성 동기화에 사용할 수 있으며, 베타 기간 동안 추가 동기화 유형이 제공될 예정입니다. 액세스하려면 고객 성공 매니저 또는 계정 매니저에게 문의하세요.
{% endalert %}

비주얼 매퍼를 사용하면 SQL을 작성하거나 데이터를 재구성하지 않고도 데이터 웨어하우스의 기존 테이블 또는 뷰를 동기화할 수 있습니다. `EXTERNAL_ID`, `UPDATED_AT`, `PAYLOAD` 열이 포함된 Braze 전용 테이블을 만드는 대신, 대시보드에서 기존 테이블의 열을 Braze 필드에 직접 매핑합니다.

## 전제 조건 {#prerequisites}

비주얼 매퍼로 동기화를 생성하기 전에 다음이 필요합니다:

- 활성 상태의 클라우드 데이터 수집 데이터 웨어하우스 소스. 아직 설정하지 않았다면 [데이터 웨어하우스 통합]({{site.baseurl}}/user_guide/data/unification/cloud_ingestion/integrations)을 참조하세요.
- 데이터 웨어하우스에 표시되는 동기화할 테이블 또는 뷰의 이름.
- 지원되는 사용자 식별자가 포함된 열과 Braze가 증분 동기화에 사용할 수 있는 타임스탬프가 포함된 열.

{% alert note %}
Braze는 데이터에 대해 읽기 전용 쿼리만 실행하며 기본 테이블을 수정하지 않습니다. 쿼리 실행 중에 임시 객체가 생성될 수 있지만 유지되지는 않습니다.
{% endalert %}

## 비주얼 매퍼로 동기화 생성하기 {#creating-a-sync-with-the-visual-mapper}

### 1단계: 동기화 구성하기 {#step-1-configure-the-sync}

1. **데이터 설정** > **클라우드 데이터 수집** > **동기화**로 이동한 다음 **데이터 동기화 생성**을 선택합니다.
2. 동기화 이름을 선택하고 활성 데이터 소스를 선택합니다. 활성 소스만 사용할 수 있습니다.
3. **데이터 대상**에서 **Braze Data Platform**을 선택합니다.
4. **데이터 유형**에서 **사용자 속성**을 선택합니다.
5. **다음: 데이터 정의**를 선택합니다.

### 2단계: 소스 스키마 매핑하기 {#step-2-map-your-source-schema}

1. **데이터 정의** 단계에서 **비주얼 매퍼**를 선택합니다.
2. **테이블** 필드에 데이터 웨어하우스에 표시되는 테이블 또는 뷰 이름을 입력합니다.
3. **소스 스키마 매핑**을 선택합니다. Braze가 테이블 또는 뷰의 스키마를 읽고 감지된 데이터 유형과 함께 모든 열을 나열합니다.

### 3단계: 매핑 검토하기 {#step-3-review-your-mappings}

**매핑 검토** 섹션에서는 두 가지 필수 매핑을 추적합니다. 두 매핑이 모두 완료되어야 동기화를 생성할 수 있습니다:

- 하나의 열을 지원되는 사용자 식별자에 매핑합니다: `external_id`, `braze_id`, `email`, `phone` 또는 사용자 별칭. 식별자 옵션은 대상 필드 드롭다운의 **식별자** 아래에 표시됩니다.
- 하나의 열을 `updated_at`에 매핑합니다. Braze는 반복 동기화에서 증분 동기화를 위해 이 타임스탬프를 사용하며, 각 동기화 실행 시 `updated_at`이 마지막 동기화 값보다 이후인 행을 가져옵니다.

나머지 각 열에 대해 다음을 수행할 수 있습니다:

- **기본 매핑 유지.** 각 열은 동일한 이름의 Braze 필드에 매핑됩니다. 워크스페이스에 해당 필드가 아직 없는 경우 **새 속성**으로 표시되며 동기화의 첫 번째 실행 시 생성됩니다.
- **기존 필드에 매핑.** 대상 필드 드롭다운을 검색하여 열을 워크스페이스의 기존 기본 또는 커스텀 속성에 매핑합니다.
- **새 필드에 매핑.** 대상 필드 드롭다운에 직접 입력하여 열을 새 커스텀 속성에 매핑합니다.
- **열 제외.** **가져오기** 체크박스를 해제하여 동기화에서 열을 제외합니다.

{% alert tip %}
새 속성을 만들기 전에 대상 드롭다운에서 기존 속성을 검색하세요. 예를 들어, 테이블에 `fav_color` 열이 있지만 워크스페이스에서 이미 `favorite_color`를 추적하고 있다면, 다른 속성을 만드는 대신 `fav_color`를 `favorite_color`에 매핑하는 것을 고려하세요.
{% endalert %}

{% alert note %}
데이터 유형이 열의 감지된 유형과 일치하지 않는 필드는 **유형 불일치** 경고를 표시합니다. 계속 진행할 수 있지만, 일치하지 않는 값은 행 오류로 동기화에 실패할 수 있습니다. 동기화의 실행 세부 정보에서 행 오류를 확인할 수 있습니다.
{% endalert %}

### 4단계: 미리보기 및 유효성 검사 {#step-4-preview-and-validate}

**미리보기 및 유효성 검사**를 선택하여 테이블 또는 뷰에 대해 읽기 전용 검사를 실행합니다. 미리보기는 매핑된 필드 이름을 사용하여 처음 10개 행을 표시하며, 가져오는 열만 포함합니다.

### 5단계: 동기화 생성 완료하기 {#step-5-finish-creating-the-sync}

1. **알림** 단계에서 동기화 오류 알림을 위한 연락처 이메일을 하나 이상 입력합니다. 선택적으로 **행 오류** 알림(행의 일정 비율이 업데이트에 실패할 때 전송)과 **동기화 성공** 알림을 켤 수 있습니다.
2. **스케줄** 단계에서 **반복 동기화**를 켜서 스케줄에 따라 동기화를 실행하거나, 끄면 일회성 동기화가 됩니다.
3. **요약** 단계를 검토합니다. 구성, 새 속성과 기존 속성, 데이터 유형 문제 또는 선택에 따라 가져오기에서 제외된 열이 나열됩니다.
4. **동기화 생성**을 선택합니다. 어떤 단계에서든 **초안으로 저장**을 선택하여 나중에 완료할 수도 있습니다.

## 스키마 변경 처리 {#handling-schema-changes}

비주얼 매퍼는 매 동기화 실행 시 테이블 또는 뷰의 스키마를 확인하고 변경 유형에 따라 응답합니다:

| 소스 테이블의 변경 사항 | 동기화 동작 |
|---|---|
| 새 열이 추가됨 | 동기화는 계속되지만 새 열은 자동으로 동기화되지 않습니다. 포함하려면 동기화를 편집하고 매핑하세요. |
| 매핑된 열이 제거됨 | 동기화 실행이 실패하고 동기화가 일시 중지됩니다. 스키마 변경 사항은 동기화의 실행 세부 정보에 표시되며, 알림 연락처에 이메일 알림이 전송됩니다. |
| 매핑된 열의 이름이 변경됨 | 열 제거와 새 열 추가로 처리됩니다. |
| 열의 데이터 유형이 변경됨 | 스키마 변경으로 감지되지 않습니다. 호환되지 않는 값은 동기화 로그에서 행 오류로 보고됩니다. |
{: .reset-td-br-1 .reset-td-br-2 aria-label="스키마 변경 처리" }

열이 제거된 후 일시 중지된 동기화를 재개하려면 **동기화 편집**을 선택하고 매핑을 검토하세요. 제거된 열은 플래그가 지정되며 매퍼에 더 이상 표시되지 않습니다. 매핑을 저장하면 해당 열 없이 동기화를 계속하는 것이 확인됩니다. 또는 데이터가 다른 열로 이동한 경우 저장하기 전에 새 열을 매핑하세요.

## 자주 묻는 질문 {#frequently-asked-questions}

### 동기화가 생성된 후 매핑을 편집할 수 있나요? {#can-i-edit-my-mappings-after-a-sync-is-created}

네. 동기화를 편집하고 **매핑 보기 및 편집**을 선택하세요. 소스 테이블의 현재 스키마가 로드되며, 동기화 생성 시 저장한 이전 매핑이 유지됩니다. 거기서 매핑을 편집할 수 있습니다.

### 비주얼 매퍼에서 데이터를 변환할 수 있나요? {#can-i-transform-my-data-in-the-visual-mapper}

아니요. 비주얼 매퍼는 소스에 표시되는 그대로 열 값을 동기화합니다. 변환, 조건 로직 또는 테이블 간 조인을 지원하지 않습니다. 이러한 사용 사례의 경우 데이터 정의 단계에서 SQL 옵션을 사용하여 쿼리로 데이터를 구성하세요. 자세한 내용은 [클라우드 데이터 수집: SQL 편집기]({{site.baseurl}}/user_guide/data/unification/cloud_ingestion/sql_editor)를 참조하세요.

### 기존 CDI 동기화가 변경되나요? {#do-my-existing-cdi-syncs-change}

아니요. `EXTERNAL_ID`, `UPDATED_AT`, `PAYLOAD` 열이 포함된 기존 테이블 형식을 사용하는 동기화는 계속 작동하며, **데이터 정의** 단계에서 **테이블**을 선택하여 계속 생성할 수 있습니다. 마이그레이션은 필요하지 않습니다.

### Braze 사용량에 어떤 영향이 있나요? {#how-is-my-braze-usage-affected}

가져오는 각 열은 속성 업데이트로 기록되며, 데이터 포인트 과금은 다른 CDI 사용자 데이터 동기화와 동일하게 작동합니다. 필요하지 않은 열을 제외하면 동기화를 효율적으로 유지할 수 있습니다. 자세한 내용은 [클라우드 데이터 수집 모범 사례]({{site.baseurl}}/user_guide/data/unification/cloud_ingestion/best_practices)를 참조하세요.
