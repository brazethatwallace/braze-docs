# 동기화 로그 및 관측성 {#sync-logs-and-observability}

> 클라우드 데이터 수집(CDI) **동기화 로그** 대시보드를 통해 CDI에서 처리된 모든 데이터를 모니터링하고, 데이터가 성공적으로 동기화되었는지 확인하며, "잘못된" 데이터나 누락된 데이터와 관련된 문제를 진단할 수 있습니다.

동기화 로그에 접근하려면 **Data Settings** > **Cloud Data Ingestion**으로 이동한 후 **Sync Log** 탭을 선택하세요.

<!-- support-analyzer-phase2:cdi_updated_at_row_sync -->
{% alert note %}
데이터 웨어하우스의 행 수가 **Rows Synced**와 일치하지 않거나 **Partial Success** 실행이 표시되는 경우, 동기화 로그에서 **Run ID**를 열고 행 수준의 **Error reason** 값을 확인하세요. CDI는 `UPDATED_AT`를 사용하여 행을 선택합니다. 이미 처리된 타임스탬프를 가진 행, 편집 후에도 `UPDATED_AT`가 변경되지 않은 행, 또는 활성 동기화 중에 기록된 행은 건너뛸 수 있습니다. 일반적인 사례는 ["Rows Synced"가 데이터 웨어하우스의 숫자와 일치하지 않는 이유는 무엇인가요?]({{site.baseurl}}/user_guide/data/unification/cloud_ingestion/faqs#why-doesnt-rows-synced-match-the-number-in-my-warehouse) 및 [클라우드 데이터 수집 FAQ]({{site.baseurl}}/user_guide/data/unification/cloud_ingestion/faqs)를 참조하세요.
{% endalert %}

## 동기화 로그 대시보드 이해하기 {#understanding-the-sync-log-dashboard}

메인 **동기화 로그** 페이지에서는 최근 동기화의 현재 또는 최종 상태별 개요를 포함하여 모든 동기화 실행에 대한 상위 수준 개요를 제공합니다.

* **실행 중:** 현재 진행 중인 동기화 작업입니다.
* **성공:** 완료되었으며 모든 행이 성공적으로 처리된 동기화 작업입니다.
* **부분 성공:** 완료되었지만 하나 이상의 행에서 오류가 발생한 동기화 작업입니다.
* **오류:** 완료되지 못한 동기화 작업입니다.
* **한도 초과:** 데이터 한도가 초과되어 처리가 중단된 동기화 작업입니다.

![총 6,576건의 성공을 보여주는 동기화 로그 예시.]({% image_buster /assets/img/cloud_ingestion/sync_logs1.png %}){: style="max-width:80%"}

동기화 로그는 각 동기화에 대해 다음과 같은 세부 정보도 제공합니다:

* **동기화 이름:** 동기화 구성의 이름입니다.
* **실행 ID:** 특정 동기화 실행에 대한 고유 식별자입니다. 이 ID를 선택하면 자세한 내용을 확인하거나 Braze 지원팀에 동기화 실행을 참조할 수 있습니다.
* **상태:** 실행 상태(성공, 부분 성공, 오류, 실행 중)입니다.
* **소스에서 읽은 새 행:** 이번 실행에서 데이터 웨어하우스로부터 가져온 새 행의 수입니다.
* **결과:** 실행 내에서 성공하거나 실패한 행 수의 분류입니다.
* **마지막 "UPDATED_AT":** 이번 동기화 실행에서 처리된 가장 최근 레코드의 타임스탬프입니다.
* **실행 시작 시간:** 동기화 작업이 시작된 시간입니다.
* **실행 소요 시간:** 동기화 작업이 완료되기까지 걸린 총 시간입니다.

### 데이터 유지 {#data-retention}

모든 행 수준 페이로드 및 오류 세부 정보를 포함한 동기화 로그 데이터는 최대 **30일** 동안 유지됩니다. 30일이 지난 로그는 자동으로 삭제됩니다.

처리된 행 수와 같은 동기화 실행 메타데이터는 최소 12개월 동안 유지됩니다.

### 동기화 로그 필터링 {#filtering-sync-logs}

동기화 로그 테이블을 필터링하여 특정 실행을 찾을 수 있습니다. 사용 가능한 필터는 다음과 같습니다:

* **작업 시작 날짜:** 사전 정의된 범위(예: "최근 30일") 또는 커스텀 날짜 범위를 선택합니다.
* **상태:** 하나 이상의 동기화 상태로 필터링합니다(예: **오류** 및 **부분 성공** 상태만 표시).
* **동기화 이름:** 이름으로 특정 동기화를 검색합니다.

특정 동기화를 조사하려면 동기화 로그 테이블에서 해당 **실행 ID**를 선택합니다. **실행 세부 정보** 페이지에서 동기화의 행별 상세 로그를 확인할 수 있습니다.

### 실행 개요 {#run-overview}

이 섹션에서는 시작 시간, 종료 시간, 소요 시간, 소스에서 읽은 총 행 수를 포함하여 선택한 실행을 요약합니다. 또한 성공한 행 수와 오류가 발생한 행 수도 제공합니다.

### 이번 실행에서 처리된 행 {#rows-processed-in-this-run}

이 테이블은 동기화 중에 처리된 데이터에 대한 행 수준 가시성을 제공하여 개별 레코드를 검증할 수 있게 합니다.

* **검색:** **사용자 ID로 검색** 바를 사용하여 실행 결과 내에서 특정 사용자를 검색할 수 있습니다.
* **사용 가능한 세부 정보:**
  * **UPDATED_AT:** 해당 행의 `UPDATED_AT` 열에 있는 타임스탬프입니다.
  * **ID:** 레코드를 Braze 고객 프로필에 매칭하는 데 사용된 사용자 식별자(예: `external_id`, `email` 또는 `alias_name`)입니다.
  * **상태:** 해당 행의 개별 처리 상태(**성공** 또는 **오류**)입니다.
  * **소스 페이로드:** 데이터 페이로드를 볼 수 있는 링크입니다.
  * **오류 사유:** 상태가 **오류**인 경우, 이 열에서 행이 동기화에 실패한 이유를 설명하는 메시지를 제공합니다.

#### 페이로드 보기 {#viewing-payloads}

특정 행에 대해 Braze로 전송된 정확한 데이터를 확인하려면 **소스** 페이로드 열에서 **페이로드 보기**를 선택합니다. 해당 사용자에 대해 처리된 원시 JSON 페이로드가 표시됩니다.

#### 동기화 로그 내보내기 {#exporting-sync-logs}

**행 내보내기**를 선택하여 동기화 실행의 행 수준 로그를 내보냅니다. 그런 다음 다음 중 하나를 선택하여 내보냅니다:

* **오류가 있는 행:** **오류** 상태인 행만 포함된 파일을 다운로드합니다.
* **모든 행:** 실행에서 처리된 모든 행을 포함하는 파일을 다운로드합니다.

{% multi_lang_include alerts/early_access_beta_alert.md feature='Exporting sync logs for all rows' %}

대시보드에서 직접 로그를 내보낼 수는 없습니다. 내보내기가 생성되면 로그 내보내기 파일을 다운로드할 수 있는 링크가 포함된 이메일을 받게 됩니다.

## 알림 {#notifications}

CDI 동기화 상태에 대한 정보를 받을 수 있도록 이메일 알림을 구성할 수 있습니다. 이러한 설정은 동기화를 생성할 때 구성되며, 언제든지 업데이트할 수 있습니다.

### 오류 알림 {#error-notifications}

동기화 수준의 오류에 대한 알림을 받으려면 최소 하나의 이메일 주소 연락처가 필요합니다. 이러한 알림은 전체 동기화 작업이 실행 또는 완료되지 못한 경우, 또는 만료된 자격 증명이나 누락된 소스 테이블과 같이 사용자 개입이 필요한 오류가 발생한 경우에 전송됩니다.

추가 알림에는 다음이 포함됩니다:

- **행 오류:** 동기화 내에서 특정 비율의 행이 업데이트에 실패할 때 알림을 받습니다.
- **실패 임계값(%):** 알림을 트리거해야 하는 행 실패 비율을 지정합니다. 예를 들어, 이 값을 **1**로 설정하면 동기화 실행에서 1% 이상의 행이 오류를 발생시킬 경우 알림이 전송됩니다.
- **동기화 성공:** 동기화가 성공적으로 완료되면 알림을 받습니다.
- **변경된 행이 없어도 알림:** 성공적인 동기화 실행에서 새로운 행이나 업데이트된 행이 없는 경우에도 알림을 받습니다.
