# 인앱 메시지 보고서 {#iam-reporting}

> 이 참조 문서에서는 캠페인 세부 정보, 메시지 성과, 과거 성과를 포함한 인앱 메시지 보고서 및 분석에 대해 다룹니다.

{% multi_lang_include analytics/campaign_analytics.md channel="in-app message" %}

## 인앱 메시지 측정기준 {#in-app-message-metrics}

다음은 분석에서 확인할 수 있는 주요 인앱 메시지 측정기준입니다. Braze에서 사용되는 모든 측정기준의 정의는 [보고서 측정기준 용어집]({{site.baseurl}}/user_guide/analytics/metrics_glossary)을 참조하세요.

{% alert note %}
인앱 메시지의 경우, 이 페이지에서는 워크스페이스 시간대의 캘린더 일 기준으로 고유 노출 횟수를 정의합니다.
{% endalert %}

| 용어 | 정의 |
| --- | --- |
| 고유 노출 횟수 | 실제로 인앱 메시지를 확인한 총 사용자 수입니다. 사용자가 워크스페이스 시간대의 같은 캘린더 일에 메시지를 두 번 이상 수신하더라도 해당 날짜에는 고유 노출 횟수가 한 번만 집계됩니다. <br><br> **재자격이 활성화된 경우:** 사용자가 트리거 동작을 다시 수행하면 워크스페이스 시간대의 새로운 캘린더 일에 고유 노출 횟수가 다시 증가할 수 있습니다. 인앱 메시지의 경우, *고유 노출 횟수*는 *고유 수신자*와 동일합니다. 둘 다 새로운 캘린더 일에 증가하기 때문입니다. |
| 총 노출 횟수 | 인앱 메시지가 조회된 횟수입니다. 메시지가 화면에 표시되면 노출이 기록됩니다. 사용자가 메시지를 두 번 조회하면 두 번으로 집계됩니다. <br><br> **기기가 여러 대이고 재자격이 비활성화된 경우:** 사용자는 인앱 메시지를 한 번만 확인합니다. 사용자가 여러 기기를 사용하더라도 타겟팅된 첫 번째 기기에서만 확인합니다. 이는 프로필에 기기가 통합되어 있고 사용자가 여러 기기에서 하나의 사용자 ID로 로그인한 경우를 전제로 합니다. <br><br> **재자격이 활성화된 경우:** 사용자가 인앱 메시지를 확인할 때마다 노출이 기록됩니다. <br><br> **참고:** *총 노출 횟수*는 각 조회를 집계합니다. *고유 수신자*는 워크스페이스 시간대의 캘린더 일 기준으로 추적되는 별도의 측정기준입니다. |
| 전환 | 전환 추적은 사용자가 인앱 메시지의 노출을 기록한 후 시작됩니다. 사용자가 인앱 메시지 Campaign을 수신하고 확인한 후, 메시지를 클릭했는지 여부와 관계없이 정의된 전환 기간 내에 특정 전환 이벤트를 수행하면 전환이 집계됩니다. <br><br> 전환은 가장 최근에 수신한 메시지에 기여합니다. 재자격이 활성화된 경우, 전환은 정의된 전환 기간 내에 발생한 경우 가장 최근에 수신한 인앱 메시지에 할당됩니다. 그러나 인앱 메시지에 이미 전환이 할당된 경우, 해당 특정 메시지에 대해 새로운 전환을 기록할 수 없습니다. 이를 통해 각 인앱 메시지 전달이 하나의 전환에만 연결됩니다. |
| 총 전환 수 | 사용자가 인앱 메시지 Campaign을 한 번만 확인한 경우, 이후에 전환 이벤트를 여러 번 수행하더라도 전환은 한 번만 집계됩니다. 그러나 재자격이 활성화되어 사용자가 인앱 메시지 Campaign을 여러 번 확인한 경우, 사용자가 인앱 메시지 Campaign의 새 인스턴스에 대한 노출을 기록할 때마다 *총 전환 수*가 한 번씩 증가할 수 있습니다. <br><br> 예를 들어, 사용자가 인앱 메시지를 두 번 트리거하고 각 노출 후 전환한 경우(전환 2회), *총 전환 수*는 2만큼 증가합니다. 그러나 노출이 한 번만 있었고 이후 전환 이벤트가 두 번 발생한 경우, 전환은 한 번만 기록되며 *총 전환 수*는 1만큼 증가합니다. |
| 전환율 | 전환율 계산에는 일별 고유 노출 횟수(*고유 노출 횟수*) 측정기준이 사용됩니다. <br><br> 전환율 = (주요 전환 수) / (고유 노출 횟수) <br><br> 인앱 메시지의 경우, *고유 노출 횟수*는 워크스페이스 시간대의 캘린더 일당 한 번만 집계될 수 있습니다. 사용자가 원하는 동작("전환")을 완료하는 횟수는 같은 캘린더 일 내에서 증가할 수 있습니다. 따라서 사용자가 하루 내에 전환을 여러 번 완료하면 *전환율*이 그에 따라 증가할 수 있지만, *고유 노출 횟수*는 해당 캘린더 일에 한 번만 집계됩니다. |
{: .reset-td-br-1 .reset-td-br-2 aria-label="인앱 메시지 측정기준" }

{% alert tip %}
사용자가 같은 캘린더 일에 메시지를 두 번 이상 조회하면 *총 노출 횟수*가 *고유 노출 횟수*를 초과할 수 있습니다(위 표의 측정기준 정의 참조). 노출 횟수가 비정상적으로 높은 사용자를 조사하려면 **기기 수** 필터를 `1`**보다 큼**으로 설정하고 특정 Campaign에 대한 **Campaign에서 메시지 수신** 필터를 적용하여 Segment를 생성하세요.
{% endalert %}

### 클릭 추적 {#click-tracking}

Braze는 인앱 메시지가 화면에 표시되면 노출을 기록합니다. [기존 편집기]({{site.baseurl}}/user_guide/channels/in_app_messages/traditional)로 생성된 인앱 메시지의 경우, 다음 표에서 클릭으로 집계되는 항목을 설명합니다.

| 사용자 동작 | 클릭 기록 |
|-------------|--------------|
| 메시지에 버튼이 없을 때 사용자가 메시지 본문을 클릭 | 예 (본문 클릭) |
| 사용자가 버튼을 클릭 | 예 (버튼 클릭) |
| 사용자가 닫기 버튼(X)을 클릭 | 아니요 |
| 사용자가 메시지 외부를 탭하거나 클릭하여 닫기(활성화된 경우) | 아니요 |
| 메시지가 표시된 상태에서 사용자가 앱을 종료 | 아니요 |
{: .reset-td-br-1 .reset-td-br-2 aria-label="클릭 추적" }

본문 클릭과 버튼 클릭의 정의는 [보고서 측정기준 용어집]({{site.baseurl}}/user_guide/analytics/metrics_glossary)을 참조하세요.

A/B 테스트에서 대조군과 배리언트 간의 노출 불균형에 대해서는 [대조군과 배리언트 간의 불일치]({{site.baseurl}}/user_guide/messaging/ab_testing/analytics#discrepancies-between-the-control-group-and-variant)를 참조하세요.

## 재자격 시 전환은 어떻게 증가하나요? {#how-do-conversions-increment-with-re-eligibility}

Braze는 각 인앱 메시지 전달에 하나의 전환만 할당하며, 가장 최근에 수신한 메시지에 기여합니다.

재자격이 활성화된 경우, 각 새로운 전달은 자체 전환을 생성할 수 있습니다. 예를 들어, 사용자가 같은 인앱 메시지를 다섯 번 확인하고 각 노출 후 전환하면 전환이 다섯 번 집계됩니다. 사용자가 메시지를 한 번만 확인하고 이후 여러 번 전환하면 전환은 한 번만 집계됩니다.

사용자가 서로 다른 이틀에 인앱 메시지를 확인하고 셋째 날에 전환하면, Braze는 둘째 날의 노출에 대해 전환을 기록합니다. Canvases의 경우, 전환은 단계별이 아닌 Canvas 진입별로 추적됩니다. 사용자가 같은 진입 중에 여러 단계에서 전환하더라도 전환은 한 번만 집계됩니다.

{% tabs local %}
{% tab 시나리오 1 %}

*사용자가 하루에 같은 인앱 메시지를 다섯 번 수신하고 같은 날 다섯 번 전환합니다.*

Sarah는 쇼핑 앱에서 좋아하는 브랜드의 신발 한정 세일에 대한 인앱 메시지를 수신합니다. 메시지를 클릭하고 신발 두 켤레를 구매합니다.

몇 시간 후, 같은 인앱 메시지를 다시 수신하고 신발을 한 켤레 더 구매하기로 합니다. 이런 일이 하루에 총 다섯 번 발생하며, Sarah는 인앱 메시지를 클릭할 때마다 총 다섯 번의 개별 구매를 합니다.

**결과:** Sarah의 *총 전환 수*와 *총 노출 횟수*는 해당 하루에 각각 5만큼 증가합니다. *고유 노출 횟수*는 워크스페이스 시간대의 캘린더 일 경계 이후에만 다시 증가할 수 있으므로, *고유 노출 횟수*는 동일하게 유지됩니다. 이로 인해 해당 기간 내 *전환율*이 증가합니다.

{% alert note %}
이 시나리오에서 각 노출과 전환은 별도의 SDK 이벤트로 처리됩니다. SDK가 노출과 전환 이벤트를 함께 배치 처리하는 경우, 전환 수가 다를 수 있습니다.
{% endalert %}

{% endtab %}
{% tab 시나리오 2 %}

*사용자가 인앱 메시지를 한 번 수신하고 같은 날 전환합니다.*

Lena는 새로운 학습 코스에 대한 인앱 메시지를 수신합니다. 메시지를 클릭하고 코스를 시작합니다. 앱에서 네 개의 코스에 추가로 등록합니다. 이 모든 것이 메시지를 한 번만 수신한 후 같은 날에 발생합니다.

**결과:** Lena의 *총 전환 수*와 *총 노출 횟수*는 각각 1만큼 증가합니다.

{% endtab %}
{% tab 시나리오 3 %}

*사용자가 인앱 메시지를 수신하고 하루 후에 전환합니다.*

Tom은 이커머스 앱의 단골 고객입니다. 관심 있던 제품의 한정 할인을 홍보하는 인앱 메시지를 수신합니다. Tom은 메시지를 클릭하지만 바로 구매하지 않기로 합니다. 다음 날, Tom은 할인을 기억하고 구매를 완료하며, 이 구매는 전날 수신한 인앱 메시지에 기여합니다.

**결과:** Tom의 *총 전환 수*와 *총 노출 횟수*는 각각 1만큼 증가합니다.

{% endtab %}
{% tab 시나리오 4 %}

*사용자가 인앱 메시지를 수신하고 하루 후에 두 번 전환합니다.*

Alex는 최근 아케이드 앱을 다운로드했습니다. 어느 날, Alex는 새 게임에서 레벨을 완료하도록 권장하는 인앱 메시지를 수신합니다. Alex는 메시지를 클릭하지만 다른 일에 집중하느라 레벨을 완료하지 못합니다. 다음 날, Alex는 같은 게임에서 두 개의 레벨을 완료합니다.

**결과:** 레벨 완료가 전환 이벤트이므로, Alex는 둘째 날에 두 번 전환했습니다. 그러나 인앱 메시지를 한 번만 수신했으므로, Alex의 *총 전환 수*와 *총 노출 횟수*는 각각 1만큼 증가합니다.

{% endtab %}
{% tab 시나리오 5 %}

*사용자가 하루에 같은 인앱 메시지를 두 번 수신하고 다음 날 두 번 전환합니다.*

John은 배달 앱을 사용하여 좋아하는 레스토랑에서 음식을 주문하는 바쁜 직장인입니다. 출근길에 지오펜스를 트리거하여 근처 레스토랑을 홍보하는 인앱 메시지를 수신합니다. 퇴근길에 재자격이 활성화되어 있어 같은 메시지를 다시 수신합니다. 제안이 마음에 들지만 그날은 주문하지 않기로 합니다.

다음 날, John은 앱을 통해 점심과 저녁을 주문하며 전환 이벤트를 두 번 수행합니다.

**결과:** John의 *총 전환 수*는 1만큼 증가하고, *총 노출 횟수*는 2만큼 증가합니다. 재자격이 활성화되어 있으므로, 전환은 John이 수신한 가장 최근의 인앱 메시지(두 번째 노출)에 할당됩니다. 각 인앱 메시지 전달에 대해 전환은 한 번만 기록될 수 있습니다.
