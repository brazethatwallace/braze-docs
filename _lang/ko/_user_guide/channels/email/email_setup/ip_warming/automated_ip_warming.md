# 자동화된 IP 워밍 {#automated-ip-warming}

> 자동화된 IP 워밍을 사용하여 새로운 IP 주소에서 이메일 볼륨을 점진적으로 증가시켜 받은편지함 제공자와의 발신자 평판을 구축하세요.

{% multi_lang_include alerts/early_access_beta_alert.md feature='Automated IP warming' %}

## 작동 방식 {#how-it-works}

자동화된 IP 워밍을 사용하여 일일 발송량을 점진적으로 늘릴 수 있으며, 이를 통해 받은편지함 제공자가 발신 패턴을 학습하고 신뢰할 수 있도록 합니다. 워크스페이스에 도메인을 추가하면 홈 대시보드의 **중단한 곳에서 계속하기** 섹션에서 **자동화된 IP 워밍** 타일을 선택할 수 있으며, 이 타일은 60일 동안 유지됩니다.

Braze는 가장 참여도가 높은 가입자에게 먼저 발송하여 일일 볼륨이 모범 사례에 맞는 속도로 성장할 수 있도록 합니다. 그런 다음 Braze는 참여 및 전달 가능성 신호를 추적합니다. Braze가 문제를 감지하면 시스템이 자동으로 스케줄을 조정합니다.

{% alert note %}
IP 워밍은 한 번만 수행할 수 있습니다.
{% endalert %}

## 필수 조건 {#prerequisites}

자동화된 IP 워밍을 수행하려면 다음이 필요합니다:

- 검증된 하위 도메인 및 활성 IP 주소
- IP 워밍을 보고 시작할 수 있는 권한
    - IP 워밍 섹션을 보려면 "사용 데이터 보기"
    - IP 워밍을 위한 이메일 템플릿을 보고 선택하려면 "이메일 템플릿 보기"
    - IP 워밍을 시작하려면 "이메일 설정 관리"
- "Campaign 접근"
- Campaign에 대한 승인 워크플로우가 활성화된 경우 "Campaign 승인 및 거부"
    - Braze는 자동화된 IP 워밍에서 생성된 Campaign을 사용자를 대신하여 자동으로 승인합니다.

## 자동화된 IP 워밍 계획 설정 {#set-up-an-automated-ip-warming-plan}

### 1단계: 스케줄 설정 {#step-1-set-a-schedule}

1. **발송 정보** 섹션에서 IP 주소를 워밍할 **보낸 사람 주소**를 선택하세요.
2. 현재 일일 발송량과 목표 발송량을 입력하세요.
3. 자동화된 IP 워밍의 시작 날짜를 선택하세요. 이 날짜는 계획이 시작된 후 최소 하루 이상이어야 합니다.
4. 발송 시간을 입력하세요. 메시지는 회사의 시간대에 맞춰 전송됩니다.
5. **다음: Segments**를 선택하여 설정을 계속합니다.

![예시 스케줄 세부 정보.]({% image_buster /assets/img/automated_ip_warming_schedule.png %})

### 2단계: Segment 선택 및 순위 지정 {#step-2-select-and-rank-segments}

1. 다음으로, 타겟할 Segments를 선택하세요. IP 워밍 중에 Braze는 참여도가 가장 높은 사용자에게 먼저 발송하기 시작하고, 시간이 지남에 따라 발송량을 점차 증가시키며 참여도가 낮은 Segments를 천천히 추가합니다.
2. 그런 다음 Segments를 드래그 앤 드롭하여 높은 참여도에서 낮은 참여도 순으로 순위를 매기세요. 높은 참여도는 이메일을 꾸준히 열람하고 클릭하는 수신자를 포함합니다. 낮은 참여도는 이메일 참여가 일관되지 않거나 오랫동안 이메일에 참여하지 않은 수신자를 포함합니다.
3. **다음: 메시지**를 선택하여 설정을 계속합니다.

![자동화된 IP 워밍을 위해 타겟으로 선택된 두 개의 Segment.]({% image_buster /assets/img/automated_ip_warming_segment.png %})

### 3단계: 발송할 메시지 선택 {#step-3-select-the-messages-to-send}

1. **이메일 템플릿 선택**을 선택합니다.
2. 발송할 메시지의 이메일 템플릿을 선택합니다. IP 워밍 중에 발송하는 콘텐츠는 열람과 클릭을 유도해야 합니다. 과거에 좋은 반응을 얻었던 콘텐츠를 선택하는 것을 권장합니다. 예를 들어, 프로모션 혜택을 사용하여 즉각적인 참여와 구매를 유도할 수 있습니다.
3. **템플릿 선택**을 선택합니다. Braze는 시작하기 전에 필요한 템플릿 수를 계산합니다. 시스템이 전달 가능성 문제에 대응하면서도 중단 없이 조정할 수 있도록 최소 필요 수보다 더 많은 템플릿을 제공하는 것을 권장합니다.
4. 필요한 수의 템플릿을 추가한 후 **다음: 요약**을 선택합니다.

{% alert important %}
IP 워밍 도구에서 생성된 Campaign에 대한 변경 사항(예: 스케줄 날짜, Segment, 발송량 변경)은 IP 워밍 **요약** 페이지에 반영되지 않습니다.
{% endalert %}

### 4단계: 전환 이벤트 선택 {#step-4-select-conversion-events}

추적할 전환 이벤트를 최대 4개까지 정의할 수 있습니다. 이 전환 이벤트는 자동화된 IP 워밍 계획이 시작된 후에는 업데이트할 수 없습니다.

- 세션 시작
- 주문 완료
- 커스텀 이벤트 수행
- 앱 업그레이드
- 이메일 열람
- 이메일 클릭

다음으로, 전환 기한을 선택합니다. 이는 사용자가 Campaign에 진입한 시점과 전환 이벤트 사이에 경과할 수 있는 최대 시간입니다.

![전환 이벤트 선택 및 전환 기한을 보여주는 전환 설정.]({% image_buster /assets/img/automated_ip_warming_conversions.png %})

### 5단계: 검토 및 시작 {#step-5-review-and-launch}

IP 워밍 계획의 세부 정보를 검토합니다. 그런 다음 **시작**을 선택합니다.

## 활성 IP 워밍 중 {#during-active-ip-warming}

IP 워밍 Campaign은 1~2일 전에 생성되며, 다음 날 IP 워밍을 시작하는 경우는 예외입니다. 이 Campaign은 다음 형식으로 자동 명명됩니다: `IP Warming Day [X] - [Date] - [Template Name]`.

목표 일일 발송량에 도달하면 시스템은 발신자 평판을 보호하기 위해 해당 날의 발송을 중단합니다.

시스템은 다음 업계 벤치마크를 기반으로 상태를 모니터링합니다:

- 전달률이 90% 이하로 하락
- 열람률이 10% 미만
- 반송률이 5% 초과
- 스팸 신고율이 0.04% 초과

통계가 벤치마크 이하인 경우, 시스템은 발신자 평판에 대한 위험을 완화하기 위해 다음 날 발송량을 늘리지 않고 유지합니다.

## IP 워밍 계획 중지 {#stop-an-ip-warmup-plan}

Braze에서는 IP 워밍과 향후 Campaign 생성을 중지할 수 있지만, Campaign이 이미 활성 상태이거나 향후 24~48시간 내에 스케줄되어 있는 경우 해당 Campaign을 수동으로 중지해야 할 수 있습니다. IP 워밍 계획을 중지하면 관련된 모든 Campaign도 중지됩니다.

그러나 중지된 IP 워밍은 재개할 수 없습니다. 대신, 중단한 지점부터 다시 시작하기 위해 새 계획을 설정해야 합니다:

- 새 IP 워밍을 시작하면 이전 추적기가 제거되므로, 기록 보관을 위해 중지된 계획의 기존 데이터를 다운로드합니다
- **현재 일일 발송량**을 가장 최근 발송량으로 업데이트합니다
- 이전 IP 워밍과 동일한 Segment를 사용할 계획이라면, 이전 Campaign을 이미 수신한 사용자를 제외하는 필터를 Segment에 추가합니다

## IP 워밍이 완료되면 {#when-an-ip-warmup-completes}

IP 워밍은 IP 워밍의 마지막 날이 회사 시간대 기준 자정에 종료될 때 완료로 표시됩니다. 예를 들어, IP 워밍 계획에서 마지막 Campaign이 오후 8시에 발송되면 4시간 후에 계획이 완료로 표시됩니다.

추적기는 계획 종료 후 90일 동안 홈페이지에 유지됩니다. 90일 후에는 추적기가 제거됩니다. 데이터를 다운로드하면 다음과 같은 표준 이메일 측정기준이 포함됩니다:

- _발송_
- _전달_
- _반송_
- _스팸 신고_
- _총 열람_
- _고유 열람_
- _클릭 수_
- _가입 취소_

하루에 발송량 요구 사항을 충족하기 위해 여러 Campaign이 사용된 경우, 일별 보기에서 집계됩니다.
