# 이메일 유효성 검사

> 이 참조 문서에서는 이메일 주소의 로컬 및 호스트 부분 유효성 검사 규칙을 다룹니다. 검증은 대시보드 이메일 주소, 최종 사용자 이메일 주소(고객), 이메일 메시지의 발신자 및 회신 주소에 사용됩니다.

## 작동 방식

Braze는 이메일 주소가 업데이트되거나 API, CSV 업로드, SDK를 통해 가져오거나 대시보드에서 수정될 때 해당 주소를 검증합니다. 이메일 주소에는 공백을 포함할 수 없습니다. API를 사용할 경우 공백은 `400` 오류를 반환합니다.

Braze는 특정 문자를 거부하고 주소를 유효하지 않다고 표시합니다. 이메일이 반송되면 Braze는 해당 주소를 유효하지 않은 것으로 표시하며 구독 상태를 변경하지 않습니다. 이메일 본문에 비표준 [ASCII](https://en.wikipedia.org/wiki/ASCII) 문자가 포함된 경우, Braze는 이메일을 발송하지 않습니다.

{% details 허용되는 문자 %}
- 문자 (A-Z)
- 숫자 (0-9)
- 기호
	- -
	- &#94;
	- +
	- $
	- '
	- &
	- #
	- /
	- %
	- *
	- =
	- `
	- |
	- ~
	- !
	- ?
	- . (문자 또는 다른 문자 사이에만)
{% enddetails %}

{% details 허용되지 않는 문자 %}
- 공백 (ASCII 및 유니코드)
{% enddetails %}

이 검증은 구문 검사이며, 검증 서비스가 아닙니다. 이 프로세스의 목표 중 하나는 이메일 주소의 로컬 부분에서 국제 문자(예: UTF-8)를 지원하는 것입니다.

Braze는 이메일 주소의 로컬 부분과 호스트 부분 모두에 대해 구문 검증을 수행합니다. 로컬 부분은 @ 기호(@) 앞의 모든 문자열이며, 호스트 부분은 그 뒤의 모든 문자열입니다. 로컬 부분은 마침표(.)를 제외한 허용된 모든 문자로 시작하고 끝날 수 있습니다. 이 프로세스는 도메인에 유효한 MX 서버가 있는지 또는 해당 도메인에 사용자가 존재하는지 여부를 고려하지 않습니다.

{% alert important %}
도메인 부분에 비표준 ASCII 문자가 포함된 경우, Braze에 제공하기 전에 [Punycode로](https://www.punycoder.com/) 인코딩해야 합니다.
{% endalert %}

Braze가 유효하지 않은 이메일 주소를 가진 사용자를 추가하라는 요청을 받으면 API는 오류를 반환합니다. CSV 업로드 시 Braze는 사용자를 생성하지만 유효하지 않은 이메일 주소는 제외합니다.

## 로컬 부분 유효성 검사 규칙

### 일반 이메일 유효성 검사

대부분의 도메인에서는 로컬 부분이 다음 매개변수를 따라야 합니다:
- 모든 문자, 숫자(유니코드 문자 및 숫자 포함)와 다음 문자를 포함할 수 있습니다: (+) (&) (#) (_) (-) (^) 또는 (/)
- 다음 문자를 포함할 수 있지만 시작 또는 끝에 사용할 수 없습니다: (.)
- 큰따옴표(")를 포함할 수 없습니다
- 길이가 1~64자여야 합니다

다음 정규표현식을 사용하여 이메일 주소가 유효한 것으로 간주되는지 확인할 수 있습니다:
```
/\A([a-zA-Z0-9_\-\^+$'\&#\/!%\*=\?`\|~]|[[^\p{ASCII}\p{Space}]&&\p{Alnum}\p{Punct}\p{S}])(([a-zA-Z0-9_\-\^+$'\&#\/!%\*=\?`\|~\.]|[[^\p{ASCII}\p{Space}]&&\p{Alnum}\p{Punct}\p{S}])*([a-zA-Z0-9_\-\^+$'\&#\/!%\*=\?`\|~]|[[^\p{ASCII}\p{Space}]&&\p{Alnum}\p{Punct}\p{S}]))?\z/
```

### Gmail 주소

도메인 부분이 Gmail인 경우, 로컬 부분은 최소 2자 이상이어야 하며 위에 나열된 정규표현식 유효성 검사를 따라야 합니다.

### Microsoft 도메인

호스트 도메인에 "msn", "hotmail", "outlook" 또는 "live"가 포함된 경우, Braze는 다음 정규표현식을 사용하여 로컬 부분의 유효성을 검사합니다: `/\A\w[\-\w]*(?:\.[\-\w]+)*\z/i`

Microsoft 주소의 로컬 부분은 다음 매개변수를 따라야 합니다:

- 문자(a-z), 밑줄(_) 또는 숫자(0-9)로 시작할 수 있습니다.
- 영숫자(a-z 또는 0-9) 또는 밑줄(_)을 포함할 수 있습니다
- 다음 문자를 포함할 수 있습니다: (.) 또는 (-)
- 마침표(.)로 시작할 수 없습니다
- 연속된 마침표(.)를 두 개 이상 포함할 수 없습니다
- 마침표(.)로 끝날 수 없습니다

유효성 검사 테스트는 "+" 앞의 로컬 부분이 정규표현식과 일치하는지 확인합니다.

## 호스트 부분 유효성 검사 규칙

호스트 부분은 IPv4 또는 IPv6 주소일 수 없습니다. 최상위 도메인(.com, .org, .net 등)은 완전히 숫자로만 구성될 수 없습니다.

다음 정규표현식을 사용하여 도메인의 유효성을 검사합니다:<br>
`/^[a-z\d](?:[a-z\d-]{0,61}[a-z\d])?(?:\.[a-z\d](?:[a-z\d-]{0,61}[a-z\d])?)+$/i`

도메인 이름은 다음 매개변수를 충족해야 합니다:

- 마침표로 구분된 두 개 이상의 레이블로 구성됩니다
	- 도메인 이름의 각 부분을 "레이블"이라고 합니다. 예를 들어, 도메인 이름 "example.com"은 "example" 레이블과 "com" 레이블로 구성됩니다.
- 최소 하나의 마침표(.)를 포함해야 합니다
- 연속된 마침표를 두 개 이상 포함할 수 없습니다
- 마침표로 구분된 각 레이블은 다음을 충족해야 합니다:
	- 영숫자(a-z 또는 0-9)와 하이픈(-)만 포함해야 합니다
	- 영숫자(a-z 또는 0-9)로 시작해야 합니다
	- 영숫자(a-z 또는 0-9)로 끝나야 합니다
	- 1~63자를 포함해야 합니다

### 추가 유효성 검사 필요

도메인의 마지막 레이블은 유효한 최상위 도메인(TLD)이어야 하며, 마지막 마침표 뒤의 모든 부분으로 결정됩니다. 이 TLD는 [ICANN의 TLD 목록](https://data.iana.org/TLD/tlds-alpha-by-domain.txt)에 나타나야 합니다. Braze 유효성 검사기는 구문만 확인합니다. 오타나 존재하지 않는 주소는 감지하지 않습니다.

{% alert important %}
유니코드는 이메일 주소의 로컬 부분에서만 허용됩니다. 유니코드는 도메인 부분에서는 허용되지 않지만, Punycode로 인코딩할 수 있습니다.
{% endalert %}
