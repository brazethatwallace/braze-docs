# 내부 그룹 {#internal-groups}

> 내부 그룹은 내부 또는 서드파티 테스트 그룹을 구축하고 구성하는 데 유용한 방법입니다. SDK 또는 API 로그에 대한 인사이트를 제공하며, SDK 통합을 테스트할 때 유용합니다. 최대 1,000명의 사용자로 구성된 커스텀 내부 그룹을 무제한으로 생성할 수 있습니다.

{% alert tip %}
[테스트 및 문제 해결](https://learning.braze.com/path/developer/testing-and-troubleshooting) Braze 학습 과정도 확인해 보시기 바랍니다. 이 과정에서는 내부 그룹을 사용하여 직접 문제 해결 및 디버깅을 수행하는 방법을 다룹니다.
{% endalert %}

## 전제 조건 {#prerequisites}

내부 그룹을 생성하고 관리하려면 다음 [사용자 권한]({{site.baseurl}}/user_guide/administer/global/user_management/permissions)이 필요합니다:

- API 키 보기
- API 키 편집
- 내부 그룹 보기
- 내부 그룹 편집
- 메시지 활동 로그 보기
- 이벤트 사용자 로그 보기
- API 식별자 보기
- API 사용량 대시보드 보기
- API 제한 보기
- API 사용량 알림 보기
- API 사용량 알림 편집
- SDK 디버거 편집
- SDK 디버거 보기

## 내부 그룹 만들기 {#creating-an-internal-group}

내부 그룹을 만들려면:

1. **설정** > **내부 그룹**으로 이동합니다.
2. **내부 그룹 만들기**를 선택합니다.
3. "이메일 테스트 그룹"과 같이 그룹 이름을 지정합니다.
4. 다음 표에 나열된 그룹 유형 중 하나 이상을 선택합니다.

| 그룹 유형 | 설명 |
|--------------------|---------------------------------------------------------------------------------------------|
| **사용자 이벤트 그룹** | 테스트 기기에서 이벤트 또는 로그를 확인하는 데 사용합니다.<br><br>그룹 멤버의 SDK 및 REST API 로그를 캡처하려면 **사용자 이벤트** 체크박스를 선택합니다. 이 설정이 없으면 그룹에 추가된 사용자의 로그가 [이벤트 사용자 로그]({{site.baseurl}}/user_guide/administer/global/workspace_settings/logs_and_alerts/event_user_log)에 표시되지 않습니다. |
| **콘텐츠 테스트 그룹** | 푸시, 이메일, 인앱 메시지 전반에서 렌더링된 메시지 사본을 전송하는 데 사용합니다. |
| **시드 그룹** | 전송 시 시드 그룹의 모든 멤버에게 이메일 사본을 자동으로 전송합니다. |
{: .reset-td-br-1 .reset-td-br-2 aria-label="내부 그룹 만들기" }

{:start="5"}
5. **내부 그룹 만들기**를 다시 선택합니다.

### 테스트 사용자 추가 {#adding-test-users}

내부 그룹을 만든 후 해당 그룹의 멤버로 테스트 사용자를 추가합니다.

1. 내부 그룹 관리 페이지에서 **테스트 사용자 추가**를 선택합니다.
2. 다음 방법 중 하나를 선택하여 테스트 사용자를 검색하고 선택합니다.

| 방법 | 설명 |
|-------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **식별된 사용자 추가** | 외부 ID, 이메일 주소, 전화번호 또는 푸시 토큰으로 사용자를 검색합니다. |
| **익명 사용자 추가** | IP 주소로 검색합니다. 그런 다음 추가하는 각 테스트 사용자의 이름을 입력합니다. 이 이름은 [이벤트 사용자 로그]({{site.baseurl}}/user_guide/administer/global/workspace_settings/logs_and_alerts/event_user_log) 페이지에서 모든 이벤트 로그와 연결됩니다. |
| **사용자 일괄 추가** | 이메일 주소 또는 외부 ID 목록을 복사하여 붙여넣습니다. 대시보드에 이미 알려진 사용자만 추가할 수 있습니다. 자세한 내용은 [사용자 가져오기]({{site.baseurl}}/user_guide/audience/manage_audience/import_users)를 참조하세요. |
{: .reset-td-br-1 .reset-td-br-2 aria-label="테스트 사용자 추가" }

### 콘텐츠 테스트 그룹 {#content-test-groups}

메시지의 미리보기 테스트를 전송하는 것과 유사하게, 콘텐츠 테스트 그룹을 사용하면 시간을 절약하고 사전 정의된 Braze 사용자 목록에 동시에 테스트를 실행할 수 있습니다. 이 기능은 Braze의 푸시, 인앱 메시지, SMS, 이메일 및 Content Cards에서 사용할 수 있습니다. 콘텐츠 테스트 그룹으로 태그된 그룹만 메시지의 미리보기 섹션에서 사용할 수 있습니다.

{% alert note %}
[SMS]({{site.baseurl}}/user_guide/channels/sms_mms_and_rcs) 테스트 메시지는 데이터베이스에 있는 유효한 전화번호로만 전송할 수 있습니다.
{% endalert %}

개별 Braze 사용자 또는 원하는 수의 내부 그룹을 선택하여 메시지를 전송합니다. 메시지에 Liquid 또는 기타 동적 개인화가 포함된 경우, Braze는 각 사용자에게 사용 가능한 속성을 사용하여 메시지 콘텐츠를 개인화합니다. 속성이 없는 사용자의 경우 Braze는 설정된 기본값을 사용합니다.

또한 메시지를 임의 사용자, 커스텀 사용자 또는 기존 사용자로 미리보기하는 경우 해당 미리보기 버전을 대신 전송할 수 있습니다. 체크박스를 해제하면 미리보기 버전 대신 각 사용자의 속성을 기반으로 전송됩니다.

IP 풀을 사용하여 이메일을 전송하는 경우, 사용 가능한 드롭다운에서 풀을 선택하여 이메일을 전송할 IP 풀을 선택합니다.

![콘텐츠 테스트 그룹을 선택하는 인앱 메시지 편집기의 테스트 섹션.]({% image_buster /assets/img_archive/content_test_preview.png %}){: style="max-width:60%" }

### 시드 그룹 {#seed-groups}

시드 그룹은 이메일 채널에서만 지원됩니다. 시드 그룹에 사용자를 추가하면 각 이메일 배리언트 메시지의 사본이 그룹의 모든 멤버에게 전송됩니다.

시드 그룹은 API Campaigns에서는 사용할 수 없지만, Campaign에서 API 트리거 항목을 사용하여 시드 그룹을 포함할 수 있습니다. 이를 사용하여 전달 가능성 측정기준을 측정하고 이메일 콘텐츠의 기록 및 보관 목적으로 기록을 유지합니다.

내부 그룹을 만들고 시드 그룹으로 사용하도록 태그한 후, Campaign 편집기의 **타겟 오디언스** 단계에서 또는 Canvas의 **전송 설정** 단계에서 선택합니다.

시드 이메일은 제목란 앞에 `[SEED]`가 추가됩니다. 시드 이메일은 다음을 수행하지 **않습니다**:

- 대시보드 분석에서 전송 수를 증가시킵니다.
- 이메일 분석 또는 리타겟팅에 영향을 줍니다.
- 고객 프로필의 **수신한 Campaign** 목록을 업데이트합니다.
- 최대 게재빈도 설정에 영향을 줍니다.
- 전송 속도 사용량 제한에 포함되거나 영향을 줍니다.

#### 가입 동작 {#subscription-behavior}

시드 전송은 내부 QA 및 검토를 위해 설계되었으므로, 시드 대상 회사 사용자에 대한 가입 확인을 의도적으로 우회합니다. 즉, 유효한 이메일 주소를 가진 사용자가 시드 그룹에 속해 있으면 가입하지 않은 경우에도 메시지를 수신합니다. 단, 해당 그룹에 시드 사본을 전송하도록 메시지가 구성되어 있어야 합니다.

{% alert tip %}
시드 그룹 멤버가 메시지를 받지 못하는 경우, 내부 그룹에 포함되어 있는지 확인하고, Gmail에서 메시지가 스레드로 묶이지 않도록 고유한 제목란을 사용하며, 스팸 폴더를 확인하도록 요청하세요.

이메일이 [`abort_message()` Liquid]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/liquid/aborting_messages)를 사용하는 경우, 시드 그룹 멤버도 전송을 수신하려면 중단 조건을 충족해야 합니다.
{% endalert %}

#### Campaigns의 경우 {#for-campaigns}

이메일 Campaign을 작성할 때 편집기의 **타겟 오디언스** 섹션에서 시드 그룹을 편집합니다.

{% alert important %}
시드 그룹을 모든 Campaign에 자동으로 첨부하도록 구성하면 새 Campaign에만 적용됩니다. 기존 Campaign을 복사할 때는 적용되지 않습니다. 복사된 Campaign의 **타겟 오디언스** 섹션에서 원하는 시드 그룹을 수동으로 적용해야 합니다.
{% endalert %}

시드 그룹은 각 이메일 배리언트에 한 번씩 전송되며, 사용자가 해당 특정 배리언트를 처음 수신할 때 전달됩니다. 예약된 메시지의 경우 일반적으로 Campaign이 처음 시작될 때입니다. 액션 기반 또는 API 트리거 Campaign의 경우 첫 번째 사용자에게 메시지가 전송되는 시점입니다.

Campaign이 다변량이고 배리언트의 전송 비율이 0%인 경우 시드 그룹에 전송되지 않습니다. 또한 배리언트가 이미 전송되었고 **타겟** 단계의 **시드 그룹 편집**에서 재전송하도록 업데이트되지 않은 경우 기본적으로 다시 전송되지 않습니다.

{% alert note %}
반복 Campaign이 있고 배리언트 중 하나가 업데이트된 경우, 업데이트된 배리언트만 다시 전송하거나, 모든 배리언트를 다시 전송하거나, 업데이트 시 시드 그룹 전송을 끌 수 있습니다.
{% endalert %}

#### Canvas의 경우 {#for-canvas}

Canvas의 시드 그룹은 트리거된 Campaign과 유사하게 작동합니다. Braze는 이메일 메시지가 포함된 모든 단계를 자동으로 감지하고, 사용자가 해당 특정 이메일 단계에 처음 도달할 때 전송합니다.

시드 그룹에 메일이 전송된 후 이메일 단계가 업데이트된 경우, Braze는 업데이트된 단계에만 전송하거나, 모든 단계에 전송하거나, 시드를 끄는 옵션을 제공합니다.
