# Decisioning Studio Go 에이전트 설정 {#set-up-your-decisioning-studio-go-agent}

> 이 문서에서는 Braze 대시보드의 셀프 서비스 설정 흐름을 사용하여 Decisioning Studio Go 에이전트를 구성하는 방법을 설명합니다.

Decisioning Studio Go의 작동 방식에 대한 개요는 [BrazeAI Decisioning Studio Go]({{site.baseurl}}/user_guide/brazeai/decisioning_studio/decisioning_studio_go)를 참조하세요. 에이전트를 구성하기 전에 프로그램이 적합한지 확인하려면 [Decisioning Studio Go 예시]({{site.baseurl}}/user_guide/brazeai/decisioning_studio/decisioning_studio_go/examples)를 참조하세요.

## 필수 조건 {#prerequisites}

다음 항목이 준비되어 있는지 확인하세요:

- 다른 Canvas나 Campaign에서 활발히 사용되지 않는 진입 오디언스용 [Segment]({{site.baseurl}}/user_guide/audience/segments/creating_a_segment)
- 최소 하나의 이메일 템플릿
- 대체 제목란, CTA, 히어로 이미지 등 테스트하려는 배리언트 콘텐츠. 설정 중에 배리언트를 생성할 수 있지만, 미리 준비해 두면 구성 속도가 빨라집니다
- AI Decisioning 에이전트를 구성할 수 있는 권한이 있는 워크스페이스 접근 권한

워크스페이스에 Decisioning Studio Go가 프로비저닝되지 않은 경우 **AI Decisioning** 탭에 에이전트 구성 옵션이 표시되지 않습니다. 접근 권한을 얻으려면 고객 성공 매니저에게 문의하세요.

## 1단계: 에이전트 설정 {#step-1-set-up-your-agent}

1. Braze 대시보드에서 **AI Decisioning** 탭으로 이동합니다.
2. **Create Agent**를 선택합니다.
3. 워크스페이스의 다른 에이전트와 구별할 수 있는 이름을 지정합니다. 예를 들어 "Email Agent"보다는 "Loyalty Members—Weekly Engagement"와 같이 지정합니다.
4. (선택 사항) 나중에 본인이나 팀원에게 필요할 수 있는 맥락을 제공하는 설명을 추가합니다. 에이전트의 용도, 타겟팅하는 Segment, 성공의 기준 등을 포함할 수 있습니다.


에이전트는 사용자당 의미 있는 클릭 활동으로 측정되는 진정한 인게이지먼트를 극대화하기 위해 이메일 크리에이티브를 최적화합니다. 클릭은 자동화된 활동과 수신 거부 관련 클릭을 걸러내는 여러 독립 검증 필터를 거치므로, 신호는 원시 클릭 볼륨이 아닌 실제 고객 관심을 반영합니다.

## 2단계: 타겟 오디언스 선택 {#step-2-select-the-target-audience}

에이전트가 발송할 Braze Segment를 선택합니다. 이 Segment의 사용자는 자동으로 두 그룹으로 나뉩니다:

- **Decisioning Studio 그룹:** AI 최적화된 이메일 콘텐츠를 수신합니다. 에이전트가 각 사용자에게 최적의 배리언트 조합을 선택합니다.
- **무작위 대조군:** Segment의 최소 5%입니다. 무작위로 선택된 날에 동일한 옵션의 무작위 조합을 수신합니다. 이 그룹은 필수입니다.

![예상 사용자 1,100명이 있는 선택된 Segment.]({% image_buster /assets/img/decisioning_studio_go/audience_details.png %})

### 전용 Segment가 중요한 이유 {#why-a-dedicated-segment-matters}

선택한 Segment의 사용자가 다른 Canvases나 Campaigns에서도 메시지를 수신하는 경우, 에이전트가 관찰하는 인게이지먼트가 해당 다른 메시지의 영향을 받습니다. 에이전트는 사용자가 자신의 결정 때문에 클릭했는지 다른 요인 때문에 클릭했는지 구분할 수 없습니다. 선택한 Segment가 다른 곳에서 사용 중인 경우 경고가 표시됩니다. 진행할 수 있지만 결과에 노이즈가 더 많을 수 있습니다.

### 사용자 조회 {#user-lookup}

**User Lookup**을 사용하여 특정 사용자가 Segment 기준을 충족하는지 확인합니다. Segment 정의를 검증하는 데 유용합니다.

### 오디언스 필터 {#audience-filters}

이번 릴리스에서는 오디언스 필터가 지원되지 않습니다. 추가 타겟팅 기준이 필요한 경우 해당 필터가 적용된 [Segment를 생성]({{site.baseurl}}/user_guide/audience/segments/creating_a_segment)한 다음 해당 Segment를 진입 오디언스로 선택하세요.

### 기존 Canvases와 통합 {#integrate-with-existing-canvases}

더 넓은 여정 내에서 Decisioning Studio Go를 사용하려면:

1. 에이전트에 포함되어야 하는 사용자를 위한 전용 Segment를 생성합니다.
2. [Canvas]({{site.baseurl}}/user_guide/messaging/canvas/create_a_canvas)에서 사용자 업데이트 단계를 사용하여 여정의 적절한 시점에 사용자를 해당 Segment에 추가합니다.
3. 사용자가 Canvas를 종료하여 해당 시점부터 Segment의 모든 사용자에 대해 에이전트(Canvas가 아닌)가 이메일 발송을 처리하도록 확인합니다.

## 3단계: 스케줄 구성 {#step-3-configure-the-schedule}

에이전트가 발송할 수 있는 시기를 결정합니다.

### 3.1단계: 발송 빈도 결정 {#step-31-determine-the-send-frequency}

이 에이전트에서 사용자가 이메일을 수신하는 빈도를 선택합니다. 예를 들어 주 3회입니다. 이것은 단일 선택입니다. 에이전트는 서로 다른 빈도 간에 최적화하지 않으며, 설정한 빈도 내에서 요일과 시간을 선택합니다.

### 3.2단계: 요일 선택 {#step-32-select-the-days-of-the-week}

에이전트가 발송할 수 있는 요일을 선택합니다. 빈도에 필요한 만큼의 요일을 최소한 선택해야 합니다(에이전트가 주 3회 발송하는 경우 최소 3일을 선택하세요. 더 많은 요일을 선택하면 에이전트에 더 많은 유연성이 부여됩니다). 에이전트는 해당 세트 내에서 최적화하여 각 사용자에게 최적의 요일을 선택합니다. 최대 유연성을 위해 7일 모두 선택하세요.

### 3.3단계: 방해금지 시간 설정 {#step-33-set-quiet-hours}

에이전트가 발송하지 않아야 하는 시간을 지정합니다. 방해금지 시간은 사용자의 현지 시간대를 사용합니다. 가장 일반적인 용도는 심야 및 이른 아침 발송을 차단하는 것입니다. 방해금지 시간 외에는 에이전트가 각 사용자에 대해 클릭을 유도할 가능성이 가장 높은 시간에 발송을 예약합니다.

### 3.4단계: 최대 게재빈도 설정 규칙 설정 {#step-34-set-frequency-capping-rules}

최대 게재빈도 설정 규칙을 에이전트 수준에서 적용할 수 있습니다:

- **최대 게재빈도 적용:** 사용자의 최대 게재빈도에 도달하면 에이전트가 해당 사용자에게 발송하는 것을 방지합니다. 규칙 구성 방식에 따라 이 한도는 개별 사용자 수준 또는 전체 계정 수준에서 적용될 수 있습니다. 어느 경우든 한도가 충족되는 동안 해당 사용자에게 메시지가 발송되지 않습니다.
- **한도에 포함:** 이 에이전트의 발송이 사용자의 전체 한도에 포함되는지 여부를 선택합니다.

{% alert tip %}
최대 게재빈도가 사용자 경험을 보호하는 경우, 에이전트의 발송은 이미 타겟팅되어 있으므로 한도에 포함할 필요가 없을 수 있습니다. 한도가 전체 발송량이나 비용을 제어하는 경우에는 포함하는 것이 좋습니다. 고객 성공 매니저 또는 솔루션 컨설턴트가 워크스페이스에 적합한 접근 방식을 확인하는 데 도움을 줄 수 있습니다.
{% endalert %}

## 4단계: 콘텐츠 및 템플릿 추가 {#step-4-add-content-and-templates}

에이전트가 작업할 수 있는 항목을 정의합니다:

- **기본 크리에이티브:** 전체 이메일 템플릿입니다. 에이전트는 먼저 특정 사용자에게 어떤 기본 크리에이티브를 발송할지 선택합니다.
- **크리에이티브 구성 요소:** 기본 크리에이티브 내의 특정 요소(제목란, CTA, 히어로 이미지)로, 에이전트가 사용자별로 개인화합니다.

기본 크리에이티브는 다음과 같은 방법으로 만들 수 있습니다:

- 표준 Braze 이메일 작성기를 사용합니다.
- 기존 Canvas 또는 Campaign에서 이메일을 가져옵니다.

단일 기본 크리에이티브 또는 여러 개를 사용할 수 있습니다. 하나의 기본 크리에이티브를 사용하면 에이전트는 그 안의 구성 요소만 개인화합니다. 여러 기본 크리에이티브(예: 캐주얼, 포멀, 프로모션 각각 하나씩)를 사용하면 에이전트가 각 사용자에게 적합한 기본 크리에이티브도 선택합니다. 에이전트는 추가 크리에이티브 구성 요소 없이 여러 기본 크리에이티브 중에서 선택할 수도 있습니다.

### 4.1단계: Liquid 태그로 개인화 포인트 표시 {#step-41-mark-personalization-points-with-liquid-tags}

에이전트가 개인화할 각 구성 요소에 대해 기본 크리에이티브의 정적 콘텐츠를 개인화 메뉴의 Liquid 태그로 교체합니다. 그런 다음 **크리에이티브 구성 요소** 섹션에서 배리언트 옵션을 제공합니다.

이번 릴리스에서 지원되는 구성 요소는 다음과 같습니다:

- **제목란:** **Sending Settings**의 제목란을 제목란용 Liquid 태그로 교체합니다.
- **CTA:** 이메일 본문의 버튼 텍스트를 CTA용 Liquid 태그로 교체합니다.
- **이미지:** 히어로 이미지 URL을 이미지용 Liquid 태그로 교체합니다.

{% alert note %}
[Content Blocks]({{site.baseurl}}/user_guide/messaging/design_and_edit/content_blocks)는 개인화된 구성 요소의 대체 포인트로 지원되지 않습니다. 개인화된 제목란, CTA, 이미지를 콘텐츠 블록 내부가 아닌 이메일 본문에 직접 배치하세요.
{% endalert %}

### 4.2단계: 배리언트 추가 {#step-42-add-variants}

**크리에이티브 구성 요소** 섹션에서 각 개인화 포인트에 대한 배리언트 옵션을 추가합니다:

- 여러 제목란 옵션
- 여러 CTA 텍스트 옵션
- 여러 이미지 URL

각 배리언트는 특정 기본 크리에이티브에 연결하거나 모든 기본 크리에이티브에서 사용할 수 있습니다. 예를 들어, 세일을 홍보하는 기본 크리에이티브와 신상품을 홍보하는 기본 크리에이티브가 있는 경우, `Don't miss our biggest savings of the year` 제목란을 세일 크리에이티브에만 제한하면서 `Just dropped` CTA는 두 크리에이티브 모두에서 사용할 수 있습니다.

이미지는 Braze 미디어 라이브러리에서 선택해야 합니다. 사용하려는 이미지가 있으면 먼저 미디어 라이브러리에 업로드하세요.

### 4.3단계: 미리보기 및 테스트 {#step-43-preview-and-test}

콘텐츠를 추가하면서 다양한 배리언트 조합이 어떻게 렌더링되는지 보여주는 동적 미리보기를 사용하여 메시지를 미리보기하고 테스트합니다. 이는 시작 전에 렌더링 문제를 발견하고 해결하는 데 유용합니다. 기본 크리에이티브와 배리언트가 구성되면 에이전트가 발송할 수 있는 모든 조합의 전체 목록을 확인할 수 있습니다.

본인이나 팀원에게 테스트 발송을 할 수도 있습니다. 테스트 발송은 에이전트가 특정 사용자에게 선택할 내용이 아닌, 선택한 특정 배리언트 조합을 표시합니다.

## 5단계: 제약 조건 정의 {#step-5-define-constraints}

제약 조건은 에이전트가 동일한 사용자에게 반복적인 콘텐츠를 발송하는 것을 방지합니다. 다음 수준을 사용할 수 있습니다:

- **기본 크리에이티브 수준:** 정의한 기간 내에 동일한 기본 크리에이티브가 사용자에게 두 번 이상 발송되는 것을 방지합니다. 각 기본 크리에이티브가 충분히 구별되어 예를 들어 일주일 내에 반복하면 진부하게 느껴질 때 유용합니다.
- **제목란 수준:** 정의한 기간 내에 동일한 제목란이 사용자에게 두 번 이상 발송되는 것을 방지합니다. 제목란이 가장 눈에 띄는 반복 신호일 때 유용합니다.

특정 이미지나 CTA에 대한 배리언트 수준 제약 조건은 이번 릴리스에서 지원되지 않습니다.

## 6단계: 검토 및 시작 {#step-6-review-and-launch}

**Review** 화면에 전체 구성이 표시됩니다: 오디언스 및 무작위 대조군 분할, 스케줄, 기본 크리에이티브, 배리언트 수, 활성 제약 조건. 이 섹션에 표시되는 유효성 검사 경고(예: 다른 Campaign과의 Segment 겹침)를 검토하고 해결합니다.

**Launch**를 선택하여 에이전트를 활성화합니다. **Draft**에서 **Live**로 전환되며 다음 적격 날짜에 발송을 시작합니다.

## 시작 후 {#after-launch}

### 학습 기간 {#training-period}

에이전트가 시작되면 학습 기간에 들어갑니다. 리포팅 인터페이스에 학습 표시기가 표시됩니다. 에이전트가 조합을 탐색하는 처음 며칠 동안 성능이 변동할 수 있습니다. 학습하는 동안에도 이메일은 계속 발송됩니다. 대기 기간은 없습니다.

의미 있는 성능 변화는 에이전트가 학습을 마치고 활성 개인화로 전환된 후에 나타납니다. 리포팅에서 해당 전환이 발생하는 시점을 표시하므로 에이전트가 어떤 단계에 있는지 항상 알 수 있습니다.

### 리포팅 뷰 {#reporting-views}

리포팅 인터페이스는 세 가지 주요 뷰를 제공합니다:

| 뷰 | 설명 |
|---|---|
| **Performance** | 클릭률, 인게이지먼트 측정기준, Decisioning Studio 그룹 대 무작위 대조군의 리프트. |
| **Configuration** | 에이전트의 현재 설정으로, 실행 중인 내용을 확인하는 데 유용합니다. |
| **Agent preferences** | 에이전트가 각 배리언트를 선택한 횟수로, 에이전트가 오디언스에 대해 어떤 방향으로 기울고 있는지 보여줍니다. |
{: .reset-td-br-1 .reset-td-br-2 aria-label="리포팅 뷰" }

요소 수준 분석은 개별 제목란, CTA, 이미지가 모든 조합에서 어떻게 성능을 발휘하는지 보여줍니다.

### 실시간 에이전트 편집 {#edit-a-live-agent}

**Configuration** 뷰로 이동하여 시작 후 오디언스, 스케줄, 크리에이티브 또는 제약 조건을 수정합니다. Configuration 뷰에 변경 사항 요약이 표시됩니다. 변경 사항이 적용되기 전에 승격합니다. 새 배리언트를 추가해도 기존 배리언트에 대한 에이전트의 학습이 초기화되지 않으며, 에이전트의 메뉴에 새 옵션이 추가됩니다.

### 일시 중지 또는 중지 {#pause-or-stop}

에이전트의 수명 주기는 **Draft** > **Live** > **Stopped**입니다. 언제든지 **Stop**을 선택하여 에이전트를 중지할 수 있습니다. 발송이 중단되며 다시 활성화하면 재개됩니다.

### 고려 사항 {#considerations}

- Content Blocks는 개인화 대체 포인트로 지원되지 않습니다.
- 이미지 URL은 수동으로 추가해야 합니다. 현재 미디어 라이브러리 통합은 지원되지 않습니다.
- Segment 선택 외의 오디언스 필터는 지원되지 않습니다.
- 본문 텍스트, 프리헤더, 헤더 개인화는 아직 사용할 수 없습니다.
