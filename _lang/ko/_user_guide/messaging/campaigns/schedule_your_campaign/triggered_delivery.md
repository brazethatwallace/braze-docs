# 실행 기반 전달 {#action-based-delivery}

> 실행 기반 전달 Campaign 또는 이벤트 트리거 Campaign은 트랜잭션 또는 성과 기반 메시지에 매우 효과적입니다. 특정 날짜에 Campaign을 발송하는 대신, 사용자가 특정 이벤트를 완료한 후 발송되도록 트리거할 수 있습니다.

## 트리거 캠페인 설정하기 {#setting-up-a-triggered-campaign}

### 1단계: 트리거 이벤트 선택 {#step-1-select-a-trigger-event}

트리거 이벤트를 선택합니다. 다음 중 하나를 선택할 수 있습니다:
- 주문하기
- 세션 시작
- 커스텀 이벤트 수행
- Campaign의 주요 전환 이벤트 수행
- 고객 프로필에 이메일 주소 추가
- 커스텀 속성 값 변경
- 구독 상태 업데이트
- 구독 그룹 상태 업데이트
- 다른 캠페인과의 상호작용
    - 인앱 메시지 조회
    - 인앱 메시지 클릭
    - 인앱 메시지 버튼 클릭
    - 이메일 클릭
    - 이메일 내 별칭 클릭
    - 다른 Campaign 또는 캔버스 단계에서 별칭 클릭
    - 이메일 열기
    - 이메일 열기(자동 열기)
    - 이메일 열기(기타 열기)
    - 푸시 알림 직접 열기
    - 푸시 알림 버튼 클릭
    - Push Stories 페이지 클릭
    - 전환 이벤트 수행
    - 이메일 수신
    - SMS 수신
    - 단축 SMS 링크 클릭
    - 푸시 알림 수신
    - 웹훅 수신
    - 대조군에 등록됨
    - 콘텐츠 카드 조회
    - 콘텐츠 카드 클릭
    - 콘텐츠 카드 닫기
- 위치 입장
- 다른 Campaign의 예외 이벤트 수행
- 캔버스 단계와 상호작용
- 지오펜스 트리거
- SMS 인바운드 메시지 전송
- WhatsApp 인바운드 메시지 전송

Braze [커스텀 이벤트 속성정보]({{site.baseurl}}/user_guide/data/activation/events/custom_events)를 통해 트리거 이벤트를 추가로 필터링할 수도 있습니다. 이를 통해 커스텀 이벤트와 인앱 구매에 대해 사용자 정의 가능한 이벤트 속성정보를 활용할 수 있습니다. 이 기능을 사용하면 커스텀 이벤트의 특정 속성을 기반으로 메시지를 수신할 사용자를 더욱 세밀하게 조정할 수 있어 캠페인 개인화와 데이터 수집의 정교함이 높아집니다.

예를 들어, '장바구니 금액' 속성정보 필터로 추가 타겟팅되는 유기한 장바구니 커스텀 이벤트가 포함된 캠페인이 있다고 가정해 보겠습니다. 이 캠페인은 장바구니에 $100~$200 상당의 상품을 남겨 둔 사용자에게만 도달합니다.

![장바구니 금액 $100~$200 사이의 커스텀 이벤트 속성정보로 필터링된 유기한 장바구니 캠페인.]({% image_buster /assets/img_archive/customEventProperties.png %})

{% alert note %}
캠페인 Segment가 신규 사용자에게 적용되는 경우, 트리거 이벤트 '세션 시작'은 사용자의 첫 번째 앱 실행일 수 있습니다(예: Segment가 세션이 없는 사용자로 구성된 경우).
{% endalert %}

트리거 캠페인은 여전히 특정 Segment의 사용자에게 전송할 수 있으므로, Segment에 속하지 않은 사용자는 트리거 이벤트를 완료하더라도 캠페인을 수신하지 못합니다.

사용자가 프로필에 이메일 주소를 추가할 때의 트리거 이벤트에 대해서는 다음 규칙이 적용됩니다:

- 트리거 이벤트는 고객 프로필 속성이 업데이트된 후에 실행됩니다. 이는 캠페인의 Segment 및 필터 평가가 속성 업데이트 이후에 이루어진다는 것을 의미합니다. 이를 통해 '이메일 주소가 gmail.com과 일치'와 같은 필터를 설정하여 Gmail 사용자에게만 전송하고 이메일 주소를 추가하는 즉시 실행되는 트리거 캠페인을 만들 수 있습니다.
- 트리거 이벤트는 고객 프로필에 이메일 주소가 추가될 때 실행됩니다. 동일한 이메일 주소로 여러 고객 프로필을 생성한 경우, 캠페인이 각 고객 프로필에 대해 한 번씩 여러 번 실행될 수 있습니다.

또한, 트리거된 인앱 메시지는 여전히 인앱 메시지 전달 규칙을 따르며 앱 세션 시작 시 표시됩니다.

![트리거 이벤트 구성 옵션이 표시된 실행 기반 캠페인 전달 스케줄.]({% image_buster /assets/img_archive/schedule_triggered1.png %})

### 2단계: 지연 시간 선택 {#step-2-select-delay-length}

트리거 기준이 충족된 후 캠페인을 전송하기까지 대기할 시간을 선택합니다. 선택한 지연 시간이 메시지 전송 기간보다 긴 경우, 캠페인을 수신하는 사용자가 없게 됩니다.

인앱 메시지 캠페인은 트리거 이벤트 이후 최대 2시간(7,200초)까지 전달을 지연할 수 있습니다. 지연 옵션은 **즉시**와 **지연 후**입니다. 더 긴 대기 시간이 필요한 경우, Canvas에서 인앱 메시지 단계 전에 [지연]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/delay_step) 단계를 추가하세요.

{% alert important %}
Braze는 커스텀 이벤트와 함께 전송된 타임스탬프를 사용하여 실행 기반 캠페인의 지연 시간을 평가합니다. 해당 타임스탬프가 과거로 설정된 경우, Braze는 지연이 이미 경과한 것으로 처리하여 메시지를 즉시 또는 예상보다 일찍 전송할 수 있습니다. 의도하지 않은 전달 타이밍을 방지하려면, 커스텀 이벤트 타임스탬프를 현재 시각으로 전송하세요.
{% endalert %}

또한, 캠페인이 시작된 후 트리거 이벤트를 완료한 사용자가 지연이 경과한 후 메시지를 가장 먼저 수신하게 됩니다. 캠페인 시작 전에 트리거 이벤트를 완료한 사용자는 해당 캠페인을 수신할 자격이 없습니다.

![2단계: 지연 시간 선택과 관련된 스크린샷.]({% image_buster /assets/img_archive/schedule_triggered22.png %})

특정 요일에 캠페인을 전송하거나(「on the next」를 선택한 후 요일을 지정), 특정 일수 후에 전송하도록(「in」을 선택) 설정할 수도 있습니다. 또는 수동으로 전달 시간을 설정하는 대신 [Intelligent Timing]({{site.baseurl}}/user_guide/brazeai/intelligence_suite/intelligent_timing) 기능을 사용하여 메시지를 전송할 수 있습니다.

![특정 요일에 캠페인을 전송하거나(「on the next」를 선택한 후 요일을 지정), 특정 일수 후에 전송하도록(「in」을 선택) 설정할 수 있습니다. 또는 수동으로 전달 시간을 설정하는 대신 Intelligent Timing 기능을 사용하여 메시지를 전송할 수 있습니다.]({% image_buster /assets/img_archive/schedule_triggered7.png %})
![특정 요일에 캠페인을 전송하거나(「on the next」를 선택한 후 요일을 지정), 특정 일수 후에 전송하도록(「in」을 선택) 설정할 수 있습니다. 또는 수동으로 전달 시간을 설정하는 대신 Intelligent Timing 기능을 사용하여 메시지를 전송할 수 있습니다.]({% image_buster /assets/img_archive/schedule_triggered8.png %})

### 3단계: 예외 이벤트 선택 {#step-3-select-exception-events}

이 캠페인을 수신할 자격을 박탈할 예외 이벤트를 선택합니다. 이 설정은 트리거된 메시지가 시간 지연 후에 전송되는 경우에만 가능합니다. [예외 이벤트]({{site.baseurl}}/user_guide/messaging/canvas/create_a_canvas/exit_criteria#exception-events)에는 구매하기, 세션 시작, Campaign에 지정된 [전환 이벤트]({{site.baseurl}}/user_guide/messaging/messaging_fundamentals/conversion_events) 수행, 또는 커스텀 이벤트 수행이 포함될 수 있습니다. 사용자가 트리거 이벤트를 완료한 후 시간 지연으로 인해 메시지가 전송되기 전에 예외 이벤트를 완료하면, 해당 사용자는 캠페인을 수신하지 못합니다. 예외 이벤트로 인해 캠페인을 수신하지 못한 사용자는, [재자격]({{site.baseurl}}/user_guide/messaging/messaging_fundamentals/re_eligibility)을 선택하지 않더라도 다음에 트리거 이벤트를 완료하면 자동으로 캠페인을 수신할 자격이 부여됩니다.

![이 캠페인을 수신할 자격을 박탈할 예외 이벤트를 선택합니다. 이 설정은 트리거된 메시지가 시간 지연 후에 전송되는 경우에만 가능합니다.]({% image_buster /assets/img_archive/schedule_triggered32.png %})

예외 이벤트를 활용하는 방법에 대한 자세한 내용은 [사용 사례]({{site.baseurl}}/user_guide/messaging/campaigns/schedule_your_campaign/triggered_delivery#use-cases) 섹션을 참조하세요.

> 트리거 이벤트와 동일한 예외 이벤트가 포함된 캠페인을 전송하면, Braze는 해당 캠페인을 취소하고 예외 이벤트의 메시지 전달 시간을 기반으로 새 캠페인을 자동으로 다시 예약합니다. 예를 들어, 첫 번째 트리거 이벤트가 5분에 시작되고 예외 이벤트가 10분에 시작되는 경우, 예외 이벤트의 10분이 공식 캠페인 메시지 전달 시간으로 적용됩니다.

{% alert note %}
'세션 시작'을 캠페인의 트리거 이벤트와 예외 이벤트로 동시에 설정할 수 없습니다. 그러나 이 옵션 외에 다른 커스텀 이벤트는 자유롭게 선택할 수 있습니다.
{% endalert %}

### 4단계: 기간 할당 {#step-4-assign-duration}

시작 시간과 선택적 종료 시간을 지정하여 캠페인의 기간을 할당합니다.

![4단계: 기간 할당과 관련된 스크린샷.]({% image_buster /assets/img_archive/schedule_triggered43.png %})

사용자가 지정된 기간 내에 트리거 이벤트를 완료했지만 예약된 지연으로 인해 기간 밖에서 메시지 수신 자격이 생기는 경우, 해당 사용자는 캠페인을 수신하지 못합니다. 따라서 메시지 기간보다 긴 시간 지연을 설정하면 캠페인을 수신하는 사용자가 없게 됩니다. 또한 사용자의 [현지 시간대]({{site.baseurl}}/user_guide/messaging/campaigns/schedule_your_campaign/scheduled_delivery#local-time-zone-campaigns)에 맞춰 메시지를 전송하도록 설정할 수 있습니다.

### 5단계: 시간대 선택 {#step-5-select-time-frame}

사용자가 하루 중 특정 시간대에 캠페인을 수신할지 선택합니다. 메시지에 시간대를 설정한 경우, 사용자가 해당 시간대 외에서 트리거 이벤트를 완료하거나 메시지 지연으로 인해 시간대를 놓치면, 기본적으로 사용자는 메시지를 수신하지 못합니다.

![사용자가 하루 중 특정 시간대에 캠페인을 수신할지 선택합니다. 메시지에 시간대를 설정한 경우, 사용자가 해당 시간대 외에서 트리거 이벤트를 완료하거나 메시지 지연으로 인해 시간대를 놓치면, 기본적으로 사용자는 메시지를 수신하지 못합니다.]({% image_buster /assets/img_archive/schedule_triggered5.png %})

사용자가 시간대 내에서 트리거 이벤트를 완료했지만 메시지 지연으로 인해 시간대를 벗어나는 경우, 다음 확인란을 선택하여 해당 사용자가 여전히 캠페인을 수신하도록 설정할 수 있습니다.

![5단계: 시간대 선택과 관련된 스크린샷.]({% image_buster /assets/img_archive/schedule_triggered_next_available.png %})

사용자가 시간대를 놓쳐 메시지를 수신하지 못한 경우, [재자격]({{site.baseurl}}/user_guide/messaging/messaging_fundamentals/re_eligibility)을 선택하지 않더라도 다음에 트리거 이벤트를 완료하면 해당 캠페인을 수신할 자격이 부여됩니다. 재자격을 선택한 경우, 사용자는 지정된 시간대 내에서 자격을 충족할 때마다 트리거 이벤트를 완료할 때마다 캠페인을 수신할 수 있습니다.

캠페인에 특정 기간도 할당한 경우, 사용자는 해당 기간과 하루 중 특정 시간대 모두에서 자격을 충족해야 메시지를 수신할 수 있습니다.

### 6단계: 재자격 결정 {#step-6-determine-re-eligibility}

사용자가 해당 캠페인에 대해 [재자격]({% image_buster /assets/img_archive/ReEligible.png %})을 받을 수 있는지 결정합니다. 사용자에게 재자격을 허용하는 경우, 사용자가 다시 캠페인을 수신하기 전에 시간 지연을 지정할 수 있습니다. 이를 통해 트리거 캠페인이 스팸처럼 되는 것을 방지할 수 있습니다.

![6단계: 재자격 결정과 관련된 스크린샷.]({% image_buster /assets/img_archive/schedule_triggered6.png %})

## 사용 사례 {#use-cases}

트리거된 Campaigns는 거래 기반 또는 성과 기반 메시지에 매우 효과적입니다.

거래 기반 Campaigns에는 사용자가 구매를 완료하거나 장바구니에 항목을 추가한 후 전송되는 메시지가 포함됩니다. 후자의 경우는 예외 이벤트의 이점을 활용할 수 있는 Campaign의 좋은 예입니다. 예를 들어, Campaign이 사용자에게 아직 구매하지 않은 장바구니 속 항목을 알려준다고 가정해 보겠습니다. 이 경우 예외 이벤트는 사용자가 장바구니에 있는 제품을 구매하는 것입니다. 성과 기반 Campaigns의 경우, 사용자가 전환을 완료하거나 게임 레벨을 클리어한 후 5분 뒤에 메시지를 보낼 수 있습니다.

또한 웰컴 캠페인을 만들 때 사용자가 등록하거나 계정을 설정한 후 메시지가 전송되도록 트리거할 수 있습니다. 등록 후 며칠에 걸쳐 메시지를 시차적으로 전송하면 체계적인 온보딩 프로세스를 구성할 수 있습니다.

## 자주 묻는 질문 {#frequently-asked-questions}

### 인앱 메시지 캠페인에서 트리거 후 최대 지연 시간은 얼마인가요? {#what-is-the-maximum-delay-after-a-trigger-for-in-app-message-campaigns}

인앱 메시지 캠페인은 트리거 이벤트 이후 최대 2시간(7,200초)까지 전달을 지연할 수 있습니다. 지연 옵션은 **즉시**와 **지연 후**입니다. 더 긴 대기 시간이 필요하면 Canvas에서 인앱 메시지 단계 앞에 [지연]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/delay_step) 단계를 추가하세요.

### 트리거된 캠페인을 사용자가 수신하지 못한 이유는 무엇인가요? {#why-did-a-user-not-receive-my-triggered-campaign}

트리거 이벤트를 완료한 사용자가 캠페인을 수신하지 못하는 원인은 다음과 같습니다:

- 시간 지연이 완전히 경과하기 전에 사용자가 예외 이벤트를 완료한 경우.
- Liquid [`abort_message` 로직]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/liquid/aborting_messages)이 사용되었고, `abort_message` 로직이나 규칙에 따라 메시지가 중단된 경우.
- 시간 지연으로 인해 캠페인 기간이 종료된 후에야 사용자가 캠페인 수신 자격을 갖추게 된 경우.
- 시간 지연으로 인해 지정된 시간대 외에 사용자가 캠페인 수신 자격을 갖추게 된 경우.
- 사용자가 이미 해당 캠페인을 수신한 경우(공유된 채널 식별자를 통한 기여도 포함—예를 들어 이메일을 수신, 열람 또는 클릭한 다른 사람과 이메일을 공유하는 경우), 사용자가 재수신 자격이 없는 경우.
- 사용자가 캠페인을 다시 수신할 자격이 있지만 일정 기간이 지나야만 다시 트리거할 수 있고, 아직 그 기간이 경과하지 않은 경우.

이벤트 발생 시점에 기록된 사용자 데이터를 기준으로 트리거된 캠페인을 [세분화]({{site.baseurl}}/user_guide/audience/segments)하면 [경합 조건]({{site.baseurl}}/help/best_practices/race_conditions#race-conditions)이 발생할 수 있습니다. 이는 캠페인이 기준으로 삼는 사용자 속성이 변경되었지만, 캠페인이 전송될 때 해당 변경 사항이 아직 사용자에 대해 처리되지 않은 경우에 발생합니다. 캠페인은 진입 시 Segment 멤버십을 확인하므로, 이로 인해 사용자가 캠페인을 수신하지 못할 수 있습니다.

예를 들어, 방금 등록한 남성 사용자에게 이벤트 트리거 캠페인을 보내려 한다고 가정합니다. 사용자가 등록할 때 커스텀 이벤트 `registration`을 기록하는 동시에 사용자의 `gender` 속성을 설정합니다. 이벤트가 Braze에서 사용자의 성별을 처리하기 전에 캠페인을 트리거하여, 사용자가 캠페인을 수신하지 못할 수 있습니다.

모범 사례로, 캠페인이 기준으로 삼는 속성이 이벤트보다 먼저 Braze 서버로 전송되도록 하세요. 이것이 불가능한 경우, 전달을 보장하는 가장 좋은 방법은 [커스텀 이벤트 속성정보]({{site.baseurl}}/user_guide/data/activation/events/custom_events/custom_event_properties)를 사용하여 관련 사용자 속성정보를 이벤트에 첨부하고, 세분화 필터 대신 특정 이벤트 속성정보에 대한 속성정보 필터를 적용하는 것입니다. 예시의 경우, 커스텀 이벤트 `registration`에 `gender` 속성정보를 추가하면 캠페인이 트리거될 때 필요한 데이터가 Braze에 반드시 있게 됩니다.

또한 캠페인이 실행 기반이고 지연이 있는 경우, **전송 시점에 Segment 멤버십 재평가** 옵션을 선택하여 메시지 전송 시 사용자가 여전히 타겟 오디언스에 포함되어 있는지 확인할 수 있습니다.

#### 오디언스 기준 평가 {#audience-criteria-evaluation}

전송 전 지연이 포함된 캠페인(사용량 제한, 현지 시간대, Intelligent Timing 또는 트리거 스케줄 포함)의 경우, Segment가 재평가되는 시점은 캠페인 유형 및 설정에 따라 다릅니다.

지연이 있는 실행 기반 캠페인에서 **전송 시점에 Segment 멤버십 재평가**를 선택하면, 메시지 전송 전에 사용자가 재평가되어 전송 시점에 여전히 Segment 기준을 충족하는 사용자만 메시지를 수신합니다.

캠페인이 특정 커스텀 이벤트에 의해 트리거되고 오디언스로 Segment를 선택한 경우, 사용자가 해당 Segment에 포함되려면 동일한 커스텀 이벤트를 수행해야 합니다. 즉, 실행 기반 캠페인이 트리거되려면 사용자가 먼저 오디언스에 포함되어 있어야 합니다. 트리거된 캠페인의 일반적인 워크플로는 다음과 같습니다:

1. **오디언스에 합류:** 사용자가 커스텀 이벤트를 수행하면 캠페인의 타겟 오디언스에 추가됩니다.
2. **이메일 트리거:** 이메일을 전송하려면 사용자가 먼저 오디언스에 포함되어 있어야 하므로, 사용자가 커스텀 이벤트를 다시 수행해야 이메일이 트리거됩니다.

타겟 오디언스를 모든 사용자를 포함하도록 변경하거나, 이벤트를 수행할 것으로 예상되는 사용자가 이미 캠페인 오디언스에 포함되어 있는지 확인하여 메시지가 트리거되도록 하는 것을 권장합니다.

#### 커스텀 이벤트 문제 해결 {#troubleshooting-custom-events}

먼저 커스텀 이벤트가 Braze로 전달되고 있는지 확인하세요. **Analytics** > **커스텀 이벤트 보고서**로 이동한 다음, 해당 커스텀 이벤트와 날짜 범위를 선택합니다. 이벤트가 표시되지 않으면 올바르게 설정되어 있는지, 그리고 사용자가 올바른 작업을 수행했는지 확인하세요.

커스텀 이벤트가 표시된다면 다음을 수행하여 추가로 문제를 해결하세요:

- 사용자의 프로필 다운로드를 확인하여 이벤트를 트리거했는지, 그리고 언제 트리거했는지 확인합니다. 이벤트가 트리거된 경우, 이벤트 트리거 시점의 타임스탬프를 캠페인이 활성화된 시점과 비교합니다. 캠페인이 활성화되기 전에 이벤트가 트리거되었을 수 있습니다.
- 캠페인 및 타겟팅에 사용된 Segments의 체인지로그를 검토하여 커스텀 이벤트가 트리거된 시점에 사용자가 Segment에 포함되어 있었는지 확인합니다. Segment에 포함되어 있지 않았다면, 해당 캠페인을 수신하지 못했을 것입니다.
- 세분화를 통해 사용자가 대조군에 배정되어 캠페인 수신이 차단되었는지 확인합니다.
- 예약된 지연이 있는 경우, 사용자의 커스텀 이벤트가 지연 전에 트리거되었는지 확인합니다. 지연 전에 이벤트가 트리거되었다면, 해당 캠페인을 수신하지 못했을 것입니다.

{% alert note %}
인앱 메시지는 SDK를 통해 전송된 이벤트로만 트리거할 수 있으며, REST API로는 트리거할 수 없습니다.
{% endalert %}

### 실행 기반 캠페인은 오디언스 멤버십을 언제 평가하나요? {#when-do-action-based-campaigns-evaluate-audience-membership}

Braze는 메시지가 전송되기 전에 트리거 이벤트를 처리하는 시점에서 오디언스 멤버십을 평가합니다. 기본적으로 Braze는 큐에 넣는 시점에 사용자가 타겟 오디언스에 해당하는지 확인합니다. 캠페인에 지연이 있는 경우, **전송 시점에 Segment 멤버십 재평가**를 선택하여 전송 직전에 오디언스 기준을 다시 확인할 수 있습니다—예를 들어, 사용자가 트리거 동작을 수행한 후 전송이 완료되기 전에 오디언스에서 이탈할 수 있는 경우입니다.

자세한 내용은 [오디언스 기준 평가](#audience-criteria-evaluation)를 참조하세요.
