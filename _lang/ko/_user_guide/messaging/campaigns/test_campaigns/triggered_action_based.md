# API 트리거 및 액션 기반 캠페인

> 캠페인을 설정할 때는 시작하기 전에 항상 메시지를 테스트하는 것이 좋습니다. 이 참조 문서에서는 API 요청과 페이로드를 검사하고 전달 가능성 로그를 확인할 수 있는 테스트 사용자 세그먼트를 생성하는 방법을 다룹니다.

## 1단계: 테스트 사용자 세그먼트 생성

API 또는 커스텀 이벤트로 캠페인 트리거를 테스트하는 유일한 방법은 캠페인을 라이브로 푸시하는 것입니다. 새 캠페인을 출시할 때는 트리거 전달 가능성을 테스트할 때 캠페인에 테스트 사용자 세그먼트를 추가하는 것을 강력히 권장합니다. 이렇게 하면 안전장치가 마련되어, 캠페인이 실수로 발송되더라도 내부 사용자에게만 전달됩니다.

1. **테스트 사용자 가져오기**<br>테스트 사용자는 CSV를 통해 또는 [Postman]({{site.baseurl}}/api/postman_collection/)을 통한 일회성 배치 요청으로 Braze에 가져올 수 있습니다. 이러한 사용자를 가져올 때는 프로필에 커스텀 속성(예: `internal_test_user: true`)을 설정하여 테스트 그룹 세그먼트를 구축하는 데 사용하는 것을 권장합니다. <br><br>
2. **테스트 사용자를 Braze 인식 테스트 사용자로 추가**<br>대시보드에서 [테스트 사용자를 Braze 인식 테스트 사용자로 표시]({{site.baseurl}}/user_guide/administer/global/user_management/internal_groups/)하면 각 사용자에 대한 상세 로깅에 접근할 수 있어 API 요청, 페이로드를 검사하고 전달 가능성 로그를 확인할 수 있습니다. 이러한 로그는 최종 사용자에게 캠페인을 전달하는 데 문제가 있었는지 파악하는 데 도움이 됩니다. <br><br>
3. **세그먼트 생성**<br>테스트 사용자 세그먼트를 생성하려면 `internal_test_user` 커스텀 속성이 `true`로 설정된 사용자 세그먼트를 생성합니다. 이 세그먼트는 캠페인이 라이브로 전환될 때 제거할 수 있습니다. 

## 2단계: 발송 테스트

다음으로, Braze 대시보드에서 테스트 발송을 하거나 Inbox Vision(이메일 전용)을 사용하여 캠페인이 아직 초안 모드인 상태에서 레이아웃이 어떻게 보이는지 확인할 수 있습니다. 그런 다음 테스트 사용자 세그먼트에 캠페인을 발송하여 예상대로 작동하는지 확인할 수 있습니다. 캠페인이 API 트리거 방식이든 액션 기반이든 관계없이, Postman을 사용하여 Braze API에 일회성 요청을 보내 캠페인을 트리거합니다. 

## 3단계: Braze 로깅을 사용하여 인바운드 결과 검사

Braze 로깅을 사용하여 트리거, 발송 및 이벤트 문제를 해결합니다. 
- [이벤트 사용자 로그]({{site.baseurl}}/user_guide/administer/global/workspace_settings/logs_and_alerts/event_user_log/)에서는 API 트리거 요청의 원시 페이로드, 캠페인을 트리거하는 커스텀 이벤트, 그리고 관련 트리거 또는 이벤트 등록정보를 확인할 수 있습니다.
- [메시지 활동 로그]({{site.baseurl}}/user_guide/administer/global/workspace_settings/logs_and_alerts/message_activity_log/)에서는 오류를 기록하고 특정 메시지가 전달되지 않은 이유를 파악하는 데 도움을 줍니다.

## 4단계: 테스트 세그먼트 제거 및 캠페인 출시

메시지가 올바르게 트리거되고 렌더링되며 클릭한 모든 링크가 등록되면, 세그먼트를 제거하고 캠페인을 업데이트할 수 있습니다. 소수의 테스트 사용자 노출 횟수가 포함되지 않도록 캠페인을 처음부터 시작하려면, 캠페인을 복제하고 테스트 사용자 세그먼트 없이 다시 시작할 수 있습니다.
