# 지연 {#delay}

> 지연 구성요소를 사용하면 Canvas에 독립적인 지연을 추가할 수 있습니다. 관련 메시지를 추가하지 않고도 Canvas에 지연을 추가할 수 있습니다.

지연을 사용하면 Canvas를 더 깔끔하게 만들 수 있습니다. 또한 이 구성요소를 사용하여 정확한 날짜, 특정 날짜 또는 특정 요일까지 다른 단계를 지연시킬 수 있습니다. 지연 구성요소는 최대 하나의 후속 단계에 연결할 수 있습니다. <br> ![Canvas의 첫 번째 단계로 1일 지연이 설정된 지연 단계.]({% image_buster /assets/img/canvas_delay.png %}){: style="float:right;max-width:35%;margin-left:15px;"}

## 딜레이 만들기 {#create-a-delay}

딜레이를 만들려면 Canvas에 단계를 추가하세요. 사이드바에서 딜레이 구성 요소를 드래그 앤 드롭하거나, 단계 하단의 <i class="fas fa-plus-circle"></i> 플러스 버튼을 선택한 다음 **딜레이**를 선택합니다.

### 확장 딜레이 {#extended-delays}

딜레이 단계를 최대 2년(730일)까지 연장할 수 있습니다. 예를 들어, 앱에 신규 사용자를 온보딩하는 경우, 2개월의 확장 딜레이를 추가한 후 메시지 단계를 전송하여 세션을 시작하지 않은 사용자에게 알림을 보낼 수 있습니다.

## 시간 지연 유형 {#time-delay-types}

Canvas에서 다음 메시지 전에 지연 유형을 선택할 수 있습니다. 사용자가 지정된 기간이 지난 후까지 대기하도록 지연을 설정하거나, 특정 날짜와 시간까지 사용자를 대기시킬 수 있습니다.

시간 지연이 있는 경우, 일부 사용자는 지연 후에만 Canvas의 다음 단계로 진행하게 됩니다. 지연 중인 사용자는 _다음 단계로 진행_ 측정기준에 추가되지 않습니다. 자세한 내용은 [지연 분석](#delay-analytics)을 참조하세요.

{% tabs %}
{% tab 기간 %}

**기간**을 선택하면 사용자를 설정된 초, 분, 시간, 일 또는 주 동안, 그리고 특정 시간에 지연시킬 수 있습니다. 예를 들어, 사용자를 4시간 또는 1일 동안 지연시킬 수 있습니다.

"일"과 "캘린더 일"의 계산 방식 차이에 유의하세요.

- "일"은 24시간이며, 사용자가 지연 단계에 진입한 시점부터 계산됩니다.
- "캘린더 일"은 다음 지정된 시간까지 대기할 시간을 정의하며, 24시간 미만일 수 있습니다. 회사 시간 또는 사용자의 현지 시간으로 지연을 선택할 수 있습니다. 시간이 지정되지 않으면, 사용자는 회사 시간 기준으로 다음 날 자정까지 지연됩니다.

### 지연 동작: 특정 시간의 "캘린더 일" 대 "일" {#delay-behavior-calendar-days-at-a-specific-time-versus-days}

**캘린더 일**을 단위로 선택하고 **특정 시간에**를 활성화하면(예: **1 캘린더 일, 오전 9시**), Canvas는 먼저 목표 캘린더 날짜를 계산한 다음 예약된 시간을 적용합니다. 예를 들어, 캔버스 단계가 월요일 오후 9시에 전송되고 지연 단계가 **1 캘린더 일, 오전 9시**로 설정된 경우, 다음 단계는 화요일 오전 9시에 전송됩니다. Canvas는 월요일 + 1 캘린더 일 = 화요일로 계산한 다음 오전 9시를 적용합니다.

반면에, **특정 시간에** 없이 **일**을 단위로 선택하면(예: **1일 후**), Canvas는 사용자가 지연 단계에 진입한 시점부터 정확히 24시간을 대기합니다. 예를 들어, 단계가 10월 13일 오전 9시 35분에 전송되고 지연 단계가 **1일 후**인 경우, 다음 단계는 10월 14일 오전 9시 35분에 전송됩니다.

또한 **특정 시간에**를 선택하여 사용자가 Canvas에서 진행하는 시점을 지정할 수 있습니다. 이 옵션은 사용자가 지연 단계에 진입한 시간을 고려합니다. 이 시간이 설정에서 구성된 시간을 초과하면, Braze는 지연에 추가 시간을 더합니다.

예를 들어, 오늘이 12월 11일이고 지연 단계가 **기간** 1주, UTC 오전 8시로 설정되어 있다고 가정해 보겠습니다. 사용자가 12월 4일에 지연 단계에 진입한 경우, 원래 UTC 오전 8시 이전에 지연 단계에 진입했다면 오늘 지연 단계에서 해제되어 여정을 계속합니다. 이 시간 이후에 지연 단계에 진입한 경우, 사용자는 다음 날(이 시간의 다음 발생 시점)까지 지연됩니다.

{% endtab %}
{% tab 캘린더 날짜 %}

**캘린더 날짜**를 선택하면 사용자를 특정 날짜와 시간까지 해당 단계에서 대기시킬 수 있습니다.

### 고려사항 {#considerations}

#### 사용자는 지난 날짜의 단계나 메시지를 받지 않습니다 {#users-wont-receive-past-dated-steps-or-messages}

선택한 날짜와 시간이 사용자가 지연 단계로 진행하기 전에 이미 지났다면, 사용자는 Canvas를 종료합니다. Canvas 시작과 "정확한 날짜까지 대기" 단계에 선택된 날짜 사이에는 최대 31일의 간격이 있을 수 있습니다.

{% alert important %}
[Canvas 컨텍스트 얼리 액세스]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/context)에 참여 중인 경우, 최대 2년까지 지연을 설정할 수 있습니다.
{% endalert %}

예를 들어, 다음 시나리오에서 사용자는 단계나 메시지를 받지 않습니다:

- 메시지가 5월 3일 오후 9시에 전송되도록 예약되었지만, 지연 단계가 5월 3일 오전 9시에 만료됩니다.
- 캔버스 단계가 사용자의 현지 시간대의 특정 시간까지 지연되지만, 사용자의 고객 프로필에 시간대가 설정되어 있지 않습니다. 이 경우 지연은 해당 사용자에 대해 회사 시간대로 기본 설정되며, 이미 지정된 시간을 지났습니다.

#### 후속 지연 단계가 이전 지연 단계의 타임라인 내에 있으면 사용자가 종료됩니다 {#users-exit-if-a-subsequent-delay-step-is-within-a-prior-delay-steps-timeline}

Canvas에 두 개의 지연 단계가 있지만 첫 번째 지연 단계가 두 번째 지연 단계보다 긴 경우, 사용자도 Canvas를 종료합니다.

예를 들어, Canvas에 다음 단계들이 있다고 가정해 보겠습니다:
- 1단계: 메시지 단계
- 2단계: 12월 13일 오후 10시까지 지연 단계
- 3단계: 메시지 단계
- 4단계: 12월 13일 오후 7시까지 지연 단계
- 5단계: 메시지 단계

4단계에 진입한 사용자는 5단계를 받기 전에 Canvas를 종료합니다. 4단계의 지연이 2단계의 타임프레임에 포함되기 때문입니다.

{% endtab %}
{% tab 요일 %}

**요일**을 선택하면 사용자를 특정 요일의 특정 시간까지 해당 단계에서 대기시킬 수 있습니다. 예를 들어, 다음 목요일이 도래할 때 회사 시간대 기준 오후 4시까지 사용자를 지연시킬 수 있습니다.

이를 성공적으로 구성하려면, 사용자가 선택한 요일(예: 목요일)에 Canvas에 진입하되 지정된 시간 이후인 경우 어떻게 처리할지도 선택해야 합니다. 같은 날에 사용자를 진행시키거나 다음 주까지 대기시키도록 선택할 수 있습니다.
{% endtab %}
{% endtabs %}

### 지연 중 프로필 업데이트 {#profile-updates-during-delays}

사용자가 Canvas에 진입하고 지연 단계가 종료되기 전에 유효한 이메일 주소를 추가하면, 다음 단계에서 이메일을 받습니다. 이는 다른 프로필 업데이트에도 동일하게 적용됩니다. 지연 중 사용자 속성 또는 연락처 정보의 변경 사항은 사용자가 후속 단계로 진행할 때 반영됩니다.

## 지연 단계 사용하기 {#using-delay-steps}

6월 10일이라고 가정해 봅시다. 6월 11일에 사용자가 Canvas에 진입하여 다가오는 프로모션에 대한 메시지를 받도록 하고 싶습니다. 그런 다음 6월 17일 오후 3시(현지 시간)까지 사용자를 Canvas에 유지하려고 합니다. 6월 17일 현지 시간 오후 3시에 사용자에게 프로모션에 대한 리마인더 메시지를 보내려고 합니다.

Canvas 단계의 순서는 다음과 같을 수 있습니다:

1. 먼저 6월 11일에 사용자가 Canvas에 진입한 직후 즉시 전송되는 메시지 단계를 추가합니다.
2. 6월 17일 현지 시간 오후 1시까지 사용자를 유지하는 지연 단계를 생성합니다.
3. 지연 단계를 메시지를 즉시 전송하는 다른 메시지 단계에 연결합니다.

### Canvas 끝에 있는 지연 구성요소 {#delay-as-last-step}

Canvas에 지연 구성요소를 추가하고 후속 단계가 없는 경우, 마지막 단계에 도달한 모든 사용자는 자동으로 Canvas에서 나가게 됩니다. 이는 지연 단계의 시간이 아직 도래하지 않은 경우에도 마찬가지입니다. 즉, 이미 지연 단계에 도달한 사용자는 이 단계 이후에 추가하는 메시지를 받지 못합니다. 그러나 사용자가 아직 지연 단계에 도달하지 않았고 메시지가 추가된 경우에는 해당 메시지를 받게 됩니다.

### 개인화된 지연 {#personalized-delays}

**지연 개인화** 토글을 선택하여 사용자를 위한 개인화된 지연을 설정할 수 있습니다. [컨텍스트 단계]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/context)와 함께 사용하여 지연에 사용할 컨텍스트 변수를 선택할 수 있습니다. 이는 선택한 속성 또는 속성정보에서 설정된 시간대를 재정의합니다. 일 또는 주 단위로 오프셋을 적용하면서 사용자가 특정 시간에 다음 단계로 이동하도록 하려는 경우에 유용합니다. 시간대는 속성 또는 속성정보에서 가져오며, 사용할 수 없는 경우 대체 시간대를 사용합니다.

#### "특정 시간에" 시간대 동작 {#time-zone-behavior-for-at-a-specific-time}

**특정 시간에** 체크박스를 선택하면, 설정한 전달 시간은 Braze가 개인화된 캘린더 날짜에 사용하는 것과 동일한 시간대를 사용합니다. Braze는 날짜와 시간에 별도의 시간대를 적용하지 않습니다. 둘 다 속성 또는 컨텍스트 변수의 시간대를 사용하며, 변수가 시간대 정보가 없는 문자열인 경우 대체 시간대를 사용합니다.

적용되는 시간대는 속성 또는 컨텍스트 변수의 데이터 유형에 따라 달라집니다:

- **시간대가 포함된 문자열 데이터 유형:** 속성 또는 컨텍스트 변수가 시간대 정보를 포함하는 문자열 데이터 유형인 경우, 문자열에 지정된 시간대를 따릅니다. 예를 들어, `2025-06-10T10:00:00-08:00`은 UTC-8을 사용합니다.
- **시간대가 없는 문자열 데이터 유형:** 속성 또는 컨텍스트 변수가 시간대 정보가 없는 문자열 데이터 유형인 경우, 대체 시간대를 따릅니다. 예를 들어, `2025-06-10`은 대체 시간대를 사용합니다.
- **시간 데이터 유형:** 속성 또는 컨텍스트 변수가 시간 데이터 유형인 경우, UTC를 따릅니다. 이는 시간 데이터 유형이 데이터베이스에 저장될 때 항상 UTC로 변환되므로, 변수가 시간 데이터 유형으로 설정된 경우 "특정 시간에"는 항상 UTC를 참조하기 때문입니다. 예를 들어, `2025-06-10T10:00:00-08:00`은 UTC+0을 사용합니다.

{% alert note %}
커스텀 속성 또는 컨텍스트 변수가 문자열 데이터 유형인 경우, 특정 시간이나 시간대가 없을 수 있습니다. 시간 데이터 유형인 경우에는 시간과 시간대를 지정해야 합니다. 그러나 커스텀 속성 또는 컨텍스트 변수가 "관련 없는" 문자열(예: "product_name")인 경우, 사용자는 Canvas에서 나가게 됩니다.
{% endalert %}

#### 사용 사례 {#use-case}

지금부터 30일 후에 고객에게 치약 구매를 리마인드하고 싶다고 가정해 봅시다. 컨텍스트 단계와 지연 단계를 조합하여 지연에 사용할 컨텍스트 변수를 선택할 수 있습니다. 이 경우 컨텍스트 단계에는 다음과 같은 필드가 있습니다:

- **컨텍스트 변수 이름:** product_reminder_interval
- **데이터 유형:** Time
- **값:** {% raw %}`{{custom_attribute.${Order_filled_time}}}`{% endraw %}

![product_reminder_interval 컨텍스트 변수와 그 값을 보여주는 화면.]({% image_buster /assets/img/context_step1.png %})

다음으로, 지금부터 30일 후에 고객에게 리마인드하고 싶으므로, 지연 옵션으로 **특정 날짜까지**를 선택하고 **지연 개인화**를 선택하여 컨텍스트 단계의 정보를 사용합니다. 이렇게 하면 사용자는 선택한 컨텍스트 변수까지 지연됩니다.

## 지연 분석 {#delay-analytics}

지연 구성요소는 활성 또는 이전에 활성 상태였던 Canvas의 분석 보기에서 다음 측정기준을 사용할 수 있습니다.

| 측정기준 | 설명 |
|---|---|
| _진입_ | 해당 단계에 진입한 횟수를 나타냅니다. Canvas에 재적격성이 설정되어 있고 사용자가 지연 단계에 두 번 진입하면, 두 건의 진입이 기록됩니다. |
| _다음 단계로 진행_ | Canvas에서 다음 단계로 진행한 진입 수를 나타냅니다. |
| _Canvas 이탈_ | Canvas를 이탈하고 다음 단계로 진행하지 않은 진입 수를 나타냅니다. |

## 문제 해결 {#troubleshooting}

### 개인화 실패 오류 {#personalization-failed-errors}

사용자가 개인화된 지연을 트리거하지 않는 경우, 지연 단계에 적합하도록 설정한 컨텍스트 단계가 예상대로 작동하지 않기 때문일 수 있습니다. [컨텍스트 변수가 유효하지 않은 경우]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/context#troubleshooting), 사용자는 컨텍스트 단계에서 컨텍스트가 설정되지 않은 채로 Canvas를 계속 진행합니다. 이로 인해 개인화된 지연과 같이 Canvas의 이후 단계에 적합하지 않게 될 수 있습니다.

## 문제 해결

### Canvas가 중지되었을 때 지연 단계에 있는 사용자 {#users-in-a-delay-step-when-a-canvas-is-stopped}

[Canvas를 중지]({{site.baseurl}}/user_guide/messaging/canvas/managing_canvases/change_your_canvas_after_launch#stopping-canvases)하면, 이미 지연 단계에서 대기 중인 사용자는 즉시 퇴출되지 않습니다. Braze는 여전히 지연 완료를 스케줄하지만, Canvas가 중지된 동안에는 **추가 메시지가 전송되지 않습니다**.

사용자의 지연이 경과하기 전에 Canvas를 다시 활성화하면, 해당 사용자는 스케줄된 대로 다음 단계로 진행할 수 있습니다. Canvas가 중지된 동안 지연 기간이 이미 경과한 경우, 해당 사용자는 다음 단계를 수신하는 대신 Canvas에서 퇴출됩니다. 예시는 [Canvas를 중지하면 어떻게 되나요?]({{site.baseurl}}/user_guide/messaging/canvas/faqs#what-happens-when-you-stop-a-canvas) 및 [Canvases 중지하기]({{site.baseurl}}/user_guide/messaging/canvas/managing_canvases/change_your_canvas_after_launch#stopping-canvases)를 참조하세요.
