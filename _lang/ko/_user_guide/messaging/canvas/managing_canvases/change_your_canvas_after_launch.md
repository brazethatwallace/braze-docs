# 시작 후 캔버스 편집 {#edit-canvases-after-launch}

> 이 참조 문서에서는 캔버스를 처음 시작한 후 변경할 수 있는 항목을 다룹니다.

시작 후 캔버스를 다음과 같은 방법으로 편집할 수 있습니다:

* 사용자 여정에 새 캔버스 단계 삽입
* 새 배리언트 및 연결 추가
* 배리언트 분배 조정
* 모든 캔버스 단계 중지 또는 재개

{% alert note %}
대조군 배리언트 분배는 시작 후에만 줄일 수 있습니다.
{% endalert %}

사용자 여정에서 다음 항목을 삭제할 수 있습니다:

- [캔버스 단계]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/about)
- 캔버스 배리언트
- 캔버스 단계 간 연결

캔버스 사용자 여정에서 단계를 편집하거나 추가하려는 경우 다음 세부 사항이 적용됩니다:

- 아직 캔버스에 진입하지 않은 사용자는 새로 생성된 모든 단계에 대해 자격이 있습니다.
- 캔버스 진입 설정에서 사용자가 단계에 재진입할 수 있도록 허용하는 경우, 새로 생성된 단계를 이미 지나간 사용자도 재진입할 자격이 있습니다.
- 현재 시작된 캔버스에 있지만 새 단계가 추가된 사용자 여정 지점에 아직 도달하지 않은 사용자는 새로 추가된 단계를 받을 자격이 있습니다.

[지연]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/delay_step) 또는 [작업 경로]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/action_paths) 단계를 삭제하는 경우, 현재 해당 단계에서 대기 중인 사용자를 다른 캔버스 단계로 선택적으로 리디렉션할 수 있습니다. 지연의 경우 사용자는 지연 기간이 끝날 때까지 해당 단계에 남아 있습니다. 작업 경로의 경우 사용자는 평가 기간이 끝날 때까지 해당 단계에 남아 있습니다.

캔버스를 처음 시작할 때 Braze는 사용자가 현재 위치한 메시지 단계에 대해 대기줄에 넣으며, 캔버스의 모든 후속 메시지에 대해 대기줄에 넣지는 않습니다. 시작 후 캔버스를 편집하면 일부 사용자가 이미 대기줄에 들어가 있어 변경 사항을 반영하지 못할 수 있습니다. 캔버스를 중지하고 복제한 다음 변경하여 새 버전을 시작하면, 캔버스는 이미 대기줄에 들어간 사용자뿐만 아니라 모든 사용자를 다시 평가합니다.

특정 편집 사용 사례에 대해서는 [모범 사례](#best-practices) 섹션을 참조하세요. 일반적으로 예상치 못한 동작이 발생할 수 있으므로 라이브 캔버스를 편집하지 않는 것이 모범 사례입니다.

{% details 원본 캔버스 편집기 세부 정보 펼치기 %}

캔버스가 어떤 워크플로로 생성되었는지에 따라 시작 후 허용되는 캔버스 편집 사항을 참고하세요. 캔버스가 원본 캔버스 워크플로를 사용하는 경우, 시작 후 편집을 수행하려면 먼저 Canvas Flow로 복제해야 합니다.

기존 연결을 편집하거나 삭제할 수 없으며, 기존 연결된 단계 사이에 단계를 삽입할 수 없습니다. 캔버스 사용자 여정에서 단계를 편집하거나 추가하려는 경우 다음 세부 사항이 적용됩니다:

- 아직 캔버스에 진입하지 않은 사용자는 새로 생성된 모든 단계에 대해 자격이 있습니다.
- 캔버스 진입 설정에서 사용자가 단계에 재진입할 수 있도록 허용하는 경우, 새로 생성된 단계를 이미 지나간 사용자도 재진입할 자격이 있습니다.
- 현재 시작된 캔버스에 있지만 사용자 여정에서 새로 추가된 단계에 아직 도달하지 않은 사용자는 새로 추가된 단계를 받을 자격이 있습니다.
- 지연 단계가 캔버스의 마지막 단계인 경우, 해당 단계에 도달한 사용자는 자동으로 캔버스에서 나가게 되며 새로 생성된 단계를 받지 않습니다.

{% alert important %}
캔버스 단계의 **지연** 또는 **기간** 설정을 업데이트하면, 업데이트 시점에 해당 단계에 있는 사용자는 원래 진입했을 때 할당된 지연 시간을 따릅니다. 캔버스에 새로 진입하는 사용자와 아직 해당 단계의 대기줄에 들어가지 않은 사용자만 업데이트된 시간에 메시지를 받습니다.
{% endalert %}

캔버스를 중지해도 메시지를 받기 위해 대기 중인 사용자는 나가지 않습니다. 캔버스를 다시 활성화하고 사용자가 여전히 메시지를 기다리고 있다면 메시지를 받게 됩니다(메시지가 발송되었어야 할 시간이 이미 지난 경우에는 받지 않습니다).

{% enddetails %}

## Canvas 세부 정보 {#canvas-details}

Canvas를 시작한 후 다음 설정 및 세부 정보를 편집할 수 있습니다:

- Canvas 이름 및 설명
- Teams
- 태그
  - 시작 후 태그를 추가하면 `Received Message from Campaign or Canvas with Tag`와 같은 필터를 사용하여 Segments에서 사용자를 리타겟할 수 있습니다.
- 항목 유형, 스케줄 및 제어
- 가입 상태
- 사용량 제한
- 최대 게재빈도 설정
- 방해금지 시간
- 타겟 오디언스

Canvas가 시작된 후:

- 전환 이벤트는 편집할 수 없습니다.
- 다음 단계는 추가하거나 제거할 수 없으며, 순위를 조정하기 위해 재정렬할 수 없습니다: [오디언스 경로]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/audience_paths), [작업 경로]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/action_paths), [실험 경로]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/experiment_step).
  - **해결 방법 1:** 새 오디언스 경로, 작업 경로 또는 실험 경로를 만들고 해당 새 단계로 경로를 재구성합니다.
  - **해결 방법 2:** Canvas를 복제하여 편집합니다.

### 개별 단계 {#individual-steps}

개별 캔버스 단계의 경우, 시작 후 다음 세부 정보를 편집할 수 있습니다:

* 이름
* 메시지 콘텐츠
* 트리거
* 오디언스
* 예외 이벤트
* 지연(지연 단계에만 해당)

그러나 단계의 스케줄 유형과 대조군 비율은 시작 후 편집할 수 없습니다. 작업 경로 및 오디언스 경로 단계의 경우, 순위와 평가 기간은 시작 후 편집할 수 없습니다.

#### 목적지로 전송 단계 {#send-to-destination-step}

실시간 Canvas에서 [목적지로 전송]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/send_to_destination) 단계를 편집할 때 다음 동작이 적용됩니다:

- **목적지 Canvas 변경:** 목적지로 전송 단계를 다른 목적지 Canvas로 변경하는 것은 동일한 일반적인 시작 후 편집 규칙을 따릅니다. 변경 사항은 아직 목적지로 전송 단계에 도달하지 않은 사용자에게만 영향을 미칩니다.
  - 이미 해당 단계를 통과한 사용자는 원래 목적지 Canvas에 남아 있으며, 다시 라우팅되지 않습니다.
  - 이전 단계에서 현재 대기줄에 있는 사용자(예: 목적지로 전송 단계 이전의 지연 단계에서 대기 중인 사용자)는 해당 단계에 도달할 때 새 목적지 Canvas의 진입 및 오디언스 기준에 따라 평가됩니다. 적격한 사용자는 새 목적지 Canvas로 전송됩니다.
- **중단된 목적지 Canvas:** 소스 Canvas가 아직 활성 상태인 동안 목적지 Canvas가 중단되면, 목적지로 전송 단계에 도달한 사용자는 목적지 Canvas로 전송되지 않습니다. 이는 목적지가 중단되어 있는 동안의 일시 정지가 아니라, 핸드오프에 대한 사용자 이탈을 유발합니다.
  - 중단된 목적지에 진입할 수 없는 사용자는 목적지로 전송 단계 이후에 더 많은 단계가 있는 경우 소스 Canvas에서 계속 진행합니다. 진행 동작에 대한 자세한 내용은 [목적지로 전송]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/send_to_destination#how-does-advancement-behavior-work-for-send-to-destination-steps)을 참조하세요.
  - 중단된 목적지를 가리키는 목적지로 전송 단계가 포함된 소스 Canvas는 시작할 수 없습니다. 이 동작은 소스 Canvas가 이미 실시간 상태인 후에 목적지 Canvas가 중단된 경우에 적용됩니다.

### 캔버스 배리언트 비율 {#canvas-variant-percentages}

Canvas를 시작한 후에는 대조군 배리언트 비율만 줄일 수 있습니다. Canvas에서 배리언트 비율이 수정되면 사용자가 다른 배리언트로 재배포될 수 있습니다.

처음에는 사용자가 Campaign을 처음 받기 전에 특정 배리언트에 무작위로 할당됩니다. 그 이후부터 Campaign을 받을 때마다(또는 사용자가 캔버스 배리언트에 다시 진입할 때마다) 배리언트 비율이 수정되지 않는 한 동일한 배리언트를 받습니다.

배리언트 비율이 변경되면 사용자가 다른 배리언트로 재배포될 수 있습니다. 사용자는 비율이 다시 수정될 때까지 해당 배리언트에 유지됩니다. 무작위 버킷 번호와 함께 `NOT` 필터를 사용하는 분기가 있는 Canvases의 경우, 사용자가 Canvas에 다시 진입할 때 사용자 여정에서 매번 동일한 브랜치를 받지 못할 수 있습니다.

#### 대조군 {#control-groups}

배리언트 비율이 변경되지 않은 경우 대조군은 일관성을 유지합니다. 대조군의 비율이 줄거나 늘어나면, 이전에 메시지를 받은 사용자는 이후 전송 시 대조군에 진입할 수 없으며, 대조군에 속한 사용자는 절대 메시지를 받지 않습니다.

### 현지 전송 시간 {#local-send-time}

현지 전송 시간에 시작하도록 예약된 Canvases는 예약된 전송 시간 24시간 전까지 편집할 수 있습니다. 이 기간을 "안전 구간"이라고 합니다.

{% alert tip %}
완전히 새로운 Canvas 사본을 만들어야 하는 대규모 편집을 의도하는 경우, 첫 번째 Canvas를 받은 사용자를 제외하고 시간대 전송을 허용하도록 Canvas 스케줄 시간을 다시 조정하는 것을 잊지 마세요.
{% endalert %}

진입 스케줄이 시작 즉시 사용자를 진입시키도록 설정된 경우, Canvas는 5분 단위의 가장 가까운 시간에 시작됩니다. 예를 들어, 오전 8시 31분(PST)에 사용자를 즉시 진입시키도록 Canvas를 업데이트하면 시작 시간은 오전 8시 30분(PST)으로 설정되며 회사의 시간대가 적용됩니다.

### 배리언트 삭제 {#deleting-variants}

Canvas에서 배리언트가 삭제되면 다음이 발생합니다:

- 배리언트 내의 단계(다른 배리언트와 공유하는 단계 포함)가 삭제됩니다.
- 단계 분석과 *총 진입 수*, *총 이탈 수*, *전환율* 등 Canvas의 최상위 분석이 삭제됩니다.
- 삭제된 배리언트에 있는 사용자는 단계에서 이탈되며, 이후 메시지는 전송되지 않습니다.

### Canvas 진입 속성 {#canvas-entry-properties}

Canvas 진입 속성은 전송 시 단계에 템플릿화되지 않습니다. 즉, Canvas가 시작된 후 Canvas 진입 속성이 편집되면 이러한 변경 사항은 Canvas에 진입하는 새 사용자에게만 적용됩니다. Canvas에서 사용자가 다시 진입할 수 있는 경우, 다시 진입하는 사용자는 업데이트된 Canvas 진입 속성에 따라 결정됩니다.

## 모범 사례 {#best-practices}

Canvas가 시작된 후 편집하거나 추가할 때 염두에 두어야 할 모범 사례를 확인하세요.

{% alert important %}
일반적으로 Canvas가 활성 상태이고 사용자가 대기줄에 추가되는 동안에는 변경을 피하세요.
{% endalert %}

### 연결 해제된 단계 {#disconnected-steps}

연결 해제된 단계가 있는 Canvas를 시작할 수 있으며, 시작 후에도 이러한 Canvases를 저장할 수 있습니다. 워크플로에서 단계를 연결 해제하기 전에, 대기 중인 사용자가 있는 단계의 분석 보기를 확인하는 것이 좋습니다.

Canvas 워크플로에서 사용자가 연결 해제된 단계에 있다고 가정해 보겠습니다. 이 사용자는 후속 단계가 있는 경우 해당 단계로 진행합니다. 단계의 설정에 따라 사용자가 어떻게 진행해야 하는지가 결정됩니다.

연결 해제된 단계를 만들거나 편집하면, 나머지 Canvas에 직접 연결하지 않고도 이러한 독립적인 단계를 변경할 수 있습니다. 이는 Canvas를 다시 시작하기 전에 단계를 테스트하는 데 도움이 됩니다.

### 실험 경로 단계 {#experiment-path-step}

Canvas에 활성 또는 진행 중인 위닝 경로 실험이 있는 상태에서 활성 Canvas를 업데이트하면 실험이 종료됩니다. 실험 경로 단계를 업데이트하지 않더라도 이 규칙이 적용됩니다. 실험을 다시 시작하려면 기존 실험 경로를 연결 해제하고 새 실험 경로를 시작하거나, Canvas를 복제한 후 복제본을 시작하세요. 그렇지 않으면 사용자는 최적화 없이 실험 경로를 통해 흐르게 됩니다.

개인화된 경로를 사용하는 기존 실험 경로 단계는 계속 실행됩니다. 활성 Canvas를 업데이트하면 진행 중인 개인화된 경로 실험도 종료됩니다.

### 시간 지연 {#time-delays}

시간 지연이 있는 Canvases를 편집하는 것은 다소 까다로울 수 있으므로, Canvases를 편집할 때 다음 세부 사항을 염두에 두세요:

- 지연 단계에서 지연 시간을 업데이트하면, Canvas에 새로 진입하는 사용자와 해당 단계의 대기줄에 아직 추가되지 않은 사용자만 업데이트된 시간 지연에 따라 메시지를 받습니다.
- 시간 지연이 있는 단계(예: 지연 또는 작업 경로)를 삭제하고 해당 사용자를 다른 캔버스 단계로 리디렉션하기로 결정한 경우, 사용자는 해당 단계의 시간 지연이 완료된 후에만 리디렉션됩니다. 예를 들어, 1일 지연이 있는 지연 단계를 삭제하고 해당 사용자를 메시지 단계로 리디렉션한다고 가정해 보겠습니다. 이 경우 사용자는 1일 지연이 완료된 후에만 리디렉션됩니다.
- Canvas에 하나 이상의 실험 경로 단계가 있는 경우, 단계를 삭제하면 해당 단계의 결과가 무효화될 수 있습니다.

### Canvases 중지 {#stopping-canvases}

Canvas를 중지해도 단계에서 대기 중인 사용자는 종료되지 않습니다. Canvas를 다시 활성화하고 사용자가 아직 대기 중인 경우, 해당 단계를 완료하고 다음 단계로 이동합니다. 그러나 사용자가 다음 단계로 진행했어야 할 시간이 이미 지난 경우, 해당 사용자는 Canvas에서 종료됩니다.

예를 들어, Canvas Flow 워크플로를 사용하여 오후 2시에 시작하도록 설정된 Canvas가 있고, 하나의 배리언트에 두 개의 단계(1시간 지연이 있는 지연 단계와 이어지는 메시지 단계)가 있다고 가정해 보겠습니다.

사용자가 오후 2시 1분에 이 Canvas에 진입하고 동시에 지연 단계에 진입합니다. 이는 사용자가 사용자 여정의 다음 단계(메시지 단계)로 오후 3시 1분에 이동하도록 스케줄되었음을 의미합니다. Canvas를 오후 2시 30분에 중지하고 오후 3시 30분에 다시 활성화하면, 오후 3시 1분이 이미 지났으므로 사용자는 Canvas에서 종료됩니다. 그러나 Canvas를 오후 2시 40분에 다시 활성화하면, 사용자는 예상대로 오후 3시 1분에 메시지 단계로 이동합니다.

## 알아두어야 할 사항 {#things-to-know}

다음과 같은 일반적인 문제는 Canvas 출시 후 Canvas 내 다른 구성 요소를 편집하거나 추가할 때 발생할 수 있습니다.

{% alert important %}
다음 문제는 예방할 수 있습니다. 출시된 Canvas를 편집해야 하는 경우, 먼저 이미 Canvas에 진입한 모든 사용자가 사용자 여정을 완료했는지 확인하는 것을 권장합니다. 또한 이미 한 명 이상의 사용자가 처리한 단계는 삭제하지 않는 것이 좋습니다.
{% endalert %}

- 리포팅 데이터 누락(메시지 배리언트가 삭제된 후 다시 추가된 경우)
- 사용자가 예상 경로를 따르지 않음
- 예상치 못한 시간에 메시지가 전송됨
- 편집 내용이 Currents 데이터를 덮어쓰지 않으므로, 캔버스 단계 간 불일치가 발생할 수 있습니다(예: 삭제로 인해 Canvas에 더 이상 존재하지 않는 `canvas_step_ids`)
- 사용자가 동일한 메시지를 두 번 받을 수 있음
- 기존 사용량 제한으로 인해 사용자가 메시지를 받지 못할 수 있음
  - 활성 Canvas의 사용량 제한을 업데이트하면, 새 사용량 제한은 변경 후 메시지 단계를 통과하는 사용자에게만 적용됩니다. 이미 메시지 단계에 대기 중인 사용자는 대기줄에 추가되었을 때 적용되었던 기존 사용량 제한을 유지합니다. 새 사용량 제한을 모든 사용자에게 적용하려면, Canvas를 중지하고 업데이트된 사용량 제한으로 복제한 다음 새 Canvas를 출시하세요. 필터를 사용하여 원래 Canvas에서 메시지를 받은 사용자가 복제된 Canvas에 진입하지 않도록 하세요.
- Canvas가 [자동 중지]({{site.baseurl}}/user_guide/messaging/governance/statuses#available-statuses)되면, Canvas의 출시 후 초안도 함께 삭제됩니다.
