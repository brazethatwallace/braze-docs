# 종료 기준 {#exit-criteria}

> Canvas 진입 규칙에 예외 이벤트를 직접 추가하면 사용자가 특정 동작을 수행할 때 여정에서 제거할 수 있습니다.
> Braze는 이벤트가 발생하는 즉시 종료를 기록합니다.
> 사용자가 Canvas를 완전히 떠나는 속도는 현재 진행 중인 단계에 따라 달라지며, 특히 지연 단계에서 차이가 있습니다.
> 자세한 내용은 [사용자가 종료하는 방법](#how-users-exit)을 참조하세요.

## 사용자가 종료하는 방법 {#how-users-exit}

사용자가 종료 이벤트를 수행하면 Braze는 즉시 해당 사용자를 Canvas 종료 대상으로 표시합니다. 이후 해당 사용자는 이후 단계로 진행하지 않습니다.

지연 단계에 있는 경우, 지연 기간이 끝날 때까지 해당 단계에 머무릅니다. 지연이 완료되어도 이후 단계로 진행하지 않으며, 대신 Canvas를 완전히 떠납니다. Canvas 데이터를 확인하는 위치에 따라 종료 이벤트가 발생할 때와 지연 단계가 완료되어 사용자가 Canvas를 완전히 떠날 때 종료 관련 활동이 표시될 수 있습니다.

예를 들어, 사용자가 30일 지연 단계에 있고 지연 단계 첫째 날에 종료 이벤트를 수행하면 즉시 종료 대상으로 표시되지만, 지연 단계가 끝날 때(29일 후)까지 Canvas를 완전히 떠나지 않습니다.

시간 기반 종료 기준을 사용하는 또 다른 예를 살펴보겠습니다. 사용자가 7월 1일 오전 12시에 24시간으로 설정된 지연 단계에 진입합니다. 이 지연 기간 중 오전 3시에 "마지막 구매가 1시간 이내" 종료 이벤트를 수행합니다. 이 사용자는 지연 단계 기간이 종료되는 7월 2일 오전 12시에 종료 기준이 평가됩니다. 7월 1일 오전 3시 구매 이후 21시간이 경과했으므로, 7월 2일 지연 단계 종료 시점 기준 1시간 이내에 구매하지 않았기 때문에 Canvas를 종료하지 않습니다. 이는 Canvas 분석의 "종료 기준별 총 종료 수"에 영향을 미치며, 이 수치는 사용자가 Canvas를 완전히 떠난 후에만 업데이트됩니다.

## 종료 기준 설정 {#setting-up-exit-criteria}

Canvas 빌더의 **타겟 오디언스** 단계에서 종료 기준을 설정하여 Canvas에서 종료할 사용자를 식별할 수 있습니다.

종료 기준에는 예외 이벤트가 포함되며, 이는 사용자가 Canvas를 종료하게 만드는 특정 동작입니다.

### 예외 이벤트 선택 {#exception-events}

사용자가 예외 이벤트를 수행하면 Braze는 [사용자가 종료하는 방법](#how-users-exit)에 따라 종료 대상으로 표시합니다. 예외 이벤트는 사용자가 Canvas에 있는 동안 적용되며, 지연 단계와 같은 단계에서 대기 중일 때도 포함됩니다.

새 제품을 홍보하기 위한 Canvas가 설정되어 있다고 가정해 보겠습니다. 이 경우 해당 제품의 구매가 예외 이벤트가 됩니다. 이렇게 하면 사용자가 구매를 완료한 후 이미 구매한 제품에 대한 메시지를 더 이상 받지 않게 됩니다. 예외 이벤트는 메시징을 관련성 있고 개인화된 상태로 유지합니다.

추가 예외 이벤트에는 다음이 포함됩니다:

- 구매하기
- 세션 시작하기
- 커스텀 이벤트 수행하기
- 전환 이벤트 수행하기
- 이메일 주소 추가하기
- 커스텀 속성 값 변경하기
- 구독 상태 업데이트하기
- 구독 그룹 상태 업데이트하기
- Campaign과 상호작용하기
- 위치 진입하기
- 지오펜스 트리거하기
- SMS 인바운드 메시지 보내기
- WhatsApp 인바운드 메시지 보내기
- LINE 인바운드 메시지 보내기
- 장바구니 업데이트 이벤트 수행하기
- 결제 완료 이벤트 수행하기
- 결제 시작 이벤트 수행하기

#### 스케줄된 단계 {#scheduled-steps}

사용자를 미래 시점까지 지연 단계에 유지하지 않는 캔버스 단계의 경우, 사용자는 일반적으로 현재 단계가 완료되는 즉시 Canvas를 떠납니다. 해당 단계에 남은 지연 타이머가 없기 때문에 이 완료는 보통 예외 이벤트 직후에 이루어집니다. 이는 사용자가 종료 대상으로 표시된 후에도 지연이 끝날 때까지 머무르는 지연 단계와 다릅니다([사용자가 종료하는 방법](#how-users-exit) 참조).

#### 트리거된 단계 {#triggered-steps}

캔버스 단계가 이벤트에 의해 트리거되는 경우, 해당 트리거에서 대기줄에 넣어진 마지막 스케줄된 발송은 취소되지만, 사용자는 기간 동안 Canvas 내에 남아 있습니다. 즉, 사용자가 기간 내에 트리거 이벤트를 다시 수행하면 해당 단계가 발송될 수 있습니다. 기간이 지나면 사용자는 Canvas를 종료합니다.

### Segments 및 필터 사용 {#using-segments-and-filters}

종료 기준에 Segments와 필터를 추가할 수도 있습니다. 이는 Segment와 필터에 일치하는 사용자가 Canvas를 종료하고 더 이상 메시지를 받지 않음을 의미합니다.

예를 들어, Canvas의 첫 번째 단계가 5일 지연이 있는 지연 단계인 경우, 해당 단계가 완료될 때 종료 기준이 평가됩니다. 사용자가 지연 단계에 있는 동안 종료 기준을 충족하면 즉시 종료 대상으로 표시되지만, 5일이 끝날 때 Canvas를 완전히 떠나게 됩니다(그리고 지연 이후의 어떤 단계로도 진행하지 않습니다).

{% alert note %}
배열 속성은 현재 예외 이벤트의 종료 기준으로 지원되지 않습니다.
{% endalert %}

### 동일한 종료 이벤트와 전환 이벤트 사용 {#having-the-same-exit-event-and-conversion-event}

종료 이벤트와 전환 이벤트가 동일한 경우, 전환과 종료 이벤트 모두 집계됩니다. 예를 들어, Canvas에 지연 단계가 있고 사용자가 해당 지연 단계에서 종료 기준을 수행하면, 사용자가 지연 단계를 종료하는 즉시 종료 이벤트가 증가합니다. 전환도 이벤트가 고객 프로필에 기록되는 즉시 증가합니다.

전환은 Canvas가 종료된 후에도 추적되지만, 종료는 사용자가 Canvas를 떠나면 더 이상 추적되지 않습니다. 전환 기간은 Canvas의 최대 기간 이후 3일까지 연장됩니다. 즉, 종료 추적이 중단된 후에도 전환은 계속 추적됩니다.

전환 기간의 최소 시간은 5분입니다. 종료 이벤트와 가능한 한 동일하게 맞추려면 전환 이벤트의 전환 기간을 5분으로 설정하세요. 또한 전환 기간을 Canvas에서 가장 긴 경로와 최소한 일치하도록 설정하는 것을 권장합니다.

분석이 어떻게 계산되는지 다음 예시를 살펴보세요:

1. 10명의 사용자가 Canvas를 통과합니다.
2. 3명의 사용자가 5분 이내에 전환 이벤트를 수행합니다(종료 이벤트 수는 3, 전환 이벤트 수는 3).
3. 추가로 5명의 사용자가 5분 후에 Canvas를 종료하지만 2일 후에 전환 이벤트를 수행합니다(종료 이벤트 수는 동일하게 유지되지만, 전환 이벤트는 8로 증가).
4. 마지막 2명의 사용자는 5분 후에 Canvas를 종료하지만 전환 이벤트를 수행하지 않거나, 3일 5분 후에 수행합니다(종료 이벤트 또는 전환 이벤트 측정기준에 포함되지 않습니다).

## 예시 {#example}

배낭 용품 회사에서 아직 구매하지 않은 사용자를 타겟팅하고 싶다고 가정해 보겠습니다. 종료 기준을 설정하려면 다음과 같이 합니다:

1. 예외 이벤트로 **Place an Order**를 선택합니다.
2. **Add Trigger**를 선택합니다.
3. **Segments**에서 **Used in last day**를 선택하여 Canvas가 시작될 때 구매한 적이 있는 사용자를 오디언스에서 제외합니다.
4. **필터**에서 **Purchase behavior** > **Number of purchases** > **Purchased product**를 선택합니다.
5. 필터 그룹을 `backpack-example exactly 1`로 설정합니다. 이렇게 하면 배낭 제품을 구매한 사용자가 Canvas를 종료합니다.
