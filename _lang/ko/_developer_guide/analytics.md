# 분석 {#analytics}

> Braze SDK의 분석에 대해 알아보고 Braze가 수집하는 데이터, 커스텀 이벤트와 커스텀 속성의 차이점, 분석 관리를 위한 모범 사례를 더 잘 이해할 수 있습니다.

{% alert tip %}
Braze를 구현하는 동안 팀과 마케팅 목표에 대해 논의하여 추적할 데이터와 Braze로 추적하는 방법을 가장 잘 결정할 수 있도록 하세요. 예시는 이 가이드 끝에 있는 [택시/차량 공유 앱](#example-case) 사례 연구를 참조하세요.
{% endalert %}

## 자동으로 수집되는 데이터 {#automatically-collected-data}

특정 사용자 데이터는 SDK에 의해 자동으로 수집됩니다. 예를 들어 최초 앱 사용, 최근 앱 사용, 총 세션 수, 기기 OS 등이 있습니다. 통합 가이드에 따라 SDK를 구현하면 이러한 [기본 데이터 수집]({{site.baseurl}}/user_guide/data/unification/user_data/sdk_data_collection)을 활용할 수 있습니다. 이 목록을 확인하면 사용자에 대한 동일한 정보를 중복으로 저장하는 것을 방지할 수 있습니다. 세션 시작 및 종료를 제외하고, 자동으로 추적되는 다른 모든 데이터는 데이터 포인트 사용량에 포함되지 않습니다.

특정 데이터 항목의 기본 수집을 차단하는 프로세스를 허용 목록에 추가하려면 [SDK 입문]({{site.baseurl}}/developer_guide/getting_started/sdk_overview) 문서를 참조하세요.

## 커스텀 이벤트 {#custom-events}

커스텀 이벤트는 사용자가 수행하는 동작으로, 애플리케이션과의 가치가 높은 사용자 상호작용을 추적하는 데 가장 적합합니다. 커스텀 이벤트를 기록하면 구성 가능한 지연 시간을 가진 후속 Campaign을 원하는 수만큼 트리거할 수 있으며, 해당 이벤트의 최근성과 빈도에 따른 다음과 같은 세분화 필터를 사용할 수 있습니다:

| 세분화 옵션 | 드롭다운 필터 | 입력 옵션 |
| ---------------------| --------------- | ------------- |
| 커스텀 이벤트가 **X회를 초과**하여 발생했는지 확인 | **MORE THAN** | **NUMBER** |
| 커스텀 이벤트가 **X회 미만**으로 발생했는지 확인 | **LESS THAN** | **NUMBER** |
| 커스텀 이벤트가 **정확히 X회** 발생했는지 확인 | **EXACTLY** | **NUMBER** |
| 커스텀 이벤트가 마지막으로 **X 날짜 이후**에 발생했는지 확인 | **AFTER** | **TIME** |
| 커스텀 이벤트가 마지막으로 **X 날짜 이전**에 발생했는지 확인 | **BEFORE** | **TIME** |
| 커스텀 이벤트가 마지막으로 **X일 이전에** 발생했는지 확인 | **MORE THAN** | **NUMBER OF DAYS AGO** (양수) |
| 커스텀 이벤트가 마지막으로 **X일 이내에** 발생했는지 확인 | **LESS THAN** | **NUMBER OF DAYS AGO** (양수) |
| 커스텀 이벤트가 **X회(최대 = 50)를 초과**하여 발생했는지 확인 | **MORE THAN** | 최근 **Y일(Y = 1,3,7,14,21,30)** 이내 |
| 커스텀 이벤트가 **X회(최대 = 50) 미만**으로 발생했는지 확인 | **LESS THAN** | 최근 **Y일(Y = 1,3,7,14,21,30)** 이내 |
| 커스텀 이벤트가 **정확히 X회(최대 = 50)** 발생했는지 확인 | **EXACTLY** | 최근 **Y일(Y = 1,3,7,14,21,30)** 이내 |
{: .reset-td-br-1 .reset-td-br-2 .reset-td-br-3 aria-label="커스텀 이벤트" }

Braze는 이러한 이벤트가 발생한 횟수와 각 사용자가 마지막으로 수행한 시점을 기록하여 세분화에 활용합니다. **커스텀 이벤트** 분석 페이지에서는 각 커스텀 이벤트가 얼마나 자주 발생하는지 전체적으로 확인할 수 있으며, 더 상세한 분석을 위해 시간 경과에 따른 Segment별 데이터도 볼 수 있습니다. 이 기능은 Braze가 시계열 위에 겹쳐 표시하는 회색 선을 통해 마지막으로 Campaign이 발송된 시점을 확인하여, Campaign이 커스텀 이벤트 활동에 어떤 영향을 미쳤는지 파악하는 데 특히 유용합니다.

![30일 기간 동안 신용카드를 추가하고 검색을 수행한 사용자의 통계를 보여주는 커스텀 이벤트 분석 그래프.]({% image_buster /assets/img_archive/custom_event_analytics_example.png %} "custom_event_analytics_example.png")

{% alert note %}
[커스텀 속성 증분]({{site.baseurl}}/api/endpoints/messaging)을 사용하여 커스텀 이벤트와 유사하게 사용자 동작에 대한 카운터를 유지할 수 있습니다. 그러나 커스텀 속성 데이터는 시계열로 볼 수 없습니다. 시계열로 분석할 필요가 없는 사용자 동작은 이 방법으로 기록해야 합니다.
{% endalert %}

### 커스텀 이벤트 저장 {#custom-event-storage}

모든 고객 프로필 데이터(커스텀 이벤트, 커스텀 속성, 커스텀 데이터)는 해당 프로필이 활성 상태인 동안 저장됩니다.

### 커스텀 이벤트 속성정보 {#custom-event-properties}

커스텀 이벤트 속성정보를 통해 Braze에서는 커스텀 이벤트 및 구매에 속성정보를 설정할 수 있습니다. 이러한 속성정보는 트리거 조건을 더 세밀하게 지정하고, 메시징의 개인화를 높이며, 원시 데이터 내보내기를 통해 보다 정교한 분석을 생성하는 데 사용할 수 있습니다. 속성정보 값은 문자열, 숫자, 부울 값 또는 시간 객체가 될 수 있습니다. 그러나 속성정보 값은 배열 객체가 될 수 없습니다.

예를 들어, 이커머스 애플리케이션이 사용자가 장바구니를 이탈할 때 메시지를 보내려면, 사용자 장바구니의 `cart_value`에 대한 커스텀 이벤트 속성정보를 추가하여 타겟 오디언스를 개선하고 Campaign 개인화를 강화할 수 있습니다.

![장바구니를 이탈했으며 장바구니 금액이 100 초과 200 미만인 사용자에게 Campaign을 발송하는 커스텀 이벤트 예시.]({% image_buster /assets/img_archive/customEventProperties.png %} "customEventProperties.png")

커스텀 이벤트 속성정보는 메시징 템플릿 내 개인화에도 사용할 수 있습니다. 트리거 이벤트와 함께 [실행 기반 전달]({{site.baseurl}}/user_guide/messaging/campaigns/schedule_your_campaign/triggered_delivery)을 사용하는 모든 Campaign은 해당 이벤트의 커스텀 이벤트 속성정보를 메시징 개인화에 활용할 수 있습니다. 게임 애플리케이션에서 레벨을 완료한 사용자에게 메시지를 보내려면, 사용자가 해당 레벨을 완료하는 데 걸린 시간에 대한 속성정보로 메시지를 더욱 개인화할 수 있습니다. 이 예시에서는 [조건 로직]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/liquid/conditional_logic)을 사용하여 세 가지 Segment에 대해 메시지가 개인화됩니다. ``time_spent``라는 커스텀 이벤트 속성정보는 ``{% raw %} {{event_properties.${time_spent}}} {% endraw %}``를 호출하여 메시지에 포함할 수 있습니다.

{% raw %}
```liquid
{% if {{event_properties.${time_spent}}} < 600 %}
Congratulations on beating that level so fast! Check out our online portal where you can play against top players from around the world!
{% elsif {{event_properties.${time_spent}}} < 1800 %}
Don't forget to visit the town store between levels to upgrade your tools.
{% else %}
Talk to villagers for essential tips on how to beat levels!
{% endif %}
```
{% endraw %}

커스텀 이벤트 속성정보는 메시징을 개인화하거나 세분화된 실행 기반 전달 Campaign을 구축하는 데 도움을 주도록 설계되었습니다. 이벤트 속성정보의 최근성과 빈도를 기반으로 Segment를 생성하려면 고객 성공 매니저 또는 지원 팀에 문의하세요.

## 커스텀 속성 {#custom-attributes}

커스텀 속성은 표준 속성보다 더 세밀하게 사용자를 타겟팅할 수 있는 매우 유연한 도구입니다. 커스텀 속성은 사용자에 대한 브랜드별 정보를 저장하는 데 매우 유용합니다. 커스텀 속성에 대해서는 시계열 정보를 저장하지 않으므로, 앞의 커스텀 이벤트 예시와 같은 그래프를 얻을 수 없다는 점을 유의하세요.

### 커스텀 속성 저장 {#custom-attribute-storage}

모든 사용자 프로필 데이터(커스텀 이벤트, 커스텀 속성, 커스텀 데이터)는 해당 프로필이 활성 상태인 한 저장됩니다.

### 커스텀 속성 데이터 유형 {#custom-attribute-data-types}

다음 데이터 유형을 커스텀 속성으로 저장할 수 있습니다:

#### 문자열(영숫자 문자) {#strings-alphanumeric-characters}

문자열 속성은 선호 브랜드, 전화번호, 애플리케이션 내 마지막 검색어 등 사용자 입력을 저장하는 데 유용합니다. 문자열 속성에는 커스텀 데이터의 [길이 제한](#length-constraints)(479바이트; 싱글바이트 문자 기준 약 479자, 일본어와 같은 멀티바이트 스크립트 기준 약 160자)이 적용됩니다.

다음 표는 문자열 속성에 사용 가능한 세분화 옵션을 설명합니다.

| 세분화 옵션 | 드롭다운 필터 | 입력 옵션 |
| ---------------------| --------------- | ------------- |
| 문자열 속성이 입력된 문자열과 **정확히 일치**하는지 확인 | **EQUALS** | **STRING** |
| 문자열 속성이 입력된 문자열 **또는** 정규표현식과 **부분 일치**하는지 확인 | **MATCHES REGEX** | **STRING** **또는** **REGULAR EXPRESSION** |
| 문자열 속성이 입력된 문자열 **또는** 정규표현식과 **부분 일치하지 않는지** 확인 | **DOES NOT MATCH REGEX** | **STRING** **또는** **REGULAR EXPRESSION** |
| 문자열 속성이 입력된 문자열과 **일치하지 않는지** 확인 | **DOES NOT EQUAL** | **STRING** |
| 문자열 속성이 사용자 프로필에 **존재하는지** 확인 | **IS BLANK** | **해당 없음** |
| 문자열 속성이 사용자 프로필에 **존재하지 않는지** 확인 | **IS NOT BLANK** | **해당 없음** |
{: .reset-td-br-1 .reset-td-br-2 .reset-td-br-3 aria-label="문자열(영숫자 문자)" }

{% alert important %}
**DOES NOT MATCH REGEX** 필터를 사용하여 세분화할 때는 해당 사용자 프로필에 값이 할당된 커스텀 속성이 이미 존재해야 합니다. Braze는 사용자를 올바르게 타겟팅하기 위해 커스텀 속성이 비어 있는지 확인하는 "OR" 로직을 사용하는 것을 권장합니다.
{% endalert %}

{% alert tip %}
정규표현식 필터 사용 방법에 대한 자세한 내용은 [Perl 호환 정규표현식(PCRE)](http://www.regextester.com/pregsyntax.html) 관련 문서를 확인하세요.
<br>
정규식 관련 추가 리소스:
- [Braze에서 정규식 사용하기]({{site.baseurl}}/user_guide/audience/segments/regex)
- [정규식 디버거 및 테스터](https://regex101.com/)
- [정규식 튜토리얼](https://medium.com/factory-mind/regex-tutorial-a-simple-cheatsheet-by-examples-649dc1c3f285)
{% endalert %}

#### 배열 {#arrays}

배열 속성은 사용자에 대한 관련 목록 정보를 저장하는 데 적합합니다. 예를 들어, 사용자가 시청한 최근 100개의 콘텐츠를 배열에 저장하면 특정 관심사 기반 세분화가 가능합니다.

커스텀 속성 배열은 1차원 집합이며, 다차원 배열은 지원되지 않습니다. **커스텀 속성 배열에 요소를 추가하면 해당 요소가 배열 끝에 추가됩니다. 단, 이미 존재하는 경우 현재 위치에서 배열 끝으로 이동합니다.** 예를 들어, 배열 `['hotdog','hotdog','hotdog','pizza']`를 가져오면 고유한 값만 지원되므로 배열 속성에 `['hotdog', 'pizza']`로 표시됩니다.

배열이 최대 요소 개수에 도달하면 첫 번째 요소가 삭제되고 새 요소가 끝에 추가됩니다. 다음은 웹 SDK에서의 배열 동작을 보여주는 예시 코드입니다:

```js
var abUser = appboy.getUser();
// initialize array for this user, assuming max length of favorite_foods is set to 4.
abUser.setCustomUserAttribute('favorite_foods', ['pizza', 'wings', 'pasta']); // => ['pizza', 'wings', 'pasta']
abUser.addToCustomAttributeArray('favorite_foods', 'fries'); // => ['pizza', 'wings', 'pasta', 'fries']
abUser.addToCustomAttributeArray('favorite_foods', 'pizza'); // => ['wings', 'pasta', 'fries', 'pizza']
abUser.addToCustomAttributeArray('favorite_foods', 'ice cream'); // => ['pasta', 'fries', 'pizza', 'ice cream']
```

배열의 기본값이자 최대 요소 개수는 500개입니다. Braze 대시보드의 **데이터 설정** > **커스텀 속성**에서 최대 요소 개수를 업데이트할 수 있습니다. 최대 요소 개수를 초과하는 배열은 최대 요소 개수까지 잘립니다.

{% alert note %}
배열 커스텀 속성이 사용자 프로필에 나타나지만 값이 표시되지 않는 경우, **데이터 설정** > **커스텀 속성**에서 해당 속성의 **최대 길이**를 확인하세요. **최대 길이**가 `0`이면 프로필에 값이 표시되지 않습니다. 문제 해결 단계는 [커스텀 속성 데이터 유형]({{site.baseurl}}/user_guide/data/activation/custom_data/data_types#arrays)을 참조하세요.
{% endalert %}

다음 표는 배열 속성에 사용 가능한 세분화 옵션을 설명합니다.

| 세분화 옵션 | 드롭다운 필터 | 입력 옵션 |
| ---------------------| --------------- | ------------- |
| 배열 속성에 입력된 값과 **정확히 일치하는 값이 포함되어 있는지** 확인 | **INCLUDES VALUE** | **STRING** |
| 배열 속성에 입력된 값과 **정확히 일치하는 값이 포함되어 있지 않은지** 확인 | **DOESN'T INCLUDE VALUE** | **STRING** |
| 배열 속성에 입력된 값 **또는** 정규표현식과 **부분 일치하는 값이 포함되어 있는지** 확인 | **MATCHES REGEX** | **STRING** **또는** **REGULAR EXPRESSION** |
| 배열 속성에 **값이 있는지** 확인 | **HAS A VALUE** | **해당 없음** |
| 배열 속성이 **비어 있는지** 확인 | **IS EMPTY** | **해당 없음** |
{: .reset-td-br-1 .reset-td-br-2 .reset-td-br-3 aria-label="배열" }

{% alert note %}
[Perl 호환 정규표현식(PCRE)](http://www.regextester.com/pregsyntax.html)을 사용합니다.

#### 날짜 {#dates}

시간 속성은 특정 작업이 마지막으로 수행된 시간을 저장하는 데 유용하며, 사용자에게 콘텐츠별 재참여 메시지를 제공할 수 있게 해줍니다.

{% alert note %}
커스텀 이벤트 또는 구매 이벤트가 마지막으로 발생한 날짜는 자동으로 기록되므로, 커스텀 시간 속성을 통해 중복 기록하면 안 됩니다.
{% endalert %}

상대 날짜를 사용하는 날짜 필터(예: 1일 이전보다 이후, 2일 이전보다 이전)는 1일을 24시간으로 측정합니다. 이러한 필터를 사용하여 실행하는 Campaign에는 24시간 단위로 모든 사용자가 포함됩니다. 예를 들어, '마지막 앱 사용이 1일 이전보다 이후'는 Campaign이 실행되는 정확한 시점으로부터 "24시간 이상 전에 마지막으로 앱을 사용한" 모든 사용자를 캡처합니다. 더 긴 날짜 범위로 설정된 Campaign에도 동일하게 적용됩니다. 활성화로부터 5일은 이전 120시간을 의미합니다.

## 택시/차량 공유 앱 활용 사례 {#example-case}

이 예제에서는 어떤 사용자 데이터를 수집할지 결정하려는 차량 공유 앱을 생각해 보겠습니다. 다음 질문과 브레인스토밍 프로세스는 마케팅팀과 개발팀이 따라야 할 훌륭한 모델입니다. 이 연습이 끝나면 두 팀 모두 목표를 달성하기 위해 수집해야 할 커스텀 이벤트와 속성을 확실히 이해할 수 있습니다.

**사례 질문 #1: 목표는 무엇인가요?**

목표는 간단합니다. 사용자가 앱을 통해 택시를 호출하는 것입니다.

**사례 질문 #2: 앱 설치부터 목표까지의 중간 단계는 무엇인가요?**

1. 사용자는 등록 절차를 시작하고 개인 정보를 입력해야 합니다.
2. 사용자는 SMS를 통해 받은 코드를 앱에 입력하여 등록 절차를 완료하고 인증해야 합니다.
3. 택시를 호출해야 합니다.
4. 택시를 호출하려면 검색 시 택시를 이용할 수 있어야 합니다.

이러한 동작은 다음과 같은 커스텀 이벤트로 태그를 지정할 수 있습니다:

- 등록 시작
- 등록 완료
- 성공적인 택시 호출
- 택시 호출 실패

이벤트를 구현한 후 이제 다음 Campaign을 실행할 수 있습니다:

1. 등록을 시작했지만 특정 시간 내에 등록 완료 이벤트가 트리거되지 않은 사용자에게 메시지를 보냅니다.
2. 등록을 완료한 사용자에게 축하 메시지를 보냅니다.
3. 택시 호출에 실패한 후 일정 시간 내에 성공적인 택시 호출이 없는 사용자에게 사과와 프로모션 크레딧을 보냅니다.
4. 성공적인 택시 호출 횟수가 많은 우수 고객에게 프로모션을 보내 로열티에 대한 감사의 마음을 전합니다.

이외에도 다양한 활용이 가능합니다!

**사례 질문 #3: 메시징에 도움이 될 사용자에 대한 다른 정보로 무엇이 있나요?**

- 프로모션 크레딧이 있는지 여부
- 드라이버에게 평균적으로 어떤 평점을 주는지
- 사용자를 위한 고유한 프로모션 코드가 있는지

그런 다음 이러한 특성에 다음과 같은 커스텀 속성으로 태그를 지정할 수 있습니다:

- 프로모션 크레딧 잔액(십진수 유형)
- 평균 운전자 평점(숫자 유형)
- 고유 프로모션 코드(문자열 유형)

이러한 속성을 추가하면 사용자에게 다음과 같은 Campaign을 보낼 수 있습니다:

1. 7일 동안 로그인하지 않았지만 프로모션 크레딧이 있는 사용자에게 크레딧이 존재하며 앱으로 돌아와서 사용해야 한다는 사실을 알려주세요!
2. 낮은 운전자 평점을 준 사용자에게 메시지를 보내 라이딩이 만족스럽지 않은 이유에 대한 직접적인 고객 피드백을 받습니다.
3. [메시지 템플릿 및 개인화 기능]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize)을 사용하여 고유 프로모션 코드 속성을 사용자 대상 메시지에 포함할 수 있습니다.

## 모범 사례 {#best-practices}

### 일반 모범 사례 {#general-best-practices}

#### 이벤트 속성정보 활용 {#use-event-properties}

- 커스텀 이벤트에는 사용자가 수행하는 동작을 설명하는 이름을 지정하세요.
- 이벤트에 대한 중요한 데이터를 나타내기 위해 커스텀 이벤트 속성정보를 적극적으로 활용하세요.
- 예를 들어, 50개의 서로 다른 영화를 시청하는 것에 대해 각각 별도의 커스텀 이벤트를 캡처하는 것보다, 단순히 영화를 시청하는 것을 하나의 이벤트로 캡처하고 영화 이름을 이벤트 속성정보로 포함하는 것이 더 효과적입니다.

### 개발 모범 사례 {#development-best-practices}

#### 모든 사용자에 대해 사용자 ID 설정 {#set-user-ids-for-every-user}

사용자 ID는 각 사용자에 대해 설정해야 합니다. 사용자 ID는 변경되지 않아야 하며 사용자가 앱을 열 때 접근 가능해야 합니다. 이 식별자를 제공하면 다음과 같은 기능이 가능하므로 **강력히 권장합니다**:

- 기기와 플랫폼 전반에 걸쳐 사용자를 추적하여 행동 및 인구통계학적 데이터의 품질을 개선합니다.
- [사용자 데이터 API]({{site.baseurl}}/api/endpoints/user_data)를 사용하여 사용자에 대한 데이터를 가져옵니다.
- [메시징 API]({{site.baseurl}}/api/endpoints/messaging)를 사용하여 일반 메시지 및 트랜잭션 메시지 모두에 대해 특정 사용자를 타겟팅합니다.

사용자 ID는 512자 미만이어야 하며, 비공개이고 쉽게 얻을 수 없어야 합니다(예: 일반 이메일 주소나 사용자 이름이 아닌 형태). 이러한 식별자를 사용할 수 없는 경우, Braze는 사용자에게 고유 식별자를 할당하지만 사용자 ID에 대해 나열된 기능은 사용할 수 없습니다. 개인으로서 연결된 고유 식별자가 없는 사용자에 대해서는 사용자 ID를 설정하지 않아야 합니다. 기기 식별자를 전달하는 것은 Braze가 기본적으로 제공하는 자동 익명 사용자 추적에 비해 이점이 없습니다. 다음은 적합한 사용자 ID와 부적합한 사용자 ID의 예입니다.

사용자 ID로 적합한 옵션:

- 해시된 이메일 주소 또는 고유 사용자 이름
- 고유 데이터베이스 식별자

사용자 ID로 사용하면 안 되는 것:

- 기기 ID
- 난수 또는 세션 ID
- 고유하지 않은 ID
- 이메일 주소
- 다른 서드파티 벤더의 사용자 ID

{% multi_lang_include alerts/important_alerts.md alert='SDK auth' %}

#### 커스텀 이벤트 및 속성에 읽기 쉬운 이름 지정 {#give-custom-events-and-attributes-readable-names}

구현 후 1~2년이 지난 시점에 Braze를 사용하기 시작하는 마케터가 추가 컨텍스트 없이 "usr_no_acct"와 같은 이름으로 가득 찬 드롭다운 목록을 본다고 상상해 보세요. 이벤트와 속성에 식별 가능하고 읽기 쉬운 이름을 지정하면 플랫폼의 모든 사용자가 더 편리하게 사용할 수 있습니다. 다음 모범 사례를 고려하세요:

- 커스텀 이벤트를 숫자로 시작하지 마세요. 드롭다운 목록은 알파벳순으로 정렬되며, 숫자로 시작하면 원하는 필터로 세분화하기가 더 어려워집니다.
- 가능하면 모호한 약어나 기술 전문 용어를 사용하지 마세요.
  - 예: `usr_ctry`는 코드 내에서 사용자의 국가를 나타내는 변수 이름으로는 적합할 수 있지만, 커스텀 속성은 `user_country`와 같이 Braze에 전송하여 이후 대시보드를 사용하는 마케터에게 명확성을 제공해야 합니다.

#### 속성이 변경될 때만 기록 {#only-log-attributes-when-they-change}

Braze에 전달되는 모든 속성은 이전에 저장된 것과 동일한 값이 포함된 속성이더라도 데이터 포인트로 계산됩니다. 데이터가 변경될 때만 기록하면 불필요한 데이터 포인트 사용을 방지하고 불필요한 API 호출을 줄여 더 원활한 경험을 지원할 수 있습니다.

#### 프로그래밍 방식으로 이벤트 이름 생성 지양 {#avoid-programmatically-generating-event-names}

새로운 이벤트 이름을 지속적으로 생성하면 사용자를 의미 있게 세분화하는 것이 불가능해집니다. 일반적으로 매우 구체적인 이벤트(예: "강남스타일 시청" 또는 "기사 읽기: 미드타운 맨해튼 점심 맛집 Top 10")보다는 일반적인 이벤트(예: "비디오 시청" 또는 "기사 읽기")를 캡처해야 합니다. 이벤트에 대한 구체적인 데이터는 이벤트 이름의 일부가 아닌 이벤트 속성정보로 포함해야 합니다.

### 기술적 제한 사항 및 제약 조건 {#technical-limitations-and-constraints}

커스텀 이벤트를 구현할 때 다음 제한 사항과 제약 조건에 유의하세요:

#### 길이 제약 {#length-constraints}

Braze는 커스텀 이벤트 이름, 커스텀 속성 이름(키) 및 커스텀 이벤트 문자열 값에 바이트 단위 길이 제한(479바이트)을 적용합니다. 이 제한을 초과하는 값은 잘립니다. 문자 수로 표현하면 약 479개의 싱글바이트 문자(예: ASCII)이거나, 한국어와 같은 멀티바이트 스크립트의 경우 약 160자(UTF-8에서 문자당 약 3바이트 기준)입니다. 앱의 네트워크 및 배터리 성능을 개선하기 위해 이름과 값은 가능한 한 짧게 유지하는 것이 좋으며, 가능하면 50자 이내로 제한하세요.

#### 콘텐츠 제약 {#content-constraints}
다음 콘텐츠는 속성 및 이벤트에서 프로그래밍 방식으로 제거됩니다. 다음 사항을 사용하지 않도록 주의하세요:

- 앞뒤 공백
- 줄 바꿈
- 전화번호 내의 숫자가 아닌 모든 문자
  - 예: "(732) 178-1038"은 "7321781038"로 축약됩니다.
- 공백이 아닌 문자는 공백으로 변환해야 합니다.
- $는 커스텀 이벤트의 접두사로 사용해서는 안 됩니다.
- 잘못된 UTF-8 인코딩 값
  - "My \x80 Field"는 "My Field"로 축약됩니다.

#### 예약 키 {#reserved-keys}

다음 키는 예약되어 있으며 커스텀 이벤트 속성정보로 사용할 수 없습니다:

- `time`
- `product_id`
- `quantity`
- `event_name`
- `price`
- `currency`

#### 값 정의 {#value-definitions}

- 정수 값은 64비트입니다.
- 소수는 기본적으로 소수점 이하 15자리입니다.

### 일반 이름 필드 파싱 {#parsing-a-generic-name-field}

사용자에 대해 단일 일반 이름 필드만 존재하는 경우(예: 'JohnDoe'), 이 전체 이름을 사용자의 이름(First Name) 속성에 할당할 수 있습니다. 또한 공백을 사용하여 사용자의 이름과 성을 분리하려고 시도할 수 있지만, 이 방법은 일부 사용자의 이름을 잘못 지정할 위험이 있습니다.
