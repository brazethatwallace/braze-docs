# リアルタイムアプリ内メッセージ配信 {#real-time-in-app-message-delivery}

> リアルタイム配信では、ユーザーが対象となった時点で、Brazeがアプリ内メッセージをデバイスに送信します。セッション途中で対象になったアプリ内メッセージを受け取るために、ユーザーが新しいセッションを開始する必要はありません。

{% multi_lang_include alerts/early_access_beta_alert.md feature='Real-time in-app message delivery' type='early_access' %}

## 仕組み {#how-it-works}

リアルタイム配信がない場合、SDKはセッション開始時に対象となるアプリ内メッセージをリクエストし、デバイスにキャッシュします。セッションの途中で対象となったユーザーは、次のセッションが開始されるまでメッセージを受信しません。この動作の詳細については、[アプリ内メッセージのトリガー]({{site.baseurl}}/developer_guide/in_app_messages/triggering_messages)を参照してください。

リアルタイム配信では、SDKがセッション中に維持するライブ接続を通じて、Brazeがデバイスにメッセージをプッシュします。Brazeは次の2つのケースでメッセージを送信します。

- ユーザーがアプリ内メッセージキャンペーンの対象になった場合。
- ユーザーがキャンバス内のアプリ内メッセージステップに進んだ場合。

リアルタイム配信は、メッセージがデバイスに届くタイミングを変更します。表示の動作は同じままで、メッセージはトリガーイベントが発生するまで表示を待機します。

### キャンペーンへの影響 {#what-this-means-for-your-campaigns}

| シナリオ | リアルタイム配信なし | リアルタイム配信あり |
| --- | --- | --- |
| ユーザーがセッション途中でアプリ内メッセージキャンペーンの対象になった場合 | メッセージは次のセッション開始時に届きます | メッセージは現在のセッション中に届きます |
| ユーザーがセッション途中でキャンバス内のアプリ内メッセージステップに到達した場合 | メッセージは次のセッション開始時に届きます | メッセージは現在のセッション中に届きます |

## SDKの要件 {#sdk-requirements}

リアルタイム配信には、以下の最小SDKバージョンが必要です。

{% sdk_min_versions swift:18.0.0 android:43.1.1 web:6.12.0 %}

SDKバージョンに関係なく、デバイスはセッション開始時にアプリ内メッセージを引き続き受信します。

## 現在の制限事項 {#current-limitations}

- **ライブキャンペーンへの編集は次のセッション開始時に適用されます：**デバイスがすでに受信したアプリ内メッセージを変更した場合、そのデバイスはユーザーの次のセッションが開始されるまで、受信済みのバージョンを保持します。

## 早期アクセスへの参加 {#participate-in-early-access}

1. Brazeアカウントマネージャーに連絡して、ワークスペースを早期アクセスに追加してもらいます。
2. アプリをプラットフォームの最小SDKバージョンにアップグレードします。
3. アップグレードしたアプリをユーザーにリリースします。

リアルタイム配信には、ダッシュボードの設定、キャンペーンの変更、SDKのコード変更は必要ありません。ワークスペースが早期アクセスに追加されると、リアルタイム配信は既存のアプリ内メッセージキャンペーンとキャンバスに適用されます。

## フィードバックの共有 {#share-feedback}

Brazeはこの機能を積極的に開発中であり、皆様のフィードバックが一般提供時にリリースされる内容に影響します。配信タイミングに関する所見、予想と異なる動作があった点、今後リアルタイム配信でカバーしてほしいシナリオについて、アカウントマネージャーにお知らせください。
