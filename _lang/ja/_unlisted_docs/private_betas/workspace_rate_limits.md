# ワークスペースのレート制限 {#workspace-rate-limits}

> ワークスペースのレート制限を設定する方法を説明します。会社全体のAPIレート制限を個々のワークスペースにどのように配分するかをコントロールし、単一のインテグレーションやチームが特定のエンドポイントに過剰なリクエストを送信することを防止できます。

## 前提条件 {#prerequisites}

ワークスペースのレート制限は、データポイントを含まないBraze契約でのみ利用できます。また、レート制限を管理するには[管理者権限]({{site.baseurl}}/user_guide/administrative/app_settings/manage_your_braze_users/user_permissions/#admin)が必要です。

## ワークスペースのレート制限について {#about-workspace-rate-limits}

デフォルトでは、会社レベルのレート制限はワークスペース間で共有されます。

ワークスペースのレート制限を使用すると、ワークスペースが `/users/track` やSDKデータなどの特定のインジェストエンドポイントに対して行えるAPIリクエストの最大数を設定できます。また、ワークスペースのグループにレート制限を適用することもでき、その場合、制限はグループ内のすべてのワークスペースで共有されます。

たとえば、`/users/track` エンドポイントの会社レベルのレート制限が1時間あたり500,000リクエストの場合、次のようなワークスペースのレート制限を設定できます。

- _ワークスペース1_に1時間あたり10,000リクエストのレート制限を適用
- _ワークスペース2_と_ワークスペース3_に1時間あたり200,000リクエストの共有レート制限を適用
- _ワークスペース4_にはレート制限を適用しない（デフォルトの会社レベルのレート制限が使用されます）

## ワークスペースのレート制限の管理 {#managing-workspace-rate-limits}

### 制限の割り当て {#assigning-a-limit}

1つ以上のワークスペースに新しいレート制限を割り当てるには、**設定** > **管理者設定** > **ワークスペースのレート制限**に移動し、**レート制限を割り当てる**を選択します。

![Brazeダッシュボードの「ワークスペースのレート制限」ページ。]({% image_buster /assets/unlisted_docs/img/workspace_rate_limits/settings.png %}){: style="max-width:85%;"}

次に、エンドポイントと1つ以上のワークスペースを選択し、レート制限を入力します。制限は1,000より大きく、会社レベルのレート制限を超えない整数である必要があります。

完了したら、**レート制限を更新**を選択します。

![エンドポイント、ワークスペース、レート制限を選択するオプションが表示された「レート制限」ポップアップウィンドウ。]({% image_buster /assets/unlisted_docs/img/workspace_rate_limits/update_rate_limit.png %}){: style="max-width:45%;"}

{% alert note %}
複数のワークスペースを選択した場合、レート制限はそのワークスペースグループ全体で共有されます。
{% endalert %}

### 制限の編集 {#editing-a-limit}

既存のワークスペースのレート制限を編集するには、**設定** > **管理者設定** > **ワークスペースのレート制限**に移動し、<i class="fas fa-ellipsis-vertical" aria-label="その他のオプション"></i>縦三点リーダーを選択して**編集**を選択します。新しいレート制限は数分以内に反映される場合があります。

### 制限のリセット {#resetting-a-limit}

既存のレート制限を会社レベルのレート制限に戻すには、**設定** > **管理者設定** > **ワークスペースのレート制限**に移動し、<i class="fas fa-ellipsis-vertical" aria-label="その他のオプション"></i>縦三点リーダーを選択して**リセット**を選択します。

## 使用状況のモニタリング {#monitoring-usage}

### 応答ヘッダー {#response-headers}

デフォルトでは、すべてのインジェスト応答に以下のヘッダーが含まれ、安定した会社レベルのレート制限が反映されます。

レート制限を効果的に管理するために、インテグレーションロジックでこれらのヘッダーを使用することをお勧めします。たとえば、制限に近づいたらリクエスト量を減らし、`Retry-After` ヘッダーを使用してリトライのタイミングを判断できます。

| ヘッダー名 | 説明 |
| ----- | ----- |
| `X-RateLimit-Limit` | 現在のレート制限時間枠で許可されるリクエストの最大数。 |
| `X-RateLimit-Remaining` | 現在の時間枠で残っているリクエスト数。 |
| `X-RateLimit-Reset` | 現在のレート制限時間枠がリセットされるタイミング（UTCエポック秒）。 |
{: .reset-td-br-1 .reset-td-br-2 role="presentation"}

### エラーコード {#error-codes}

ワークスペースのレート制限に達した場合、リクエストは `429` 応答コードを返し、ヘッダーに `Retry-After` 値が含まれます。これはレート制限がリセットされるまでの秒数を表します。

`Retry-After` 値は、ワークスペースのレート制限がリセットされる次の正時までの秒数を反映します。

### API使用状況ダッシュボード {#api-usage-dashboard}

ワークスペース全体のリクエスト量、応答コード、インジェスト動作をモニタリングするには、[API使用状況ダッシュボード]({{site.baseurl}}/user_guide/analytics/dashboard/api_usage_dashboard/)も使用できます。

ダッシュボードを `429 Workspace Rate Limited` または `429 Company Rate Limited` でフィルタリングすることで、リクエストが会社レベルとワークスペースレベルのどちらのレート制限によって制限されたかをすばやく特定できます。
