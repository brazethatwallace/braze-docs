# 2025年5月27日リリース {#may-27-2025-release}

## データの柔軟性 {#data-flexibility}

### ワークスペース間でのキャンバスのコピー {#copying-canvases-across-workspaces}

{% multi_lang_include release_type.md release="General availability" %}

ワークスペース間でキャンバスをコピーできるようになりました。別のワークスペースにあるキャンバスのコピーから始めることで、メッセージ作成をすばやく開始できます。コピーされる内容の詳細については、[ワークスペース間でのキャンペーンとキャンバスのコピー]({{site.baseurl}}/copying_to_workspaces)を参照してください。

### 承認ワークフローのメッセージングルール {#messaging-rules-for-approval-workflow}

{% multi_lang_include release_type.md release="General availability" %}

承認ワークフローで[メッセージングルール]({{site.baseurl}}/user_guide/messaging/governance/approvals/messaging_rules)を使用して、追加の承認が必要になるまでにリーチ可能なユーザー数を制限できます。これにより、より大きなオーディエンスをターゲットにする前に、キャンペーンやキャンバスを確認できます。

### SnowflakeとBrazeのエンティティリレーションシップ図 {#entity-relationship-diagrams-for-snowflake-and-braze}

今年の初めに、SnowflakeとBraze間で共有されるデータのエンティティリレーションシップテーブルを作成しました。今月、[新しいインタラクティブな図]({{site.baseurl}}/partners/data_and_analytics/data_warehouses/snowflake/entity_relationships)を追加しました。この図では、各テーブルの詳細をパン、グラブ、ズームして確認でき、データがBrazeとどのように関連しているかをより深く理解できます。

## 創造性を引き出す {#unlocking-creativity}

### 推奨イベント {#recommended-events}

{% multi_lang_include release_type.md release="Early access" %}

[推奨イベント]({{site.baseurl}}/user_guide/data/activation/events/recommended_events)は、最も一般的なeコマースのユースケースにマッピングされます。推奨イベントを使用することで、ビルド済みのキャンバステンプレート、カスタマーライフサイクルにマッピングされたレポートダッシュボードなどを活用できます。

## 堅牢なチャネル {#robust-channels}

### バナーチャネル {#banners-channel}

{% multi_lang_include release_type.md release="General availability" %}

[バナー]({{site.baseurl}}/user_guide/channels/banners)を使用すると、ユーザー向けにパーソナライズされたメッセージングを作成でき、メールやプッシュ通知などの他のチャネルのリーチを拡大できます。バナーをアプリやWebサイトに直接埋め込むことで、自然な体験を通じてユーザーとエンゲージメントを築くことができます。

### Rich Communication Services（RCS）チャネル {#rich-communication-services-rcs-channel}

{% multi_lang_include release_type.md release="General availability" %}

[Rich Communication Services（RCS）]({{site.baseurl}}/user_guide/channels/sms_mms_and_rcs)は、従来のSMSを強化し、ブランドが情報を伝えるだけでなく、はるかに魅力的なメッセージを配信できるようにします。AndroidとiOSの両方でサポートされているRCSは、高品質のメディア、インタラクティブなボタン、ブランド化された送信者プロファイルなどの機能を、ユーザーのプリインストールされたメッセージングアプリに直接提供するため、別のアプリをダウンロードする必要がありません。

### プッシュ設定ページ {#push-settings-page}

{% multi_lang_include release_type.md release="General availability" %}

[**プッシュ設定**ページ]({{site.baseurl}}/user_guide/administer/global/workspace_settings/push_settings)を使用して、プッシュTTLやAndroidキャンペーンのデフォルトFCM優先度など、プッシュ通知の主要な設定を構成できます。これらの設定は、プッシュ通知の配信と効果を最適化し、ユーザーにより良い体験を提供するのに役立ちます。

### アプリ内メッセージキャンペーン用のプロモーションコード {#promotion-codes-for-in-app-message-campaigns}

{% multi_lang_include release_type.md release="Early access" %}

アプリ内メッセージキャンペーンのメッセージ本文に[プロモーションコードリストスニペット]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/sources/promotion_codes/create#create)を挿入することで、アプリ内メッセージキャンペーンで[プロモーションコード]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/sources/promotion_codes)を使用できます。

### Webhookエラーとレート制限の処理 {#handling-webhook-errors-and-rate-limiting}

[Webhookについて]({{site.baseurl}}/user_guide/message_building_by_channel/webhooks/understanding_webhooks#webhook-error-handling-and-rate-limiting)に、BrazeがWebhookエラーとレート制限をどのように処理するかを説明する新しいセクションが追加されました。

### アプリ内メッセージのロケール {#in-app-message-locales}

ワークスペースに[ロケールを追加]({{site.baseurl}}/locales_in_messages)すると、単一のアプリ内メッセージ内でさまざまな言語のユーザーをターゲットにできます。

### メールサービスプロバイダー（ESP）としてのAmazon SES {#amazon-ses-as-an-email-sending-provider-esp}

SendGridやSparkPostと同様に、Amazon SESをESPとして使用できるようになりました。SSLの設定とリンクごとのクリックトラッキングの詳細については、[BrazeにおけるSSL]({{site.baseurl}}/user_guide/channels/email/email_setup/ssl#what-is-a-cdn-and-why-do-i-need-it)と[ユニバーサルリンクとアプリリンク]({{site.baseurl}}/user_guide/channels/email/customize/universal_links_and_app_links#turning-off-click-tracking-on-a-link-to-link-basis)を参照してください。

## Brazeの新しいパートナーシップ {#new-braze-partnerships}

### Eagle Eye - ロイヤルティ {#eagle-eye-loyalty}

Brazeと[Eagle Eye]({{site.baseurl}}/partners/eagle_eye)の双方向インテグレーションにより、ロイヤルティやプロモーションデータをBrazeで直接活用でき、マーケターはポイント残高、プロモーション、リワードアクティビティなどのリアルタイムデータを使用してカスタマーエンゲージメントをパーソナライズできます。

### Eppo - ABテスト {#eppo-ab-testing}

Brazeと[Eppo]({{site.baseurl}}/partners/eppo)のインテグレーションにより、BrazeでABテストを設定し、Eppoで結果を分析してインサイトを得たり、メッセージのパフォーマンスを収益やリテンションなどの長期的なビジネス指標に結び付けたりすることができます。

### Mention Me - リファラル {#mention-me-referrals}

[Mention Me](https://www.mention-me.com/)とBrazeを組み合わせることで、プレミアムな顧客を獲得し、揺るぎないブランドロイヤルティを育む入り口となります。ファーストパーティのリファラルデータをBrazeにシームレスに統合することで、ブランドファンに対して高度にパーソナライズされたオムニチャネル体験を提供できます。開始するには、[テクノロジーパートナー：Mention Me]({{site.baseurl}}/partners/mention_me)をご覧ください。

### Shopify - eコマース {#shopify-ecommerce}

[複数のShopifyストアドメインを接続]({{site.baseurl}}/shopify_connecting_multiple_stores)して単一のワークスペースにまとめることで、すべての市場にわたる顧客の全体像を把握できます。地域ごとのストアで作業を重複させることなく、単一のワークスペースでオートメーションプログラムやジャーニーを構築・開始できます。

## SDKの更新 {#sdk-updates}

最新の SDK 更新がリリースされました。重大な変更は SDKの更新セクションに記載されています。その他すべての更新については、対応する SDKの変更ログを参照してください。

- [Android SDK 36.0.0](https://pub.dev/packages/braze_plugin/changelog)
    - このリリースでは、34.0.0で導入された Braze Android SDKの最小 Android SDK バージョンの API 21 から API 25 への引き上げを元に戻しています。これにより、SDKは API 21 以降をサポートするアプリに再びコンパイルできるようになりました。コンパイル可能な状態を再導入していますが、API 25 未満の正式サポートを再導入するものではなく、それらのバージョンを実行しているデバイスでSDKが意図どおりに動作することを保証するものではありません。
    - アプリがそれらのバージョンをサポートしている場合は、以下を行う必要があります。
        - それらの API バージョンについて、物理デバイス（エミュレーターだけでなく）でSDK統合が意図どおりに動作することを検証してください。
        - 期待どおりの動作を検証できない場合は、[disableSDK](https://braze-inc.github.io/braze-android-sdk/kdoc/braze-android-sdk/com.braze/-braze/-companion/disable-sdk.html) を呼び出すか、それらのバージョンでSDKを初期化しないでください。そうしないと、エンドユーザーのデバイスで意図しない副作用やパフォーマンスの低下を引き起こす可能性があります。
    - アプリ内メッセージがメインスレッドで読み取りを引き起こす問題を修正しました。
    `BrazeInAppMessageManager.displayInAppMessage` は Kotlin のサスペンド関数になりました。
        - この関数を直接呼び出していない場合は、変更を行う必要はありません。
    - Jetpack Compose API の更新に対応するため、AndroidX Compose BOM を 2025.04.01 に更新しました。
- [React Native SDK 15.0.0](https://github.com/braze-inc/braze-react-native-sdk/blob/master/CHANGELOG.md)
    - ネイティブ Android ブリッジを Braze Android SDK 35.0.0 から 36.0.0 に更新しました。
    - ネイティブ iOS バージョンバインディングを Braze Swift SDK 11.9.0 から 12.0.0 に更新しました。
    - iOS での PushNotificationEvent.timestamp の単位表現をミリ秒に更新しました。
        - 以前は、この値は iOS では秒で表現されていました。これにより、既存の Android の実装と一致するようになりました。
- [Web SDK 5.9.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [Flutter SDK 14.0.0 5.9.0](https://pub.dev/packages/braze_plugin/changelog)
    - このリリースでは、34.0.0で導入された Braze Android SDKの最小 Android SDK バージョンの API 21 から API 25 への引き上げを元に戻しています。これにより、SDKは API 21 以降をサポートするアプリに再びコンパイルできるようになりました。ただし、API 25 未満の正式サポートを再導入するものではありません。[Braze Android SDKの変更ログエントリ](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#3600)をお読みください。
    - ネイティブ Android ブリッジを Braze Android SDK 35.0.0 から 36.0.0 に更新しました。
    - ネイティブ iOS ブリッジを Braze Swift SDK 11.9.0 から 12.0.0 に更新しました。
