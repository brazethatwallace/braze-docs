# 2023年10月17日リリース {#october-17-2023-release}

## ワークスペースへのコピー {#copying-to-workspaces}

[ワークスペース間でのキャンペーンのコピー]({{site.baseurl}}/user_guide/messaging/governance/copy_across_workspaces)を使用すると、別のワークスペースにあるキャンペーンのコピーから始めることで、メッセージ作成をすばやく開始できます。このコピーは編集して公開するまで下書きのままになるため、成功したメッセージング戦略を維持し、それを基に構築することができます。

## Currentsコネクターのテスト {#test-currents-connectors}

[Currentsコネクターのテスト]({{site.baseurl}}/user_guide/data_and_analytics/braze_currents/setting_up_currents#test-currents-connectors)は、既存のコネクターの無料バージョンであり、さまざまな送信先のテストや試用に使用できます。テスト用Currentsには以下の特徴があります。

- 構築できるテスト用Currentsコネクターの数に制限はありません。
- 30日間のローリング期間で合計最大10,000イベントの上限があります。このイベント合計はダッシュボード上で1時間ごとに更新されます。

## フィーチャーフラグ {#feature-flags}

[フィーチャーフラグ]({{site.baseurl}}/developer_guide/feature_flags)を使用すると、特定のユーザーまたはランダムに選択したユーザーに対して、機能をリモートで有効または無効にできます。重要なのは、追加のコードデプロイやアプリストアの更新なしに、本番環境で機能のオンとオフを切り替えられることです。これにより、新機能を安心して安全にロールアウトできます。

## フィーチャーフラグの実験 {#feature-flag-experiments}

[フィーチャーフラグの実験]({{site.baseurl}}/developer_guide/feature_flags/experiments)では、アプリケーションへの変更をA/Bテストしてコンバージョン率を最適化できます。マーケターはフィーチャーフラグを使用して、新機能がコンバージョン率にプラスまたはマイナスの影響を与えるかどうか、またはどのフィーチャーフラグプロパティのセットが最も最適かを判断できます。

## ユーザープロファイルの統合 {#merging-user-profiles}

**ユーザー検索**ページでの検索で複数のユーザープロファイルが返された場合、**重複を統合**ボタンをクリックして[ユーザープロファイルを統合]({{site.baseurl}}/user_guide/audience/manage_audience/merge_duplicate_users)できます。保持するユーザープロファイルを選択でき、そのプロファイルが保持され、統合されたプロファイルの属性が引き継がれます。

## セグメント別のパフォーマンスデータ {#performance-data-by-segment}

クエリビルダーのレポートテンプレートを使用して、キャンペーン、キャンバス、バリアント、およびステップのパフォーマンスデータをセグメント別に[分析]({{site.baseurl}}/user_guide/data_and_analytics/reporting/viewing_and_understanding_segment_data#performance-data-by-segment)できるようになりました。

## ユーザープロファイルの更新 {#updating-user-profiles}

[`/users/track` エンドポイント]({{site.baseurl}}/api/endpoints/user_data/post_user_track)を使用して、電話番号またはメールでユーザープロファイルを更新できるようになりました。

## SDKの更新 {#sdk-updates}

最新のSDK更新がリリースされました。破壊的な更新はSDK更新セクションに記載されています。その他すべての更新は、対応するSDKの変更ログで確認できます。

- [Braze セグメント Swift Plugin v2.1.0](https://github.com/braze-inc/braze-segment-swift/blob/main/CHANGELOG.md)
- [Web SDK v4.10.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [Web SDK v5.0.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
    - [`subscribeToFeatureFlagsUpdates()`](https://js.appboycdn.com/web-sdk/latest/doc/modules/braze.html#subscribetofeatureflagsupdates)のコールバックは、リフレッシュの成功・失敗に関係なく常に呼び出されるようになりました。更新の受信に失敗した場合、コールバックは現在キャッシュされているフィーチャーフラグで呼び出されます。
    - [`getFeatureFlag()`](https://js.appboycdn.com/web-sdk/latest/doc/modules/braze.html#getfeatureflag)メソッドは、フィーチャーフラグが存在しない場合、またはフィーチャーフラグが無効になっている場合にnullを返すようになりました。
    - 4.0.4で非推奨となっていた`logContentCardsDisplayed()`メソッドが削除されました。
    - 非推奨の初期化オプション`enableHtmlInAppMessages`が削除されました。代わりに`allowUserSuppliedJavascript`オプションを使用してください。
    - 4.9.0で[`ImageOnly`](https://js.appboycdn.com/web-sdk/latest/doc/classes/braze.imageonly.html)に置き換えられて非推奨となっていたBannerクラスが削除されました。
    - `Banner`クラスの削除に伴い、`ab-banner` CSSクラス名が削除されました。CSSのカスタマイズは代わりに`ab-image-only`クラスを対象にしてください。
    - SDKはどこでもランタイムエラーをスローしなくなりました。初期化前にBrazeメソッドが呼び出された場合、代わりにコンソールに警告がログ出力されます。
    - SDKは、カスタムHTMLアプリ内メッセージにデフォルトのBrazeアプリ内メッセージスタイルを追加しなくなりました。これらのスタイルは、以前はレガシーアプリ内メッセージタイプで使用されていました。
- [Android SDK 29.0.0](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md)
    - `BannerImageCard`、`BannerImageCardView`、`BannerImageContentCardView`がそれぞれ`ImageOnlyCard`、`ImageOnlyCardView`、`ImageOnlyContentCardView`に名前変更されました。
    - Bannerカードに使用されていたすべてのスタイルがImage Onlyカードに更新されました。`banner`という単語を含むすべてのキーは`image_only`に置き換える必要があります。
    - デバイスのブランド情報が送信されるようになりました。これをブロックしたい場合は、「データ収集のブロック」を参照してください。
- [Flutter SDK 7.0.0](https://pub.dev/packages/braze_plugin/changelog)
    - ネイティブのAndroidブリッジを[Braze Android SDK 26.1.1から27.0.1に更新](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#2701)しました。
    - Gradle 8のサポートが追加されました。
- [Swift SDK 7.0.0](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md)
    - `useUUIDAsDeviceId`設定がデフォルトで有効になりました。
        - 影響の詳細については、[IDFVの収集 - Swift]({{site.baseurl}}/developer_guide/analytics/managing_data_collection/?sdktab=swift)を参照してください。
    - Bannerコンテンツカードタイプおよびそれに対応するUI要素が`ImageOnly`に名前変更されました。すべてのメンバーメソッドとプロパティはそのままです。
        - `Braze.ContentCard.Banner` → `Braze.ContentCard.ImageOnly`
        - `BrazeContentCardUI.BannerCell` → `BrazeContentCardUI.ImageOnlyCell`
    - BrazeUIの一部のテキストレイアウトロジックが新しいBraze.ModalTextViewクラスにリファクタリングされました。
    - フィーチャーフラグメソッドの動作が更新されました。
        - `FeatureFlags.featureFlag(id:)`は、存在しないIDに対してnilを返すようになりました。
        - `FeatureFlags.subscribeToUpdates(:)`は、リフレッシュリクエストが成功または失敗で完了した際にコールバックをトリガーします。
            - 以前にキャッシュされたデータが存在する場合、初回のサブスクリプション時にもコールバックが即座にトリガーされます。
- [AppboyKit iOS SDK 4.6.0](https://github.com/Appboy/appboy-ios-sdk/releases/tag/4.6.0)
    - このリリースにはXcode `14.x`が必要です。
    - iOS 9およびiOS 10のサポートが終了しました。
    - Carthage経由でインポートする際の古い`.framework`アセットのサポートが削除され、新しい`.xcframework`アセットが採用されました。
        - 適切なBrazeアセットをインポートするには、`carthage update --use-xcframeworks`コマンドを使用してください。
        - `appboy_ios_sdk_full.json`のサポートが削除され、代わりに`appboy_ios_sdk.json`を使用するようになりました。
