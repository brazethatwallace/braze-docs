# 2023年10月17日リリース {#october-17-2023-release}

## ワークスペースへのコピー {#copying-to-workspaces}

[ワークスペース間でのキャンペーンのコピー]({{site.baseurl}}/user_guide/messaging/governance/copy_across_workspaces)を使用すると、別のワークスペースにあるキャンペーンのコピーから始めることで、メッセージの作成をすぐに開始できます。このコピーは、編集して起動するまで下書きとして残るため、成功したメッセージング戦略を維持し、それを基に構築するのに役立ちます。

## Currentsのテストコネクター {#test-currents-connectors}

[Currentsのテストコネクター]({{site.baseurl}}/user_guide/data_and_analytics/braze_currents/setting_up_currents#test-currents-connectors)は、既存のコネクターの無料版であり、さまざまな送信先のテストや試行に使用できます。Currentsのテストには以下の特徴があります。

- 作成できるCurrentsテストコネクターの数に制限はありません。
- 30日間のローリング期間あたり、集計で最大10,000件のイベントが利用可能です。このイベント合計はダッシュボードで1時間ごとに更新されます。

## フィーチャーフラグ {#feature-flags}

[フィーチャーフラグ]({{site.baseurl}}/developer_guide/feature_flags)を使用すると、特定のユーザーまたはランダムに選択したユーザーに対して、機能をリモートで有効または無効にできます。重要なのは、追加のコードデプロイやアプリストアの更新なしに、本番環境で機能のオン・オフを切り替えられることです。これにより、新しい機能を安全かつ確信を持ってロールアウトできます。

## フィーチャーフラグ実験 {#feature-flag-experiments}

[フィーチャーフラグ実験]({{site.baseurl}}/developer_guide/feature_flags/experiments)では、コンバージョン率を最適化するためにアプリケーションの変更をA/Bテストできます。マーケターはフィーチャーフラグを使用して、新機能がコンバージョン率にプラスまたはマイナスの影響を与えるかどうか、あるいはどのフィーチャーフラグプロパティのセットが最適かを判断できます。

## ユーザープロファイルのマージ {#merging-user-profiles}

**ユーザーを検索**ページでの検索結果として複数のユーザープロファイルが返された場合、**Merge duplicates**ボタンをクリックして[ユーザープロファイルをマージ]({{site.baseurl}}/user_guide/engagement_tools/segments/user_profiles#merge-profiles)できます。どのユーザープロファイルを保持するかを選択でき、そのプロファイルが保持され、マージされたプロファイルから属性を取得します。

## セグメント別パフォーマンスデータ {#performance-data-by-segment}

クエリビルダーのレポートテンプレートを使用して、キャンペーン、キャンバス、バリアント、ステップの[パフォーマンスデータをセグメント別に分類]({{site.baseurl}}/user_guide/data_and_analytics/reporting/viewing_and_understanding_segment_data#performance-data-by-segment)できるようになりました。

## ユーザープロファイルの更新 {#updating-user-profiles}

[`/users/track`エンドポイント]({{site.baseurl}}/api/endpoints/user_data/post_user_track)を使用して、電話番号またはメールでユーザープロファイルを更新できるようになりました。

## SDKの更新 {#sdk-updates}

以下のSDK更新がリリースされました。破壊的な更新は下記のとおりです。その他すべての更新は、対応するSDKの変更ログをご確認ください。

- [Braze セグメント Swift Plugin v2.1.0](https://github.com/braze-inc/braze-segment-swift/blob/main/CHANGELOG.md)
- [Web SDK v4.10.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [Web SDK v5.0.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
    - [`subscribeToFeatureFlagsUpdates()`](https://js.appboycdn.com/web-sdk/latest/doc/modules/braze.html#subscribetofeatureflagsupdates)コールバックは、リフレッシュの成否にかかわらず常に呼び出されるようになりました。更新の受信に失敗した場合、コールバックは現在キャッシュされているフィーチャーフラグで呼び出されます。
    - [`getFeatureFlag()`](https://js.appboycdn.com/web-sdk/latest/doc/modules/braze.html#getfeatureflag)メソッドは、フィーチャーフラグが存在しない場合、またはフィーチャーフラグが無効になっている場合にnullを返すようになりました。
    - 以前4.0.4で非推奨になった`logContentCardsDisplayed()`メソッドを削除しました。
    - 非推奨の初期化オプション`enableHtmlInAppMessages`を削除しました。代わりに`allowUserSuppliedJavascript`オプションに置き換える必要があります。
    - 以前4.9.0で非推奨になったBannerクラスを[`ImageOnly`](https://js.appboycdn.com/web-sdk/latest/doc/classes/braze.imageonly.html)に置き換えて削除しました。
    - `Banner`クラス削除の一環として、`ab-banner` CSSクラス名を削除しました。CSSのカスタマイズでは、代わりに`ab-image-only`クラスをターゲットにする必要があります。
    - SDKがランタイムエラーをスローしなくなりました。初期化前にBrazeのメソッドが呼び出された場合、代わりに警告がコンソールに記録されます。
    - SDKで、カスタムHTMLアプリ内メッセージにデフォルトのBrazeアプリ内メッセージスタイルが追加されなくなりました。これらのスタイルは、以前はレガシーなアプリ内メッセージタイプで使用されていました。
- [Android SDK 29.0.0](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md)
    - `BannerImageCard`、`BannerImageCardView`、`BannerImageContentCardView`を`ImageOnlyCard`、`ImageOnlyCardView`、`ImageOnlyContentCardView`に名称変更しました。
    - バナーカードに使用されていたすべてのスタイルが画像のみのカードに更新されました。`banner`という単語を含むすべてのキーは`image_only`に置き換える必要があります。
    - デバイスのブランド情報が送信されるようになりました。これをブロックする場合は、「データ収集のブロック」を参照してください。
- [Flutter SDK 7.0.0](https://pub.dev/packages/braze_plugin/changelog)
    - ネイティブAndroidブリッジを[Braze Android SDK 26.1.1から27.0.1](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#2701)に更新しました。
    - Gradle 8のサポートを追加しました。
- [Swift SDK 7.0.0](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md)
    - `useUUIDAsDeviceId`設定がデフォルトで有効になりました。
        - 影響の詳細については、「[IDFVの収集 - Swift]({{site.baseurl}}/developer_guide/analytics/managing_data_collection/?sdktab=swift)」を参照してください。
    - バナーContent Cardsタイプと対応するUI要素の名前が`ImageOnly`に変更されました。すべてのメンバーメソッドおよびプロパティはそのままです。
        - `Braze.ContentCard.Banner` → `Braze.ContentCard.ImageOnly`
        - `BrazeContentCardUI.BannerCell` → `BrazeContentCardUI.ImageOnlyCell`
    - BrazeUIの一部のテキストレイアウトロジックを新しいBraze.ModalTextViewクラスにリファクタリングしました。
    - フィーチャーフラグメソッドの動作を更新しました。
        - `FeatureFlags.featureFlag(id:)`は、存在しないIDに対してnilを返すようになりました。
        - `FeatureFlags.subscribeToUpdates(:)`は、リフレッシュリクエストが成功または失敗で完了するとコールバックをトリガーします。
            - 以前にキャッシュされたデータが存在する場合、コールバックは最初の購読時にすぐにトリガーされます。
- [AppboyKit iOS SDK 4.6.0](https://github.com/Appboy/appboy-ios-sdk/releases/tag/4.6.0)
    - このリリースにはXcode `14.x`が必要です。
    - iOS 9とiOS 10のサポートを終了しました。
    - Carthage経由でインポートする際、古い`.framework`アセットのサポートを削除し、最新の`.xcframework`アセットを使用するようにしました。
        - コマンド`carthage update --use-xcframeworks`を使用して、適切なBrazeアセットをインポートしてください。
        - `appboy_ios_sdk_full.json`のサポートを削除し、代わりに`appboy_ios_sdk.json`を使用します。
