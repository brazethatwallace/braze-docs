# 2023年9月19日リリース {#september-19-2023-release}

## クラウドデータ取り込み向けBigQuery {#bigquery-for-cloud-data-ingestion}

[BigQuery](https://cloud.google.com/bigquery)（サーバーレスのエンタープライズデータウェアハウス）を使用したクラウドデータ取り込みの統合を作成できるようになりました。詳細については、[クラウドデータ取り込みの統合]({{site.baseurl}}/user_guide/data_and_analytics/cloud_ingestion/integrations/?tab=bigquery)を参照してください。

## Braze Data Transformation

[Braze Data Transformation]({{site.baseurl}}/user_guide/data/unification/data_transformation)を使用すると、Webhook統合を構築・管理して、外部プラットフォームからBrazeユーザープロファイルへのデータフローを自動化できます。この新たに統合されたユーザーデータにより、さらに高度なマーケティングユースケースを実現できます。

## キャンバスでのコメント {#commenting-in-canvas}

[キャンバスのコメント]({{site.baseurl}}/user_guide/messaging/canvas/create_a_canvas/canvas_comments)は、マーケティングチームがキャンバスの詳細を特定し、議論し、レビューするための優れたコラボレーションスペースです。キャンバスを構築する際に、同僚からの追加のフィードバックが必要な箇所を特定するためのコメントを作成・管理できます。

## 配信センター {#deliverability-center}

[配信センター]({{site.baseurl}}/user_guide/analytics/dashboards/deliverability_center)は、Gmail Postmaster Tools の利用をサポートし、送信済みメールのデータを追跡して送信ドメインに関するデータを収集することで、メールパフォーマンスに関するより深いインサイトを提供します。

メールの配信性能は、キャンペーン成功の核となる要素です。Brazeダッシュボードの配信センターを使用すると、IP レピュテーションや配信エラーごとにドメインを確認し、メール配信に関する潜在的な問題を発見してトラブルシューティングできます。

## アプリ内メッセージのドラッグ＆ドロップエディター {#drag-and-drop-editor-for-in-app-messages}

[アプリ内メッセージのドラッグ＆ドロップエディター]({{site.baseurl}}/user_guide/channels/in_app_messages/drag_and_drop)に以下の機能が追加されました。

- メッセージを閉じないテキストリンク
- プッシュプライマーをリクエストするボタンアクション
- カスタムコードエディターブロック

ドラッグ＆ドロップエディターで利用可能なすべての機能を活用するには、SDKを推奨バージョンに更新してください。

### カスタムテンプレートの保存（早期アクセス） {#save-custom-templates-early-access}

アプリ内メッセージのドラッグ＆ドロップエディターでは、早期アクセス参加者はエディターを終了した後に表示される**テンプレートとして保存**ボタンを使用して、カスタムアプリ内メッセージテンプレートを作成および保存できます。テンプレートとして保存するには、まずキャンペーンを開始するか、下書きとして保存する必要があります。

また、**テンプレート** > **アプリ内メッセージテンプレート**に移動して、アプリ内メッセージテンプレートを作成および保存することもできます。

## アプリ内メッセージのダークモードを無効にする {#disabling-dark-mode-for-in-app-messages}

開発者は、ユーザーのデバイスでダークモードがオンになっている場合に、アプリ内メッセージがダークモードのスタイリングを適用しないようにすることができます。実装手順については、プラットフォームごとの以下のドキュメントを参照してください。

- [Swift]({{site.baseurl}}/developer_guide/platform_integration_guides/swift/in-app_messaging/customization/setting_delegates#disabling-dark-mode)
- [Objective-C]({{site.baseurl}}/developer_guide/platform_integration_guides/ios/in-app_messaging/customization/handling_in_app_display#disabling-dark-mode)

## メッセージアーカイブの新しいフィールド {#new-fields-for-message-archiving}

[メッセージアーカイブ]({{site.baseurl}}/user_guide/data/distribution/export_braze_data/message_archiving)を使用すると、アーカイブまたはコンプライアンスの目的でユーザーに送信されたメッセージのコピーをS3バケットに保存できます。メッセージが送信されるたびにS3バケットに配信されるJSONペイロードに、以下のフィールドが追加されました。

- `user_id`
- `campaign_name`
- `canvas_name`
- `canvas_step_name`

## 新しいLiquidパーソナライゼーションタグ {#new-liquid-personalization-tags}

アプリ内メッセージでは、Liquid内で以下のアプリ属性を使用できます。値は、アプリがメッセージングをリクエストする際に使用するSDK APIキーに基づきます。

- {% raw %}`{{app.${api_id}}}`{% endraw %}
- {% raw %}`{{app.${name}}}`{% endraw %}

詳細については、[サポートされているパーソナライゼーションタグ]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/liquid/supported_personalization_tags#targeted-app-information)を参照してください。

## Brazeの新しいパートナーシップ {#new-braze-partnerships}

### Antavo Loyalty Cloud – チャネル拡張 {#antavo-loyalty-cloud-channel-extensions}

[Antavo]({{site.baseurl}}/partners/data_and_analytics/loyalty/antavo)とBrazeの連携により、ロイヤルティプログラム関連のデータを活用して、顧客体験を向上させるパーソナライズされたキャンペーンを構築できます。Antavoは2つのプラットフォーム間のロイヤルティデータの同期をサポートしています。これはAntavoからBrazeへの一方向のデータ同期のみです。

### Ketch – 顧客データプラットフォーム {#ketch-customer-data-platform}

Brazeと[Ketch]({{site.baseurl}}/partners/data_and_analytics/data_privacy/ketch)の連携により、Ketchユーザー設定センター内で顧客のコミュニケーション設定を管理し、これらの変更をBrazeに自動的に反映できます。

### Redpoint – 顧客データプラットフォーム {#redpoint-customer-data-platform}

Redpointは、マーケターに完全に統合されたキャンペーンオーケストレーションプラットフォームを提供するテクノロジープラットフォームです。Brazeと[Redpoint]({{site.baseurl}}/partners/data_and_analytics/customer_data_platform/redpoint)の連携により、Redpoint CDPデータに基づいてBrazeセグメントを作成できます。

### Simon Data – 顧客データプラットフォーム {#simon-data-customer-data-platform}

Brazeと[Simon Data]({{site.baseurl}}/partners/data_and_analytics/customer_data_platform/simonai)の連携を使用して、高度なオーディエンスを作成し、コーディング不要でリアルタイムにBrazeに同期してオーケストレーションを行えます。この連携により、Simonのキャンペーン優先順位付け機能やIDマッチング機能、複雑な集計サポートなどを活用して、下流のBrazeキャンペーンをさらに強化できます。

## SDKの更新 {#sdk-updates}

最新のSDK更新がリリースされました。破壊的な更新はSDK更新セクションに記載されています。その他の更新については、対応するSDKの変更ログをご確認ください。

- [Swift SDK 6.6.1](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md#661)
- [Web SDK 4.9.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md#490)
- [Android SDK 28.0.0](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#2800)
    - 最小SDKバージョンが21（Lollipop）に更新されました。
    - フィーチャーフラグの関数が変更されました。
    - `Braze.getFeatureFlag(id)` は、フィーチャーフラグが存在しない場合にnullを返すようになりました。
    - `Braze.subscribeToFeatureFlagsUpdates()` は、リフレッシュリクエストが完了した場合、および以前にキャッシュされたデータが存在する場合に初回のみコールバックします。また、リフレッシュが失敗した場合にもキャッシュされたフィーチャーフラグで呼び出されます。
        - アプリ起動時にキャッシュされた値をすぐに取得したい場合は、`Braze.getFeatureFlag(id)` を使用してください。
    - `DefaultInAppMessageViewWrapper.createButtonClickListener()` が `DefaultInAppMessageViewWrapper.createButtonClickListeners()` にリファクタリングされました。
- [React Native SDK 7.0.0](https://github.com/braze-inc/braze-react-native-sdk/blob/master/CHANGELOG.md#700)
    - ネイティブAndroidブリッジが [Braze Android SDK 26.3.2から27.0.1](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#2701) に更新されました。
- [Cordova SDK 7.0.0](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#2800)
    - ネイティブAndroidブリッジが [Braze Android SDK 26.3.2から27.0.1](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#2701) に更新されました。
- [Roku SDK 2.0.0](https://github.com/braze-inc/braze-roku-sdk/blob/main/CHANGELOG.md#200)
    - `getFeatureFlag` は、フラグが存在しない場合にinvalidを返します。
    - `BrazeTask` は `BrazeFeatureFlagsUpdated` を監視して、フィーチャーフラグのリフレッシュが成功したか失敗したかを把握するようになりました。データ値は常に異なるとは限りません。
