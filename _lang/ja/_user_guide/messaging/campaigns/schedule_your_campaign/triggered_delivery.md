# アクションベースの配信 {#action-based-delivery}

> アクションベースの配信キャンペーン（イベントトリガーキャンペーン）は、トランザクションメッセージや達成ベースのメッセージに非常に効果的です。特定の日にキャンペーンを送信する代わりに、ユーザーが特定のイベントを完了した後に送信をトリガーできます。

## トリガーキャンペーンの設定 {#setting-up-a-triggered-campaign}

### ステップ1：トリガーイベントを選択する {#step-1-select-a-trigger-event}

トリガーイベントを選択します。イベントはカテゴリーごとに整理されており、ワークスペースと有効なチャネルに応じて利用可能です。

- **eコマース**
    - **Place Order**
    - **Perform Cart Updated Event**
    - **Perform Checkout Started Event**
    - **Perform Checkout Completed Event**
    - **Make Purchase**
- **一般的なアクティビティ**
    - **Interact With キャンペーン**
    - **Interact With Step**
    - **Interact with Landing Page**
    - **Perform Conversion Event**
    - **カスタムイベントを実行**
    - **Perform Exception Event For キャンペーン**
    - **Start Session**
- **インバウンドメッセージング**
    - **Send an SMS inbound message**
    - **WhatsApp インバウンドメッセージを送信**
    - **Send a LINE inbound message**
- **位置情報**
    - **Enter a Location**
    - **Trigger a Geofence**
- **プロファイルの更新**
    - **Add an Email Address**
    - **Change Custom Attribute Value**
    - **Update Subscription Status**
    - **Update Subscription Group Status**

**eコマース**グループには、**Perform Product Viewed Event**、**Perform Order Cancelled Event**、**Perform Order Refunded Event**などの推奨eコマースイベントも一覧表示されます。これらのオプションは、イベント名が事前入力された**カスタムイベントを実行**を使用します。

アプリ内メッセージキャンペーンでは、サポートされるトリガーが限定されています。**Make Purchase**、**Place Order**、**Start Session**、**カスタムイベントを実行**、**Interact With キャンペーン**です。アプリ内メッセージキャンペーンの場合、**Interact With キャンペーン**は任意のキャンペーンまたは特定のキャンペーンからのプッシュ通知の開封のみを対象とします。以下のキャンペーンインタラクション一覧は含まれません。

アプリ内メッセージ以外のキャンペーンでは、**Interact With キャンペーン**、**Interact With Step**、または**Interact with Landing Page**を選択した場合、トリガーするインタラクションを選択します。これらのトリガーにはそれぞれ独自のインタラクションがあり、利用可能なインタラクションは有効なチャネルによって異なります。

また、Brazeの[カスタムイベントプロパティ]({{site.baseurl}}/user_guide/data/activation/events/custom_events)を通じてトリガーイベントをさらにフィルタリングすることもできます。これにより、カスタムイベントやアプリ内購入のイベントプロパティをカスタマイズできます。この機能を使用すると、カスタムイベントの特定の属性に基づいてメッセージを受信するユーザーをさらに絞り込むことができ、より高度なキャンペーンのパーソナライゼーションと洗練されたデータ収集が可能になります。

たとえば、「カート金額」のプロパティフィルターでさらに絞り込まれた放棄カートのカスタムイベントを持つキャンペーンがあるとします。このキャンペーンは、カートに100ドルから200ドル相当の商品を残したユーザーにのみ配信されます。

![カート金額が100ドルから200ドルの間のカスタムイベントプロパティでフィルタリングされた放棄カートキャンペーン。]({% image_buster /assets/img_archive/customEventProperties.png %})

{% alert note %}
トリガーイベント**Start Session**は、キャンペーンのセグメントが新規ユーザーに適用される場合（たとえば、セグメントがセッション数ゼロのユーザーで構成されている場合）、ユーザーの最初のアプリ起動時に発生することがあります。
{% endalert %}

トリガーキャンペーンは特定のセグメントのユーザーに送信できるため、セグメントに含まれていないユーザーは、トリガーイベントを完了してもキャンペーンを受信しません。

ユーザーがプロファイルにメールアドレスを追加した場合のトリガーイベントに関して、以下のルールが適用されます。

- トリガーイベントは、ユーザープロファイルの属性が更新された後に発生します。つまり、キャンペーンのセグメントやフィルターの評価は、属性の更新後に行われます。これにより、「メールアドレスがgmail.comに一致する」などのフィルターを設定して、Gmailユーザーにのみ送信するトリガーキャンペーンを作成し、ユーザーがメールアドレスを追加するとすぐに発動させることができます。
- トリガーイベントは、ユーザープロファイルにメールアドレスが追加されたときに発生します。同じメールアドレスで複数のユーザープロファイルを作成した場合、キャンペーンは各ユーザープロファイルに対して1回ずつ、複数回発動する可能性があります。

また、トリガーされたアプリ内メッセージは引き続きアプリ内メッセージの配信ルールに従い、アプリセッションの開始時に表示されます。

### ステップ2：遅延の長さを選択する {#step-2-select-delay-length}

トリガー条件が満たされた後、キャンペーンを送信するまでの待機時間を選択します。選択した遅延の長さがメッセージの送信期間より長い場合、キャンペーンを受信するユーザーはいません。

アプリ内メッセージキャンペーンでは、トリガーイベント後最大2時間（7,200秒）まで配信を遅延できます。遅延のオプションは**即時**と**遅延後**です。より長い待機時間が必要な場合は、キャンバスのアプリ内メッセージステップの前に[遅延]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/delay_step)ステップを追加してください。

{% alert important %}
Brazeは、アクションベースのキャンペーンの遅延を評価する際に、カスタムイベントと一緒に送信されたタイムスタンプを使用します。そのタイムスタンプが過去の日時に設定されている場合、Brazeは遅延がすでに経過したとみなし、メッセージを即座に、または予想より早く送信する可能性があります。配信タイミングが意図しないものにならないよう、カスタムイベントのタイムスタンプは現在の時刻で送信してください。
{% endalert %}

さらに、キャンペーンが開始された後にトリガーイベントを完了したユーザーが、遅延後に最初にメッセージを受信します。キャンペーンの開始前にトリガーイベントを完了したユーザーは、キャンペーンの受信対象にはなりません。

また、**次の曜日に**を選択してキャンペーンを特定の曜日に送信したり、**カレンダー日数後に**を選択して一定日数後に送信したりすることもできます。あるいは、配信時間を手動で選択する代わりに、[インテリジェントタイミング]({{site.baseurl}}/user_guide/brazeai/intelligence_suite/intelligent_timing)を使用してメッセージを送信することもできます。

### ステップ3：例外イベントを選択する {#step-3-select-exception-events}

このキャンペーンの受信対象からユーザーを除外する例外イベントを選択します。これは、トリガーメッセージが時間遅延後に送信される場合にのみ設定できます。[例外イベント]({{site.baseurl}}/user_guide/messaging/canvas/create_a_canvas/exit_criteria#exception-events)には、購入の実行、セッションの開始、キャンペーンに指定された[コンバージョンイベント]({{site.baseurl}}/user_guide/messaging/messaging_fundamentals/conversion_events)のいずれかの実行、またはカスタムイベントの実行があります。

ユーザーがトリガーイベントを完了した後、時間遅延によりメッセージが送信される前に例外イベントを完了した場合、そのユーザーはキャンペーンを受信しません。例外イベントによりキャンペーンを受信しなかったユーザーは、次にトリガーイベントを完了したときに自動的に受信対象となります。これは、ユーザーが[再適格]({{site.baseurl}}/user_guide/messaging/messaging_fundamentals/re_eligibility)になるよう設定していなくても同様です。

例外イベントの使用方法の詳細については、[例](#examples)を参照してください。

例外イベントと一致するトリガーイベントでキャンペーンを送信した場合、Brazeはそのキャンペーンをキャンセルし、例外イベントのメッセージ配信時間に基づいて新しいキャンペーンを自動的にリスケジュールします。たとえば、最初のトリガーイベントが5分後に開始され、例外イベントが10分後に開始される場合、例外イベントの10分がキャンペーンの公式なメッセージ配信時間として使用されます。

{% alert note %}
キャンペーンでは、「セッション開始」をトリガーイベントと例外イベントの両方にすることはできません。ただし、このオプション以外のカスタムイベントは常に選択可能です。
{% endalert %}

### ステップ4：期間を設定する {#step-4-assign-duration}

開始時間とオプションの終了時間を指定して、キャンペーンの期間を設定します。

ユーザーが指定された時間枠内にトリガーイベントを完了したものの、スケジュールされた遅延によりメッセージの対象期間外になった場合、そのユーザーはキャンペーンを受信しません。そのため、メッセージの期間より長い時間遅延を設定すると、キャンペーンを受信するユーザーはいなくなります。また、ユーザーの[ローカルタイムゾーン]({{site.baseurl}}/user_guide/messaging/campaigns/schedule_your_campaign/scheduled_delivery#local-time-zone-campaigns)でメッセージを送信するよう設定することもできます。

### ステップ5：時間帯を選択する {#step-5-select-time-frame}

ユーザーが1日の特定の時間帯にキャンペーンを受信するかどうかを選択します。メッセージに時間帯を設定し、ユーザーがその時間帯の外でトリガーイベントを完了した場合、またはメッセージの遅延によって時間帯を逃した場合、デフォルトではユーザーはメッセージを受信しません。

ユーザーが時間帯内にトリガーイベントを完了したが、メッセージの遅延によりユーザーが時間帯の外になる場合は、**配信時間が指定された時間帯外になった場合、次に利用可能な時間に送信する**チェックボックスを選択することで、これらのユーザーにもキャンペーンを配信できます。

ユーザーが時間帯を逃したためにメッセージを受信しなかった場合、ユーザーが[再適格]({{site.baseurl}}/user_guide/messaging/messaging_fundamentals/re_eligibility)になるよう設定していなくても、次にトリガーイベントを完了したときに受信対象となります。ユーザーが再適格になるよう設定している場合は、指定された時間帯内に条件を満たすたびに、トリガーイベントを完了するたびにキャンペーンを受信できます。

キャンペーンに特定の期間も設定している場合、ユーザーはメッセージを受信するためにその期間と特定の時間帯の両方の条件を満たす必要があります。

### ステップ6：再適格性を決定する {#step-6-determine-re-eligibility}

ユーザーがキャンペーンに[再適格]({{site.baseurl}}/user_guide/messaging/messaging_fundamentals/re_eligibility)になれるかどうかを決定します。ユーザーが再適格になれるようにする場合、ユーザーが再度キャンペーンを受信できるまでの時間遅延を指定できます。これにより、トリガーキャンペーンが「スパム的」になるのを防ぎます。

## 例 {#examples}

トリガーキャンペーンは、トランザクションベースまたは達成ベースのメッセージに非常に効果的です。

トランザクションキャンペーンには、ユーザーが購入を完了した後やカートにアイテムを追加した後に送信されるメッセージが含まれます。後者のケースは、例外イベントを活用するキャンペーンの優れた例です。たとえば、ユーザーがカートに入れたまま購入していないアイテムをリマインドするキャンペーンを考えてみましょう。この場合の例外イベントは、ユーザーがカート内の商品を購入することです。達成ベースのキャンペーンでは、ユーザーがコンバージョンを完了したりゲームのレベルをクリアした5分後にメッセージを送信できます。

さらに、ウェルカムキャンペーンを作成する際には、ユーザーが登録またはアカウントを設定した後にメッセージをトリガーして送信できます。登録後の異なる日にメッセージを段階的に送信することで、包括的なオンボーディングプロセスを構築できます。

## よくある質問 {#frequently-asked-questions}

### アプリ内メッセージキャンペーンのトリガー後の最大遅延時間はどれくらいですか？ {#what-is-the-maximum-delay-after-a-trigger-for-in-app-message-campaigns}

2時間（7,200秒）です。利用可能な遅延オプションと長めの待機時間の設定方法については、[ステップ2: 遅延時間を選択する](#step-2-select-delay-length)を参照してください。

### トリガーキャンペーンをユーザーが受信しなかったのはなぜですか？ {#why-did-a-user-not-receive-my-triggered-campaign}

トリガーイベントを完了したユーザーがキャンペーンを受信できない原因として、以下のいずれかが考えられます。

- 時間遅延が完全に経過する前に、ユーザーが例外イベントを完了した。
- Liquidの[`abort_message`ロジック]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/liquid/aborting_messages)が使用され、`abort_message`ロジックまたはルールに基づいてメッセージが中止された。
- 時間遅延により、キャンペーンの期間が終了した後にユーザーがキャンペーンの受信資格を得た。
- 時間遅延により、指定された時間帯の外でユーザーがキャンペーンの受信資格を得た。
- ユーザーがすでにキャンペーンを受信している（共有チャネル識別子によるアトリビューションを含む。たとえば、キャンペーンを受信、開封、またはクリックした別のユーザーとメールアドレスを共有している場合）。かつ、ユーザーが再適格にならない設定になっている。
- ユーザーはキャンペーンの再受信資格がありますが、一定期間が経過した後にのみ再トリガーでき、その期間がまだ経過していない。

トリガーキャンペーンを、イベント発生時に記録されたユーザーデータに基づいて[セグメント化]({{site.baseurl}}/user_guide/audience/segments)すると、[競合]({{site.baseurl}}/help/best_practices/race_conditions#race-conditions)が発生する可能性があります。これは、キャンペーンのセグメントに使用されているユーザー属性が変更されたものの、キャンペーン送信時にその変更がまだユーザーに対して処理されていない場合に発生します。キャンペーンはエントリ時にセグメントメンバーシップを確認するため、ユーザーがキャンペーンを受信しない可能性があります。

たとえば、登録したばかりの男性ユーザーにイベントトリガーキャンペーンを送信したいとします。ユーザーが登録すると、カスタムイベント`registration`を記録し、同時にユーザーの`gender`属性を設定します。Brazeがユーザーの性別を処理する前にイベントがキャンペーンをトリガーし、ユーザーがキャンペーンを受信できなくなる可能性があります。

ベストプラクティスとして、キャンペーンのセグメントに使用される属性がイベントの前にBrazeサーバーにフラッシュされていることを確認してください。これが不可能な場合、配信を確実にする最善の方法は、[カスタムイベントプロパティ]({{site.baseurl}}/user_guide/data/activation/events/custom_events/custom_event_properties)を使用して、関連するユーザープロパティをイベントに添付し、セグメンテーションフィルターの代わりに特定のイベントプロパティのプロパティフィルターを適用することです。この例では、カスタムイベント`registration`に`gender`プロパティを追加することで、キャンペーンがトリガーされた時点でBrazeが必要なデータを確実に保持しているようにします。

さらに、キャンペーンがアクションベースで遅延がある場合は、**送信時にセグメントメンバーシップを再評価する**オプションをオンにすることで、メッセージ送信時にユーザーがまだターゲットオーディエンスに含まれていることを確認できます。

#### オーディエンス基準の評価 {#audience-criteria-evaluation}

送信前に遅延を伴うキャンペーン（レート制限、ローカルタイムゾーン、インテリジェントタイミング、またはトリガースケジュールを含む）では、セグメントが再評価されるタイミングはキャンペーンの種類と設定によって異なります。

遅延のあるアクションベースキャンペーンで**送信時にセグメントメンバーシップを再評価する**を選択した場合、メッセージ送信前にユーザーが再評価されるため、送信時にセグメント基準を満たしているユーザーのみがメッセージを受信します。

キャンペーンが特定のカスタムイベントによってトリガーされ、オーディエンスとしてセグメントを選択している場合、ユーザーはそのセグメントに含まれるために同じカスタムイベントを実行する必要があります。つまり、アクションベースキャンペーンがトリガーされる前に、ユーザーがオーディエンスの一部である必要があります。トリガーキャンペーンの一般的なワークフローは以下の通りです。

1. **オーディエンスに参加する:** ユーザーがカスタムイベントを実行すると、キャンペーンのターゲットオーディエンスに追加されます。
2. **メールをトリガーする:** メールが送信される前にユーザーがオーディエンスの一部である必要があるため、ユーザーはメールをトリガーするためにカスタムイベントを再度実行する必要があります。

ターゲットオーディエンスをすべてのユーザーに変更するか、イベントを実行すると予想されるユーザーがメッセージをトリガーするためにすでにキャンペーンのオーディエンスに含まれていることを確認することをお勧めします。

#### カスタムイベントのトラブルシューティング {#troubleshooting-custom-events}

まず、カスタムイベントがBrazeに渡されていることを確認します。**Analytics** > **カスタムイベントレポート**に移動し、該当するカスタムイベントと日付範囲を選択します。イベントが表示されない場合は、イベントが正しく設定されていること、およびユーザーが正しいアクションを実行したことを確認してください。

カスタムイベントが表示される場合は、以下の手順でさらにトラブルシューティングを行います。

- ユーザーのプロファイルダウンロードを確認し、イベントをトリガーしたかどうか、およびいつトリガーしたかを確認します。イベントがトリガーされている場合は、イベントがトリガーされたタイムスタンプとキャンペーンが公開された時刻を比較します。キャンペーンが公開される前にイベントがトリガーされている可能性があります。
- キャンペーンとターゲティングに使用されたセグメントの変更ログを確認し、カスタムイベントがトリガーされた時点でユーザーがセグメントに含まれていたかどうかを判断します。セグメントに含まれていなかった場合、ユーザーはキャンペーンを受信していません。
- セグメンテーションによってユーザーがコントロールグループに登録され、結果としてキャンペーンの受信が阻止されたかどうかを確認します。
- スケジュールされた遅延がある場合、ユーザーのカスタムイベントが遅延前にトリガーされたかどうかを確認します。遅延前にイベントがトリガーされた場合、ユーザーはキャンペーンを受信していません。

{% alert note %}
アプリ内メッセージは、SDKを通じて送信されたイベントによってのみトリガーでき、REST APIではトリガーできません。
{% endalert %}

### アクションベースキャンペーンはいつオーディエンスメンバーシップを評価しますか？ {#when-do-action-based-campaigns-evaluate-audience-membership}

Brazeは、トリガーイベントを処理する際に、メッセージ送信前にオーディエンスメンバーシップを評価します。デフォルトでは、Brazeはエンキュー時にユーザーがターゲットオーディエンスに一致するかどうかを確認します。キャンペーンに遅延がある場合は、**送信時にセグメントメンバーシップを再評価する**を選択して、送信直前にオーディエンス基準を再確認できます。たとえば、ユーザーがトリガーアクションを実行した後、送信が完了する前にオーディエンスから外れる可能性がある場合に便利です。

詳細については、[オーディエンス基準の評価](#audience-criteria-evaluation)を参照してください。
