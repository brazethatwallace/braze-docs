# アクションベースの配信 {#action-based-delivery}

> アクションベースの配信キャンペーン（イベントトリガーキャンペーン）は、トランザクションメッセージや達成ベースのメッセージに非常に効果的です。特定の日にキャンペーンを送信する代わりに、ユーザーが特定のイベントを完了した後に送信をトリガーできます。

## トリガーキャンペーンの設定 {#setting-up-a-triggered-campaign}

### ステップ1：トリガーイベントを選択する {#step-1-select-a-trigger-event}

トリガーイベントを選択します。以下のいずれかを指定できます。
- 注文の完了
- セッションの開始
- カスタムイベントの実行
- キャンペーンの1次コンバージョンイベントの実行
- ユーザープロファイルへのメールアドレスの追加
- カスタム属性値の変更
- 購読ステータスの更新
- 購読グループステータスの更新
- 他のキャンペーンとのインタラクション
    - アプリ内メッセージを表示
    - アプリ内メッセージをクリック
    - アプリ内メッセージボタンをクリック
    - メールをクリック
    - メール内のエイリアスをクリック
    - 任意のキャンペーンまたはキャンバスステップでエイリアスをクリック
    - メールを開封
    - メールを開封（機械による開封）
    - メールを開封（その他の開封）
    - プッシュ通知を直接開封
    - プッシュ通知ボタンをクリック
    - Push Storiesページをクリック
    - コンバージョンイベントを実行
    - メールを受信
    - SMSを受信
    - 短縮SMSリンクをクリック
    - プッシュ通知を受信
    - Webhookを受信
    - コントロールグループに登録
    - コンテンツカードを表示
    - コンテンツカードをクリック
    - コンテンツカードを閉じる
- ロケーションへの入場
- 別のキャンペーンの例外イベントの実行
- キャンバスステップとのインタラクション
- ジオフェンスのトリガー
- SMSインバウンドメッセージの送信
- WhatsAppインバウンドメッセージの送信

また、Brazeの[カスタムイベントプロパティ]({{site.baseurl}}/user_guide/data/activation/events/custom_events)を使用して、トリガーイベントをさらにフィルタリングできます。これにより、カスタムイベントやアプリ内購入のイベントプロパティをカスタマイズできます。この機能を使えば、カスタムイベントの特定の属性に基づいてメッセージを受け取るユーザーをさらに絞り込むことができ、キャンペーンのパーソナライゼーションの向上や、より精緻なデータ収集が可能になります。

たとえば、「カート価格」プロパティフィルターでさらに絞り込まれた放棄カートのカスタムイベントを持つキャンペーンがあるとします。このキャンペーンは、カートに100ドルから200ドル相当の商品を残したユーザーにのみ配信されます。

![カート価格が100ドルから200ドルの間のカスタムイベントプロパティでフィルタリングされた放棄カートキャンペーン。]({% image_buster /assets/img_archive/customEventProperties.png %})

{% alert note %}
キャンペーンのセグメントが新規ユーザーに適用される場合、トリガーイベント「セッション開始」はユーザーの最初のアプリ起動になる場合があります（たとえば、セッション数がゼロのユーザーで構成されるセグメントの場合）。
{% endalert %}

トリガーキャンペーンは特定のセグメントのユーザーに送信できるため、セグメントに含まれないユーザーは、トリガーイベントを完了してもキャンペーンを受信しません。

ユーザーがプロファイルにメールアドレスを追加した際のトリガーイベントについては、以下のルールが適用されます。

- トリガーイベントは、ユーザープロファイル属性が更新された後に発火します。つまり、キャンペーンのセグメントとフィルターの評価は、属性の更新後に行われます。これにより、「メールアドレスがgmail.comと一致する」などのフィルターを設定して、Gmailユーザーにのみ送信し、メールアドレスが追加された時点で発火するトリガーキャンペーンを作成できます。
- トリガーイベントは、ユーザープロファイルにメールアドレスが追加されたときに発火します。同じメールアドレスで複数のユーザープロファイルを作成している場合、キャンペーンはユーザープロファイルごとに1回ずつ、複数回発火する可能性があります。

また、トリガーされたアプリ内メッセージは、引き続きアプリ内メッセージの配信ルールに従い、アプリセッションの開始時に表示されます。

![トリガーイベント設定オプションが表示されたアクションベースのキャンペーン配信スケジュール。]({% image_buster /assets/img_archive/schedule_triggered1.png %})

### ステップ2：遅延時間を選択する {#step-2-select-delay-length}

トリガー条件が満たされた後、キャンペーンの送信までの待機時間を選択します。選択した遅延時間がメッセージの送信期間よりも長い場合、キャンペーンを受信するユーザーはいません。

アプリ内メッセージキャンペーンは、トリガーイベント後、最大2時間（7,200秒）まで配信を遅延できます。遅延オプションは**即時**と**遅延後**です。より長い待機時間が必要な場合は、キャンバスのアプリ内メッセージステップの前に[遅延]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/delay_step)ステップを追加してください。

{% alert important %}
Brazeは、アクションベースのキャンペーンの遅延を評価する際に、カスタムイベントとともに送信されたタイムスタンプを使用します。そのタイムスタンプが過去の日時にバックデートされている場合、Brazeは遅延が既に経過したとみなし、メッセージを即座にまたは予想よりも早く送信する可能性があります。意図しない配信タイミングを避けるため、カスタムイベントのタイムスタンプは現在時刻で送信してください。
{% endalert %}

また、キャンペーンの公開後にトリガーイベントを完了したユーザーが、遅延経過後に最初にメッセージを受信します。キャンペーンの公開前にトリガーイベントを完了したユーザーは、キャンペーンの受信対象にはなりません。

![ステップ2：遅延時間の選択に関するスクリーンショット。]({% image_buster /assets/img_archive/schedule_triggered22.png %})

また、特定の曜日にキャンペーンを送信する（「次の」を選択して曜日を指定する）か、特定の日数後に送信する（「後」を選択する）ことも可能です。あるいは、配信時間を手動で選択する代わりに、[インテリジェントタイミング]({{site.baseurl}}/user_guide/brazeai/intelligence_suite/intelligent_timing)機能を使用してメッセージを送信することもできます。

![特定の曜日にキャンペーンを送信する（「次の」を選択して曜日を指定する）か、特定の日数後に送信する（「後」を選択する）ことも可能です。あるいは、配信時間を手動で選択する代わりに、インテリジェントタイミング機能を使用してメッセージを送信することもできます。]({% image_buster /assets/img_archive/schedule_triggered7.png %})
![特定の曜日にキャンペーンを送信する（「次の」を選択して曜日を指定する）か、特定の日数後に送信する（「後」を選択する）ことも可能です。あるいは、配信時間を手動で選択する代わりに、インテリジェントタイミング機能を使用してメッセージを送信することもできます。]({% image_buster /assets/img_archive/schedule_triggered8.png %})

### ステップ3：例外イベントを選択する {#step-3-select-exception-events}

このキャンペーンの受信対象からユーザーを除外する例外イベントを選択します。これは、トリガーメッセージが時間遅延後に送信される場合にのみ設定できます。[例外イベント]({{site.baseurl}}/user_guide/messaging/canvas/create_a_canvas/exit_criteria#exception-events)には、購入の実行、セッションの開始、キャンペーンに指定された[コンバージョンイベント]({{site.baseurl}}/user_guide/messaging/messaging_fundamentals/conversion_events)のいずれかの実行、またはカスタムイベントの実行を設定できます。ユーザーがトリガーイベントを完了しても、時間遅延によりメッセージが送信される前に例外イベントを完了した場合、そのユーザーはキャンペーンを受信しません。例外イベントによりキャンペーンを受信しなかったユーザーは、次回トリガーイベントを完了した際に自動的にキャンペーンの受信対象となります。これは、ユーザーの[再適格性]({{site.baseurl}}/user_guide/messaging/messaging_fundamentals/re_eligibility)を有効にしていない場合でも同様です。

![このキャンペーンの受信対象からユーザーを除外する例外イベントを選択します。これは、トリガーメッセージが時間遅延後に送信される場合にのみ設定できます。例外イベントには、購入の実行、セッションの開始、キャンペーンに指定されたコンバージョンイベントのいずれかの実行、またはカスタムイベントの実行を設定できます。ユーザーがトリガーイベントを完了しても、時間遅延によりメッセージが送信される前に例外イベントを完了した場合、そのユーザーはキャンペーンを受信しません。例外イベントによりキャンペーンを受信しなかったユーザーは、次回トリガーイベントを完了した際に自動的にキャンペーンの受信対象となります。これは、ユーザーの再適格性を有効にしていない場合でも同様です。]({% image_buster /assets/img_archive/schedule_triggered32.png %})

例外イベントの活用方法の詳細については、[ユースケース]({{site.baseurl}}/user_guide/messaging/campaigns/schedule_your_campaign/triggered_delivery#use-cases)のセクションをご覧ください。

> 例外イベントと一致するトリガーイベントでキャンペーンを送信した場合、Brazeはそのキャンペーンをキャンセルし、例外イベントのメッセージ配信時間に基づいて新しいキャンペーンを自動的に再スケジュールします。たとえば、最初のトリガーイベントが5分後に開始し、例外イベントが10分後に開始する場合、例外イベントの10分がキャンペーンの公式メッセージ配信時間として適用されます。

{% alert note %}
「セッション開始」を同一キャンペーンのトリガーイベントと例外イベントの両方に設定することはできません。ただし、このオプション以外の任意のカスタムイベントをいつでも選択できます。
{% endalert %}

### ステップ4：期間を設定する {#step-4-assign-duration}

開始時間とオプションの終了時間を指定して、キャンペーンの期間を設定します。

![ステップ4：期間の設定に関するスクリーンショット。]({% image_buster /assets/img_archive/schedule_triggered43.png %})

ユーザーが指定された時間枠内にトリガーイベントを完了しても、スケジュールされた遅延により時間枠外でメッセージの対象となった場合、そのユーザーはキャンペーンを受信しません。そのため、メッセージの時間枠よりも長い遅延時間を設定すると、キャンペーンを受信するユーザーはいなくなります。また、ユーザーの[ローカルタイムゾーン]({{site.baseurl}}/user_guide/messaging/campaigns/schedule_your_campaign/scheduled_delivery#local-time-zone-campaigns)でメッセージを送信することも可能です。

### ステップ5：時間帯を選択する {#step-5-select-time-frame}

ユーザーが1日のうちの特定の時間帯にキャンペーンを受信するかどうかを選択します。メッセージに時間帯を設定し、ユーザーがその時間帯外にトリガーイベントを完了した場合、またはメッセージの遅延により時間帯を逃した場合、デフォルトではそのユーザーはメッセージを受信しません。

![ユーザーが1日のうちの特定の時間帯にキャンペーンを受信するかどうかを選択します。メッセージに時間帯を設定し、ユーザーがその時間帯外にトリガーイベントを完了した場合、またはメッセージの遅延により時間帯を逃した場合、デフォルトではそのユーザーはメッセージを受信しません。]({% image_buster /assets/img_archive/schedule_triggered5.png %})

ユーザーが時間帯内にトリガーイベントを完了したものの、メッセージの遅延によりユーザーが時間帯外になった場合、以下のチェックボックスをオンにすることで、これらのユーザーにもキャンペーンを配信できます。

![ステップ5：時間帯の選択に関するスクリーンショット。]({% image_buster /assets/img_archive/schedule_triggered_next_available.png %})

時間帯を逃してメッセージを受信できなかったユーザーも、次回トリガーイベントを完了した際にメッセージの受信対象となります。これは、ユーザーの[再適格性]({{site.baseurl}}/user_guide/messaging/messaging_fundamentals/re_eligibility)を有効にしていない場合でも同様です。ユーザーの再適格性を有効にしている場合、ユーザーはトリガーイベントを完了するたびに、指定された時間帯内に条件を満たす限りキャンペーンを受信できます。

キャンペーンに特定の期間も設定している場合、ユーザーがメッセージを受信するには、期間と特定の時間帯の両方の条件を満たす必要があります。

### ステップ6：再適格性を設定する {#step-6-determine-re-eligibility}

ユーザーがキャンペーンの[再適格性]({% image_buster /assets/img_archive/ReEligible.png %})を得られるかどうかを設定します。ユーザーの再適格性を有効にする場合、ユーザーがキャンペーンを再度受信できるまでの遅延時間を指定できます。これにより、トリガーキャンペーンがスパムのようになるのを防ぐことができます。

![ステップ6：再適格性の設定に関するスクリーンショット。]({% image_buster /assets/img_archive/schedule_triggered6.png %})

## ユースケース {#use-cases}

トリガーキャンペーンは、トランザクションベースや達成ベースのメッセージに非常に効果的です。

トランザクションキャンペーンには、ユーザーが購入を完了した後やカートにアイテムを追加した後に送信されるメッセージが含まれます。後者のケースは、例外イベントを活用するキャンペーンの良い例です。たとえば、ユーザーがカートに入れたまま購入していないアイテムをリマインドするキャンペーンがあるとします。この場合の例外イベントは、ユーザーがカート内の商品を購入することです。達成ベースのキャンペーンでは、ユーザーがコンバージョンを完了したりゲームのレベルをクリアした5分後にメッセージを送信できます。

さらに、ウェルカムキャンペーンを作成する際には、ユーザーが登録したりアカウントを設定した後にメッセージをトリガーして送信できます。登録後の異なる日にメッセージを段階的に送信することで、包括的なオンボーディングプロセスを構築できます。

## よくある質問 {#frequently-asked-questions}

### アプリ内メッセージキャンペーンのトリガー後の最大遅延はどのくらいですか？ {#what-is-the-maximum-delay-after-a-trigger-for-in-app-message-campaigns}

アプリ内メッセージキャンペーンは、トリガーイベント後の配信を最大2時間（7,200秒）遅延させることができます。遅延オプションは**即時**と**遅延後**です。より長い待機時間が必要な場合は、キャンバスのアプリ内メッセージステップの前に[遅延]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/delay_step)ステップを追加してください。

### トリガーされたキャンペーンをユーザーが受信しなかったのはなぜですか？ {#why-did-a-user-not-receive-my-triggered-campaign}

トリガーイベントを完了したユーザーがキャンペーンを受信しない原因として、以下のいずれかが考えられます。

- 時間遅延が完全に経過する前に、ユーザーが例外イベントを完了した。
- Liquidの[`abort_message`ロジック]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/liquid/aborting_messages)が使用されており、`abort_message`ロジックまたはルールに基づいてメッセージが中止された。
- 時間遅延により、キャンペーンの期間終了後にユーザーがキャンペーンの受信資格を得た。
- 時間遅延により、指定された時間帯の外でユーザーがキャンペーンの受信資格を得た。
- ユーザーがすでにキャンペーンを受信している（共有チャネル識別子によるアトリビューションを含む。例えば、キャンペーンを受信、開封、またはクリックした他のユーザーとメールアドレスを共有している場合）。そしてユーザーが再受信資格を得ていない。
- ユーザーはキャンペーンの再受信資格を持っているが、一定期間が経過した後にのみ再トリガーでき、その期間がまだ経過していない。

トリガーされたキャンペーンを、イベント発生時に記録されたユーザーデータで[セグメンテーション]({{site.baseurl}}/user_guide/audience/segments)すると、[競合]({{site.baseurl}}/help/best_practices/race_conditions#race-conditions)が発生する可能性があります。これは、キャンペーンのセグメンテーションに使用されるユーザー属性が変更されたものの、キャンペーン送信時にその変更がまだユーザーに対して処理されていない場合に発生します。キャンペーンはエントリ時にセグメントメンバーシップを確認するため、ユーザーがキャンペーンを受信しない場合があります。

例えば、登録したばかりの男性ユーザーにイベントトリガーのキャンペーンを送信したい場合を考えます。ユーザーが登録すると、カスタムイベント`registration`を記録し、同時にユーザーの`gender`属性を設定します。Brazeがユーザーの性別を処理する前にイベントがキャンペーンをトリガーし、ユーザーがキャンペーンを受信できない可能性があります。

ベストプラクティスとして、キャンペーンのセグメンテーションに使用される属性がイベントの前にBrazeサーバーにフラッシュされていることを確認してください。それが不可能な場合、配信を保証する最善の方法は、[カスタムイベントプロパティ]({{site.baseurl}}/user_guide/data/activation/events/custom_events/custom_event_properties)を使用して関連するユーザープロパティをイベントに添付し、セグメンテーションフィルターの代わりに特定のイベントプロパティのプロパティフィルターを適用することです。この例では、カスタムイベント`registration`に`gender`プロパティを追加することで、キャンペーンがトリガーされた時にBrazeが必要なデータを確実に保持しているようにします。

さらに、キャンペーンがアクションベースで遅延がある場合は、**送信時にセグメントメンバーシップを再評価する**オプションをチェックして、メッセージ送信時にユーザーがまだターゲットオーディエンスに含まれていることを確認できます。

#### オーディエンス基準の評価 {#audience-criteria-evaluation}

送信前に遅延を伴うキャンペーン（レート制限、ローカルタイムゾーン、インテリジェントタイミング、またはトリガースケジュールを含む）では、セグメントが再評価されるタイミングはキャンペーンの種類と設定によって異なります。

アクションベースのキャンペーンで遅延がある場合、**送信時にセグメントメンバーシップを再評価する**を選択すると、メッセージ送信前にユーザーが再評価されるため、送信時にセグメント基準を満たしているユーザーのみがメッセージを受信します。

キャンペーンが特定のカスタムイベントによってトリガーされ、オーディエンスとしてセグメントを選択した場合、ユーザーはセグメントに含まれるために同じカスタムイベントを実行する必要があります。つまり、アクションベースのキャンペーンがトリガーされるには、ユーザーが事前にオーディエンスの一員である必要があります。トリガーキャンペーンの一般的なワークフローは以下のとおりです。

1. **オーディエンスに参加する：** ユーザーがカスタムイベントを実行すると、キャンペーンのターゲットオーディエンスに追加されます。
2. **メールをトリガーする：** メールを送信するにはユーザーがオーディエンスの一員である必要があるため、ユーザーはメールをトリガーするためにカスタムイベントを再度実行する必要があります。

ターゲットオーディエンスをすべてのユーザーに変更するか、イベントを実行すると予想されるユーザーがメッセージのトリガーのためにキャンペーンのオーディエンスにすでに含まれていることを確認することをお勧めします。

#### カスタムイベントのトラブルシューティング {#troubleshooting-custom-events}

まず、カスタムイベントがBrazeに送信されていることを確認します。**分析** > **カスタムイベントレポート**に移動し、該当するカスタムイベントと日付範囲を選択します。イベントが表示されない場合は、正しくセットアップされていること、およびユーザーが正しいアクションを実行したことを確認してください。

カスタムイベントが表示される場合は、以下の手順でさらにトラブルシューティングを行います。

- ユーザーのプロファイルダウンロードを確認して、イベントがトリガーされたかどうか、またいつトリガーされたかを確認します。イベントがトリガーされた場合は、イベントがトリガーされたタイムスタンプとキャンペーンが公開された時刻を比較します。キャンペーンが公開される前にイベントがトリガーされた可能性があります。
- キャンペーンとターゲティングに使用されるセグメントの変更履歴を確認し、カスタムイベントがトリガーされた時点でユーザーがセグメントに含まれていたかどうかを判断します。セグメントに含まれていなかった場合、キャンペーンを受信しません。
- セグメンテーションによってユーザーがコントロールグループに入れられ、キャンペーンの受信が阻止されたかどうかを確認します。
- スケジュールされた遅延がある場合、ユーザーのカスタムイベントが遅延前にトリガーされたかどうかを確認します。遅延前にイベントがトリガーされた場合、キャンペーンを受信しません。

{% alert note %}
アプリ内メッセージは、SDKを通じて送信されたイベントによってのみトリガーでき、REST APIではトリガーできません。
{% endalert %}

### アクションベースのキャンペーンはいつオーディエンスメンバーシップを評価しますか？ {#when-do-action-based-campaigns-evaluate-audience-membership}

Brazeは、トリガーイベントを処理する際に、メッセージが送信される前にオーディエンスメンバーシップを評価します。デフォルトでは、Brazeはエンキュー時にユーザーがターゲットオーディエンスに一致するかどうかを確認します。キャンペーンに遅延がある場合、**送信時にセグメントメンバーシップを再評価する**を選択して、送信直前にオーディエンス基準を再確認できます。例えば、ユーザーがトリガーアクションを実行した後、送信完了前にオーディエンスから外れる可能性がある場合に有効です。

詳細については、[オーディエンス基準の評価](#audience-criteria-evaluation)を参照してください。
