# アクションベースの配信 {#action-based-delivery}

> アクションベースの配信キャンペーン（イベントトリガーキャンペーン）は、トランザクションメッセージや達成ベースのメッセージに非常に効果的です。特定の日にキャンペーンを送信する代わりに、ユーザーが特定のイベントを完了した後に送信をトリガーできます。

## トリガーキャンペーンの設定 {#setting-up-a-triggered-campaign}

### ステップ 1:トリガーイベントを選択する {#step-1-select-a-trigger-event}

トリガーイベントを選択します。以下のいずれかを含めることができます。
- 購入する
- セッションを開始する
- カスタムイベントを実行する
- キャンペーンの1次コンバージョンイベントを実行する
- ユーザープロファイルにメールアドレスを追加する
- カスタム属性値を変更する
- サブスクリプションステータスを更新する
- サブスクリプショングループのステータスを更新する
- 他のキャンペーンとインタラクションする
    - アプリ内メッセージを表示する
    - アプリ内メッセージをクリックする
    - アプリ内メッセージのボタンをクリックする
    - メールをクリックする
    - メール内のエイリアスをクリックする
    - 任意のキャンペーンまたはキャンバスステップでエイリアスをクリックする
    - メールを開封する
    - メールを開封する（マシンオープン）
    - メールを開封する（その他のオープン）
    - プッシュ通知を直接開く
    - プッシュ通知ボタンをクリックする
    - Push Storiesページをクリックする
    - コンバージョンイベントを実行する
    - メールを受信する
    - SMSを受信する
    - 短縮SMSリンクをクリックする
    - プッシュ通知を受信する
    - Webhookを受信する
    - コントロールグループに登録される
    - コンテンツカードを表示する
    - コンテンツカードをクリックする
    - コンテンツカードを閉じる
- ロケーションに入る
- 別のキャンペーンの例外イベントを実行する
- キャンバスステップとインタラクションする
- ジオフェンスをトリガーする
- SMSインバウンドメッセージを送信する
- WhatsAppインバウンドメッセージを送信する

Brazeの[カスタムイベントプロパティ]({{site.baseurl}}/user_guide/data/activation/events/custom_events)を使用して、トリガーイベントをさらにフィルタリングすることもできます。これにより、カスタムイベントやアプリ内購入のイベントプロパティをカスタマイズできます。この機能を使用すると、カスタムイベントの特定の属性に基づいてメッセージを受信するユーザーをさらに絞り込むことができ、キャンペーンのパーソナライゼーションの向上とより高度なデータ収集が可能になります。

例えば、放棄カートのカスタムイベントを持つキャンペーンがあり、「カート金額」プロパティフィルターでさらにターゲティングされているとします。このキャンペーンは、カートに100ドルから200ドル相当の商品を残したユーザーにのみ配信されます。

![カート金額が100ドルから200ドルの間のカスタムイベントプロパティでフィルタリングされた放棄カートキャンペーン。]({% image_buster /assets/img_archive/customEventProperties.png %})

{% alert note %}
トリガーイベント「セッション開始」は、キャンペーンのセグメントが新規ユーザーに適用される場合、ユーザーの最初のアプリ起動になることがあります（例えば、セグメントがセッション数ゼロのユーザーで構成されている場合）。
{% endalert %}

トリガーキャンペーンは特定のセグメントのユーザーに送信できるため、セグメントに含まれていないユーザーは、トリガーイベントを完了してもキャンペーンを受信しないことに注意してください。

ユーザーがプロファイルにメールアドレスを追加した場合のトリガーイベントについては、以下のルールが適用されます。

- トリガーイベントは、ユーザープロファイル属性が更新された後に発火します。つまり、キャンペーンのセグメントとフィルターの評価は、属性の更新後に行われます。これは、「メールアドレスが gmail.com に一致する」などのフィルターを設定して、Gmailユーザーにのみ送信し、メールアドレスを追加した直後に発火するトリガーキャンペーンを作成できるため、有益です。
- トリガーイベントは、ユーザープロファイルにメールアドレスが追加されたときに発火します。同じメールアドレスで複数のユーザープロファイルを作成した場合、キャンペーンはユーザープロファイルごとに1回ずつ、複数回発火する可能性があります。

さらに、トリガーされたアプリ内メッセージは、アプリ内メッセージの配信ルールに従い、アプリセッションの開始時に表示されます。

![トリガーイベントの設定オプションが表示されたアクションベースのキャンペーン配信スケジュール。]({% image_buster /assets/img_archive/schedule_triggered1.png %})

### ステップ 2:遅延時間を選択する {#step-2-select-delay-length}

トリガー条件が満たされた後、キャンペーンを送信するまでの待機時間を選択します。選択した遅延時間がメッセージの送信期間よりも長い場合、キャンペーンを受信するユーザーはいません。

{% alert important %}
Brazeは、カスタムイベントとともに送信されたタイムスタンプを使用して、アクションベースのキャンペーンの遅延を評価します。そのタイムスタンプが過去の日時に設定されている場合、Brazeは遅延がすでに経過したものとして扱い、メッセージを即座にまたは予想より早く送信する可能性があります。意図しない配信タイミングを避けるため、カスタムイベントのタイムスタンプには現在時刻を送信してください。
{% endalert %}

さらに、キャンペーンの開始後にトリガーイベントを完了したユーザーが、遅延が経過した後に最初にメッセージを受信します。キャンペーンの開始前にトリガーイベントを完了したユーザーは、キャンペーンの受信対象になりません。

![ステップ2：遅延時間の選択に関するスクリーンショット。]({% image_buster /assets/img_archive/schedule_triggered22.png %})

特定の曜日（「次の」を選択してから曜日を選択）または将来の特定の日数後（「後」を選択）にキャンペーンを送信することもできます。あるいは、配信時間を手動で選択する代わりに、[インテリジェントタイミング]({{site.baseurl}}/user_guide/brazeai/intelligence_suite/intelligent_timing)機能を使用してメッセージを送信することもできます。

![特定の曜日（「次の」を選択してから曜日を選択）または将来の特定の日数後（「後」を選択）にキャンペーンを送信することもできます。あるいは、配信時間を手動で選択する代わりに、インテリジェントタイミング機能を使用してメッセージを送信することもできます。]({% image_buster /assets/img_archive/schedule_triggered7.png %})
![特定の曜日（「次の」を選択してから曜日を選択）または将来の特定の日数後（「後」を選択）にキャンペーンを送信することもできます。あるいは、配信時間を手動で選択する代わりに、インテリジェントタイミング機能を使用してメッセージを送信することもできます。]({% image_buster /assets/img_archive/schedule_triggered8.png %})

### ステップ 3:例外イベントを選択する {#step-3-select-exception-events}

このキャンペーンの受信対象からユーザーを除外する例外イベントを選択します。これは、トリガーメッセージが時間遅延後に送信される場合にのみ設定できます。[例外イベント]({{site.baseurl}}/user_guide/messaging/canvas/create_a_canvas/exit_criteria#exception-events)には、購入する、セッションを開始する、キャンペーンの指定された[コンバージョンイベント]({{site.baseurl}}/user_guide/messaging/messaging_fundamentals/conversion_events)のいずれかを実行する、またはカスタムイベントを実行するなどがあります。ユーザーがトリガーイベントを完了した後、時間遅延によりメッセージが送信される前に例外イベントを完了した場合、そのユーザーはキャンペーンを受信しません。例外イベントによりキャンペーンを受信しなかったユーザーは、次回トリガーイベントを完了したときに自動的に受信対象となります。これは、ユーザーの[再適格性]({{site.baseurl}}/user_guide/messaging/messaging_fundamentals/re_eligibility)を有効にしていない場合でも同様です。

![このキャンペーンの受信対象からユーザーを除外する例外イベントを選択します。これは、トリガーメッセージが時間遅延後に送信される場合にのみ設定できます。例外イベントには、購入する、セッションを開始する、キャンペーンの指定されたコンバージョンイベントのいずれかを実行する、またはカスタムイベントを実行するなどがあります。ユーザーがトリガーイベントを完了した後、時間遅延によりメッセージが送信される前に例外イベントを完了した場合、そのユーザーはキャンペーンを受信しません。例外イベントによりキャンペーンを受信しなかったユーザーは、次回トリガーイベントを完了したときに自動的に受信対象となります。これは、ユーザーの再適格性を有効にしていない場合でも同様です。]({% image_buster /assets/img_archive/schedule_triggered32.png %})

例外イベントの活用方法については、[ユースケース]({{site.baseurl}}/user_guide/messaging/campaigns/schedule_your_campaign/triggered_delivery#use-cases)のセクションで詳しく説明しています。

> 例外イベントと一致するトリガーイベントでキャンペーンを送信した場合、Brazeはキャンペーンをキャンセルし、例外イベントのメッセージ配信時間に基づいて新しいキャンペーンを自動的に再スケジュールします。例えば、最初のトリガーイベントが5分後に開始し、例外イベントが10分後に開始する場合、例外イベントの10分がキャンペーンの公式メッセージ配信時間として使用されます。

{% alert note %}
キャンペーンのトリガーイベントと例外イベントの両方に「セッション開始」を設定することはできません。ただし、このオプション以外の他のカスタムイベントはいつでも選択できます。
{% endalert %}

### ステップ 4:期間を割り当てる {#step-4-assign-duration}

開始時間とオプションの終了時間を指定して、キャンペーンの期間を割り当てます。

![ステップ4：期間の割り当てに関するスクリーンショット。]({% image_buster /assets/img_archive/schedule_triggered43.png %})

ユーザーが指定された期間内にトリガーイベントを完了したが、スケジュールされた遅延により期間外にメッセージの受信対象となった場合、そのユーザーはキャンペーンを受信しません。したがって、メッセージの期間よりも長い時間遅延を設定した場合、キャンペーンを受信するユーザーはいません。さらに、ユーザーの[ローカルタイムゾーン]({{site.baseurl}}/user_guide/messaging/campaigns/schedule_your_campaign/scheduled_delivery#local-time-zone-campaigns)でメッセージを送信することもできます。

### ステップ 5:時間枠を選択する {#step-5-select-time-frame}

ユーザーが1日の特定の時間帯にキャンペーンを受信するかどうかを選択します。メッセージに時間枠を設定し、ユーザーが時間枠外にトリガーイベントを完了した場合、またはメッセージの遅延により時間枠を逃した場合、デフォルトではユーザーはメッセージを受信しません。

![ユーザーが1日の特定の時間帯にキャンペーンを受信するかどうかを選択します。メッセージに時間枠を設定し、ユーザーが時間枠外にトリガーイベントを完了した場合、またはメッセージの遅延により時間枠を逃した場合、デフォルトではユーザーはメッセージを受信しません。]({% image_buster /assets/img_archive/schedule_triggered5.png %})

ユーザーが時間枠内にトリガーイベントを完了したが、メッセージの遅延によりユーザーが時間枠外になった場合、以下のチェックボックスをオンにすると、これらのユーザーにもキャンペーンが配信されます。

![ステップ5：時間枠の選択に関するスクリーンショット。]({% image_buster /assets/img_archive/schedule_triggered_next_available.png %})

ユーザーが時間枠を逃したためにメッセージを受信しなかった場合でも、次回トリガーイベントを完了したときに受信対象となります。これは、ユーザーの[再適格性]({{site.baseurl}}/user_guide/messaging/messaging_fundamentals/re_eligibility)を有効にしていない場合でも同様です。ユーザーの再適格性を有効にした場合、ユーザーは指定された時間枠内に条件を満たす限り、トリガーイベントを完了するたびにキャンペーンを受信できます。

キャンペーンに特定の期間も割り当てている場合、ユーザーはメッセージを受信するために期間と1日の特定の時間帯の両方の条件を満たす必要があります。

### ステップ 6:再適格性を決定する {#step-6-determine-re-eligibility}

ユーザーがキャンペーンの[再適格性]({% image_buster /assets/img_archive/ReEligible.png %})を得られるかどうかを決定します。ユーザーの再適格性を許可する場合、ユーザーが再度キャンペーンを受信できるまでの時間遅延を指定できます。これにより、トリガーキャンペーンが「スパム的」になるのを防ぎます。

![ステップ6：再適格性の決定に関するスクリーンショット。]({% image_buster /assets/img_archive/schedule_triggered6.png %})

## ユースケース {#use-cases}

トリガーキャンペーンは、トランザクションメッセージや達成ベースのメッセージに非常に効果的です。

トランザクションキャンペーンには、ユーザーが購入を完了した後やカートにアイテムを追加した後に送信されるメッセージが含まれます。後者は、例外イベントの恩恵を受けるキャンペーンの好例です。例えば、キャンペーンがカート内の未購入アイテムをユーザーにリマインドするとします。この場合の例外イベントは、ユーザーがカート内の商品を購入することです。達成ベースのキャンペーンでは、ユーザーがコンバージョンを完了した後やゲームレベルをクリアした後に5分後にメッセージを送信できます。

さらに、ウェルカムキャンペーンを作成する際には、ユーザーが登録またはアカウントを設定した後にメッセージの送信をトリガーできます。登録後の異なる日にメッセージを段階的に送信することで、包括的なオンボーディングプロセスを作成できます。

## トリガーキャンペーンをユーザーが受信しなかったのはなぜですか？ {#why-did-a-user-not-receive-my-triggered-campaign}

トリガーイベントを完了したユーザーがキャンペーンを受信しない原因として、以下のいずれかが考えられます。

- 時間遅延が完全に経過する前に、ユーザーが例外イベントを完了した。
- Liquidの[`abort_message`ロジック]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/liquid/aborting_messages)が使用されており、`abort_message`のロジックまたはルールに基づいてメッセージが中止された。
- 時間遅延により、期間の終了後にユーザーがキャンペーンの受信対象となった。
- 時間遅延により、指定された時間帯の外でユーザーがキャンペーンの受信対象となった。
- ユーザーがすでにキャンペーンを受信しており（共有チャネル識別子によるアトリビューションを含む。例えば、メールを受信、開封、またはクリックした人とメールアドレスを共有している場合）、ユーザーの再適格性が有効になっていない。
- ユーザーはキャンペーンの再適格性があるが、一定期間後にのみ再トリガーでき、その期間がまだ経過していない。

トリガーキャンペーンをイベント発生時に記録されたユーザーデータで[セグメンテーション]({{site.baseurl}}/user_guide/audience/segments)すると、[競合]({{site.baseurl}}/help/best_practices/race_conditions#race-conditions)が発生する可能性があります。これは、キャンペーンのセグメンテーションに使用されるユーザー属性が変更されたが、キャンペーンの送信時にその変更がユーザーに対して処理されていない場合に発生します。キャンペーンはエントリ時にセグメントメンバーシップをチェックするため、ユーザーがキャンペーンを受信しない可能性があります。

例えば、登録したばかりの男性ユーザーにイベントトリガーキャンペーンを送信したいとします。ユーザーが登録すると、カスタムイベント `registration` を記録し、同時にユーザーの `gender` 属性を設定します。Brazeがユーザーの性別を処理する前にイベントがキャンペーンをトリガーし、ユーザーがキャンペーンを受信できない可能性があります。

ベストプラクティスとして、キャンペーンのセグメンテーションに使用される属性が、イベントの前にBrazeサーバーにフラッシュされていることを確認してください。これが不可能な場合、配信を保証する最善の方法は、[カスタムイベントプロパティ]({{site.baseurl}}/user_guide/data/activation/events/custom_events/custom_event_properties#custom-event-properties)を使用して関連するユーザープロパティをイベントに添付し、セグメンテーションフィルターの代わりに特定のイベントプロパティのプロパティフィルターを適用することです。この例では、カスタムイベント `registration` に `gender` プロパティを追加することで、キャンペーンがトリガーされたときに必要なデータがBrazeに確実に存在するようにします。

さらに、キャンペーンがアクションベースで遅延がある場合、**送信時にセグメントメンバーシップを再評価する**オプションをオンにすることで、メッセージの送信時にユーザーがまだターゲットオーディエンスに含まれていることを確認できます。

### オーディエンス条件の評価 {#audience-criteria-evaluation}

送信前に遅延を伴うキャンペーン（レート制限、ローカルタイムゾーン、インテリジェントタイミング、またはトリガースケジュールを含む）では、セグメントの再評価はキャンペーンの種類と設定によって異なります。

アクションベースのキャンペーンで遅延がある場合、**送信時にセグメントメンバーシップを再評価する**を選択すると、メッセージの送信前にユーザーが再評価されるため、送信時にセグメント条件を満たしているユーザーのみがメッセージを受信します。

キャンペーンが特定のカスタムイベントによってトリガーされ、オーディエンスとしてセグメントを選択した場合、ユーザーはセグメントに含まれるために同じカスタムイベントを実行する必要があります。つまり、アクションベースのキャンペーンがトリガーされる前に、ユーザーがオーディエンスの一部である必要があります。トリガーキャンペーンの一般的なワークフローは以下のとおりです。

1. **オーディエンスに参加する:** ユーザーがカスタムイベントを実行すると、キャンペーンのターゲットオーディエンスに追加されます。
2. **メールをトリガーする:** メールを送信するには、ユーザーがオーディエンスの一部である必要があるため、ユーザーはカスタムイベントを再度実行してメールをトリガーする必要があります。

ターゲットオーディエンスをすべてのユーザーに変更するか、イベントを実行すると予想されるユーザーがすでにキャンペーンのオーディエンスに含まれていることを確認して、メッセージがトリガーされるようにすることをお勧めします。

![オーディエンス条件の評価に関するスクリーンショット。]({% image_buster /assets/img_archive/reevaluate_segment_membership.png %})

### カスタムイベントのトラブルシューティング {#troubleshooting-custom-events}

まず、カスタムイベントがBrazeに渡されていることを確認します。**Analytics** > **カスタムイベントレポート**に移動し、該当するカスタムイベントと日付範囲を選択します。イベントが表示されない場合は、正しく設定されていること、およびユーザーが正しいアクションを実行したことを確認してください。

カスタムイベントが表示される場合は、以下の手順でさらにトラブルシューティングを行います。

- ユーザーのプロファイルダウンロードを確認して、イベントがトリガーされたこととそのタイミングを確認します。イベントがトリガーされた場合は、イベントがトリガーされたタイムスタンプとキャンペーンが開始された時間を比較します。キャンペーンの開始前にイベントがトリガーされた可能性があります。
- キャンペーンとターゲティングに使用されたセグメントの変更ログを確認して、カスタムイベントがトリガーされた時点でユーザーがセグメントに含まれていたかどうかを判断します。セグメントに含まれていなかった場合、キャンペーンを受信していません。
- ユーザーがセグメンテーションによりコントロールグループに入れられ、キャンペーンの受信が妨げられていないかを確認します。
- スケジュールされた遅延がある場合、ユーザーのカスタムイベントが遅延前にトリガーされたかどうかを確認します。遅延前にイベントがトリガーされた場合、キャンペーンを受信していません。

{% alert note %}
アプリ内メッセージは、SDKを通じて送信されたイベントによってのみトリガーでき、REST APIではトリガーできません。
{% endalert %}
