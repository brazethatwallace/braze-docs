# Canvasでユーザーパスをプレビューする {#preview-user-paths-in-canvas}

> ユーザーのために作成したCanvasジャーニーを実際に体験することができます。これには、ユーザーが受け取るタイミングとメッセージのプレビューが含まれます。これらのテスト実行は、Canvasを送信する前に、メッセージが適切なオーディエンスに送信されているかどうかの品質保証として機能します。

## テスト実行の作成 {#creating-a-test-run}

ユーザージャーニーをプレビューするには、以下のステップに従ってください。

1. Canvasビルダーに移動します。未保存の変更を保存し、エラーがある場合はすべて解決します。
2. フッターで**Test Canvas**を選択します。
3. テストユーザーを選択します。
4. (オプション) テストの受信者を選択します。
5. **Run Test**を選択します。

Canvasを編集する権限がなくてもプレビューを実行できますが、未保存の変更がある場合、そのプレビューは未保存の変更を含んだ状態で実行されます。

### サポートされているステップ {#supported-steps}

以下のステップがサポートされています。
- メッセージ
- オーディエンスパス
- 条件分岐
- 遅延
- アクションパス
- 実験パス
- ユーザーの更新（UIエディターでのみ有効。つまりJSONエディターを使用するステップはスキップされます）

テストがリストにないステップタイプと重なる場合、サポートされていないステップはスキップされ、テストユーザーは次のサポートされているステップに進みます。

### キャンバスステップの詳細 {#canvas-step-details}

エントリ条件の詳細を表示するには、**See more**を選択します。セグメンテーションを含むステップでは、満たされた条件と満たされていない条件が表示されます。メッセージでは、配信バリデーションとチャネル適格性についても表示されます。メッセージステップでは、送信されたチャネルと送信されなかったチャネルが表示されます。

### Liquid

Brazeは、実際のテストメッセージを送信していない場合でも、テスト実行中にLiquidロジックを処理します。つまり、[メッセージの中止ロジック]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/liquid/aborting_messages#abort-messages)やその他のLiquidロジックが反映され、Canvasのユーザージャーニーに影響を与える可能性があります。

プレビューが中止ではなくユーザージャーニーの最後のステップを送信する場合、プレビューはCanvasのエントリ時間に基づくユーザーが実際にステップにいる時間ではなく、Liquid評価のテスト対象時間として現在の時間を使用している可能性があります。

## タイミングのプレビュー {#previews-for-timing}

スケジュールされたCanvasの場合、テストユーザーは次のスケジュールされたエントリ時間にエントリします。開始日があるアクションベースのCanvasの場合、テストユーザーは開始日時にエントリします。

デフォルトの開始時間は引き続き適用されますが、エントリ時間はすべてのケースで設定可能です。つまり、過去または未来の日付をシミュレートできます。ただし、Canvasの開始日より前や終了日より後のテストはできません。

メッセージステップと遅延ステップでは、遅延を再設定することなく、ユーザーが進行するタイミングやメッセージを受信するタイミングが表示されます。ステップにインテリジェントタイミングが使用されているかどうかは表示されますが、このユーザーパスのプレビューではテストユーザーの推定値は計算されません。

「カスタム属性値の変更」のようなアクショントリガーを持つCanvasの場合、Brazeはトリガー内のユーザーの属性を一時的に空白に設定することで変更をシミュレートしようとします。これは**Canvasのテスト実行のみ**に適用されます（ユーザープロファイルには影響しません）。これは、属性が現在の値から変更されることをテストするためのものです。

## ユーザーのエントリとエグジット {#when-users-enter-and-exit}

テストユーザーは、実際には適格でない場合でもプレビューにエントリします。適格でない場合は、条件を満たしていない理由を確認できます。テストユーザーがプレビューにエントリすると、テストユーザーはターゲットオーディエンスの条件を満たし、アクショントリガーの条件を実行したものと見なされます。たとえば、エントリ条件にカスタムイベントを使用するCanvasの場合、テストユーザーはエントリ条件で期待されるカスタムイベントを実行したものと見なされます。ただし、同じカスタムイベントがCanvasの他の場所（エグジット条件など）で使用されている場合、ユーザーパスへの影響を考慮してください。

テストユーザーがCanvasにエントリするために想定されるイベント、APIトリガー、カスタム属性、およびCanvasエントリプロパティは、実際のユーザープロファイルでは更新されず、テスト実行を超えて保持されません。たとえば、テスト中にカスタム属性がCanvasトリガーとして使用される場合、トリガー条件はカスタム属性の変更をトリガーした**かのように**ユーザーのプレビューに適用されます。

### 考慮事項 {#consideration}

エグジット条件に対応するアクション（イベントプロパティを含む）を持つアクションパスをテストすると、エグジット条件がトリガーされ、テスト実行が終了します。エグジット条件に対応するメッセージステップをテストすると、エグジット条件がトリガーされ、テスト実行が終了します。

現時点では、アクションパス内の特定のイベントやプロパティを選択してエグジット条件をトリガーすることはできません（パス全体のみ）。ユーザーが複数のエグジット条件を満たす可能性がある場合、最初に処理され、ユーザーが満たした条件が結果として表示されます。

## 実験パスとCanvasバリアント {#experiment-paths-and-canvas-variants}

- トップレベルのバリアントを持つCanvasの場合、テストの開始時にバリアントを選択します。
- 実験パスの場合、テストユーザーがステップに到達したときにユーザーが進むバリアントを選択します。
- パーソナライズドパスまたは勝者バリアントを使用する実験パスの場合、テストユーザーがメッセージステップで待機する遅延期間がありますが、Brazeはユーザーが選択したバリアントを即座に進んだものと見なすため、この遅延は考慮されません。

## テスト送信 {#test-sends}

テスト実行の結果が表示される際に、内部テストグループまたは個別のユーザーにテストメッセージを送信することを選択できます。つまり、テストパスに沿ってユーザーが遭遇するメッセージのみが送信されます。受信者はデフォルトで自身の属性を含むメッセージを受け取りますが、テストユーザーの属性で上書きすることもできます。

パスをプレビューせずに、Canvas内のすべてのテストメッセージをパスに関係なく一度に送信するには、**Test Sends**タブで**Send All Test Messages**を選択します。

## レスポンシブ性 {#responsiveness}

キャンバスステップは、ユーザーパスのプレビュー時にタイミングに対してレスポンシブです。ユーザーの更新ステップで行われた更新は、フロー内の後続のステップに反映されますが、実際のユーザープロファイルには適用されません。ユーザーがバリアントにエントリした効果は、プレビュー内の後続のステップに反映されます。

同様に、フィルターはテストユーザーがCanvas内の他のステップとインタラクションした結果として発生したアクションを認識します。たとえば、このプレビューモードでは、ユーザーがCanvasの前のステップで「送信」されたメッセージステップに遭遇したことを認識し、テストユーザーがアクションパスを進むために「アクションを実行した」ことを認識します。

レスポンシブな動作の詳細については、[エグジット条件]({{site.baseurl}}/user_guide/messaging/canvas/create_a_canvas/exit_criteria)を参照してください。

## コネクテッドコンテンツ {#connected-content}

コネクテッドコンテンツがCanvasに含まれている場合、実行されます。つまり、コネクテッドコンテンツの呼び出しやコネクテッドコンテンツを含むContent Blocksを持つCanvasをテストすると、Canvasがコネクテッドコンテンツの呼び出しを送信し、他のCampaignsやCanvasesで参照されているデータが変更される可能性があります。

ユーザーパスをプレビューする際は、ユーザープロファイルや他のCanvasesやCampaignsで参照されているデータを変更するコネクテッドコンテンツを削除することを検討してください。

## Webhook {#webhooks}

Webhookはテストメッセージの送信時に実行されますが、テスト実行中には実行されません。コネクテッドコンテンツと同様に、ユーザープロファイルや他のCanvasesやCampaignsで参照されているデータを変更するwebhookの削除を検討してください。

## コンテキスト変数とシードグループ {#context-variables-and-seed-groups}

メッセージングチャネルとしてメールを使用するメッセージステップの場合、シードグループはユーザーがCanvasのこのステップに到達したときにメールのシードコピーを送信します。これらのシードコピーはシードグループ受信者自身のCanvasジャーニーの一部として送信されるわけではないため、Brazeはそれらの受信者に対して[コンテキストステップ]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/context)を実行したり、コンテキスト変数を評価したりしません。メールコンテンツがコンテキスト変数を参照している場合、シードグループの受信者はそのデータが入力されていないシードコピーを受け取ります。コンテキスト変数データに依存するメッセージをテストするには、シードグループの代わりに**Test Canvas**プレビューのテスト送信を使用してください。

## ユースケース {#use-case}

このシナリオでは、Canvasはアプリでセッションがないユーザーをターゲットにするように設定されています。このジャーニーには、ウェルカムメールを含むメッセージステップ、1日に設定された遅延ステップ、および2つのパスに分岐するオーディエンスパスステップが含まれます。1つは少なくとも1回のセッションがあるユーザー、もう1つはその他のユーザーです。ユーザーがどのオーディエンスパスに該当するかに応じて、後続のメッセージステップが送信されます。
