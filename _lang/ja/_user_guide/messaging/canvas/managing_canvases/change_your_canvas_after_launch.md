# 起動後のキャンバスの編集 {#edit-canvases-after-launch}

> このリファレンス記事では、初回起動後にキャンバスで変更できる内容について説明します。

起動後のキャンバスは、以下の方法で編集できます。

* ユーザージャーニーへの新しいキャンバスステップの挿入
* 新しいバリアントと接続の追加
* バリアント配分の調整
* すべてのキャンバスステップの停止または再開

{% alert note %}
コントロールバリアントの配分は、起動後に減少させることのみ可能です。
{% endalert %}

ユーザージャーニーでは、以下の項目を削除できます。

- [キャンバスステップ]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/about)
- キャンバスバリアント
- キャンバスステップ間の接続

キャンバスのユーザージャーニーでステップを編集または追加する場合、以下の詳細が適用されます。

- まだキャンバスに入っていないユーザーは、新しく作成されたすべてのステップの対象となります。
- キャンバスのエントリ設定でユーザーがステップに再入場できる場合、新しく作成されたステップをすでに通過したユーザーも再入場の対象となります。
- 起動済みのキャンバスに現在いるユーザーで、新しいステップが追加されたユーザージャーニーのポイントにまだ到達していないユーザーは、新しく追加されたステップを受け取る対象となります。

[遅延]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/delay_step)ステップまたは[アクションパス]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/action_paths)ステップを削除する場合、そのステップで現在待機中のユーザーを別のキャンバスステップにリダイレクトすることもできます。遅延の場合、ユーザーは遅延期間の終了までステップに留まります。アクションパスの場合、ユーザーは評価時間枠の終了までステップに留まります。

キャンバスを最初に起動すると、Brazeはユーザーが現在いるメッセージステップのキューにユーザーを追加しますが、キャンバス内の後続のすべてのメッセージのキューには追加しません。起動後にキャンバスを編集した場合、一部のユーザーはすでにキューに追加されており、変更が反映されない場合があります。キャンバスを停止し、複製してから変更を加え、新しいバージョンを起動すると、キャンバスはすでにキューに追加されたユーザーだけでなく、すべてのユーザーを再評価します。

具体的な編集のユースケースについては、[ベストプラクティス](#best-practices)セクションを参照してください。一般的に、予期しない動作が発生する可能性があるため、ライブキャンバスの編集は避けることがベストプラクティスです。

{% details オリジナルキャンバスエディターの詳細を展開 %}

キャンバスがどのワークフローで作成されたかに応じて、起動後に許可されるキャンバスの編集内容を以下に示します。キャンバスがオリジナルのキャンバスワークフローを使用している場合、起動後の編集を行うには、まずキャンバスフローに複製する必要があります。

既存の接続を編集または削除することはできず、既存の接続されたステップの間にステップを挿入することもできません。キャンバスのユーザージャーニーでステップを編集または追加する場合、以下の詳細が適用されます。

- まだキャンバスに入っていないユーザーは、新しく作成されたすべてのステップの対象となります。
- キャンバスのエントリ設定でユーザーがステップに再入場できる場合、新しく作成されたステップをすでに通過したユーザーも再入場の対象となります。
- 起動済みのキャンバスに現在いるユーザーで、ユーザージャーニーの新しく追加されたステップにまだ到達していないユーザーは、新しく追加されたステップを受け取る対象となります。
- 遅延ステップがキャンバスの最後のステップである場合、そのステップに到達したユーザーは自動的にキャンバスから退出し、新しく作成されたステップを受け取りません。

{% alert important %}
キャンバスステップの**遅延**または**時間枠**設定を更新した場合、更新時にそのステップにいるユーザーは、最初にステップに入った時に割り当てられた遅延時間に従います。キャンバスに新しく入るユーザーと、そのステップのキューにまだ追加されていないユーザーのみが、更新された時間にメッセージを受け取ります。
{% endalert %}

キャンバスを停止しても、メッセージの受信を待っているユーザーは退出しません。キャンバスを再度有効にし、ユーザーがまだメッセージを待っている場合、ユーザーはメッセージを受け取ります（メッセージが送信されるべき時間が過ぎている場合は受け取りません）。

{% enddetails %}

## キャンバスの詳細 {#canvas-details}

キャンバスの開始後、以下の設定と詳細を編集できます。

- キャンバスの名前と説明
- チーム
- タグ
  - 開始後にタグを追加すると、`Received Message from キャンペーン or キャンバス with Tag` などのフィルターを使用して、セグメント内のユーザーをリターゲティングできます。
- エントリタイプ、スケジュール、コントロール
- 購読ステータス
- レート制限
- フリークエンシーキャップ
- クワイエットアワー
- ターゲットオーディエンス

キャンバスの開始後：

- コンバージョンイベントは編集できません。
- 以下のステップは追加・削除できず、ランキング調整のための並べ替えもできません：[オーディエンスパス]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/audience_paths)、[アクションパス]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/action_paths)、[実験パス]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/experiment_step)。
  - **回避策 1:** 新しいオーディエンスパス、アクションパス、または実験パスを作成し、その新しいステップにパスを再構成します。
  - **回避策 2:** キャンバスを複製して編集を行います。

### 個別のステップ {#individual-steps}

個別のキャンバスステップについては、開始後に以下の詳細を編集できます。

* 名前
* メッセージ内容
* トリガー
* オーディエンス
* 例外イベント
* 遅延（遅延ステップのみ）

ただし、ステップのスケジュールタイプとコントロールの割合は、開始後に編集できません。アクションパスとオーディエンスパスのステップでは、ランキングと評価ウィンドウは開始後に編集できません。

#### 宛先への送信ステップ {#send-to-destination-step}

ライブキャンバスで[宛先への送信]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/send_to_destination)ステップを編集する場合、以下の動作が適用されます。

- **宛先キャンバスの変更:** 宛先への送信ステップを別の宛先キャンバスに変更する場合、開始後の編集に関する一般的なルールと同じルールが適用されます。変更は、宛先への送信ステップにまだ到達していないユーザーにのみ影響します。
  - すでにステップを通過したユーザーは元の宛先キャンバスに残り、再ルーティングされません。
  - 前のステップで待機中のユーザー（例：宛先への送信ステップの前の遅延ステップで待機中）は、ステップに到達した時点で新しい宛先キャンバスのエントリとオーディエンス基準に基づいて評価されます。対象となるユーザーは新しい宛先キャンバスに送信されます。
- **停止された宛先キャンバス:** ソースキャンバスがまだアクティブな状態で宛先キャンバスが停止された場合、宛先への送信ステップに到達したユーザーは宛先キャンバスに送信されません。これにより、ハンドオフにおけるユーザーの離脱が発生します（宛先が停止している間の一時停止ではありません）。
  - 停止された宛先にエントリできないユーザーは、宛先への送信ステップの後にさらにステップがある場合、ソースキャンバスで続行します。進行動作の詳細については、[宛先への送信]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/send_to_destination#how-does-advancement-behavior-work-for-send-to-destination-steps)を参照してください。
  - 停止された宛先を指す宛先への送信ステップを含むソースキャンバスを開始することはできません。この動作は、ソースキャンバスがすでにライブになった後に宛先キャンバスが停止された場合に適用されます。

### キャンバスのバリアントの割合 {#canvas-variant-percentages}

キャンバスの開始後、コントロールバリアントの割合のみ減らすことができます。キャンバスでバリアントの割合が変更された場合、ユーザーが他のバリアントに再配分される可能性があります。

最初に、ユーザーはキャンペーンを初めて受信する前に、特定のバリアントにランダムに割り当てられます。それ以降、キャンペーンを受信するたび（またはユーザーがキャンバスのバリアントに再エントリするたび）、バリアントの割合が変更されない限り、同じバリアントを受信します。

バリアントの割合が変更されると、ユーザーは他のバリアントに再配分される可能性があります。ユーザーは割合が再び変更されるまでそのバリアントにとどまります。なお、ランダムバケット番号を使用した `NOT` フィルターによる分岐を使用するキャンバスの場合、ユーザーがキャンバスに再エントリした際に、ユーザージャーニー内で毎回同じブランチを受信するとは限りません。

#### コントロールグループ {#control-groups}

バリアントの割合が変更されていない場合、コントロールグループは一貫性を維持します。コントロールグループの割合が減少または増加された場合、以前にメッセージを受信したユーザーは、その後の送信でコントロールグループにエントリできなくなります。また、コントロールグループに属するユーザーがメッセージを受信することはありません。

### ローカル送信時間 {#local-send-time}

ローカル送信時間で開始するようにスケジュールされたキャンバスは、スケジュールされた送信時間の24時間前まで編集できます。このウィンドウは「セーフゾーン」と呼ばれます。

{% alert tip %}
新しいキャンバスのコピーを作成するような大規模な編集を行う場合は、最初のキャンバスを受信したユーザーを除外し、タイムゾーン送信を考慮してキャンバスのスケジュール時間を再調整してください。
{% endalert %}

エントリスケジュールが開始時に即座にユーザーをエントリするよう設定されている場合、キャンバスは5分刻みの最も近い時間に開始されます。例えば、ユーザーを午前8時31分（PST）に即座にエントリするようキャンバスを更新した場合、開始時間は午前8時30分（PST）に設定され、会社のタイムゾーンで適用されます。

### バリアントの削除 {#deleting-variants}

キャンバスからバリアントが削除されると、以下のことが発生します。

- バリアント内のステップ（他のバリアントと共有されているステップを含む）が削除されます。
- ステップの分析データと、_合計エントリ数_、_合計離脱数_、_コンバージョン率_などのキャンバスのトップレベルの分析データが削除されます。
- 削除されたバリアントのユーザーはステップから離脱し、後続のメッセージは送信されません。

### キャンバスエントリプロパティ {#canvas-entry-properties}

キャンバスエントリプロパティは、送信時にステップにテンプレート化されません。つまり、キャンバスの開始後にキャンバスエントリプロパティが編集された場合、これらの変更は新しくキャンバスにエントリするユーザーにのみ適用されます。キャンバスがユーザーの再エントリを許可している場合、再エントリするユーザーは更新されたキャンバスエントリプロパティに基づいて判定されます。

## ベストプラクティス {#best-practices}

キャンバスの公開後に編集や追加を行う際に念頭に置くべきベストプラクティスをご確認ください。

{% alert important %}
一般的に、キャンバスがアクティブでユーザーをエンキューしている間は変更を避けてください。
{% endalert %}

### 切断されたステップ {#disconnected-steps}

切断されたステップを含むキャンバスを公開したり、公開後にそのようなキャンバスを保存したりできます。ワークフローからステップを切断する前に、保留中のユーザーがいないかステップの分析ビューを確認することをお勧めします。

たとえば、ユーザーがキャンバスワークフローの切断されたステップにいるとします。このユーザーは、後続のステップがある場合、そのステップに進みます。ステップの設定によって、ユーザーがどのように進むかが決まります。

切断されたステップを作成または編集することで、キャンバスの残りの部分に直接接続しなくても、これらの独立系ステップに変更を加えることができます。これにより、キャンバスを再度公開する前にステップをテストするのに役立ちます。

### 実験パスステップ {#experiment-path-step}

キャンバスにアクティブまたは進行中の勝者パス実験があり、アクティブなキャンバスを更新すると、実験が終了します。これは、実験パスステップを更新しなかった場合でも適用されます。実験を再開するには、既存の実験パスを切断して新しいものを公開するか、キャンバスを複製して複製を公開してください。そうしないと、ユーザーは最適化なしで実験パスを通過します。

パーソナライズされたパスを使用する既存の実験パスステップは引き続き実行されます。アクティブなキャンバスを更新すると、進行中のパーソナライズされたパス実験も終了します。

### 時間遅延 {#time-delays}

時間遅延のあるキャンバスの編集は少しややこしい場合がありますので、キャンバスを編集する際には以下の詳細を念頭に置いてください。

- 遅延ステップの遅延を更新した場合、キャンバスに新しく入ったユーザーと、そのステップのキューにまだ入っていないユーザーのみが、更新された時間遅延でメッセージを受け取ります。
- 時間遅延のあるステップ（遅延やアクションパスなど）を削除し、それらのユーザーを別のキャンバスステップにリダイレクトする場合、ユーザーはステップの時間遅延が完了した後にのみリダイレクトされます。たとえば、1日の遅延がある遅延ステップを削除し、ユーザーをメッセージステップにリダイレクトするとします。この場合、ユーザーは1日の遅延が完了した後にのみリダイレクトされます。
- キャンバスに1つ以上の実験パスステップがある場合、ステップを削除すると、このステップの結果が無効になる可能性があります。

### キャンバスの停止 {#stopping-canvases}

キャンバスを停止しても、ステップで待機中のユーザーは退出しません。キャンバスを再有効化し、ユーザーがまだ待機中の場合、ユーザーはそのステップを完了して次のステップに進みます。ただし、ユーザーが次のステップに進むべき時間がすでに過ぎている場合、ユーザーはキャンバスから退出します。

たとえば、キャンバスフローワークフローを使用して午後2時に公開するように設定されたキャンバスがあり、1つのバリアントに2つのステップがあるとします。1時間の遅延がある遅延ステップと、その後のメッセージステップです。

ユーザーが午後2時1分にこのキャンバスに入り、同時に遅延ステップに入ります。これは、ユーザーがユーザージャーニーの次のステップ（メッセージステップ）に午後3時1分に進むようにスケジュールされていることを意味します。午後2時30分にキャンバスを停止し、午後3時30分にキャンバスを再有効化した場合、午後3時1分を過ぎているため、ユーザーはキャンバスから退出します。ただし、午後2時40分にキャンバスを再有効化した場合、ユーザーは予定通り午後3時1分にメッセージステップに進みます。

## 知っておくべきこと {#things-to-know}

以下の一般的な問題は、キャンバスの開始後に他のコンポーネントを編集または追加することで発生する可能性があります。

{% alert important %}
以下の問題は回避可能です。開始後のキャンバスを編集する必要がある場合は、まずすでにキャンバスに入ったすべてのユーザーがユーザージャーニーを完了していることを確認することをお勧めします。また、少なくとも1人のユーザーによってすでに処理されたステップは削除しないことをお勧めします。
{% endalert %}

- レポートデータの欠落（メッセージバリアントが削除されて再追加された場合）
- ユーザーが期待されるパスをたどらない
- メッセージが予期しないタイミングで送信される
- 編集によってCurrentsデータは上書きされないため、キャンバスステップ間で不一致が生じる場合があります（削除によりキャンバスに存在しなくなった `canvas_step_ids` など）
- ユーザーが同じメッセージを2回受信する可能性がある
- 既存のレート制限によりユーザーがメッセージを受信しない
  - アクティブなキャンバスのレート制限を更新した場合、新しいレート制限はレート制限の変更後にメッセージステップを通過するユーザーにのみ適用されます。すでにメッセージステップのキューに入っているユーザーには、キューに入った時点で有効だった元のレート制限が保持されます。新しいレート制限をすべてのユーザーに適用するには、キャンバスを停止し、更新されたレート制限で複製してから、新しいキャンバスを開始してください。元のキャンバスからメッセージを受信したユーザーが複製に入らないようにフィルターを使用してください。
- キャンバスが[自動的に停止]({{site.baseurl}}/user_guide/messaging/governance/statuses#available-statuses)された場合、キャンバスの開始後の下書きも削除されます。
