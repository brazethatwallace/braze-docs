# 終了条件 {#exit-criteria}

> キャンバスのエントリルールに例外イベントを直接追加することで、ユーザーが特定のアクションを実行した際にジャーニーから退出させることができます。
> Brazeはイベントが発生するとすぐに退出を記録します。
> ユーザーがキャンバスから完全に退出するまでの速さは、特に遅延ステップの場合、ユーザーが現在いるステップによって異なります。
> 詳細については、[ユーザーの退出方法](#how-users-exit)を参照してください。

### ユーザーの退出方法 {#how-users-exit}

ユーザーが退出イベントを実行すると、Brazeはただちにそのユーザーをキャンバスから退出するようマークします。その後、ユーザーは後続のステップに進むことはありません。

ユーザーが遅延ステップにいる場合、遅延期間が終了するまでそのステップに留まります。遅延が終了しても後続のステップには進まず、代わりにキャンバスから完全に退出します。キャンバスデータを確認する場所によっては、退出イベントが発生した時点と、遅延ステップが完了してユーザーがキャンバスから完全に退出した時点の両方で、退出関連のアクティビティが表示されることがあります。

例えば、ユーザーが30日間の遅延ステップにいて、遅延ステップの初日に退出イベントを実行した場合、すぐに退出がマークされますが、遅延ステップが終了するまで（29日後まで）キャンバスから完全には退出しません。

時間ベースの終了条件を使用する別の例を考えてみましょう。ユーザーが7月1日の午前0時に24時間に設定された遅延ステップに入ります。この遅延期間中に、午前3時に「最後の購入が1時間未満前」という退出イベントを実行します。このユーザーは、遅延ステップの期間が終了する7月2日の午前0時に終了条件が評価されます。7月1日の午前3時の購入から21時間が経過しているため、7月2日の遅延ステップ終了時の1時間以内に購入を行っていないことになり、キャンバスから退出しません。これはキャンバス分析の「終了条件による合計退出数」に影響し、ユーザーがキャンバスから完全に退出した後にのみ更新されます。

## 終了条件の設定 {#setting-up-exit-criteria}

キャンバスビルダーの**ターゲットオーディエンス**ステップで、キャンバスから退出させたいユーザーを特定するための終了条件を設定できます。

終了条件には例外イベントが含まれます。これは、ユーザーをキャンバスから退出させる特定のアクションです。

### 例外イベントの選択 {#exception-events}

ユーザーが例外イベントを実行すると、Brazeは[ユーザーの退出方法](#how-users-exit)に従ってユーザーを退出するようマークします。例外イベントは、遅延ステップなどのステップで待機中の場合を含め、ユーザーがキャンバス内にいる間適用されます。

新製品をプロモーションするためのキャンバスが設定されているとしましょう。この場合、その製品の購入が例外イベントになります。これにより、ユーザーが購入を行った後、すでに購入した製品に関するメッセージを受け取ることがなくなります。例外イベントにより、メッセージングの関連性とパーソナライズが維持されます。

その他の例外イベントには以下が含まれます：

- 購入を行う
- セッションを開始する
- カスタムイベントを実行する
- コンバージョンイベントを実行する
- メールアドレスを追加する
- カスタム属性値を変更する
- サブスクリプションステータスを更新する
- サブスクリプショングループのステータスを更新する
- キャンペーンとインタラクションする
- ロケーションに入る
- ジオフェンスをトリガーする
- SMSインバウンドメッセージを送信する
- WhatsAppインバウンドメッセージを送信する
- LINEインバウンドメッセージを送信する
- カート更新イベントを実行する
- チェックアウト完了イベントを実行する
- チェックアウト開始イベントを実行する

#### スケジュールされたステップ {#scheduled-steps}

ユーザーを将来の時点まで遅延ステップに留めないキャンバスステップの場合、ユーザーは通常、現在のステップが完了するとすぐにキャンバスから退出します。その完了は、そのステップに残りの遅延タイマーがないため、例外イベントの直後であることが多いです。これは、ユーザーが退出マークされた後も遅延が終了するまで留まる遅延ステップとは異なります（[ユーザーの退出方法](#how-users-exit)を参照）。

#### トリガーされたステップ {#triggered-steps}

キャンバスステップがイベントによってトリガーされた場合、そのトリガーからキューに入れられた最後のスケジュール済み送信はキャンセルされますが、ユーザーは時間枠の間キャンバス内に留まります。つまり、ユーザーが時間枠内に再度トリガーイベントを実行した場合、そのステップが送信される可能性があります。時間枠が経過すると、ユーザーはキャンバスから退出します。

### セグメントとフィルターの使用 {#using-segments-and-filters}

終了条件にセグメントとフィルターを追加することもできます。これにより、セグメントとフィルターに一致するユーザーはキャンバスから退出し、それ以降のメッセージを受け取りません。

例えば、キャンバスの最初のステップが5日間の遅延を持つ遅延ステップの場合、そのステップが完了した時点で終了条件が評価されます。ユーザーが遅延ステップにいる間に終了条件を満たした場合、すぐに退出がマークされますが、5日間の終了時にキャンバスから完全に退出します（遅延後のステップには進みません）。

{% alert note %}
配列属性は現在、例外イベントの終了条件としてサポートされていません。
{% endalert %}

### 退出イベントとコンバージョンイベントが同じ場合 {#having-the-same-exit-event-and-conversion-event}

退出イベントとコンバージョンイベントが同じ場合、コンバージョンと退出イベントの両方がカウントされます。例えば、キャンバスに遅延ステップがあり、ユーザーがその遅延ステップ中に終了条件を実行した場合、退出イベントはユーザーが遅延ステップを退出するとすぐにインクリメントされます。コンバージョンも、イベントがユーザープロファイルに記録されるとすぐにインクリメントされます。

コンバージョンはキャンバス終了後も追跡されますが、退出はユーザーがキャンバスから退出した後は追跡されません。コンバージョンウィンドウは、キャンバスの最大期間を超えて3日間延長されます。つまり、退出の追跡が停止した後もコンバージョンは引き続き追跡されます。

コンバージョンウィンドウの最小時間は5分です。コンバージョンイベントのコンバージョンウィンドウを5分に設定すると、退出イベントとできるだけ近い値を得ることができます。また、コンバージョンウィンドウをキャンバス内の最長パスに少なくとも一致するように設定することをお勧めします。

分析がどのように計算されるかについて、以下の例を考えてみましょう：

1. 10人のユーザーがキャンバスを通過します。
2. 3人のユーザーが5分以内にコンバージョンイベントを実行します（退出イベント数は3、コンバージョンイベント数は3）。
3. さらに5人のユーザーが5分後にキャンバスから退出しますが、2日後にコンバージョンイベントを実行します（退出イベント数は変わりませんが、コンバージョンイベントは8に増加します）。
4. 残りの2人のユーザーは5分後にキャンバスから退出しますが、コンバージョンイベントを実行しないか、3日と5分後に実行します（退出イベントにもコンバージョンイベントの指標にもカウントされません）。

## 例 {#example}

バックパック用品会社でまだ購入を行っていないユーザーをターゲットにしたいとしましょう。終了条件を設定するには、以下の手順を行います：

1. 例外イベントとして**Place an Order**を選択します。
2. **Add Trigger**を選択します。
3. **セグメント**で**Used in last day**を選択し、キャンバスの起動時に購入を行ったユーザーがオーディエンスから除外されるようにします。
4. **Filters**で**Purchase behavior** > **Number of purchases** > **Purchased product**を選択します。
5. フィルターグループを `backpack-example exactly 1` に設定します。これにより、バックパック製品を購入したユーザーがキャンバスから退出します。

![例外イベントとして「Makes Any Purchase」が設定された終了条件。ユーザーが任意の購入を行うと、このキャンバスから退出します。]({% image_buster /assets/img_archive/exit_criteria_example.png %}){: style="max-width:80%;"}

{% endalert %}
