# 実験パスの勝者パス {#winning-path-in-experiment-paths}

> 勝者パスはキャンペーンの[勝者バリアント]({{site.baseurl}}/user_guide/messaging/ab_testing/optimizations)と同様の機能で、A/Bテストを自動化できます。

実験パスステップで勝者パスを有効にすると、指定した期間の経過後、以降のすべてのユーザーはコンバージョン率が最も高いパスに送られます。

## 勝者パスの使用 {#using-winning-path}

### ステップ 1: 実験パスステップを追加する {#step-1-add-an-experiment-path-step}

キャンバスに[実験パス]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/experiment_step)を追加し、**勝者パス**を有効にします。

![「後続のユーザーを勝者パスに配信」というタイトルの実験パスの設定。このセクションには勝者パスのトグルと、コンバージョンイベントおよび実験時間枠を設定するオプションが含まれています。]({% image_buster /assets/img/experiment_step/experiment_winning_path_recurring.png %})

### ステップ 2: 勝者パスの設定を構成する {#step-2-configure-winning-path-settings}

勝者を決定するコンバージョンイベントを指定します。利用可能なコンバージョンイベントがない場合は、キャンバス設定の最初のステップに戻り、[コンバージョンイベントを割り当て]({{site.baseurl}}/user_guide/messaging/canvas/create_a_canvas#choose-conversion-events)てください。

コンバージョンイベントとして開封またはクリックを選択する場合は、パスの最初のステップが[メッセージステップ]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/message_step)であることを確認してください。Brazeは各パスの最初のメッセージステップからのエンゲージメントのみをカウントします。パスが別のステップ（遅延やオーディエンスパスステップなど）で始まり、メッセージが後に来る場合、そのメッセージはパフォーマンス評価時に含まれません。

次に、**実験時間枠**を設定します。**実験時間枠**は、勝者パスが決定され、以降のすべてのユーザーがそのパスに送られるまでの実験の実行期間を指定します。時間枠は最初のユーザーがステップに入った時点から開始されます。

![コンバージョンイベント「クリック数」が選択され、実験時間枠が12時間に設定された勝者パスの設定。]({% image_buster /assets/img/experiment_step/experiment_winning_settings.png %})

### ステップ 3: フォールバックを決定する {#statistical-significance}

デフォルトでは、テスト結果が統計的に有意な勝者を決定するのに十分でない場合、以降のすべてのユーザーは最もパフォーマンスの高いパスに送られます。代わりに、**今後のすべてのユーザーにパスの組み合わせを送信し続ける**を選択することもできます。このオプションでは、実験パスの配分で指定されたパーセンテージに従って、以降のユーザーにパスの組み合わせが送信されます。

同点の場合、Brazeは最初に表示されるパスを選択します。

![テスト結果が統計的に有意でない場合のユーザーの処理として「今後のすべてのユーザーにパスの組み合わせを送信し続ける」が選択されている状態。]({% image_buster /assets/img/experiment_step/experiment_winning_statistical.png %})

{% alert note %}
遅延グループは、キャンバスが1回限りのエントリに設定されており、実験ステップのパスが3つ以下の場合にのみ、パス配分に表示されます。定期的およびトリガー済みのキャンバスでは、勝者パスが有効になっている場合、遅延グループはありません。
{% endalert %}

### ステップ 4: パスを追加してキャンバスを起動する {#step-4-add-your-paths-and-launch-the-canvas}

1つの実験パスコンポーネントには最大4つのパスを収めることができます。ただし、キャンバスが[1回限りのエントリ](#one-time-entry)に設定されている場合、勝者パスが有効になるとBrazeが自動的に追加する遅延グループ用に1つのパスを予約する必要があります。つまり、1回限りのエントリのキャンバスでは、実験に最大3つのパスを追加できます。

必要に応じてキャンバスの設定を完了し、起動します。最初のユーザーが実験に入ったら、キャンバスを確認して分析データの推移を確認し、[実験のパフォーマンスを追跡]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/experiment_step#tracking-performance)できます。

勝者パスが確定した後、キャンバスに入るすべての後続ユーザーは勝者パスに進みます。これには、再エントリしたユーザーや、以前に実験パスステップのコントロールグループにいたユーザーも含まれます。

## 分析 {#analytics}

勝者パスが有効になっている場合、分析ビューは**初期実験**と**勝者パス**の2つのタブに分かれます。

- **初期実験:** 実験時間枠中の各パスの指標、勝者として選択されたパス、およびキャンバスのコンバージョン指標を表示します。勝者パスの設定で構成された勝者を選択するために使用されるコンバージョンイベントは、キャンバスの分析でハイライトされるコンバージョン指標と同じでない場合があります。実験パスの分析がキャンバスのコンバージョンイベントおよび勝者指標とどのように関連するかの詳細については、[実験パス]({{site.baseurl}}/user_guide/engagement_tools/canvas/canvas_components/experiment_step#winning-path-and-personalized-paths-performance)を参照してください。
- **勝者パス:** 初期実験が終了した時点からの勝者パスの指標のみを表示します。

## 知っておくべきこと {#things-to-know}

### 1回限りのエントリ {#one-time-entry}

ユーザーが1回のみエントリできるキャンバスで勝者パスを使用する場合、遅延グループが自動的に含まれます。実験期間中、一定の割合のユーザーが遅延グループに保持され、残りのユーザーは実験パスに入ります。

![勝者パス用の遅延グループを含む実験ステップ]({% image_buster /assets/img/experiment_step/experiment_one_time.png %}){: style="max-width:75%"}

テストが終了し勝者パスが決定されると、遅延グループに割り当てられたユーザーは選択されたパスに誘導され、キャンバスを続行します。

![遅延グループが勝者パスに送られた実験ステップ]({% image_buster /assets/img/experiment_step/experiment_one_time_results.png %}){: style="max-width:75%"}

### ローカルタイム配信 {#local-time-delivery}

勝者パスを使用するキャンバスでのローカルタイム配信の使用は推奨しません。これは、実験時間枠が最初のユーザーが通過した時点で開始されるためです。非常に早いタイムゾーンのユーザーがステップに入り、予想よりもはるかに早く実験時間枠の開始をトリガーする可能性があります。その結果、より一般的なタイムゾーンの大多数のユーザーがキャンバスに入ったりコンバージョンしたりするのに十分な時間がないまま、実験が終了してしまう場合があります。

代わりに、ローカル配信を使用したい場合は、24〜48時間以上の実験時間枠を使用してください。そうすることで、早いタイムゾーンのユーザーがキャンバスに入り実験の開始をトリガーしても、実験時間枠には十分な時間が残ります。遅いタイムゾーンのユーザーも、実験時間枠が終了する前にキャンバスおよび勝者パスを含む実験ステップに入り、コンバージョンするのに十分な時間があります。

### クリックに基づくバリアント {#variants-based-on-clicks}

クリックに基づく勝者パスバリアントを設定する場合、開封とクリックの定義はチャネルによって異なることに注意してください。チャネル別の具体的な指標と定義については、[レポート指標用語集]({{site.baseurl}}/user_guide/analytics/reporting/report_metrics)および[メールレポート指標用語集]({{site.baseurl}}/user_guide/message_building_by_channel/email/reporting_and_analytics/analytics_glossary)を参照してください。
