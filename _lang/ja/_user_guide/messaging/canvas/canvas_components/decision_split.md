# 条件分岐 {#decision-split}

> キャンバスの条件分岐コンポーネントを使用すると、ユーザーにパーソナライズされたリアルタイムの体験を提供できます。

![プッシュが有効なユーザーと有効でないユーザーを対象とした「プッシュ有効？」という名前の条件分岐ステップ。]({% image_buster /assets/img/decision-split-1.png %}){: style="float:right;max-width:40%;margin-left:15px;margin-top:15px;margin-bottom:15px;"}

このコンポーネントを使用すると、ユーザーがクエリに一致するかどうかに基づいてキャンバスの分岐を作成できます。

## 条件分岐を作成する {#create-a-decision-split}

ワークフローで条件分岐を作成するには、キャンバスにステップを追加します。次に、サイドバーからコンポーネントをドラッグ＆ドロップするか、ステップの下部にある <i class="fas fa-plus-circle"></i> プラスボタンを選択して**条件分岐**を選択します。

### 分岐を定義する {#define-your-split}

ユーザーをどのように分岐させますか？[セグメント]({{site.baseurl}}/user_guide/audience/segments/)とフィルターを使用して条件を設定できます。基本的には、ユーザーを評価して一方のステップまたはもう一方のステップに振り分ける `true` または `false` のクエリを作成します。少なくとも1つのセグメントまたは1つのフィルターを使用する必要があります。セグメントとフィルターの両方を使用する必要はありません。

![「フォアグラウンドプッシュ有効がtrue」というフィルターが選択された条件分岐ステップ。]({% image_buster /assets/img/define-split-2.png %})

{% alert note %}
デフォルトでは、条件分岐ステップのセグメントとフィルターは、遅延を追加しない限り、前のステップを受信した直後にチェックされます。
{% endalert %}

## 分岐を使用する {#use-your-split}

条件分岐を使用すると、ユーザーのセグメントや属性に基づいてパスを区別できます。さらに、特定のメッセージングチャネルを使用してメッセージを受信しているかどうかに基づいて区別することもできます。

例えば、オンボーディングフローを作成するとします。サインアップ時にウェルカムメールから始めます。その2日後にプッシュメッセージを送信しますが、プッシュが有効なユーザーのみが対象です。その後、サインアップから3日後にすべてのユーザーに別のメールを送信します。また、条件分岐を使用して、プッシュが有効でないユーザーにアプリ内メッセージを送信し、プッシュを有効にするよう促すこともできます。

いずれかのパスの後にステップがない場合、そのパスに進んだユーザーはキャンバスを退出します。

![プッシュが有効でないユーザーと有効なユーザーを対象とした「プッシュ有効？」という名前の条件分岐ステップ。プッシュが有効でないユーザーは3日間の遅延の後にメールメッセージを受信します。プッシュが有効なユーザーは1日間の遅延の後にプッシュ通知を受信し、さらに2日間の遅延の後にプッシュが有効でないユーザーと同じメールメッセージを受信します。]({% image_buster /assets/img/use-split-onboarding-3.png %}){: style="max-width:60%"}

## 分析 {#analytics}

このステップの分析の説明については、以下の表を参照してください。

| 指標 | 説明 |
|---|---|
| _エントリー_ | ステップに入った合計回数です。キャンバスに再エントリー資格があり、ユーザーが条件分岐ステップに2回入った場合、2回のエントリーが記録されます。 |
| _はい_ | 指定された条件を満たし、「はい」のパスに進んだエントリーの数です。 |
| _いいえ_ | 指定された条件を満たさず、「いいえ」のパスに進んだエントリーの数です。 |
