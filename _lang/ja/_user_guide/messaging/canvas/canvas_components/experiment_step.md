# 実験パス {#experiment-paths}

> 実験パスを使用すると、ユーザージャーニーの任意のポイントで複数のキャンバスパスを相互に、またコントロールグループと比較テストできます。このコンポーネントを使用してパスのパフォーマンスをトラッキングし、キャンバスジャーニーについて十分な情報に基づいた意思決定を行うことができます。

ユーザージャーニーに実験パスステップを含めると、作成した異なるパス（またはオプションのコントロールグループ）にユーザーがランダムに割り当てられます。選択したパーセンテージに従ってオーディエンスの一部が異なるパスに割り当てられるため、異なるメッセージやパスを相互にテストし、どれが最も効果的かを判断できます。

![パス1、パス2、コントロールに分岐する実験パスステップ。]({% image_buster /assets/img/experiment_step/experiment_step.png %}){: style="float:right;max-width:50%;margin-left:15px;"}

## 前提条件 {#prerequisites}

実験パスを使用するには、キャンバスにコンバージョンイベントが含まれている必要があります。キャンバスの起動後にコンバージョンイベントを追加することはできませんが、起動済みのキャンバスを複製してコンバージョンイベントを追加することで、実験パスを追加できます。

## ユースケース {#use-cases}

実験パスは、配信、ケイデンス、メッセージコピー、チャネルの組み合わせのテストに最適です。

- **配信:** 異なる時間[遅延]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/delay_step)で送信されたメッセージ、ユーザーアクションに基づくメッセージ（[アクションパス]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/action_paths))、[インテリジェントタイミング]({{site.baseurl}}/user_guide/brazeai/intelligence_suite/intelligent_timing#canvas)を使用したメッセージの結果を比較します。<br><br>
- **ケイデンス:** 特定の期間にわたって複数のメッセージングフローをテストします。たとえば、2つの異なるオンボーディングケイデンスをテストできます：
    - ケイデンス1：ユーザーの最初の2週間で2通のメッセージを送信
    - ケイデンス2：ユーザーの最初の2週間で3通のメッセージを送信

    離脱ユーザーをターゲットにする場合、1週間に2通のウィンバックメッセージを送信する場合と1通だけ送信する場合の効果を比較テストできます。
- **メッセージコピー:** 標準的な[A/Bテスト]({{site.baseurl}}/user_guide/messaging/ab_testing)と同様に、異なるメッセージコピーをテストして、どの文言がより高いコンバージョン率をもたらすかを確認できます。<br><br>
- **チャネルの組み合わせ:** 異なるメッセージチャネルの組み合わせの効果をテストします。たとえば、メールのみの使用と、メールとプッシュを組み合わせた場合の影響を比較できます。

## 実験パスの作成 {#creating-an-experiment-path}

実験パスコンポーネントを作成するには、まずキャンバスにステップを追加します。サイドバーからコンポーネントをドラッグ＆ドロップするか、ステップの下部にある<i class="fas fa-plus-circle"></i>プラスボタンをクリックして**実験パス**を選択します。

このコンポーネントのデフォルト設定では、**パス1**と**パス2**の2つのデフォルトパスがあり、オーディエンスの50%がそれぞれのパスに送られます。コンポーネントをクリックして**実験設定**パネルを展開すると、コンポーネントの設定オプションが表示されます。

### ステップ 1: パスの数とオーディエンス配分を選択する {#step-1-choose-the-number-of-paths-and-audience-distribution}

**パスを追加**をクリックして最大4つのパスを追加でき、**コントロールグループを追加**にチェックを入れてオプションのコントロールグループを追加できます。各パスのパーセンテージボックスを使用して、各パスとコントロールグループに送るオーディエンスのパーセンテージを指定できます。指定したパーセンテージの合計は100%になる必要があります。利用可能なすべてのパス（およびコントロール）を同じパーセンテージにすばやく設定したい場合は、**パスを均等に配分**をクリックします。

また、**コントロールグループの動作**として、コントロールグループのユーザーがキャンバスを続行するか、コンバージョントラッキング時間枠の後に退出するかを選択できます。オプションで、この実験パスがテストする内容を他のメンバーに説明するための説明を追加したり、メモしておくと役立つ追加情報を含めたりすることもできます。

![パスを追加し、各パスのユーザーのパーセンテージを配分できる実験設定。]({% image_buster /assets/img/experiment_step/exp_settings.png %})

{% alert note %}
キャンバスの再エントリが有効になっている場合、キャンバスに入ってランダムに選ばれたパスを進んだユーザーは、再エントリの資格を得てキャンバスに再度入った場合、同じパスを再び進みます。これにより、実験と関連する分析の妥当性が維持されます。ステップで常にパスの割り当てをランダム化したい場合は、**実験パスでのランダム化パス**を選択します。このオプションは、勝者パスまたはパーソナライズ済みパスを使用している場合は利用できません。
{% endalert %}

### ステップ 2: 勝者パスまたはパーソナライズ済みパスを有効にする（オプション） {#step-2}

[勝者パス]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/experiment_step/winning_path)または[パーソナライズ済みパス]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/experiment_step/personalized_paths)を有効にして実験を最適化できます。どちらのオプションも、最初にオーディエンスの一部でパスをテストします。実験が終了すると、残りのユーザーおよびその後のユーザーは、全体で最もパフォーマンスの高いパス（勝者パス）または各ユーザーにとって最もパフォーマンスの高いパス（パーソナライズ済みパス）に送られます。

### ステップ 3: パスを作成する {#step-3-create-paths}

最後に、下流のパスを構築する必要があります。**完了**を選択してキャンバスビルダーに戻ります。各パスの下にある<i class="fas fa-plus-circle"></i>プラスボタンをクリックして、通常のキャンバスツールを使用してジャーニーの作成を開始し、準備ができたらキャンバスを起動します。

![実験パスコンポーネントから分岐する各パスにステップを追加する。]({% image_buster /assets/img/experiment_step/experiment_downstream_paths.gif %}){: style="max-width:75%"}

パスとその下流のステップは、作成後にキャンバスから削除できないことに注意してください。ただし、起動後は必要に応じてパス間のオーディエンス配分を変更できます。たとえば、キャンバスの起動から1日後に、分析に基づいて1つのパスが他のパスよりも優れていると判断した場合、そのパスを100%に設定し、他のパスを0%に設定できます。または、必要に応じて、複数のパスにユーザーを送り続けることもできます。

{% alert important %}
実験の汚染を防ぐため、キャンバスにアクティブまたは進行中の勝者パスまたはパーソナライズ済みパスの実験がある状態でアクティブなキャンバスを更新すると、実験パスステップ自体を更新するかどうかに関係なく、進行中の実験は終了し、実験ステップは勝者パスやパーソナライズ済みパスを決定しません。実験を再開するには、既存の実験パスを切断して新しいものを起動するか、キャンバスを複製して新しいキャンバスを起動します。それ以外の場合、ユーザーは最適化方法が選択されていないかのように実験パスを通過します。また、実験パスステップを持つすでにアクティブなキャンバスに対して、パーソナライズ済みパスや勝者パスを有効にすることはできません。<br><br>詳細については、[起動後のキャンバスの編集]({{site.baseurl}}/post-launch_edits)を参照してください。
{% endalert %}

## パフォーマンスのトラッキング {#tracking-performance}

**キャンバス Analytics**ページから実験パスを選択すると、**バリアントの分析**タブと同じ[詳細テーブル]({{site.baseurl}}/user_guide/messaging/canvas/managing_canvases/change_your_canvas_after_launch#performance-breakdown-by-variant)が開き、パス間の詳細なパフォーマンスとコンバージョン統計を比較できます。テーブルをCSVでエクスポートしたり、選択したパスまたはコントロールに対する関心のある指標のパーセント変化を比較したりすることもできます。

各パスの各ステップは、他のキャンバスステップと同様に[キャンバス Analytics]({{site.baseurl}}/user_guide/messaging/canvas/testing_canvases/measuring_and_testing_with_canvas_analytics)ビューに統計を表示します。ただし、個々のステップの分析と実験パスの分析ではコンバージョンの測定方法が異なることに注意してください：

- **実験パスの分析**は、ユーザーが実験パスステップに入った時点からコンバージョンをトラッキングします。すべてのパスが同じ開始点を共有するため、パス間のパフォーマンスを比較するにはこのビューが推奨されます。
- **個々のステップの分析**（メッセージステップの分析など）は、ユーザーがその特定のステップを受信した時点（たとえば、メッセージが送信された時点）からコンバージョンをトラッキングします。

これらのコンバージョン時間枠は開始点が異なるため、同じパスでも異なるコンバージョン率を示す場合があります。特に、実験ステップと下流のメッセージの間に遅延がある場合に顕著です。パス間の最も信頼性の高い比較には、実験パスの分析を使用してください。

### 勝者パスとパーソナライズ済みパスのパフォーマンス {#winning-path-and-personalized-paths-performance}

勝者パスを活用して、一定期間にわたってパフォーマンスをトラッキングし、その後のユーザーを最もパフォーマンスの高いパスに自動的に送ることができます。実験で**勝者パス**または**パーソナライズ済みパス**が有効になっている場合の分析の詳細については、以下を参照してください：

- [勝者パス]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/experiment_step/winning_path#analytics)
- [パーソナライズ済みパス]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/experiment_step/personalized_paths#analytics)

勝者指標と実験パスに表示される分析は異なる場合があります：

- **勝者パス**または**パーソナライズ済みパス**に設定したコンバージョンイベントは、実験時間枠中にBrazeがパスを比較して勝者を選択する方法を決定します。
- 実験パスの分析は、キャンバスの残りの部分と同じキャンバスの[コンバージョンイベント]({{site.baseurl}}/user_guide/engagement_tools/messaging_fundamentals/conversion_events)フレームワークに従います。これには[1次コンバージョンイベント]({{site.baseurl}}/user_guide/engagement_tools/messaging_fundamentals/conversion_events#primary-conversion-event)も含まれます。そのため、ダッシュボードで強調される指標が勝者指標と一致しない場合があります。
- プッシュの場合、*直接開封数*と*合計開封数*は異なります。詳細については、[影響を受けた開封]({{site.baseurl}}/user_guide/analytics/tracking/influenced_opens)を参照してください。

### 追加設定 {#additional-settings}

実験パスは、各ステップに入り、割り当てられたパス内でコンバージョンしたユーザーを記録します。これにより、キャンバスの設定で指定されたすべてのコンバージョンイベントがトラッキングされます。**追加設定**タブで、この実験がコンバージョンをトラッキングする日数（1〜30日）を入力します。ここで指定する時間枠は、実験に対してコンバージョンイベント（キャンバスの設定で選択したもの）がトラッキングされる期間を決定します。キャンバスの設定で指定されたイベントごとのコンバージョン時間枠は、このステップのトラッキングには適用されず、このコンバージョン時間枠に置き換えられます。

コンバージョン時間枠は、下流のメッセージが送信された時点ではなく、ユーザーが実験パスステップに入った時点から開始されます。パスに遅延（遅延ステップや[インテリジェントタイミング]({{site.baseurl}}/user_guide/brazeai/intelligence_suite/intelligent_timing)など）が含まれている場合、それらの遅延はコンバージョン時間枠の一部を消費します。

{% alert important %}
実験パス内のメッセージステップでインテリジェントタイミングを使用している場合、実験エントリから実際のメッセージ送信までの時間により、そのパスの有効なコンバージョン時間枠が短くなります。たとえば、実験のコンバージョン時間枠が5日間で、インテリジェントタイミングによりメッセージが2日遅延した場合、そのパスのユーザーは実験時間枠内でコンバージョンするために、メッセージ受信後3日間しかありません。メッセージステップ自体の分析はメッセージ送信時点からコンバージョンをトラッキングしますが、実験時間枠は異なります。<br><br>よりクリーンな実験分析のために、遅延（遅延ステップなど）は実験パス内ではなく、実験パスステップの**前**に配置してください。こうすることで、すべてのパスが同じポイントから開始され、遅延がコンバージョン時間枠を消費しなくなります。
{% endalert %}

## よくある質問 {#frequently-asked-questions}

### 実験の分割が均等に見えるのに、パス間で送信数が異なるのはなぜですか？ {#why-do-sends-differ-across-paths-when-the-experiment-split-looks-even}

下流の*送信数*は、実験パスでのパーセンテージ分割だけでなく、各パスのステップ、遅延、チャネルの適格性、コンテンツに依存します。たとえば、異なる遅延、インテリジェント送信時間、またはサブスクリプションステータスにより、パスの割り当てが均等であっても、メッセージを受信するユーザー数が変わる場合があります。パスの結果を比較するには、共通のエントリポイントからコンバージョンを測定する[実験パスの分析](#tracking-performance)を使用してください。

### 実験のコンバージョン時間枠はどのくらい続きますか？ {#how-long-does-the-experiment-conversion-window-last}

**追加設定**のコンバージョン時間枠（1〜30日）は、ユーザーが実験パスステップに入った時点から開始されます。下流の遅延ステップやインテリジェントタイミングの待機時間は、この時間枠にカウントされます。詳細については、[パフォーマンスのトラッキング](#tracking-performance)を参照してください。
