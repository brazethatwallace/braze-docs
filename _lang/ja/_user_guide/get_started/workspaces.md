# はじめに: ワークスペース {#get-started-workspaces}

> Brazeプラットフォームでの操作はすべて、ワークスペース内で行われます。ワークスペースは独立したデータのサイロとして機能し、異なるブランドやアクティビティを分離して管理できます。Webサイトやモバイルアプリの複数のバージョンから、同じワークスペースにデータを送信できます。ワークスペース内に収集されたさまざまなサイトやアプリを「アプリインスタンス」と呼びます。

## ワークスペースを理解する {#understanding-workspaces}

ワークスペースには2つの重要な目的があります。

- **ユーザーデータの統合:** 1つのワークスペースに複数のアプリインスタンスがある場合、iOS、Android、Webなど、アプリのさまざまなバージョンにわたってシームレスにユーザーデータを収集し、ターゲティングできます。これにより、ユーザーが使用しているプラットフォームに関係なく、各ユーザーに関する最新の情報を常に把握できます。
- **異なるアクティビティの分離:** ワークスペースは、異なるブランドやアクティビティを分離するための手段も提供します。たとえば、異なるユーザー群を持つ複数のサブブランドがある場合、それぞれに個別のワークスペースを作成すると効果的です。

{% alert tip %}
このアプローチは、各ゲームごとに個別のワークスペースを管理できるモバイルゲーム企業や、事業展開する地域ごとに個別のワークスペースを持ちたいeコマースサイトなどの企業に特に有用です。
{% endalert %}

## ワークスペースの計画 {#planning-workspaces}

各プラットフォーム上のアプリの各バージョンに対して、個別のアプリインスタンスを作成する必要があります。ワークスペースに含めるアプリインスタンスを決定する際は、ターゲットにしたいユーザーを考え、それに応じてグループ分けしてください。

1つのワークスペースに複数のアプリインスタンスを含めることは魅力的に映ることがあります。アプリポートフォリオ全体でメッセージングのレート制限を適用できるためです。ただし、ベストプラクティスとして、同じ（または非常に類似した）アプリの異なるバージョンのみを1つのワークスペースにまとめることをお勧めします。

### 共有ワークスペース {#shared-workspaces}

同じワークスペースに複数のアプリインスタンスを含めたい場合の一般的な例を紹介します。

- 異なるプラットフォームにほぼ同一のアプリが複数ある場合
- アプリのメジャーリビジョンが異なるが、ユーザーがアップグレードしても引き続きエンゲージメントを維持したい場合
- 同じユーザーが出入りする可能性のある異なるバージョンのアプリがある場合（無料版からプレミアム版など）

#### セグメンテーションフィルターへの影響 {#impact-on-segmentation-filters}

1つのワークスペースに含めるアプリを選択すると、それらのデータが集約されます。これは、Braze の以下のセグメンテーションフィルターに顕著な影響を与えます（これは網羅的なリストではありません）。

- 最後に使用したアプリ
- 最初に使用したアプリ
- セッション数
- アプリ内課金額
- プッシュ購読（これは全か無かの状況になります。ユーザーが1つのアプリで購読解除すると、ワークスペース内のすべてのアプリから購読解除されます。）
- メール購読（これは全か無かの状況になり、コンプライアンスの問題が発生する可能性があります。）

{% alert note %}
これらのフィルターにおいてアプリインスタンス間でデータが集約されるため、大きく異なるアプリを同じワークスペースに配置することは推奨していません。ターゲティングが複雑になる可能性があります。
{% endalert %}

### 個別ワークスペース {#separate-workspaces}

他の場合には、複数の個別ワークスペースを持つことが望ましい場合もあります。一般的な例を紹介します。

- 同じアプリの開発環境と本番環境を分けるための個別ワークスペース
- 異なるサブブランド（例: 複数のゲームを提供するモバイルゲーム会社）
- 異なる国で運営される、または異なる言語をターゲットとする同じアプリまたは Web サイトの異なるローカライゼーション

### 重要な考慮事項 {#important-considerations}

ワークスペースはデータの個別のサイロとして機能することを忘れないでください。ユーザーデータやマーケティングアセットなど、すべてのデータはワークスペース内に保存されます。このデータはそのワークスペースの外部と簡単に共有することはできません。

以下はすべてワークスペース内で構成される主要な要素です。

- [アプリインスタンス](#app-instances)
- [チーム](#teams)
- [会社ユーザーの権限](#company-user-permissions)（ただし会社ユーザーそのものは含まれません）
- [Currents コネクター](#currents-connectors)
- [ユーザープロファイル](#user-profiles)と関連するユーザーデータ
- [セグメント、キャンペーン、キャンバス](#segments-campaigns-and-canvases)

#### アプリインスタンス {#app-instances}

各プラットフォーム上のアプリの各バージョンに対して、個別のアプリインスタンスを作成する必要があります。たとえば、iOS と Android の両方に無料版とプロ版のアプリがある場合、ワークスペース内に4つのアプリインスタンス（無料 iOS アプリ、無料 Android アプリ、プロ iOS アプリ、プロ Android アプリ）を作成します。これにより、各アプリインスタンスに1つずつ、4つの API キーを使用できるようになります。

#### チーム {#teams}

[チーム]({{site.baseurl}}/user_guide/administer/global/user_management/teams)は、顧客基盤の地域、言語、カスタム属性に基づいて設定できます。これにより、チームメンバーと非チームメンバーがメッセージング機能や顧客データに対して異なるアクセス権を持つことができます。

#### 会社ユーザーの権限 {#company-user-permissions}

ワークスペースには独立したアクセス権とユーザー権限の定義があります。[ユーザー権限]({{site.baseurl}}/user_guide/administer/global/user_management/permissions)を使用すると、個々のダッシュボードユーザーまたはチームが単一のワークスペース内でアクセスできる範囲について、きめ細かなコントロールを作成できます。

#### Currents コネクター {#currents-connectors}

[Currents]({{site.baseurl}}/user_guide/data/distribution/braze_currents) ツールは、エンゲージメントイベントのリアルタイムデータストリームであり、Braze プラットフォームからの最も堅牢かつきめ細かなエクスポートです。Currents コネクターは特定の Braze パッケージに含まれており、単一のワークスペースを前提として最初に1つ提供されている場合があります。

個別ワークスペースと統合ワークスペースのどちらにするかを決定する際は、保有している Currents コネクターの数を考慮することが重要です。Currents コネクターはワークスペース間で共有されないためです。

たとえば、同じアプリの開発環境と本番環境で個別のワークスペースを使用している場合は、本番ワークスペースで Currents コネクターを有効にしてください。両方のワークスペースで Currents を有効にするには、追加の Currents コネクターを購入する必要があります。

#### ユーザープロファイル {#user-profiles}

ユーザーに関連するすべての永続データは、[ユーザープロファイル]({{site.baseurl}}/user_guide/audience/manage_audience/user_profiles)に保存されます。ただし、ユーザープロファイルはトラブルシューティングやテストにも優れたリソースです。ユーザーのエンゲージメント履歴、セグメントメンバーシップ、デバイス、オペレーティングシステムに関する情報に簡単にアクセスできるためです。

#### セグメント、キャンペーン、キャンバス {#segments-campaigns-and-canvases}

セグメント、キャンペーン、キャンバスは、別のワークスペースに格納されているデータを参照したりアクセスしたりすることはできません。逆に、同じワークスペースに複数のアプリがある場合、すべてのアプリのデータが集約されます。これは [Braze のフィルターに影響](#impact-on-segmentation-filters)を与えます。

### 各アプローチの概要 {#overview-of-each-approach}

以下の表は、ワークスペース計画における2つのアプローチのメリットとデメリットを説明しています。

- **個別のワークスペースとユーザープロファイル:** 1つのワークスペースに1つのアプリインスタンスがあり、1人のユーザーがそのアプリインスタンスに対して1つのユーザープロファイルを持ちます。
- **共有のワークスペースとユーザープロファイル:** 1つのワークスペースに複数のアプリインスタンスがあり、1人のユーザーがそれらすべてのアプリインスタンスに対して1つのユーザープロファイルを持ちます。

## ベストプラクティス {#best-practices}

### テストワークスペースの設定 {#set-up-a-testing-workspace}

ベストプラクティスとして、本番ワークスペース（実際のユーザーにメッセージを送信するワークスペース）を設定する予定がある場合は、テストワークスペースも併せて設定してください。テストワークスペースは、実際のユーザーデータを含まない本番ワークスペースの複製です。

これがベストプラクティスと見なされる理由はいくつかあります。

- **変更の分離:** 新しい機能、構成、または更新を、本番環境に影響を与えることなく隔離された環境でテストできます。これにより、テスト中に問題が発生しても、本番環境は影響を受けません。
- **正確なテスト:** テスト環境のデータは、実際のデータを心配することなく制御・操作できるため、より正確なテストが可能になります。
- **デバッグ:** テスト環境では本番環境への影響を心配せずに環境を自由に操作できるため、問題のデバッグが容易になります。
- **トレーニング:** 新しいチームメンバーは、ミスが実際の影響を及ぼさない安全な環境でワークスペースに慣れることができます。

{% alert tip %}
テストワークスペースと本番ワークスペースを設定する順序は、具体的なニーズや状況によって異なります。ただし、一般的にはまずテストワークスペースを設定することをお勧めします。これにより、本番ワークスペースに実装する前に機能、構成、更新をテストできます。テストと結果に満足した後で、本番ワークスペースを構築してください。
{% endalert %}

### 管理者の追加 {#add-administrators}

1つのワークスペースに対して、管理者権限を持つBrazeユーザーを複数名設定してください。これにより、組織内で他のユーザーの権限を管理できる人が十分に確保されます。
