# はじめに: ワークスペース {#get-started-workspaces}

> Brazeプラットフォームでの操作はすべて、ワークスペース内で行われます。ワークスペースは独立したデータのサイロとして機能し、異なるブランドやアクティビティを分離して管理できます。Webサイトやモバイルアプリの複数のバージョンから、同じワークスペースにデータを送信できます。ワークスペース内に収集されたさまざまなサイトやアプリを「アプリインスタンス」と呼びます。

## ワークスペースを理解する {#understanding-workspaces}

ワークスペースには2つの重要な目的があります。

- **ユーザーデータの統合:** 1つのワークスペースに複数のアプリインスタンスがある場合、iOS、Android、Webなど、アプリのさまざまなバージョンにわたってユーザーデータをシームレスに収集し、ターゲティングできます。これにより、ユーザーが使用しているプラットフォームに関係なく、各ユーザーに関する最新の情報を常に把握できます。
- **異なるアクティビティの分離:** ワークスペースは、異なるブランドやアクティビティを分離する手段も提供します。たとえば、異なるユーザー群を持つ複数のサブブランドがある場合、それぞれに個別のワークスペースを作成することが有益です。

{% alert tip %}
このアプローチは、モバイルゲーム企業がゲームごとに個別のワークスペースを管理する場合や、eコマースサイトが運営する地域ごとに個別のワークスペースを設ける場合に特に便利です。
{% endalert %}

## ワークスペースの計画 {#planning-workspaces}

アプリの各バージョンに対して、プラットフォームごとに個別のアプリインスタンスを作成する必要があります。ワークスペースに含めるアプリインスタンスを決定する際は、ターゲットにしたいユーザーを考え、それに応じてグループ化してください。

1つのワークスペースに複数のアプリインスタンスを配置することは魅力的に思えるかもしれません。アプリポートフォリオ全体でメッセージングのレート制限を適用できるためです。ただしベストプラクティスとして、同じ（または非常に類似した）アプリの異なるバージョンのみを1つのワークスペースにまとめることを推奨します。

### 共有ワークスペース {#shared-workspaces}

同じワークスペースに複数のアプリインスタンスを配置するケースの代表的な例は次のとおりです。

- 異なるプラットフォームにほぼ同一のアプリが複数ある場合
- アプリのメジャーリビジョンが異なるが、ユーザーがアップグレードしても同じユーザーにエンゲージメントを続けたい場合
- 同じユーザーが移動する可能性のあるアプリの異なるバージョンがある場合（無料版からプレミアム版など）

#### セグメンテーションフィルターへの影響 {#impact-on-segmentation-filters}

1つのワークスペースに含めたアプリのデータはすべて集約されます。これにより、Brazeの以下のセグメンテーションフィルターに大きな影響があります（以下は網羅的なリストではありません）。

- 最後に使用したアプリ
- 最初に使用したアプリ
- セッション数
- アプリ内課金額
- プッシュ購読（これはオール・オア・ナッシングの状況になります。ユーザーが1つのアプリで購読解除すると、ワークスペース内のすべてのアプリで購読解除されます。）
- メール購読（これもオール・オア・ナッシングの状況となり、コンプライアンスの問題が生じる可能性があります。）

{% alert note %}
これらのフィルターでアプリインスタンス間のデータが集約されるため、大きく異なるアプリを同じワークスペースに配置することは推奨しません。ターゲティングが複雑になる可能性があります。
{% endalert %}

### 個別のワークスペース {#separate-workspaces}

一方で、複数の個別のワークスペースを用意したい場合もあります。代表的な例は次のとおりです。

- 同じアプリの開発環境と本番環境用に個別のワークスペースを用意する場合
- 異なるサブブランドがある場合（例：複数のゲームを提供するモバイルゲーム会社）
- 同じアプリやWebサイトの異なるローカライゼーションが、異なる国で運用されたり異なる言語をターゲットにしている場合

### 重要な考慮事項 {#important-considerations}

ワークスペースはデータの個別のサイロとして機能することを覚えておいてください。ユーザーデータでもマーケティングアセットでも、すべてのデータはワークスペース内に保存されます。このデータをワークスペースの外部で簡単に共有することはできません。

以下はすべて、ワークスペース内で設定される主要な要素です。

- [アプリインスタンス](#app-instances)
- [チーム](#teams)
- [会社のユーザー権限](#company-user-permissions)（会社のユーザーは含まれません）
- [Currentsコネクタ](#currents-connectors)
- [ユーザープロファイル](#user-profiles)および関連するユーザーデータ
- [セグメント、キャンペーン、キャンバス](#segments-campaigns-and-canvases)

#### アプリインスタンス {#app-instances}

アプリの各バージョンに対して、プラットフォームごとに個別のアプリインスタンスを作成する必要があります。例えば、iOSとAndroidの両方にアプリの無料版とプロ版がある場合、ワークスペース内に4つのアプリインスタンスを作成します（無料版iOSアプリ、無料版Androidアプリ、プロ版iOSアプリ、プロ版Androidアプリ）。これにより、各アプリインスタンスに1つずつ、合計4つのAPIキーが提供されます。

#### チーム {#teams}

[チーム]({{site.baseurl}}/user_guide/administer/global/user_management/teams)は、顧客ベースの所在地、言語、カスタム属性に基づいて設定できます。これにより、チームメンバーと非チームメンバーがメッセージング機能や顧客データに対して異なるアクセス権を持てるようになります。

#### 会社のユーザー権限 {#company-user-permissions}

ワークスペースには独立したアクセス権とユーザー権限の定義があります。[ユーザー権限]({{site.baseurl}}/user_guide/administer/global/user_management/permissions)を使用すると、個々のダッシュボードユーザーまたはチームが1つのワークスペース内でアクセスできる範囲を細かく制御できます。

#### Currentsコネクタ {#currents-connectors}

[Currents]({{site.baseurl}}/user_guide/data/distribution/braze_currents)ツールは、エンゲージメントイベントのリアルタイムデータストリームであり、Brazeプラットフォームからの最も堅牢かつ精緻なエクスポート手段です。Currentsコネクタは特定のBrazeパッケージに含まれており、1つのワークスペースを前提として最初に1つ提供されている場合があります。

個別のワークスペースにするか統合ワークスペースにするかを決定する際は、保有するCurrentsコネクタの数を考慮することが重要です。Currentsコネクタはワークスペース間で共有されません。

例えば、同じアプリの開発環境と本番環境に個別のワークスペースがある場合、本番ワークスペースでCurrentsコネクタを有効にしてください。両方のワークスペースでCurrentsを有効にするには、追加のCurrentsコネクタを購入する必要があります。

#### ユーザープロファイル {#user-profiles}

ユーザーに関連するすべての永続データは、[ユーザープロファイル]({{site.baseurl}}/user_guide/audience/manage_audience/user_profiles)に保存されます。ただし、ユーザープロファイルはトラブルシューティングやテストにも役立つリソースです。ユーザーのエンゲージメント履歴、セグメントのメンバーシップ、デバイス、オペレーティングシステムに関する情報に簡単にアクセスできるためです。

#### セグメント、キャンペーン、キャンバス {#segments-campaigns-and-canvases}

セグメント、キャンペーン、キャンバスは、別のワークスペースに保存されているデータを参照したりアクセスしたりすることはできません。逆に、複数のアプリが同じワークスペースにある場合、すべてのアプリのデータが集約されます。これは[Brazeのフィルターに影響](#impact-on-segmentation-filters)を与えます。

### 各アプローチの概要 {#overview-of-each-approach}

以下の表は、ワークスペース計画における2つのアプローチのメリットとデメリットを説明しています。

- **個別のワークスペースとユーザープロファイル：** 1つのワークスペースに1つのアプリインスタンスがあり、1人のユーザーがそのアプリインスタンスに対して1つのユーザープロファイルを持ちます。
- **共有ワークスペースとユーザープロファイル：** 1つのワークスペースに複数のアプリインスタンスがあり、1人のユーザーがそれらすべてのアプリインスタンスに対して1つのユーザープロファイルを持ちます。

## ベストプラクティス {#best-practices}

### テスト用ワークスペースの設定 {#set-up-a-testing-workspace}

ベストプラクティスとして、本番用ワークスペース（実際のユーザーにメッセージを送信するワークスペース）を設定する場合は、常にテスト用ワークスペースも設定してください。テスト用ワークスペースは、実際のユーザーデータを含まない本番用ワークスペースの複製です。

これがベストプラクティスとされる理由はいくつかあります。

- **変更の分離:** 新しい機能、設定、更新を隔離された環境でテストでき、本番環境に影響を与えることがありません。テスト中に問題が発生しても、本番環境は影響を受けません。
- **正確なテスト:** テスト環境のデータは実際のデータに影響を与えることなく制御・操作できるため、より正確なテストが可能になります。
- **デバッグ:** テスト環境では本番環境への影響を心配せずに自由に環境を操作できるため、問題のデバッグが容易になります。
- **トレーニング:** 新しいチームメンバーが、ミスが実際に影響を及ぼさない安全な環境でワークスペースに慣れることができます。

{% alert tip %}
テスト用ワークスペースと本番用ワークスペースを設定する順序は、具体的なニーズや状況によって異なります。ただし、一般的にはまずテスト用ワークスペースを設定することをお勧めします。これにより、本番用ワークスペースに実装する前に、機能、設定、更新をテストできます。テストと結果に満足した後で、本番用ワークスペースを構築できます。
{% endalert %}

### 管理者の追加 {#add-administrators}

1つのワークスペースに対して、管理者権限を持つBrazeユーザーを複数人設定してください。これにより、組織内で他のユーザーの権限を管理できる人員が十分に確保されます。
