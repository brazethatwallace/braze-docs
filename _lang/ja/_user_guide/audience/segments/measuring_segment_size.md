# セグメントサイズの測定 {#measure-segment-size}

> このページでは、セグメントのメンバーシップとサイズを監視する方法について説明します。

## セグメントメンバーシップの計算 {#segment-membership-calculation}

Brazeは、データがサーバーに送信されて処理されると、ユーザーのセグメントメンバーシップを更新します。通常、これは即座に行われます。ユーザーのセグメントメンバーシップは、そのセッションが処理されるまで変更されません。たとえば、セッション開始時に休眠ユーザーセグメントに該当するユーザーは、セッションが処理されると即座に休眠ユーザーセグメントから移動されます。

### 到達可能なユーザー総数の計算 {#total-reachable-users-calculation}

各セグメントには、そのセグメントのメンバーであるユーザーの総数が表示されます。**すべてのアプリのユーザー**でフィルタリングすると、最も頻繁に使用されるメッセージングチャネル（Webプッシュやメールなど）と、それらの特定のチャネルで到達可能なユーザー数も表示されます。

ユーザーの総数が、各チャネルで到達可能なユーザー数と異なる場合があります。また、到達可能なユーザーテーブルにはすべてのチャネルが表示されるわけではありません。たとえば、Content Cards、webhook、WhatsAppは内訳に表示されません。つまり、到達可能なユーザーの総数は、表示されている各チャネルのユーザー数の合計よりも大きくなる可能性があります。

![メール、iOSプッシュ、Androidプッシュ通知、Webプッシュ、Kindleプッシュで到達可能なユーザーごとに分類された到達可能なユーザー総数を表示するテーブル。]({% image_buster /assets/img_archive/segmenter_reachable_users.png %})

特定のチャネルで到達可能としてリストされるには、ユーザーは以下の両方を満たす必要があります:
* プロファイルに有効なメールアドレスまたはプッシュトークンが関連付けられていること
* アプリにオプトインまたは購読中であること

1人のユーザーが異なる到達可能なユーザーグループに属する場合があります。たとえば、あるユーザーが有効なメールアドレスと有効なAndroidプッシュトークンの両方を持ち、両方にオプトインしているが、関連するiOSプッシュトークンがない場合があります。到達可能なユーザーの総数と各チャネルの合計との差は、セグメントに該当するがそれらのコミュニケーションチャネルでは到達できないユーザーの数です。

{% alert note %}
**到達可能なユーザー総数**には、チャネルの購読を解除していても、セグメントフィルターに一致するすべてのユーザーが含まれます。**iOS**などのチャネル行は、[チャネル別の到達可能なユーザー](#reachable-users-by-channel)のルールに基づいて、そのチャネルでのみ到達可能なユーザーをカウントします。セグメントの合計を購読中のユーザーに合わせるには、**Push enabled for iOS**がtrueなどのフィルター（またはチャネルに応じた同等のフィルター）を追加してください。
{% endalert %}

## セグメントサイズの統計 {#statistics-for-segment-size}

推定統計はセグメントの一部のみをサンプリングして近似されるため、推定サイズは実際の値よりも大きくなったり小さくなったりすることが予想されます。ワークスペースが大きいほど、誤差の幅が大きくなる可能性があります。セグメントのユーザーの正確な数を取得するには、**Calculate Exact Statistics**を選択してください。正確なセグメントメンバーシップは、CampaignまたはCanvasで送信されるメッセージによってセグメントが影響を受ける前に常に計算されます。

Brazeは、セグメントサイズに関する以下の統計を提供します。

### フィルター統計 {#filter-statistics}

各フィルターグループについて、推定到達可能ユーザーを確認できます。**Expand extra funnel statistics**を選択すると、チャネルごとの内訳が表示されます。

![セッション数がちょうど1回のユーザーのフィルターを含むフィルターグループ。]({% image_buster /assets/img_archive/segment_filter_stats.png %})

## 到達可能なユーザーの推定 {#reachable-users-estimate}

**Reachable users**サイドパネルで、セグメント全体の推定到達可能ユーザー（各チャネルの推定ユーザー数を含む）を確認できます。この**推定**は、セグメントサイズのおおよその範囲と、全体のユーザー群のうちこのセグメントに該当するユーザーの推定割合を示します。推定統計は、セグメントを編集しない限り15分間キャッシュされます。編集した場合、推定統計は自動的に更新されます。**Calculate exact statistics**を選択すると、到達可能なユーザーの正確な数（セグメント全体およびチャネルごと）を確認することもできます。

![推定ユーザーが230万〜240万であることを示す「Reachable users」パネル。]({% image_buster /assets/img_archive/reachable_users_side_panel.png %})

### 推定数に関する考慮事項 {#considerations-for-estimate-counts}

Brazeは、ユーザーのサブセットをクエリし、その結果をオーディエンス全体に外挿することで推定ユーザー数を測定します。Brazeがクエリするユーザーのサブセットは推定を計算するたびに異なる場合があるため、オーディエンスのメンバーシップが技術的に同じであるべき場合でも、推定値が変わることがあります。たとえば、フィルターの順序を変更したり、異なる時間に同じセグメントを再確認したりすると、推定数が変わる可能性があります（ただし、セグメントが変更されていなければ、**Calculate exact stats**では同じ結果が表示されます）。

ワークスペースに大規模なユーザー群がある場合、特にセグメントがワークスペース全体の人口に対して非常に小さい割合である場合、推定数と正確な計算数の間により大きな差異が見られることがあります。これは、Brazeがユーザーのサブセットをクエリし、その結果をユーザー群全体に外挿して推定を測定するためです。ユーザー群が大きいほど、推定数と正確な数の間の差異が大きくなることが予想されます。

非常に小さなSegmentsでは、推定範囲に0が含まれることがあり、ユーザー総数に対する割合が0に丸められる場合があります。このような場合、**Calculate exact stats**を使用すると、セグメントサイズの正確な数を確認でき、実際には0ではない可能性があります。

![正確なユーザー数「31」を表示する「Reachable users」サイドパネル。]({% image_buster /assets/img_archive/reachable_users_panel.png %})

### チャネル別の到達可能なユーザー {#reachable-users-by-channel}

各メッセージチャネルで到達可能なユーザー数を確認するには、**Reachable users**パネルで**Show breakdown**を選択します。これにより、最も頻繁に使用されるメッセージングチャネル（Webプッシュやメールなど）と、それらの特定のチャネルで到達可能なユーザー数が表示されます。

_Total_指標はユニークユーザーを表します。たとえば、あるユーザーがAndroidプッシュ通知とiOSプッシュの両方を持っている場合、それぞれの行でカウントされますが、_Total_行では1ユーザーとしてのみカウントされます。

ただし、1人のユーザーが異なる到達可能なユーザーグループに属する場合があるため、ユーザーの総数が各チャネルで到達可能なユーザーの合計と異なる可能性があります。たとえば、あるユーザーが有効なメールアドレスと有効なAndroidプッシュトークンの両方を持ち、両方にオプトインしているが、関連するiOSプッシュトークンがない場合があります。

**Reachable users**テーブルにはすべてのチャネルが表示されるわけではないことに注意してください（Content Cards、webhook、WhatsAppなど）。たとえば、WhatsAppでのみ到達可能なユーザーがいる場合、_Total_には反映されますが、チャネル固有の行には表示されません。つまり、到達可能なユーザーの総数は、表示されている各チャネルのユーザー数の合計と異なる場合があります。

_Total_が各チャネルの合計よりも高い場合、その差はセグメントに該当するがそれらのコミュニケーションチャネルでは到達できないユーザーの数を表します。

特定のチャネルで到達可能としてリストされるには、ユーザーは以下を満たす必要があります:
- プロファイルに有効なメールアドレスまたはプッシュトークンが関連付けられていること
- アプリにオプトインまたは購読中であること

#### チャネル固有の到達可能なユーザーに適用されるフィルター {#applied-filters-for-channel-specific-reachable-users}

到達可能なユーザーを判定する際に、各チャネルに以下のフィルターが適用されます。

| チャネル | フィルター |
| --- | --- |
| メール | **Email Available**がtrueであること。 |
| プッシュ | **Foreground Push Enabled**がtrueであること。 |
| SMS | **Subscription Group**がいずれかのSMSサブスクリプショングループであること。**Invalid Phone Number**がfalseであること。 |

## 正確な統計の計算 {#calculating-exact-statistics}

セグメントのユーザー数の正確な数を確認するには、**Reachable users**ペインで**Calculate exact stats**を選択します。

以前実行した計算の統計を更新するには、**Refresh exact statistics**を選択します。この計算が最後に実行された日付は自動的に更新されます。

計算の精度は99.999%以上です。そのため、大きなSegmentsでは、正確な統計を計算する場合でもわずかな変動が見られることがありますが、これは正常な動作です。また、正確な統計の結果は、セグメントを編集しない限り24時間キャッシュされます。編集した場合は、正確な統計を再計算できます。

{% alert note %}
[ランダムバケット番号]({{site.baseurl}}/user_guide/messaging/ab_testing/concepts/random_bucket_numbers/)で均等に分割されたSegmentsは同じサイズにはなりません。たとえば、**ランダムバケット番号が5000未満**のフィルターを持つセグメントと、**ランダムバケット番号が5000以上**のフィルターを持つセグメントを作成した場合、セグメントサイズが数パーセントポイント異なることがあり得ます。これは、非アクティブなユーザーが削除されたり、ユーザーが到達不能になったりする状況によるものです。
{% endalert %}

![正確な統計と展開された内訳メニューを表示するReachable usersパネルのスクリーンショット。]({% image_buster /assets/img_archive/reachable_users_breakdown.png %})

フィルターレベルの統計は、正確な統計を計算した場合でも常に推定値です。**Calculate exact stats**は、フィルターやフィルターグループレベルではなく、セグメントレベルでのみ正確な統計を計算します。この計算の実行には数分かかる場合があります。特に大きなワークスペースでは、計算の完了により長い時間がかかることがあります。**Reachable users**パネルの進行状況バーで進捗を追跡できます。計算に5分以上かかると予想される場合、Brazeは結果をメールで送信します。

Brazeはワークスペースごとに一度に1つの計算を優先するため、複数の計算を同時に実行すると遅延が発生します。**View calculation queue**を選択すると、自分の前にあるSegments、その進捗状況、開始者を確認でき、自分の計算がいつ優先されるかの目安を得ることができます。

![1つの計算がある計算キュー。]({% image_buster /assets/img_archive/calculation_queue.png %})

**Cancel**を選択すると、正確な統計の計算をキャンセルできます。これは、キューに複数の計算がある場合に、別の計算を先に優先したい場合に便利です。

![キャンセルオプションのあるアクティブな計算]({% image_buster /assets/img_archive/cancel_calculation.png %}){: style="max-width:35%"}

## 過去のセグメントメンバーシップサイズの表示 {#viewing-historical-segment-membership-size}

すべてのSegmentsについて、各日の推定セグメントメンバーシップを示す過去のメンバーシップチャートを確認できます。このチャートは、セグメントのサイズが時間の経過とともにどのように変化したかを示します。ドロップダウンを使用して、日付範囲でセグメントメンバーシップをフィルタリングします。

![「Historical Membership」ドロップダウンを使用して、日付範囲でセグメントメンバーシップをフィルタリングします。]({% image_buster /assets/img_archive/historical_membership2.png %})

このチャートの目的は、セグメントメンバーシップの全体的な傾向を把握することであるため、日次カウントは推定値です。これは、**Calculate Exact Statistics**を選択する前のセグメントサイズが推定値であるのと同様です。このグラフは推定値を表示するため、実際のサイズ（**Calculate Exact Stats**を選択した後に確認できます）が「0」でなくても、このチャートではセグメントのサイズが「0」と表示される可能性があります。特に、セグメントがワークスペースの人口に対して非常に小さい場合、チャートで「0」の推定値が表示される可能性が高くなります。

たとえば、ワークスペースに1億人のユーザーがいて、セグメントに約700人のユーザーがいるとします。ある日にはセグメントにユーザーがおらず、過去のメンバーシップ推定に使用されるランダムバケット範囲にユーザーが該当しない場合があり、その日のメンバーシップカウントが0になることがあります。

Brazeは、ユーザーのサブセットをクエリし、その結果をオーディエンス全体に外挿することでセグメントメンバーシップ数を推定します。つまり、チャートの結果はその日のセグメントメンバーシップの推定値のみを提供し、毎日異なるユーザーのサンプルがこの推定のためにクエリされる可能性があるため、日ごとに変動することが予想されます。

{% alert note %}
すべての推定値は、ワークスペースの全人口サイズの約1%の範囲で、表示されている値よりも高くなったり低くなったりする可能性があります。ユーザー数が多い大きなワークスペースでは、正確な計算との差異が数値的に大きくなる可能性がありますが、それでもワークスペースのユーザー人口の1%の範囲内です。つまり、大きなワークスペースでは推定値と正確な数の間の差異が大きくなることが予想されます。
{% endalert %}

### 大幅な変化の理由 {#reasons-for-significant-changes}

メンバーシップ数は、以下のテーブルに示すようなさまざまな理由で大幅に変化する場合があります。

| 理由 | 例 |
| --- | --- |
| 通常のユーザー行動 | 特に成功したCampaignの後にユーザーが購読する。 |
| CSVによるユーザーのインポート | CSVファイルのユーザーがインポートされ、セグメントメンバーシップが大幅に増加した。 |
| セグメントオーディエンス基準の変更 | 既存のセグメントのオーディエンスルール（フィルターなど）が変更され、セグメントメンバーシップに大幅な変化が生じた。 |
| ユーザーの削除 | 大量のユーザーが削除された。 |
| パートナー連携がBrazeと同期 | サードパーティがBrazeにデータを送信し、セグメントメンバーシップに大きな影響を与えた。 |
| 休眠ユーザーのアーカイブ | 大量の非アクティブなプロファイルがアーカイブされた。たとえば、CSVインポートされた大量のユーザーがアクティビティを記録せず、同時にアーカイブされた場合。 |
{: .reset-td-br-1 .reset-td-br-2 aria-label="大幅な変化の理由" }
