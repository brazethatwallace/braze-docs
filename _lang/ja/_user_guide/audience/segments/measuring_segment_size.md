# セグメントサイズの測定 {#measure-segment-size}

> このページでは、セグメントのメンバーシップとサイズを監視する方法について説明します。

## セグメントメンバーシップの計算 {#segment-membership-calculation}

Brazeは、データがサーバーに送信されて処理されると、ユーザーのセグメントメンバーシップを更新します。通常、これは即座に行われます。ユーザーのセグメントメンバーシップは、そのセッションが処理されるまで変更されません。たとえば、セッション開始時に休眠ユーザーセグメントに該当するユーザーは、セッションが処理されると直ちに休眠ユーザーセグメントから移動されます。

### リーチ可能なユーザー総数の計算 {#total-reachable-users-calculation}

各セグメントには、そのセグメントのメンバーであるユーザーの総数が表示されます。**すべてのアプリのユーザー**でフィルタリングすると、最も頻繁に使用されるメッセージングチャネル（Webプッシュやメールなど）と、それらの特定のチャネルでリーチ可能なユーザー数も表示されます。

ユーザーの総数が、各チャネルでリーチ可能なユーザー数と異なる場合があります。また、リーチ可能なユーザーテーブルにすべてのチャネルが表示されるわけではありません。たとえば、Content Cards、webhook、WhatsAppは内訳に表示されません。つまり、リーチ可能なユーザーの総数は、表示されている各チャネルのユーザー数の合計よりも大きくなる可能性があります。

![メール、iOSプッシュ、Androidプッシュ、Webプッシュ、Kindleプッシュでリーチ可能なユーザーごとに分類されたリーチ可能なユーザー総数を表示するテーブル。]({% image_buster /assets/img_archive/segmenter_reachable_users.png %})

ユーザーが特定のチャネルでリーチ可能としてリストされるには、以下の両方が必要です。
* プロフィールに関連付けられた有効なメールアドレスまたはプッシュトークンがあること
* アプリにオプトインまたは購読していること

1人のユーザーが異なるリーチ可能なユーザーグループに属する場合があります。たとえば、あるユーザーが有効なメールアドレスと有効なAndroidプッシュトークンの両方を持ち、両方にオプトインしているが、関連付けられたiOSプッシュトークンがない場合があります。リーチ可能なユーザー総数と各チャネルの合計との差は、セグメントの条件を満たしているが、それらのコミュニケーションチャネルではリーチできないユーザーの数です。

{% alert note %}
**リーチ可能なユーザー総数**には、チャネルの購読を解除していても、セグメントフィルターに一致するすべてのユーザーが含まれます。**iOS**などのチャネル行は、[チャネル別リーチ可能なユーザー](#reachable-users-by-channel)のルールに基づいて、そのチャネルでのみリーチ可能なユーザーをカウントします。セグメントの合計を購読ユーザーと一致させるには、**iOSのプッシュが有効**がtrue（またはチャネルに応じた同等のフィルター）などのフィルターを追加してください。
{% endalert %}

## セグメントサイズの統計 {#statistics-for-segment-size}

推定統計はセグメントの一部のみをサンプリングして算出されるため、推定サイズは実際の値より大きくなったり小さくなったりすることがあります。ワークスペースが大きいほど、誤差の幅も大きくなる可能性があります。セグメント内のユーザーの正確な数を取得するには、**Calculate Exact Statistics** を選択してください。正確なセグメントメンバーシップは、キャンペーンやキャンバスで送信されるメッセージによってセグメントが影響を受ける前に、常に計算されます。

Brazeはセグメントサイズに関する以下の統計を提供しています。

### フィルター統計 {#filter-statistics}

各フィルターグループについて、推定リーチ可能ユーザー数を確認できます。**Expand extra funnel statistics** を選択すると、チャネルごとの内訳が表示されます。

![セッション数がちょうど1回のユーザーを条件とするフィルターを含むフィルターグループ。]({% image_buster /assets/img_archive/segment_filter_stats.png %})

## リーチ可能なユーザーの推定値 {#reachable-users-estimate}

セグメント全体の推定リーチ可能ユーザー数（各チャネルの推定ユーザー数を含む）は、**リーチ可能なユーザー**サイドパネルで確認できます。この推定値は、セグメントサイズのおおよその範囲と、ユーザー群全体のうちこのセグメントに該当するユーザーの割合の推定値を示します。推定統計はセグメントを編集しない限り15分間キャッシュされます。セグメントを編集した場合は、推定統計が自動的に更新されます。また、**正確な統計を計算**を選択すると、リーチ可能なユーザーの正確な数（セグメント全体およびチャネルごと）を確認できます。

{% alert note %}
50,000人を超えるユーザーを持つワークスペースでは**推定ユーザー数**が表示されます。それより小さいワークスペースでは**正確なユーザー数**が表示されます。
{% endalert %}

![推定ユーザー数が230万〜240万であることを示す「リーチ可能なユーザー」パネル。]({% image_buster /assets/img_archive/reachable_users_side_panel.png %})

### 推定カウントに関する考慮事項 {#considerations-for-estimate-counts}

Brazeは、ユーザーのサブセットにクエリを実行し、その結果をオーディエンス全体に外挿することで、推定ユーザー数を算出します。Brazeがクエリを実行するユーザーのサブセットは推定を計算するたびに異なる場合があるため、オーディエンスのメンバーシップが技術的には変わっていないはずの場合でも、推定値が変動することがあります。たとえば、フィルターの順序を変更したり、異なるタイミングで同じセグメントを再確認したりすると、推定カウントが変わる可能性があります（セグメントが変更されていなければ、**正確な統計を計算**では同じ結果が表示されます）。

ワークスペースに大規模なユーザー群がある場合、推定カウントと正確な計算カウントの間により大きな差異が生じることがあります。特に、セグメントがワークスペース全体のユーザー群に対して非常に小さな割合を占める場合に顕著です。これは、Brazeがユーザーのサブセットにクエリを実行し、その結果をユーザー群全体に外挿して推定値を算出するためです。ユーザー群が大きいほど、推定値と正確なカウントの間の差異が大きくなることが予想されます。

非常に小さなセグメントでは、推定範囲に0が含まれることがあり、ユーザー全体に対する割合が0に丸められる場合があります。このような場合、**正確な統計を計算**を使用すると、セグメントサイズの正確なカウントを確認でき、実際には0ではない可能性があります。

![正確なユーザー数「31」を示す「リーチ可能なユーザー」サイドパネル。]({% image_buster /assets/img_archive/reachable_users_panel.png %})

### チャネル別のリーチ可能なユーザー {#reachable-users-by-channel}

各メッセージチャネルでリーチ可能なユーザー数を確認するには、**リーチ可能なユーザー**パネルで**内訳を表示**を選択します。これにより、最も頻繁に使用されるメッセージングチャネル（Webプッシュやメールなど）と、それらの特定のチャネルでリーチ可能なユーザー数が表示されます。

_合計_の指標はユニークユーザーを表します。たとえば、あるユーザーがAndroidプッシュとiOSプッシュの両方を持っている場合、そのユーザーは両方の行でカウントされますが、_合計_行では1ユーザーとしてのみカウントされます。

ただし、1人のユーザーが異なるリーチ可能なユーザーグループに属する可能性があるため、合計ユーザー数が各チャネルでリーチ可能なユーザーの合計と異なる場合があります。たとえば、あるユーザーが有効なメールアドレスと有効なAndroidプッシュトークンの両方を持ち、両方にオプトインしているが、関連するiOSプッシュトークンを持っていない場合があります。

**リーチ可能なユーザー**テーブルにはすべてのチャネルが表示されるわけではないことに注意してください（Content Cards、webhook、WhatsAppなど）。たとえば、WhatsAppでのみリーチ可能なユーザーがいる場合、そのユーザーは_合計_には反映されますが、チャネル固有の行には表示されません。つまり、リーチ可能なユーザーの合計数は、表示されている各チャネルのユーザー数の合計とは異なる場合があります。

_合計_がチャネルの合計よりも大きい場合、その差はセグメントの条件を満たしているが、それらのコミュニケーションチャネルではリーチできないユーザーの数を表します。

特定のチャネルでリーチ可能としてリストされるには、ユーザーは以下の条件を満たす必要があります：
- プロファイルに有効なメールアドレスまたはプッシュトークンが関連付けられていること
- アプリにオプトインまたは購読していること

#### チャネル別リーチ可能ユーザーに適用されるフィルター {#applied-filters-for-channel-specific-reachable-users}

リーチ可能なユーザーを判定する際に、各チャネルに以下のフィルターが適用されます。

| チャネル | フィルター |
| --- | --- |
| メール | **Email Available**がtrueであること。 |
| プッシュ | **Foreground Push Enabled**がtrueであること。 |
| SMS | **Subscription Group**がいずれかのSMS購読グループであること。**Invalid Phone Number**がfalseであること。 |

## 正確な統計の計算 {#calculating-exact-statistics}

セグメント内のユーザー数の正確なカウントを表示するには、**リーチ可能なユーザー**ペインで**正確な統計を計算**を選択します。

以前実行した計算の統計を更新するには、**正確な統計を更新**を選択します。この計算が最後に実行された日付は自動的に更新されます。

計算の精度は99.999%以上にすぎないことに注意してください。そのため、大規模なセグメントでは、正確な統計を計算した場合でもわずかな変動が見られることがありますが、これは正常な動作です。また、正確な統計の結果はセグメントを編集しない限り24時間キャッシュされます。編集した場合は、正確な統計を再計算できます。

{% alert note %}
[ランダムバケット番号]({{site.baseurl}}/user_guide/messaging/ab_testing/concepts/random_bucket_numbers)で均等に分割されたセグメントは同じサイズにはなりません。たとえば、**ランダムバケット番号が5000未満**というフィルターで1つのセグメントを作成し、**ランダムバケット番号が5000以上**というフィルターでもう1つのセグメントを作成した場合、セグメントサイズが数パーセントポイントまで異なることがあり得ますが、これは想定される動作です。これは、非アクティブなユーザーが削除されたり、ユーザーにリーチできなくなったりする状況が原因です。
{% endalert %}

![正確な統計と展開された内訳メニューが表示されたリーチ可能なユーザーパネルのスクリーンショット。]({% image_buster /assets/img_archive/reachable_users_breakdown.png %})

フィルターレベルごとの統計は、正確な統計を計算した場合でも常に推定値です。**正確な統計を計算**は、セグメントレベルでの正確な統計のみを計算し、フィルターやフィルターグループレベルでは計算しません。この計算の実行には数分かかる場合があります。特に大規模なワークスペースでは、計算の完了に長い時間がかかることがあります。**リーチ可能なユーザー**パネルのプログレスバーで進捗状況を確認できます。計算に5分以上かかると予想される場合、Brazeは結果をメールで送信します。

Brazeはワークスペースごとに一度に1つの計算を優先するため、複数の計算を同時に実行すると遅延が発生します。**計算キューを表示**を選択すると、自分の計算より前にあるセグメント、その進捗状況、開始者を確認でき、自分の計算がいつ優先されるかの目安を得ることができます。

![1つの計算が含まれる計算キュー。]({% image_buster /assets/img_archive/calculation_queue.png %})

**キャンセル**を選択すると、正確な統計の計算をキャンセルできます。これは、キューに複数の計算がある場合に、別の計算を先に優先したいときに便利です。

## セグメントメンバーシップサイズの履歴を表示する {#viewing-historical-segment-membership-size}

すべてのセグメントについて、各日の推定セグメントメンバーシップを示す履歴メンバーシップチャートを表示できます。このチャートは、セグメントのサイズが時間の経過とともにどのように変化したかを示します。ドロップダウンを使用して、日付範囲でセグメントメンバーシップをフィルターできます。

![履歴メンバーシップのドロップダウンを使用して、日付範囲でセグメントメンバーシップをフィルターします。]({% image_buster /assets/img_archive/historical_membership2.png %})

このチャートの目的は、セグメントメンバーシップ全体のトレンドを把握することであるため、日次カウントは推定値であり、**正確な統計を計算**を選択する前のセグメントサイズが推定値であるのと同様です。このグラフは推定値を表示するため、セグメントの実際のサイズ（**正確な統計を計算**を選択した後に確認できます）が「0」でなくても、このチャートではセグメントのサイズが「0」と表示される場合があります。特に、ワークスペースの全体人口に対してセグメントが非常に小さい場合、チャートに推定値「0」が表示される可能性が高くなります。

たとえば、ワークスペースに1億人のユーザーが含まれ、セグメントに約700人のユーザーがいるとします。一部の日には、セグメントにユーザーがおらず、履歴メンバーシップの推定に使用されるランダムバケット範囲にユーザーが入らないことがあり、その日のメンバーシップカウントが0になる場合があります。

Brazeは、ユーザーのサブセットをクエリし、その結果をオーディエンス全体に外挿することで、セグメントメンバーシップカウントを推定します。つまり、チャートの結果はその日のセグメントメンバーシップの推定値のみを提供し、毎日異なるユーザーサンプルがこの推定のためにクエリされる可能性があるため、日ごとに変動することが予想されます。

{% alert note %}
すべての推定値は、ワークスペースの全体人口サイズの約1%の範囲で、表示値より高くなったり低くなったりする場合があります。ユーザー数が多い大規模なワークスペースでは、ワークスペースのユーザー人口の1%の差であっても、正確な計算との差が数値的に大きくなる可能性が高くなります。これは、大規模なワークスペースにおける推定値と正確なカウントの間の大きな差は想定されるものであることを意味します。
{% endalert %}

### 大幅な変化の理由 {#reasons-for-significant-changes}

メンバーシップカウントは、以下の表に示すようなさまざまな理由で大幅に変化する場合があります。

| 理由 | 例 |
| --- | --- |
| 通常のユーザー行動 | 特に成功したキャンペーンの後にユーザーが購読します。 |
| CSVによるユーザーのインポート | ユーザーのCSVファイルがインポートされ、セグメントメンバーシップが大幅に増加しました。 |
| セグメントのオーディエンス条件の変更 | 既存のセグメントのオーディエンスルール（フィルターなど）が変更され、セグメントメンバーシップに大幅な変化が生じました。 |
| ユーザーの削除 | 大量のユーザーが削除されました。 |
| パートナー連携がBrazeと同期 | サードパーティがBrazeにデータを送信し、セグメントメンバーシップに大きな影響を与えました。 |
| 休眠ユーザーのアーカイブ | 大量の非アクティブなプロファイルがアーカイブされました。たとえば、CSVでインポートされた多数のユーザーがアクティビティを記録せず、同時にアーカイブされた場合などです。 |
