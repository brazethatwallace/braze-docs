# ジオフェンス {#geofences}

> ジオフェンスは、緯度と経度に半径を組み合わせた仮想的な地理的エリアで、特定のグローバル位置を中心とした円を形成します。ジオフェンスは建物サイズから都市全体のサイズまでさまざまです。ジオフェンスを使用して、ユーザーがその境界に出入りする際にリアルタイムでCampaignをトリガーしたり、数時間後や数日後にフォローアップCampaignを送信したりできます。

{% alert tip %}
ガイド付きウォークスルーについては、Brazeラーニングコース[ジオフェンスの作成](https://learning.braze.com/create-a-geofence)を参照してください。
{% endalert %}

## 仕組み {#how-it-works}

ジオフェンスはジオフェンスセット（プラットフォーム全体でユーザーのセグメンテーションやエンゲージメントに使用できるジオフェンスのグループ）に整理されます。各ジオフェンスセットには最大10,000個のジオフェンスを保持できます。ジオフェンスは無制限に作成またはアップロードできます。

ジオフェンスに出入りするユーザーは、セグメンテーションやリターゲティングに使用できる新しいユーザーデータのレイヤーを追加します。

以下のデバイス制限に注意してください：

- Androidアプリは一度にローカルで最大100個のジオフェンスを保存できます。Brazeはアプリごとにローカルで最大20個のジオフェンスのみを保存するように設定されています。
- iOSデバイスはアプリごとに一度に最大20個のジオフェンスを監視できます。Brazeは空きがある場合、最大20のロケーションを監視します。
- ユーザーが20個を超えるジオフェンスの受信対象である場合、Brazeはセッション開始時にユーザーへの近接度に基づいて最大数のロケーションをダウンロードします。
- ジオフェンスが正しく機能するには、アプリが利用可能なジオフェンススポットをすべて使い切っていないことを確認してください。

以下の表は一般的なジオフェンス用語を説明しています：

| 用語 | 説明 |
|---|---|
| 緯度と経度 | ジオフェンスの地理的中心。 |
| 半径 | ジオフェンスの半径（メートル単位）。地理的中心から測定されます。すべてのジオフェンスに対して最小半径を100メートルから150メートルに設定してください。 |
| クールダウン | ユーザーは個々のジオフェンスで入場または退場のトランジションを実行した後、ジオフェンストリガーの通知を受け取ります。トランジションが発生した後、そのユーザーが同じ個別のジオフェンスで同じトランジションを再度実行できない事前定義された期間があります。この「クールダウン」はBrazeによって事前定義されており、主な目的は不要なネットワークリクエストを防ぐことです。 |
{: .reset-td-br-1 .reset-td-br-2 aria-label="How it works" }

## 前提条件 {#prerequisites}

### SDKとプラットフォームの要件 {#sdk-and-platform-requirements}

ジオフェンストリガーのCampaignはiOSとAndroidで利用できます。ジオフェンスをサポートするには、以下が必要です：

* Brazeジオフェンスまたは位置情報収集が有効になっていること。
* ユーザーが「常に許可」の位置情報アクセスを付与していること。

{% alert important %}
Brazeの位置情報収集はデフォルトで無効になっています。Androidで有効になっていることを確認するには、`braze.xml`で`com_braze_enable_location_collection`が`true`に設定されていることを確認してください。
{% endalert %}

プラットフォーム固有のセットアップ手順については、開発者ガイドの[ジオフェンス]({{site.baseurl}}/developer_guide/geofences/)を参照してください。

### 位置情報の権限 {#location-permissions}

ジオフェンスが機能するには、ユーザーがアプリに位置情報へのアクセス権限を付与する必要があります。さまざまな権限レベルとジオフェンシングへの影響を理解することは、効果的な位置情報ベースの戦略を構築するために不可欠です。

## 位置情報の権限について {#understanding-location-permissions}

iOSとAndroidの両方で、複数レベルの位置情報アクセスが提供されています。ユーザーが付与する権限レベルは、ジオフェンシングが機能するかどうか、および位置情報データの精度に直接影響します。

### 権限レベル {#permission-levels}

{% tabs local %}
{% tab iOS %}

| 権限 | 説明 | ジオフェンシングのサポート |
|---|---|---|
| **1回だけ許可** | 単一セッションの位置情報アクセスを付与します。次にユーザーがアプリを開いたときにプロンプトが再表示されます。 | いいえ。バックグラウンドトラッキングが無効なため、デバイスはアプリが開いているときのみ位置情報の更新を受信します。 |
| **アプリの使用中は許可** | アプリがフォアグラウンドにあるときに位置情報アクセスを付与します。これが付与された後、iOSは「常に許可」へのアップグレードを求めるフォローアッププロンプトを表示する場合があります。 | はい。iOSはこの権限を持つアプリに対して、ジオフェンストランジションを含むバックグラウンド位置情報監視を有効にします。 |
| **常に許可** | バックグラウンドやアプリが閉じているときを含む、継続的な位置情報アクセスを付与します。 | はい。最も信頼性の高いジオフェンス監視を提供します。 |
| **許可しない** | すべての位置情報アクセスを拒否します。 | いいえ。 |

### 正確な位置情報と概算位置情報 {#precise-versus-approximate-location}

iOS 14以降およびAndroid 12以降では、ユーザーは正確な位置情報と概算位置情報を選択できます。

| 設定 | 精度 | ジオフェンシングへの影響 |
|---|---|---|
| **正確な位置情報（オン）** | GPS、Wi-Fi、セルラー三角測量を使用して5メートルから50メートルの範囲の精度。 | ジオフェンスは期待どおりに機能します。すべてのジオフェンスベースのユースケースに推奨されます。 |
| **概算位置情報（オフ）** | 約3平方キロメートル（約1平方マイル）の精度。デバイスは正確な座標ではなく一般的なエリアを返します。 | ジオフェンスは確実にトリガーされません。デバイスはユーザーがジオフェンス境界の内側にいるか外側にいるかを正確に判断できません。 |
{: .reset-td-br-1 .reset-td-br-2 .reset-td-br-3 aria-label="Precise versus approximate location" }

{% alert important %}
ジオフェンシングが確実に機能するには、ユーザーが正確な位置情報を有効にする必要があります。位置情報権限プライマーのメッセージングにこのガイダンスを含めて、正確な位置情報が重要な理由をユーザーに理解してもらいましょう。
{% endalert %}

## 位置情報権限プライマーの設定 {#setting-up-a-location-permission-primer}

位置情報権限プライマーは、ユーザーがネイティブOSの権限プロンプトを見る前に、位置情報データを共有する価値を説明するアプリ内メッセージです。ネイティブの位置情報プロンプトは（iOSでは）1回のみ、または（Androidでは）限られた回数しか表示できないため、事前にユーザーを準備することでオプトイン率が向上します。

### ステップ 1：開発チームと連携する {#step-1-work-with-your-development-team}

Brazeのアプリ内メッセージにはネイティブの位置情報権限プロンプトを呼び出す組み込みボタンアクションが含まれていないため、開発チームがデバイス側で位置情報の権限を処理する必要があります。Brazeでアプリ内メッセージを構築する前に、開発チームと連携して、アプリ内メッセージが呼び出せるディープリンクを設定してください。具体的な実装はアプリのアーキテクチャによって異なりますが、一般的なアプローチには以下が含まれます：

- アプリ内からネイティブの位置情報権限プロンプトをトリガーするディープリンク。
- デバイスのOS設定でアプリの位置情報設定ページを開くディープリンク。これは以前に権限を拒否または制限したユーザーに再度プロンプトを表示する場合に便利です。

ディープリンクの詳細については、[アプリ内コンテンツへのディープリンク]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/actions_and_media_urls/)を参照してください。位置情報とジオフェンスのインテグレーションに関するプラットフォーム固有のガイダンスについては、開発者ガイドの[ジオフェンス]({{site.baseurl}}/developer_guide/geofences/)を参照してください。

### ステップ 2：位置情報プライマーのアプリ内メッセージを構築する {#step-2-build-the-location-primer-in-app-message}

位置情報アクセスの価値を説明するアプリ内メッセージCampaignを作成します。ドラッグ＆ドロップを含むすべてのアプリ内メッセージタイプがこのオプトインをサポートしています。

1. **Messaging** > **Campaigns**に移動し、**キャンペーンを作成** > **アプリ内メッセージ**を選択します。
2. メッセージタイプとレイアウトを選択します。**モーダル**または**フル**レイアウトを使用すると、メリットを説明するためのスペースが広くなります。
3. 位置情報アクセスがユーザーにとってなぜ有益かを明確に説明するメッセージを作成します。例：
    - 「位置情報を有効にして、近くのお得な情報の通知を受け取りましょう。」
    - 「位置情報をオンにすると、最寄りの店舗で注文の受け取り準備ができたときにお知らせできます。」
4. プライマリのコールトゥアクションボタン（**Turn On Location**など）を追加し、クリック時の動作を**Deep Link into App**に設定して、開発チームがネイティブの位置情報プロンプトをトリガーするために作成したディープリンクを使用します。
5. セカンダリボタン（**Not Now**など）を追加して、メッセージを閉じるようにします。

### ステップ 3：適切なオーディエンスをターゲットにする {#step-3-target-the-right-audience}

最良の結果を得るには、ユーザーがエンゲージしていて位置情報の共有に価値を感じる可能性が高いときに位置情報プライマーを表示します。

- **まだ位置情報アクセスを付与していないユーザーをターゲットにします。** 位置情報の権限ステータスに基づいてユーザーを追跡しセグメント化する最適な方法を開発チームと協力して決定してください。
- **購入の完了、お気に入りの店舗の保存、近くのイベントの閲覧など、高価値のアクションの後にプライマーのタイミングを合わせます。** ユーザーはメリットを理解しているときにオプトインする可能性が高くなります。
- **初回起動時にプライマーを表示することは避けてください。** ユーザーがよりパーソナライズされた体験を望むほどアプリから十分な価値を体験するまで待ちましょう。

### ステップ 4：推奨される権限レベルを促す {#step-4-encourage-the-recommended-permission-level}

プライマーのメッセージングでは、ジオフェンシングを有効にする権限レベルの付与をユーザーに促す必要があります：

- **iOSでは、** 最低でも**アプリの使用中は許可**を選択するようユーザーに促します。iOSは後で独自に**常に許可**へのアップグレードをユーザーに促す場合があります。「常に許可」がなぜ最良の体験を提供するかを説明する別のCampaignでフォローアップすることもできます。
- **Androidでは、** **常に許可**を付与するようユーザーに促します。Android 10以降では、ユーザーはまず「アプリの使用中のみ」を付与し、その後別のフォローアッププロンプトで「常に許可」を付与する必要があります。両方のステップをガイドしてください。

いずれの場合も、最良の体験のために**正確な位置情報**をオンにしておくようユーザーに伝えてください。

## ユーザーをOS設定にリダイレクトする {#redirecting-users-to-os-settings}

ユーザーが以前に位置情報アクセスを拒否したか、制限付きの権限を選択した場合、ほとんどのOSバージョンではアプリ内からネイティブプロンプトを再度トリガーすることはできません。代わりに、デバイス設定で権限を更新するよう案内します。

カスタム[アプリ内メッセージ]({{site.baseurl}}/user_guide/channels/in_app_messages/traditional/)内のディープリンクを使用して、OSのアプリの位置情報設定ページにユーザーを誘導します。開発チームは、アプリの位置情報権限処理の一部としてこのためのディープリンクを設定できます（[ステップ 1](#step-1-work-with-your-development-team)を参照）。

このアプリ内メッセージを構築する際は、以下を考慮してください：

- **表示するタイミング：** 「常に許可」が必要なときに「アプリの使用中のみ」の権限を持つユーザー、または以前に位置情報アクセスを拒否したユーザーをターゲットにします。
- **メッセージの例：** 「位置情報ベースの機能を最大限に活用するには、位置情報の設定を『常に許可』に更新してください。下のボタンをタップして設定に移動します。」

{% alert tip %}
このアプリ内メッセージは、ユーザージャーニーの任意のポイント（購入後、近くのコンテンツを閲覧しているとき、またはCanvasフローの一部として）でトリガーできます。再プロンプトする際は選択的に行いましょう。オプトイン疲れを避けるため、これらのCampaignをロイヤルまたは高エンゲージメントのユーザーに限定してください。
{% endalert %}

## 位置情報プライミング戦略の例 {#example-location-priming-strategies}

### 「アプリの使用中は許可」プライマー {#while-using-the-app-primer}

小売アプリが、ユーザーがお気に入りの店舗を保存した後にモーダルのアプリ内メッセージを表示します：

- **見出し：** 「店舗内のお得な情報の通知を受け取る」
- **本文：** 「位置情報をオンにすると、お気に入りの店舗の近くにいるときに限定オファーをお送りできます。位置情報はアプリの使用中のみアクセスされます。」
- **CTA：** **Turn On Location**がネイティブの位置情報権限プロンプトにディープリンクします
- **閉じる：** **Maybe Later**がメッセージを閉じます

このアプローチは、ユーザーがすでに特定の店舗に興味を示しているため、位置情報権限リクエストの自然なコンテキストが生まれ、効果的です。

### 「常に許可」フォローアップ {#always-allow-follow-up}

ユーザーが「アプリの使用中は許可」の権限を付与した後、次のセッション中にフォローアップのアプリ内メッセージを表示します：

- **見出し：** 「近くのお得な情報を見逃さない」
- **本文：** 「位置情報の設定を『常に』に更新すると、アプリを閲覧していないときでもオファーについて通知できます。参加店舗の近くにいるときのみ関連するアラートを送信します。」
- **CTA：** **Update Settings**がOSのアプリの位置情報設定ページにディープリンクします
- **閉じる：** **Keep Current Settings**がメッセージを閉じます

このフォローアップにより、「常に許可」へのアップグレードが最初の権限レベルを超えた追加の価値を提供する理由をユーザーに伝えます。

## ジオフェンスを手動で作成する {#manually-create-geofences}

### ステップ 1：ジオフェンスセットを作成する {#step-1-create-a-geofence-set}

ジオフェンスを作成するには、まずジオフェンスセットを作成します。

1. Brazeダッシュボードで**Audience** > **Locations**に移動します。
2. **Create Geofence Set**を選択します。
3. **Set name**にジオフェンスセットの名前を入力します。
4. （オプション）セットをフィルタリングするためのタグを追加します。

### ステップ 2：ジオフェンスを追加する {#step-2-add-the-geofences}

次に、ジオフェンスセットにジオフェンスを追加します。

1. **Draw Geofence**を選択して、マップ上の円をクリックしてドラッグします。必要に応じて繰り返してセットにジオフェンスを追加します。
2. （オプション）**Edit**を選択して、ジオフェンスの説明を名前に置き換えます。
3. （オプション）**Show Advanced Settings**を選択し、これらの設定を使用してジオフェンス分析の記録方法を制御します：
  - **Enable Analytics for Enter**と**Enable Analytics for Exit**を選択して、レポートと分析のために[`USERS_BEHAVIORS_GEOFENCE_DATAEVENT_SHARED` SQLテーブル]({{site.baseurl}}/user_guide/audience/segments/segment_extension/sql_segments/sql_segments_tables/#USERS_BEHAVIORS_GEOFENCE_DATAEVENT_SHARED)に入場と退場のアクティビティを記録します。
  - クールダウン期間を設定して、同じユーザーがそのジオフェンスの別の入場または退場イベントをトリガーするまでに経過する必要がある秒数を設定します。クールダウンを設定しない場合、デフォルトは6時間です。
  - **Android Notification Responsiveness**を使用して、Androidデバイスが入場または退場イベントをアプリに配信する際の最大遅延（秒単位）を設定します。

{: start="4" }
4. **Save Geofence Set**を選択して保存します。

{% alert tip %}
最適な機能のために、半径200メートル以上のジオフェンスを作成してください。詳細については、[ジオフェンスのベストプラクティス](#geofence-best-practices)を参照してください。
{% endalert %}

## ジオフェンスの一括アップロード {#creating-geofence-sets-via-bulk-upload}

ジオフェンスは`FeatureCollection`タイプのGeoJSONオブジェクトとして一括アップロードできます。各ジオフェンスはフィーチャーコレクション内の`Point`ジオメトリタイプです。各フィーチャーのプロパティには`radius`キーが必要で、各ジオフェンスにオプションの`name`キーがあります。

JSONファイルをアップロードするには、**More** > **Upload JSON**を選択します。

ジオフェンスを作成する際は、以下の詳細を考慮してください：

- GeoJSONの`coordinates`値は`[経度, 緯度]`の形式です。
- アップロードできるジオフェンスの最大半径は10,000メートル（約10キロメートルまたは6.2マイル）です。

### 例 {#example}

以下の例は、2つのジオフェンスを指定するための正しいGeoJSON形式を示しています：1つはニューヨークのBraze本社、もう1つはマンハッタン南部の自由の女神像です。

```json
{
  "type": "FeatureCollection",
  "features": [
    {
      "type": "Feature",
      "geometry": {
        "type": "Point",
        "coordinates": [-73.9853689, 40.7434683]
      },
      "properties": {
        "radius": 200,
        "name": "Braze HQ"
      }
    },
    {
      "type": "Feature",
      "geometry": {
        "type": "Point",
        "coordinates": [-74.044468, 40.689225]
```

## ジオフェンスイベントの使用 {#using-geofence-events}

ジオフェンスを設定した後、それらを使用してユーザーとのコミュニケーション方法を強化し充実させることができます。

### CampaignとCanvasのトリガー {#triggering-campaigns-and-canvases}

ジオフェンスデータをCampaignとCanvasのトリガーの一部として使用するには、配信方法として**アクションベースの配信**を選択します。次に、`Trigger a Geofence`のトリガーアクションを追加します。最後に、メッセージのジオフェンスセットとジオフェンストランジションイベントタイプを選択します。ジオフェンスイベントを使用してCanvasでユーザーを進めることもできます。

## ジオフェンスセットの更新 {#updating-geofence-sets}

Braze SDKはセッション開始時に1日1回のみジオフェンスをリクエストします。セッション開始後にジオフェンスセットに変更を加えた場合、更新されたセットを受信するには、セットが最初にプルダウンされた時点から24時間待つ必要があります。

{% alert note %}
ジオフェンスがデバイスにローカルで読み込まれていない場合、ユーザーがエリアに入ってもジオフェンスをトリガーできません。
{% endalert %}

## ジオフェンスのベストプラクティス {#geofence-best-practices}

### ジオフェンスの設定 {#geofence-configuration}

- 信頼性の高いトリガーのために200メートル以上の半径を使用してください。
- 重複したり入れ子になったりするジオフェンスの設定は避けてください。トリガーに問題が発生する可能性があります。
- ジオフェンスは6時間に1回のみ入場イベントをトリガーできます。このクールダウン期間はローカルで適用されます。ユーザーがアプリをアンインストールしたりアプリデータをクリアしたりすると、すべてのクールダウンがリセットされます。
- デバイスには合計20個以下のジオフェンスしか保存できません。ユーザーが20個を超える対象である場合、Brazeはセッション開始時に近接度に基づいて最も近いロケーションをダウンロードします。
- Brazeはユーザーから2,000キロメートル以内のジオフェンスのみをデバイスに送信します。

### デバイスの要件 {#device-requirements}

- アプリケーションのユーザーが位置情報の権限を付与する必要があります。詳細については、[位置情報の権限](#location-permissions)セクションを参照してください。

{% alert note %}
基本的なSDKインテグレーションでは位置情報の追跡のみが有効になります。ジオフェンシングにはiOSとAndroidの両方で追加のセットアップステップが必要です。詳細については、開発者ガイドの[ジオフェンス]({{site.baseurl}}/developer_guide/geofences/)を参照してください。
{% endalert %}

[Radar]({{site.baseurl}}/partners/message_personalization/location/radar/)や[Foursquare]({{site.baseurl}}/partners/message_personalization/location/foursquare/)などのBrazeテクノロジーパートナーとジオフェンスを使用することもできます。

## よくある質問 {#frequently-asked-questions}

### Brazeジオフェンスの精度はどの程度ですか？ {#how-accurate-are-braze-geofences}

Brazeジオフェンスは、Wi-Fi、GPS、セルラータワーなど、デバイスで利用可能なすべての位置情報プロバイダーの組み合わせを使用してユーザーの位置を三角測量します。

一般的な精度は20メートルから50メートルの範囲で、最良の場合は5メートルから10メートルの範囲です。農村部では精度が大幅に低下し、数キロメートルに達する可能性があります。農村部のロケーションではより大きな半径のジオフェンスを作成してください。

精度は、ユーザーが正確な位置情報を有効にしているかどうかにも依存します。概算位置情報のみの場合、精度は約3平方キロメートルに低下し、ジオフェンスは信頼性が低くなります。詳細については、[正確な位置情報と概算位置情報](#precise-versus-approximate-location)を参照してください。

### ジオフェンスはバッテリー寿命にどのように影響しますか？ {#how-do-geofences-affect-battery-life}

Brazeのジオフェンシングは、iOSとAndroidのネイティブジオフェンスシステムサービスを使用しています。精度と電力をインテリジェントにトレードオフするように調整されており、基盤となるサービスが改善されるにつれてバッテリー寿命を節約しパフォーマンスを向上させます。

### ジオフェンスはいつアクティブになりますか？ {#when-are-geofences-active}

Brazeジオフェンスは、アプリが閉じているときも含め、1日中いつでも機能します。定義されてBrazeダッシュボードにアップロードされるとすぐにアクティブになります。ただし、ユーザーが位置情報の追跡を無効にしている場合、ジオフェンスは機能しません。

ジオフェンスが機能するには、ユーザーがデバイスで位置情報サービスを有効にし、アプリに必要な位置情報の権限レベルを付与している必要があります。詳細については、[位置情報の権限について](#understanding-location-permissions)を参照してください。

### ジオフェンスデータはユーザープロファイルに保存されますか？ {#is-geofence-data-stored-in-user-profiles}

いいえ、Brazeはユーザープロファイルにジオフェンスデータを保存しません。ジオフェンスはAppleとGoogleの位置情報サービスによって監視され、Brazeはユーザーがジオフェンスをトリガーしたときにのみ通知を受けます。その時点で、Brazeは関連するトリガーCampaignを処理します。

### ジオフェンスの中にジオフェンスを設定できますか？ {#can-i-set-up-a-geofence-within-a-geofence}

ベストプラクティスとして、互いに重複するジオフェンスの設定は避けてください。通知のトリガーに問題が発生する可能性があります。

### ユーザーが位置情報アクセスを拒否した場合はどうなりますか？ {#what-if-a-user-denies-location-access}

開発チームは、OSのアプリの位置情報設定ページを開くディープリンクを設定でき、ユーザーはそこで権限を更新できます。このディープリンクをユーザージャーニーの任意のポイントでカスタムアプリ内メッセージ内で使用できます。このメッセージを表示するタイミングは選択的に行いましょう。オプトインの可能性を高めるために、エンゲージしているユーザーや高価値のアクションを実行したユーザーをターゲットにしてください。詳細については、[ユーザーをOS設定にリダイレクトする](#redirecting-users-to-os-settings)を参照してください。
