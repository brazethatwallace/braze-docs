# 再入荷通知 {#back-in-stock-notifications}

> カタログとカスタムイベントを使用して再入荷通知を設定する方法を説明します。このように設定することで、商品が再入荷したときに通知を受け取るように、顧客を自動的に購読登録できます。これは、すでに通知をオプトインしているユーザーにのみ適用されます。

## 仕組み {#how-it-works}

`product_clicked` イベントなど、サブスクリプションイベントとして使用するカスタムイベントを設定できます。このイベントには、アイテムID（カタログアイテムID）のプロパティが含まれている必要があります。カタログ名を含めることをお勧めしますが、必須ではありません。在庫数量フィールドの名前も指定する必要があり、これは数値データタイプでなければなりません。

ユーザーが正常に購読登録するには、カタログアイテムの在庫がゼロである必要があります。アイテムの在庫数がゼロより大きくなると、Brazeはそのアイテムを購読しているすべてのユーザーを検索し、キャンペーンやキャンバスのトリガーとして使用できるカスタムイベントを送信します。

イベントプロパティはユーザーと一緒に送信されるため、送信するキャンペーンまたはキャンバスにアイテムの詳細をテンプレートとして挿入できます。

## 再入荷通知の設定 {#setting-up-back-in-stock-notifications}

次のステップに従って、特定のカタログで再入荷通知を設定します。

1. カタログに移動し、**設定**タブを選択します。
2. **Back in stock** トグルを選択します。
3. グローバルな再入荷設定がまだ構成されていない場合、再入荷通知をトリガーするために使用されるカスタムイベントとプロパティを設定するように求められます。
    <br> ![カタログ設定ドロワー。]({% image_buster /assets/img/catalog_settings_drawer.png %}){: style="max-width:70%;"}
    - **フォールバックカタログ**: カスタムイベントに `catalog_name` プロパティが存在しない場合に、再入荷サブスクリプションに使用されるカタログです。
    - **サブスクリプション用カスタムイベント**: ユーザーを再入荷通知に購読登録するために使用されるBrazeのカスタムイベントです。このイベントが発生すると、そのイベントを実行したユーザーが購読登録されます。
    - **購読解除用カスタムイベント**: 再入荷通知からユーザーの購読を解除するために使用されるBrazeのカスタムイベントです。このイベントはオプションです。ユーザーがこのイベントを実行しなかった場合、90日後または再入荷イベントがトリガーされた時点のいずれか早い方で購読解除されます。
    - **アイテムIDイベントプロパティ**: 上記のカスタムイベントのプロパティで、再入荷の購読または購読解除を行うアイテムを決定するために使用されます。カスタムイベントのこのプロパティには、カタログに存在するアイテムID（`id`）を含める必要があります。アイテムIDは、ターゲットカタログに格納されている `id` データタイプと一致するように、文字列として送信される必要があります。カスタムイベントには、このアイテムがどのカタログに属するかを指定する `catalog_name` プロパティも含める必要があります。

    - カスタムイベントのサンプルは次のようになります。

```json
{
    "events": [
        {
            "external_id": "<external_id>",
            "name": "subscription",
            "time": "2024-04-15T19:22:28Z",
            "properties": {
                "id": "shirt-xl",
                "catalog_name": "on_sale_products",
                "type": ["back_in_stock"]
            }
        }
    ]
}
```

{% alert note %}
再入荷トリガーと値下げトリガーは、同じイベントを使用してユーザーを通知に購読登録するため、`type` プロパティを使用して同じイベントで値下げと再入荷の両方の通知を設定できます。`type` プロパティは配列でなければなりません。
{% endalert %}

{: start="4"}
4. **Save** を選択し、カタログの**設定**ページに進みます。
5. 通知ルールを設定します。2つのオプションがあります。
    - **Notify all subscribed users** は、商品が再入荷したときに、待機中のすべての顧客に通知します。
    - **Set notification limits** は、設定した通知期間ごとに指定した数の顧客に通知します。Brazeは、通知対象の顧客がいなくなるか、商品が在庫切れになるまで、指定された数の顧客に段階的に通知を行います。通知速度は1分あたり10,000ユーザーを超えることはできません。
6. **Inventory field in catalog** を設定します。このカタログフィールドは、アイテムが在庫切れかどうかを判断するために使用されます。フィールドは数値型でなければなりません。
7. **Save settings** を選択します。

![カタログ設定で、再入荷機能がオンになっていることを示しています。通知ルールは、10分ごとに1,000人のユーザーに通知する設定です。]({% image_buster /assets/img/back_in_stock_settings.png %})

{% alert important %}
これらの設定の通知ルールは、サイレント時間などのキャンバスの通知設定を置き換えるものではありません。
{% endalert %}

## キャンバスでの再入荷通知の使用 {#using-back-in-stock-notifications-in-a-canvas}

カタログで再入荷機能を設定した後、キャンバスで使用するには以下のステップに従います。

1. アクションベースのキャンバスを設定します。
2. トリガーとして**Back in stock**を選択します。
3. 再入荷通知があるカタログの名前を選択します。
4. 通常どおりキャンバスの[セットアップ]({{site.baseurl}}/user_guide/messaging/canvas/create_a_canvas)を続けます。

これで、商品が再入荷した際に顧客に通知できるようになります。

### Liquidの使用 {#using-liquid}

再入荷したカタログアイテムの詳細をテンプレート化するには、`context` Liquidタグを使用して `item_id` にアクセスできます。

{%raw%}``{{context.${catalog_update}.item_id}}``{%endraw%}を使用すると、再入荷したアイテムのIDが返されます。{%raw%}``{{context.${catalog_update}.previous_value}}``{%endraw%}は更新前のアイテムの在庫値を返し、{%raw%}``{{context.${catalog_update}.new_value}}``{%endraw%}は更新後の新しい在庫値を返します。

メッセージの先頭にLiquidタグ{%raw%}``{% catalog_items <name_of_your_catalog> {{context.${catalog_update}.item_id}} %}``{%endraw%}を配置し、その後{%raw%}``{{ items[0].<field_name> }}``{%endraw%}を使用してメッセージ全体でそのアイテムに関するデータにアクセスします。

## 考慮事項 {#considerations}

- ユーザーの購読期間は90日間のみです。アイテムが90日以内に再入荷しない場合、ユーザーは購読解除されます。
- **Notify all subscribed users** の通知ルールを使用する場合、Brazeは10分間で100,000人のユーザーに通知します。
- Brazeは、再入荷通知のトリガー対象となる更新アイテムを1日あたり最大50,000件サポートしています。同時に最大1億件のアクティブなサブスクリプションを持つことができ、各サブスクリプションはカタログアイテムの監視を購読登録したユーザープロファイルを表します。
