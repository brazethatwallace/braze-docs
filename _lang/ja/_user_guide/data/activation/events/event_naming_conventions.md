# イベントの命名規則

> このページでは、適切なイベントの命名規則とベストプラクティスについて説明します。イベントと属性の分類体系に一貫性を持たせることで、データをクリーンで使いやすい状態に保つことができ、Braze プラットフォームの新規ユーザーにも既存ユーザーにも役立ちます。これにより、誤ったオーディエンスにキャンペーンをトリガーしたり、間違ったイベントを使用して誤った結果を生成したりするなど、後々の問題を回避できます。

## ベストプラクティス

- 命名規則を明確に保ちましょう。
- イベント名の大文字・小文字の使い分けとフォーマットに一貫性を持たせましょう。
- 類似した名前のイベントを作成しないようにしましょう。
- 長いイベント属性の文字列は避けましょう。Braze ダッシュボードで切り詰められたり、途中で切れたりする可能性があります。

## 命名規則

### イベントグループを使用する

イベントの命名には、グループを使用して製品の各部分を区別しましょう。製品をグループに分類することで、どのユーザーでもそのイベントが何を指し、何を行うのかを明確に理解できます。

### イベントの命名構造

最も一般的な命名構造は `group_noun_action` です。イベントはすべて小文字にして、大文字・小文字の計測エラーやプロパティの識別に関する問題を回避しましょう。

### プロパティ

1つのイベントにタグを付け、プロパティを使用して違いを識別しましょう。これは、キャンペーンのチャネルなど、本質的に同じでありながら細かな違いがあるイベントに役立ちます。また、ユーザーがイベントをどのように遷移するかも簡単に確認できます。例と追加のコンテキストについては、[イベントプロパティオブジェクト]({{site.baseurl}}/api/objects_filters/event_object/#event-properties-object)を参照してください。

## 例

例えば、e コマース企業に所属していて、顧客がアプリにサインアップした時やニュースレターを購読した時をトラッキングしたいとします。以下は効果的なイベント名の例です。

- `user_signup`
- `newsletter_subscribed`

これら2つのイベント名は、トラッキングしているイベントを明確に示しています。カスタムイベントを追加で作成する際は、命名規則をわかりやすく保つようにしましょう。例えば、`signup_event_1` のようなイベント名は明確さに欠け、`user_signup` と比較してそのイベントが何をトラッキングしているのかが伝わらないため、使用を避けましょう。
