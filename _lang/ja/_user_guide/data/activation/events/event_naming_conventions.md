# イベントの命名規則 {#event-naming-conventions}

> このページでは、イベントの適切な命名規則とベストプラクティスについて説明します。イベントと属性のタクソノミーの一貫性を維持することで、Brazeプラットフォームの新規および既存のユーザーにとって、データをクリーンで使いやすいものに保つことができます。これにより、間違ったオーディエンスに対してCampaignをトリガーしたり、間違ったイベントを使用して誤った結果を生成したりするなどの問題を後から回避できます。

## ベストプラクティス {#best-practices}

- 命名規則を明確にしてください。
- イベント名について、大文字小文字の区別と書式設定を統一して使用してください。
- 複数のイベントに類似した名前を付けないでください。
- イベント属性に長い文字列を使用しないでください。Brazeダッシュボードで切り詰められたり、途切れたりします。

## 命名規則 {#naming-conventions}

### イベントグループの使用 {#use-event-groups}

グループを使用して、イベントの命名に使用する製品の部分を区別します。製品をグループに分類することで、イベントが何を参照し、何を行うものであるかを明確に理解できます。

### イベントの命名構造 {#event-naming-structure}

最も一般的な命名構造は `group_noun_action` です。イベントはすべて小文字にして、大文字小文字の計測エラーやプロパティの誤認を防いでください。

### プロパティ {#properties}

1つのイベントにタグを付け、プロパティを使用して差異を特定します。これは、Campaignのチャネルなど、本質的には同じでもわずかな違いのあるイベントで役立ちます。また、ユーザーがどのようにイベントを通過するかを簡単に確認することもできます。例と追加のコンテキストについては、[イベントプロパティオブジェクト]({{site.baseurl}}/api/objects_filters/event_object#event-properties-object)を参照してください。

## 例 {#examples}

例えば、eコマース企業に所属していて、顧客がアプリにサインアップした時やニュースレターを購読した時をトラッキングすることに興味があるとします。効果的なイベント名の例を以下に示します。

- `user_signup`
- `newsletter_subscribed`

この2つのイベント名は、トラッキングしているイベントを明確に示しています。カスタムイベントを作成する際は、分かりやすい命名規則を心がけてください。例えば、`signup_event_1` のようなイベント名は、`user_signup` に比べて明確さに欠け、そのイベントが何をトラッキングしているのかが伝わらないため、使用を避けてください。
