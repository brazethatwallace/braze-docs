# アカウントオブジェクト {#account-objects}

> アカウントオブジェクトを使用して、アカウントデータによるセグメンテーションとメッセージングのパーソナライゼーションを行います。

{% alert important %}
アカウントは早期アクセス段階です。機能の進化に伴い、これらの手順は変更される場合があります。
{% endalert %}

アカウントオブジェクトを使用すると、以下のことができます。

- アカウント条件でセグメントを構築する
- Liquidを通じてアカウント属性でメッセージをパーソナライズする
- アカウントレコードを一元管理する

アカウントオブジェクトは、ユーザープロファイルに接続されたワークスペースレベルのデータモデルです。アカウントレコードは、1つの特定のアカウントとそれに関連するフィールドデータです。
企業属性などのアカウントコンテキストがターゲティングやメッセージングのパーソナライゼーションに役立つ場合に、アカウントオブジェクトを使用します。
また、アカウント階層（親アカウントと子アカウントなど）をモデル化し、1つのユーザープロファイルを複数のアカウントにリンクすることもできます。

## なぜアカウントオブジェクトを使用するのですか？ {#why-use-account-objects}

キャンペーンやキャンバスが個々のユーザーに送信される場合でも、一部のユースケースではアカウントレベルのコンテキストが必要です。

アカウントオブジェクトを使用すると、アカウントデータを一度保存し、Braze全体でセグメンテーションやパーソナライゼーションに再利用できます。

これにより、以下のことが可能になります。

- アカウント属性でセグメントを作成する
- 共有アカウントコンテキスト（会社名や業種など）を使用してメッセージをパーソナライズする
- アカウント間の関係をモデル化し、1つのユーザープロファイルを複数のアカウントに接続する

このアプローチは、多くのユーザープロファイルに同じアカウント属性を重複して保存する方法に代わるものです。

## 前提条件 {#prerequisites}

始める前に:

- ワークスペースでアカウントの早期アクセスが有効になっている必要があります。Brazeアカウントチームにお問い合わせください。
- Brazeにユーザーが既に存在している必要があります。
- アカウントが有効になると、**データ設定** > **アカウント**に表示されます。アカウントを初めて使用する場合は、画面上の初期化手順に従ってください。

## アカウントデータモデル {#account-data-model}

各アカウントにはexternal ID（`id`）と名前（`name`）が必要です。

このセクションのアカウントフィールドは、アカウントオブジェクトスキーマを定義します。これらのフィールドは、Brazeに保存するすべての個別アカウントレコードに適用されます。

Brazeには、デフォルトで標準フィールドを持つアカウントオブジェクトが含まれています。ユースケースに基づいてカスタムフィールドを追加または削除できます。

| フィールド名 | フィールドタイプ | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string | はい | アカウントのシステムID（例：CRM ID）。ワークスペース内で一意である必要があります。 |
| `name` | string | はい | アカウント名。 |
| `type` | string | いいえ | 顧客、パートナー、リセラーなどのアカウントタイプ。 |
| `annual_revenue` | number | いいえ | アカウントの年間収益。 |
| `industry` | string | いいえ | アカウントの業種。 |
| `number_of_employees` | number | いいえ | 従業員数。 |
| `address` | string | いいえ | 住所。 |
| `city` | string | いいえ | 市区町村。 |
| `state` | string | いいえ | 都道府県。 |
| `postal_code` | string | いいえ | 郵便番号。 |
| `country` | string | いいえ | 国。 |
| `notes` | string | いいえ | 追加メモ。 |
| `website` | string | いいえ | WebサイトURL。 |
| `main_phone` | string | いいえ | 主要電話番号。 |
| `created_date` | time | いいえ | アカウント作成のタイムスタンプ。 |
| `sic_code` | string | いいえ | 標準産業分類コード。 |
| カスタムフィールド | custom | いいえ | ユーザーが定義・管理するフィールド。 |

## データ統合オプション {#data-integration-options}

アカウントレコードは、以下の方法で管理できます。

- アカウントレコード用のREST APIエンドポイント
- **データ設定** > **アカウント**でのブラウザー内編集（個別レコード向け）

## はじめに {#get-started}

### ステップ1：Accountsを有効にする {#step-1-enable-accounts}

Accountsは会社レベルで有効化されます。早期アクセス期間中は、Brazeアカウントチームが1回限りのイネーブルメントを行います。

Accountsが有効になったら、**データ設定** > **Accounts** に移動し、プロンプトが表示された場合は1回限りの初期化フローを完了してください。

### ステップ2：アカウントレコードを追加する {#step-2-add-account-records}

REST APIまたはブラウザ内の編集機能を使用して、アカウントレコードを追加または更新します。

### ステップ3：アカウント条件の算出フィルターを作成する {#step-3-create-a-calculated-filter-for-account-criteria}

アカウントデータでセグメンテーションを行う前に、アカウント条件を定義する算出フィルターを作成します。

1. **オーディエンス** > **算出フィルター** に移動します。
2. **フィルターを作成** を選択し、次に **データオブジェクトフィルター** を選択します。
3. アカウント条件を定義します。

詳細については、[算出フィルター]({{site.baseurl}}/user_guide/audience/segments/calculated_filters#create-a-calculated-filter)を参照してください。

### ステップ4：セグメントビルダーで算出フィルターを使用する {#step-4-use-the-calculated-filter-in-segment-builder}

セグメントビルダーで、作成した算出フィルターを選択し、キャンペーンやキャンバスのターゲティングをサポートする追加のユーザー属性フィルターを設定します。

## アカウントベースのセグメントを作成する {#build-account-based-segments}

アカウントレコードと計算フィルターの準備ができたら、以下を行います。

1. [セグメントビルダー]({{site.baseurl}}/user_guide/audience/segments/creating_a_segment)に移動します。
2. アカウント条件用に事前設定した計算フィルターを追加します。
3. 追加のユーザー属性フィルターを必要に応じて追加します。
4. セグメントを保存します。

例：

- **計算フィルター：** アカウントの `industry` が `healthcare` と完全一致
- **ユーザー属性フィルター：** `days_since_last_login` が `30` 未満

## Liquidによるパーソナライゼーション {#personalize-with-liquid}

`{% raw %}{% data_object account %}{% endraw %}` Liquidタグを使用して、ユーザーのアカウントデータを `data_objects` 配列に読み込みます。

{% alert note %}
**プレビューとテスト**を使用する場合は、アカウントデータを含むセグメントを使用して、パーソナライゼーションが正しく解決されるようにしてください。
{% endalert %}

{% raw %}
```liquid
{% data_object account %}
Hi {{${first_name}}},
We'd love to invite you and your peers at {{ data_objects[0].name }}.
```
{% endraw %}

一致するすべてのアカウントを反復処理するには：

{% raw %}
```liquid
{% data_object account %}
{% for acct in data_objects %}
- {{ acct.name }}
{% endfor %}
```
{% endraw %}

## APIの基本 {#api-basics}

REST APIを使用して、早期アクセス期間中にアカウントレコードを管理できます。

エンドポイントの詳細については、[カスタムオブジェクトエンドポイント]({{site.baseurl}}/api/endpoints/custom_objects)を参照してください。

認証やRESTエンドポイントの基本については、[Braze API概要]({{site.baseurl}}/api/basics)を参照してください。

## よくある質問 {#frequently-asked-questions}

### アカウントにカスタムフィールドを追加できますか？ {#can-i-add-custom-fields-to-accounts}

はい。ワークスペースでカスタムアカウントフィールドを定義および管理できます。フィールドの要件については、[アカウントデータモデル](#account-data-model)を参照してください。

### Accounts は有料アドオンですか？ {#is-accounts-a-paid-add-on}

いいえ。Accounts は有料アドオンではなく、すべてのプランでご利用いただけます。早期アクセス期間中は、Brazeアカウントチームがワークスペースで有効にする必要があります。
