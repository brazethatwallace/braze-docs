# データポイント {#data-points}

> Brazeでのデータはアクションを意味します。Brazeに届いた個々のデータはセグメントのメンバーシップを更新し、メッセージングのトリガーやキャンセル、メッセージングのパーソナライゼーションなどにすぐに利用できます。データポイントは、ビジネスにとって最も影響力のある情報の定義に役立ちます。追跡する情報を慎重に検討することで、ユーザーエクスペリエンスにとって最も影響の大きいデータを確実にターゲットにすることができます。

データポイントは、ユーザープロファイルに対してログに記録された情報に基づいています。この定義の詳細な内容は、Brazeの契約書に記載されています。当社のカスタマーサクセスチームは、お客様のニーズに合わせてデータのベストプラクティスを提案できます。

## 定義 {#definition}

「データポイント」とは、Brazeサービスの使用における課金可能な単位を指し、セッション開始、セッション終了、カスタムイベント、または記録された購入、およびエンドユーザープロファイルに設定された属性によって測定されます。明確にするために、このセクションで前述したデータ（セッション開始、セッション終了、カスタムイベント、または記録された購入、およびすべての属性）がある時点でエンドユーザーのプロファイルに設定された場合、それぞれが1つのデータポイントとしてカウントされます。

Brazeサービスによってデフォルトで収集されるデータおよびイベント（例えば、プッシュトークン、デバイス情報、およびメール開封やプッシュ通知クリックなどのすべてのキャンペーンエンゲージメントトラッキングイベントを含む）は、データポイントとしてカウント*されません*。

データポイントの割り当てに対してどのデータがカウントされるかについては、この記事の[消費カウント](#consumption-count)セクションを参照してください。

## データポイント使用量の確認 {#viewing-data-point-usage}

データポイント使用量を確認するには、**設定** > **請求**に移動し、**データポイント使用量合計**タブを選択します。

### データポイントの更新スケジュール {#data-point-refresh-schedule}

データポイント使用量はキャッシュされており（リアルタイムではありません）、24時間ごとに米国東部時間の午前2時頃に更新されます。キャッシュが更新されるまでは、同じ日の異なる時間にタブを開いた場合でも、異なるダッシュボードユーザーに同じ合計が表示されることがあります。他の請求ビューでの同じキャッシュ動作については、[データポイント使用量合計ダッシュボード]({{site.baseurl}}/user_guide/administer/global/billing#total-data-points-dashboard)を参照してください。

データポイントダッシュボードのコンポーネントの詳細については、[請求]({{site.baseurl}}/user_guide/administer/global/billing)を参照してください。

{% alert tip %}
**データポイントを無駄にしないでください。変更されたデータのみを更新しましょう！**<br><br>
データポイント使用量を最小限に抑えるために、同じ変更のないデータの送信を防止し、新しく関連性のあるデータのみをBrazeに渡すプログラムを設定することをお勧めします。Brazeはオンボーディング中に、このベストプラクティスの確立をサポートします。
{% endalert %}

## 消費カウント {#consumption-count}

まとめると、データポイントはユーザーのプロファイルデータが更新されたとき、またはユーザーが特定のアクションを実行したときに蓄積されます。基本的に、データポイントは各ユーザーの`session starts`、`session ends`、`events`、`purchases`のカウントです。

Brazeがデータポイントをどのように蓄積するかの内訳は、以下のセクションで確認できます。Brazeデータポイントのニュアンスについてご不明な点がある場合は、Brazeアカウントマネージャーがお答えします。

APIインジェストでは、[`/users/track`]({{site.baseurl}}/api/endpoints/user_data/post_user_track)を通じた各課金対象の更新は、他のプロファイル更新と同じルールに従います。たとえば、記録された各**カスタムイベント**は1データポイントとしてカウントされ、**カスタム属性**は通常、そのリクエストで更新された属性ごとにカウントされます（次のセクションの課金対象テーブルと[特殊なケース](#special-circumstances)を参照してください）。

以下のアクションはデータポイントを記録しません：
- Brazeからのユーザーの削除
- メッセージングでのConnected Contentの使用
- グローバルおよび購読グループに関する購読状態の変更
- [API呼び出し]({{site.baseurl}}/api/endpoints/user_data/external_id_migration/post_external_ids_rename)によるユーザーのexternal IDの名前変更
- イベント、属性、またはイベントプロパティのブロック

### 特殊なケース {#special-circumstances}

#### 配列 {#arrays}

配列とは、カスタム属性内に格納された項目の順序付きコレクションです。配列の更新は、配列が実際に変更されない場合でも、API呼び出しごとに1データポイントのコストがかかります。たとえば、配列に存在しない値に対して`remove`操作を送信しても、1データポイントが消費されます。同様に、カスタム属性を`null`に設定してプロファイルから削除する場合も、1データポイントが消費されます。配列に値を段階的に追加する場合は、値ごとに1データポイントとしてカウントされます。

{% alert tip %}
単純な配列の場合、配列全体を一度に設定すると、1データポイントとしてカウントされます。そのため、配列はユーザープロファイルを関連情報で最新の状態に保ち、コストを削減するための優れたツールです。<br><br>オブジェクトの配列は、更新されたキーごとに1データポイントを消費します。不要なデータポイントの消費を減らすために、更新のみをBrazeに渡すようにしてください。
{% endalert %}

#### 階層化カスタム属性 {#nested-custom-attributes}

階層化カスタム属性とは、別の属性のプロパティとして属性のセットを定義するオブジェクトを指します。オブジェクト内のすべてのキーが1データポイントとしてカウントされます。

{% alert note %}
カスタム属性オブジェクトを`null`に更新する場合も、1データポイントが消費されます。
{% endalert %}

#### CSV

CSVインポートを通じてアップロードされたカスタム属性は、データポイントにカウントされます。ただし、セグメンテーション目的のCSVインポート（`external_id`、`braze_id`、または`user_alias_name`のみをフィールドとしてインポートされたもの）は、データポイントを記録しません。

また、購読状態の変更はデータポイントを記録しないため、CSVファイル内の`email_subscribe`、`push_subscribe`、`subscription_group_id`、または`subscription_state`フィールドを更新しても課金は発生しません。
