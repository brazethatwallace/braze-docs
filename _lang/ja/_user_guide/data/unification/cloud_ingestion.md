# Brazeクラウドデータ取り込み {#braze-cloud-data-ingestion}

> Brazeクラウドデータ取り込み（CDI）を使用すると、データストレージソリューションからBrazeへの直接接続を設定して、関連するユーザーデータやその他の非ユーザーデータを同期できます。このデータは、マーケティングユースケースを強化するためのパーソナライゼーションやセグメンテーションに活用できます。クラウドデータ取り込みの柔軟な統合は、ネストされたJSONやオブジェクトの配列を含む複雑なデータ構造をサポートしています。

## 仕組み {#how-it-works}

Brazeクラウドデータ取り込み（CDI）では、データウェアハウスインスタンスとBrazeワークスペース間の連携を設定し、定期的にデータを同期します。この同期は設定したスケジュールに従って実行され、連携ごとに異なるスケジュールを設定できます。同期は15分ごとの高頻度から月1回の低頻度まで設定可能です。15分より高い頻度で同期が必要な場合は、カスタマーサクセスマネージャーにお問い合わせいただくか、リアルタイムデータ取り込みのためにREST API呼び出しの使用をご検討ください。

Amazon S3ファイルストレージ連携はイベント駆動型です。BrazeはS3/SQS通知が届くと新しいファイルを取り込みます。設定の詳細については、[ファイルストレージ連携]({{site.baseurl}}/user_guide/data/unification/cloud_ingestion/file_storage_integrations)を参照してください。

{% alert note %}
ダッシュボードの同期頻度は、Brazeが同期を実行する頻度を制御します（たとえば、1時間ごとや1時間以内のより高頻度な実行などのオプション）。実行間の1時間を超えるカスタム間隔を設定するものではありません。スケジュールされたケイデンス外で同期を実行するには（たとえば、データウェアハウスの読み込み完了後にオンデマンドで実行する場合）、連携IDを指定して[同期をトリガーする]({{site.baseurl}}/api/endpoints/cdi/post_job_sync)エンドポイントを使用してください。
{% endalert %}

同期が実行されると、Brazeはデータウェアハウスインスタンスに直接接続し、指定されたテーブルからすべての新しいデータを取得し、Brazeダッシュボード上の対応するデータを更新します。同期が実行されるたびに、更新されたデータがBrazeに反映されます。

### 連携IDの確認方法 {#finding-your-integration-id}

連携IDは、Brazeダッシュボードで連携を表示しているときのURLで確認できます。**Data Settings** > **Cloud Data Ingestion**に移動し、連携を選択します。連携IDはURLに`https://[instance].braze.com/integrations/cloud_data_ingestion/[integration_id]`の形式で表示されます。たとえば、URLが`https://dashboard-01.braze.com/integrations/cloud_data_ingestion/abc123xyz`の場合、連携IDは`abc123xyz`です。このIDを使用して、同期のトリガーや同期ステータスの確認のためのAPI呼び出しを行うことができます。

## ユースケース {#use-cases}

Brazeクラウドデータ取り込み機能を使用すると、以下のことができます。

- データウェアハウスやファイルストレージソリューションからBrazeへの直接統合を、わずか数分で簡単に作成できます。
- 属性、イベント、購入を含むユーザーデータを、データウェアハウスからBrazeに安全に同期できます。
- クラウドデータ取り込みとCurrentsまたはSnowflakeデータシェアリングを組み合わせることで、Brazeとのデータループを閉じることができます。

さらに、[接続されたソース]({{site.baseurl}}/user_guide/data/unification/cloud_ingestion/connected_sources)はゼロコピーの代替手段です。Brazeがデータウェアハウスやファイルストレージソリューションに直接クエリを行い、基盤となるデータをBrazeにコピーすることなくCDIセグメントを構築できます。

## サポートされるデータソース {#supported-data-sources}

クラウドデータ取り込みは、以下のソースからデータを同期できます。

   - Amazon Redshift
   - Databricks
   - Google BigQuery
   - Microsoft Fabric
   - Snowflake
   - Amazon S3

## サポートされるデータ型 {#supported-data-types}

クラウドデータ取り込みは以下のデータ型をサポートしています：

### ユーザーデータ {#user-data}
- ユーザー属性（以下を含む）:
   - 階層化カスタム属性
   - オブジェクトの配列
   - 購読ステータス
- カスタムイベント
- 購入イベント
- ユーザー削除リクエスト

### 非ユーザーオブジェクト {#non-user-objects}
- カタログアイテム

### ゼロコピーメッセージング {#zero-copy-messaging}
- 接続されたソース

## データ取り込み用のユーザー識別子 {#user-identifiers-for-data-ingestion}

クラウドデータ取り込みを通じてユーザーデータを同期する際、以下の識別子タイプを1つ以上使用してユーザーを特定できます。ソーステーブルの各行には、一度に1つの識別子タイプの値のみを含める必要がありますが、テーブルには1つ、2つ、3つ、4つ、または5つすべての識別子タイプの列を含めることができます。

| 識別子 | 説明 |
|------------|-------------|
| `EXTERNAL_ID` | 作成または更新するユーザープロファイルを特定するexternal IDです。Brazeで使用される`external_id`値と一致する必要があります。 |
| `ALIAS_NAME`と`ALIAS_LABEL` | この2つの列でユーザーエイリアスオブジェクトを作成します。`alias_name`は一意の識別子であり、`alias_label`はエイリアスの種類を指定します。ユーザーは異なるラベルで複数のエイリアスを持つことができますが、1つの`alias_label`につき`alias_name`は1つのみです。 |
| `BRAZE_ID` | Braze SDKによって生成されるBrazeユーザー識別子です。クラウドデータ取り込みを通じてBraze IDで新しいユーザーを作成することはできません。新しいユーザーを作成するには、external IDまたはユーザーエイリアスを指定してください。 |
| `EMAIL` | ユーザーのメールアドレスです。同じメールアドレスを持つ複数のプロファイルが存在する場合、最後に更新されたプロファイルが優先されます。メールと電話番号の両方を含める場合、メールがプライマリ識別子として使用されます。 |
| `PHONE` | ユーザーの電話番号です。同じ電話番号を持つ複数のプロファイルが存在する場合、最後に更新されたプロファイルが優先されます。 |
{: .reset-td-br-1 .reset-td-br-2 aria-label="データ取り込み用のユーザー識別子" }

テーブル列の設定やペイロードのフォーマット要件の詳細については、[Cloud Data Ingestionのテーブル設定]({{site.baseurl}}/user_guide/data/unification/cloud_ingestion/table_setup)を参照してください。

ソース固有の設定手順やSQLの例については、[データウェアハウス統合]({{site.baseurl}}/user_guide/data/unification/cloud_ingestion/integrations)を参照してください。

## データポイント使用量 {#data-point-usage}

データポイントベースの課金をご利用のお客様の場合、クラウドデータ取り込みのデータポイント課金は、[`/users/track`エンドポイント]({{site.baseurl}}/api/endpoints/user_data/post_user_track)を通じた更新の課金と同等です。詳細については、[データポイント]({{site.baseurl}}/user_guide/data/infrastructure/data_points)を参照してください。

{% alert important %}
Brazeクラウドデータ取り込みは利用可能なレート制限にカウントされます。そのため、別の方法でもデータを送信している場合、レート制限はBraze APIとクラウドデータ取り込みの間で合算されます。
{% endalert %}

## 製品の制限事項 {#product-limitations}

| 制限事項            | 説明                                                                                                                                                                        |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 統合数 | 設定できる統合の数に制限はありません。ただし、1つのテーブルまたはビューにつき設定できる統合は1つのみです。                                             |
| 行数         | デフォルトでは、各実行で最大5億行を同期できます。5億行を超える新しい行を含む同期は停止されます。これより高い制限が必要な場合は、BrazeカスタマーサクセスマネージャーまたはBrazeサポートにお問い合わせください。 |
| 行あたりの属性数     | 各行には、1つのユーザーIDと最大250個の属性を含むJSONオブジェクトを含める必要があります。JSONオブジェクト内の各キーは1つの属性としてカウントされます（つまり、配列は1つの属性としてカウントされます）。 |
| ペイロードサイズ           | 各行には最大1 MBのペイロードを含めることができます。1 MBを超えるペイロードは拒否され、「Payload was greater than 1MB」というエラーが、関連するexternal IDおよび切り詰められたペイロードとともに同期ログに記録されます。 |
| データタイプ              | クラウドデータ取り込みを使用して、ユーザー属性、カスタムイベント、購入イベント、カタログアイテム、ユーザー削除リクエスト、およびキャンバストリガーを同期できます。                                                                                                  |
| Brazeリージョン           | この製品はすべてのBrazeリージョンで利用可能です。どのBrazeリージョンからでも、任意のソースデータリージョンに接続できます。                                                                              |
| ソースリージョン       | Brazeは、任意のリージョンまたはクラウドプロバイダーのデータウェアハウスまたはクラウド環境に接続します。                                                                                        |
{: .reset-td-br-1 .reset-td-br-2 aria-label="製品の制限事項" }
