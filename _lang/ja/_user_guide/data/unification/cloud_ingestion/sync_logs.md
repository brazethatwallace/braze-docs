# 同期ログと可観測性 {#sync-logs-and-observability}

> クラウドデータ取り込み（CDI）の**同期ログ**ダッシュボードでは、CDIによって処理された全データを監視し、データの同期が正常に行われたかどうかを確認し、「不正」または欠落したデータに関する問題を診断できます。

同期ログにアクセスするには、**データ設定** > **クラウドデータ取り込み**に移動し、**同期ログ**タブを選択します。

{% alert note %}
データウェアハウスの行数が**同期済み行数**と一致しない場合や、**部分的な成功**の実行が表示される場合は、同期ログで**実行ID**を開き、行レベルの**エラー理由**の値を確認してください。CDIは`UPDATED_AT`を使用して行を選択します。すでに処理済みのタイムスタンプを持つ行、編集後に`UPDATED_AT`が変更されていない行、またはアクティブな同期中に書き込まれた行はスキップされる場合があります。一般的なケースについては、[「同期済み行数」がデータウェアハウスの数と一致しないのはなぜですか？]({{site.baseurl}}/user_guide/data/unification/cloud_ingestion/faqs#why-doesnt-rows-synced-match-the-number-in-my-warehouse)および[クラウドデータ取り込みFAQ]({{site.baseurl}}/user_guide/data/unification/cloud_ingestion/faqs)を参照してください。

## 同期ログダッシュボードについて {#understanding-the-sync-log-dashboard}

メインの**同期ログ**ページでは、現在のステータスまたは最終ステータスごとの最近の同期の概要を含む、すべての同期実行のハイレベルな概要が表示されます。

* **実行中:** 現在進行中の同期ジョブです。
* **成功:** 完了し、すべての行が正常に処理された同期ジョブです。
* **部分的成功:** 完了したものの、1つ以上の行でエラーが発生した同期ジョブです。
* **エラー:** 完了できなかった同期ジョブです。
* **制限超過:** データ制限を超えたために処理が停止した同期ジョブです。

![合計6,576件の成功を示す同期ログの例。]({% image_buster /assets/img/cloud_ingestion/sync_logs1.png %}){: style="max-width:80%"}

同期ログには、各同期について以下の詳細も表示されます。

* **同期名:** 同期設定の名前です。
* **実行 ID:** 同期の特定の実行に対する一意の識別子です。この ID を選択すると、詳細を確認したり、Braze サポートに同期実行を参照してもらったりできます。
* **ステータス:** 実行のステータスです（成功、部分的成功、エラー、実行中）。
* **ソースから読み取った新しい行:** この実行でデータウェアハウスから取得された新しい行の数です。
* **結果:** 実行内で成功した行と失敗した行の内訳です。
* **最終 `UPDATED_AT`:** この同期実行で処理された最新のレコードのタイムスタンプです。
* **実行開始時刻:** 同期ジョブが開始された時刻です。
* **実行時間:** 同期ジョブの完了にかかった合計時間です。

### データ保持 {#data-retention}

すべての行レベルのペイロードとエラーの詳細を含む同期ログデータは、最大**30日間**保持されます。30日を超えたログは自動的に削除されます。

処理された行数などの同期実行メタデータは、少なくとも12か月間保持されます。

### 同期ログのフィルタリング {#filtering-sync-logs}

同期ログテーブルをフィルタリングして、特定の実行を見つけることができます。利用可能なフィルターは以下のとおりです。

* **ジョブ開始日:** 事前定義された範囲（「過去30日間」など）またはカスタム日付範囲を選択します。
* **ステータス:** 1つ以上の同期ステータスでフィルタリングします（**エラー**と**部分的成功**のステータスのみを表示するなど）。
* **同期名:** 名前で特定の同期を検索します。

特定の同期を調査するには、同期ログテーブルから該当する**実行 ID** を選択します。**実行の詳細**ページでは、同期の行ごとの詳細なログを確認できます。

### 実行の概要 {#run-overview}

このセクションでは、選択した実行の開始時刻、終了時刻、実行時間、ソースから読み取った行の合計数などの概要が表示されます。また、成功した行数とエラーになった行数も表示されます。

### この実行で処理された行 {#rows-processed-in-this-run}

このテーブルでは、同期中に処理されたデータの行レベルの可視性が提供され、個々のレコードを検証できます。

* **検索:** **ユーザー ID で検索**バーを使用して、実行結果内の特定のユーザーを検索できます。
* **利用可能な詳細:**
  * **UPDATED_AT:** その特定の行の `UPDATED_AT` 列のタイムスタンプです。
  * **ID:** レコードを Braze ユーザープロファイルに一致させるために使用されるユーザー識別子（`external_id`、`email`、`alias_name` など）です。
  * **ステータス:** その行の個別の処理ステータスです（**成功**または**エラー**）。
  * **ソースペイロード:** データペイロードを表示するためのリンクです。
  * **エラー理由:** ステータスが**エラー**の場合、この列には行の同期が失敗した理由を説明するメッセージが表示されます。

#### ペイロードの表示 {#viewing-payloads}

特定の行について Braze に送信された正確なデータを確認するには、**ソース**ペイロード列の**ペイロードを表示**を選択します。そのユーザーに対して処理された生の JSON ペイロードが表示されます。

#### 同期ログのエクスポート {#exporting-sync-logs}

**行をエクスポート**を選択して、同期実行の行レベルのログをエクスポートします。次に、以下のいずれかでエクスポートを選択します。

* **エラーのある行:** **エラー**ステータスの行のみを含むファイルをダウンロードします。
* **すべての行:** 実行で処理されたすべての行を含むファイルをダウンロードします。

{% multi_lang_include alerts/early_access_beta_alert.md feature='Exporting sync logs for all rows' %}

ログはダッシュボードから直接エクスポートすることはできません。エクスポートが生成されると、ログエクスポートファイルをダウンロードするためのリンクが記載されたメールが届きます。

## 通知 {#notifications}

CDI同期のステータスを把握するために、メール通知を設定できます。これらの設定は同期の作成時に構成され、いつでも更新できます。

### エラー通知 {#error-notifications}

同期レベルのエラーに関する通知を受信するには、少なくとも1つのメールアドレスの連絡先が必要です。これらのアラートは、同期ジョブ全体の実行または完了に失敗した場合、または期限切れの認証情報やソーステーブルの欠落など、ユーザーの介入が必要なエラーが発生した場合に送信されます。

追加の通知には以下が含まれます。

- **行エラー：** 同期内で一定の割合の行が更新に失敗した場合にアラートを受信します。
- **失敗しきい値（%）：** アラートをトリガーする行の失敗率を指定します。たとえば、これを **1** に設定すると、同期実行内の行の1%以上がエラーになった場合に通知が送信されます。
- **同期成功：** 同期が正常に完了した際に通知を受信します。
- **行の変更がない場合もアラート：** 同期の実行が成功しても、新規または更新された行がゼロの場合に通知を受信します。
