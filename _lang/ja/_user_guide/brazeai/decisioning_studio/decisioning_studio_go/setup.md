# Decisioning Studio Goエージェントを設定する {#set-up-your-decisioning-studio-go-agent}

> この記事では、Brazeダッシュボードのセルフサーブ設定フローを使用してDecisioning Studio Goエージェントを設定する方法について説明します。

Decisioning Studio Goの仕組みの概要については、[BrazeAI Decisioning Studio Go]({{site.baseurl}}/user_guide/brazeai/decisioning_studio/decisioning_studio_go)を参照してください。エージェントを設定する前にプログラムが適切かどうかを確認するには、[Decisioning Studio Goの例]({{site.baseurl}}/user_guide/brazeai/decisioning_studio/decisioning_studio_go/examples)を参照してください。

## 前提条件 {#prerequisites}

以下の準備が整っていることを確認してください。

- 他のキャンバスやキャンペーンで使用されていないエントリオーディエンス用の[セグメント]({{site.baseurl}}/user_guide/audience/segments/creating_a_segment)
- 少なくとも1つのメールテンプレート
- テストしたいバリアントコンテンツ（代替の件名、CTA、ヒーロー画像など）。設定中にバリアントを作成することもできますが、事前に準備しておくと設定が速くなります
- AI意思決定エージェントを設定する権限を持つワークスペースへのアクセス

ワークスペースがDecisioning Studio Go用にプロビジョニングされていない場合、**AI Decisioning**タブにエージェント設定オプションが表示されません。アクセスを取得するには、カスタマーサクセスマネージャーにお問い合わせください。

## ステップ1：エージェントを設定する {#step-1-set-up-your-agent}

1. Brazeダッシュボードで、**AI Decisioning**タブに移動します。
2. **Create Agent**を選択します。
3. ワークスペース内の他のエージェントと区別できる名前を付けます。例えば、「Email Agent」ではなく「Loyalty Members—Weekly Engagement」のような名前にします。
4. （オプション）後で自分やチームメイトが必要になるかもしれないコンテキストを提供する説明を追加します。エージェントの目的、対象セグメント、成功の基準などを含めることができます。


エージェントは、ユーザーごとの意味のあるクリックアクティビティで測定される真のエンゲージメントを最大化するようにメールクリエイティブを最適化します。クリックは、自動化されたアクティビティやオプトアウト関連のクリックをスクリーニングする複数の独立した検証フィルターを通過するため、シグナルは生のクリック量ではなく実際の顧客の関心を反映します。

## ステップ2：ターゲットオーディエンスを選択する {#step-2-select-the-target-audience}

エージェントが送信するBrazeセグメントを選択します。このセグメント内のユーザーは自動的に2つのグループに分割されます。

- **Decisioning Studioグループ：** AI最適化されたメールコンテンツを受信します。エージェントが各ユーザーに最適なバリアントの組み合わせを選択します。
- **ランダムコントロールグループ：** セグメントの最低5%。ランダムに選択された日にランダムに選択された同じオプションの組み合わせを受信します。このグループは必須です。

![推定ユーザー数1,100人のセグメントが選択されている画面。]({% image_buster /assets/img/decisioning_studio_go/audience_details.png %})

### 専用セグメントが重要な理由 {#why-a-dedicated-segment-matters}

選択したセグメント内のユーザーが他のキャンバスやキャンペーンからもメッセージを受信している場合、エージェントが観察するエンゲージメントはそれらの他のメッセージの影響を受けます。エージェントは、ユーザーがエージェントの判断によってクリックしたのか、他の要因によるものかを区別できません。選択したセグメントが他で使用されている場合は警告が表示されます。続行できますが、結果にノイズが多くなることが予想されます。

### ユーザー検索 {#user-lookup}

**ユーザー検索**を使用して、特定のユーザーがセグメント条件を満たしているかどうかを確認します。これはセグメント定義の検証に役立ちます。

### オーディエンスフィルター {#audience-filters}

このリリースではオーディエンスフィルターはサポートされていません。追加のターゲティング条件が必要な場合は、それらのフィルターを適用した[セグメントを作成]({{site.baseurl}}/user_guide/audience/segments/creating_a_segment)し、そのセグメントをエントリオーディエンスとして選択してください。

### 既存のキャンバスとの統合 {#integrate-with-existing-canvases}

Decisioning Studio Goをより広範なジャーニー内で使用するには：

1. エージェントに含めるべきユーザー用の専用セグメントを作成します。
2. [キャンバス]({{site.baseurl}}/user_guide/messaging/canvas/create_a_canvas)で、ユーザー更新ステップを使用して、ジャーニーの適切なポイントでユーザーをそのセグメントに追加します。
3. ユーザーがキャンバスを退出し、その時点からセグメント内の全員に対してエージェント（キャンバスではなく）がメール送信を処理するようにします。

## ステップ3：スケジュールを設定する {#step-3-configure-the-schedule}

エージェントが送信できるタイミングを決定します。

### ステップ3.1：送信頻度を決定する {#step-31-determine-the-send-frequency}

エージェントからユーザーがメールを受信する頻度を選択します（例：週3回）。これは単一の選択です。エージェントは異なる頻度間の最適化は行いません。設定した頻度内で日時を選択します。

### ステップ3.2：曜日を選択する {#step-32-select-the-days-of-the-week}

エージェントが送信できる曜日を選択します。頻度が要求する数以上の曜日を選択する必要があります（エージェントが週3回送信する場合、少なくとも3日を選択します。より多くの曜日を選択すると、エージェントの柔軟性が高まります）。エージェントはそのセット内で最適化し、各ユーザーに最適な曜日を選択します。最大限の柔軟性を得るには、7日すべてを選択してください。

### ステップ3.3：静粛時間を設定する {#step-33-set-quiet-hours}

エージェントが送信すべきでない時間帯を指定します。静粛時間はユーザーのローカルタイムゾーンを使用します。最も一般的な用途は、深夜や早朝の送信をブロックすることです。静粛時間外では、エージェントは各ユーザーのクリックを促す可能性が最も高い時間に送信をスケジュールします。

### ステップ3.4：フリークエンシーキャップルールを設定する {#step-34-set-frequency-capping-rules}

フリークエンシーキャップルールはエージェントレベルで適用できます。

- **フリークエンシーキャップを適用：** フリークエンシーキャップに達したユーザーへのエージェントからの送信を防止します。ルールの設定方法に応じて、このキャップは個々のユーザーレベルまたはアカウント全体レベルで適用される場合があります。いずれの場合も、キャップに達している間はそのユーザーにメッセージは送信されません。
- **キャップにカウント：** このエージェントからの送信をユーザーの全体的なキャップにカウントするかどうかを選択します。

{% alert tip %}
フリークエンシーキャップがユーザー体験を保護するためのものである場合、エージェントの送信はすでにターゲットが絞られているため、キャップにカウントする必要がない場合があります。キャップが全体的な送信量や費用を制御するためのものである場合は、カウントした方がよいでしょう。カスタマーサクセスマネージャーまたはソリューションコンサルタントが、ワークスペースに適したアプローチを確認するお手伝いをします。
{% endalert %}

## ステップ4：コンテンツとテンプレートを追加する {#step-4-add-content-and-templates}

エージェントが使用するものを定義します。

- **ベースクリエイティブ：** 完全なメールテンプレートです。エージェントはまず、特定のユーザーに送信するベースクリエイティブを選択します。
- **クリエイティブコンポーネント：** ベースクリエイティブ内の特定の要素（件名、CTA、ヒーロー画像）で、エージェントがユーザーごとにパーソナライズします。

ベースクリエイティブは以下の方法で作成できます。

- 標準のBrazeメールコンポーザーを使用する。
- 既存のキャンバスやキャンペーンからメールをインポートする。

単一のベースクリエイティブまたは複数のベースクリエイティブを使用できます。1つのベースクリエイティブの場合、エージェントはその中のコンポーネントのみをパーソナライズします。複数のベースクリエイティブ（例：カジュアル、フォーマル、プロモーション）の場合、エージェントは各ユーザーに適したベースクリエイティブも選択します。エージェントは、追加のクリエイティブコンポーネントなしで複数のベースクリエイティブから選択することもできます。

### ステップ4.1：Liquidタグでパーソナライゼーションポイントをマークする {#step-41-mark-personalization-points-with-liquid-tags}

エージェントにパーソナライズさせたい各コンポーネントについて、ベースクリエイティブ内の静的コンテンツをパーソナライゼーションメニューのLiquidタグに置き換えます。次に、**Creative Components**セクションでバリアントオプションを提供します。

このリリースでサポートされているコンポーネントは以下のとおりです。

- **件名：** **Sending Settings**の件名を件名用のLiquidタグに置き換えます。
- **CTA：** メール本文のボタンテキストをCTA用のLiquidタグに置き換えます。
- **画像：** ヒーロー画像のURLを画像用のLiquidタグに置き換えます。

{% alert note %}
[Content Blocks]({{site.baseurl}}/user_guide/messaging/design_and_edit/content_blocks)は、パーソナライズされたコンポーネントの置換ポイントとしてサポートされていません。パーソナライズされた件名、CTA、画像は、コンテンツブロック内ではなくメール本文に直接配置してください。
{% endalert %}

### ステップ4.2：バリアントを追加する {#step-42-add-variants}

**Creative Components**セクションで、各パーソナライゼーションポイントのバリアントオプションを追加します。

- 複数の件名オプション
- 複数のCTAテキストオプション
- 複数の画像URL

各バリアントは特定のベースクリエイティブに関連付けるか、すべてのベースクリエイティブで利用可能にすることができます。例えば、セールを宣伝するベースクリエイティブと新着商品を宣伝するベースクリエイティブがある場合、`Don't miss our biggest savings of the year`の件名をセールクリエイティブのみに制限し、`Just dropped`のCTAは両方で利用可能にすることができます。

画像はBrazeメディアライブラリから選択する必要があります。使用したい画像がある場合は、まずメディアライブラリにアップロードしてください。

### ステップ4.3：プレビューとテスト {#step-43-preview-and-test}

コンテンツを追加するにつれて、異なるバリアントの組み合わせがどのようにレンダリングされるかを示すダイナミックプレビューを使用してメッセージをプレビューおよびテストします。これは、起動前にレンダリングの問題を発見して解決するのに役立ちます。ベースクリエイティブとバリアントが設定されると、エージェントが送信を許可されているすべての組み合わせの完全なリストを確認できます。

自分やチームメイトにテスト送信することもできます。テスト送信では、エージェントが特定のユーザーに対して選択するものではなく、選択した特定のバリアントの組み合わせが表示されます。

## ステップ5：制約を定義する {#step-5-define-constraints}

制約は、エージェントが同じユーザーに繰り返しコンテンツを送信することを防止します。以下のレベルが利用可能です。

- **ベースクリエイティブレベル：** 定義したウィンドウ内で同じベースクリエイティブが同じユーザーに複数回送信されることを防止します。各ベースクリエイティブが十分に異なり、例えば1週間以内に繰り返すと古く感じる場合に便利です。
- **件名レベル：** 定義したウィンドウ内で同じ件名が同じユーザーに複数回送信されることを防止します。件名が最も目に見える繰り返しのシグナルである場合に便利です。

このリリースでは、特定の画像やCTAに対するバリアントレベルの制約はサポートされていません。

## ステップ6：確認して起動する {#step-6-review-and-launch}

**Review**画面には、オーディエンスとランダムコントロールの分割、スケジュール、ベースクリエイティブ、バリアント数、アクティブな制約など、完全な設定が表示されます。このセクションに表示される検証警告（例：別のキャンペーンとのセグメントの重複）を確認して解決してください。

**Launch**を選択してエージェントをアクティブにします。エージェントは**下書き**から**ライブ**に移行し、次の対象日に送信を開始します。

## 起動後 {#after-launch}

### トレーニング期間 {#training-period}

エージェントが起動すると、トレーニング期間に入ります。レポートインターフェイスにトレーニングインジケーターが表示されます。エージェントが組み合わせを探索する最初の数日間はパフォーマンスが変動する可能性があります。学習中もメールは引き続き送信されます。待機期間はありません。

パフォーマンスの意味のある変化は、エージェントがトレーニングを終了してアクティブなパーソナライゼーションに移行した後に現れます。レポートはその移行がいつ発生するかを示すため、エージェントがどの段階にあるかを常に把握できます。

### レポートビュー {#reporting-views}

レポートインターフェイスには3つの主要なビューがあります。

| ビュー | 説明 |
|---|---|
| **パフォーマンス** | クリック率、エンゲージメント指標、およびDecisioning Studioグループとランダムコントロールのリフト。 |
| **設定** | エージェントの現在の設定。何が実行されているかを確認するのに便利です。 |
| **エージェントの選好** | エージェントが各バリアントを選択した回数のカウント。エージェントがオーディエンスに対してどのバリアントに傾いているかを示します。 |
{: .reset-td-br-1 .reset-td-br-2 aria-label="レポートビュー" }

要素レベルの内訳では、個々の件名、CTA、画像がすべての組み合わせにわたってどのようにパフォーマンスしているかを示します。

### ライブエージェントを編集する {#edit-a-live-agent}

**Configuration**ビューに移動して、起動後にオーディエンス、スケジュール、クリエイティブ、または制約を変更します。Configurationビューには変更の概要が表示されます。変更を適用する前にプロモートしてください。新しいバリアントを追加しても、既存のバリアントに対するエージェントのトレーニングはリセットされません。エージェントのメニューに新しいオプションが追加されます。

### 一時停止または停止 {#pause-or-stop}

エージェントのライフサイクルは**下書き** > **ライブ** > **停止**です。いつでも**Stop**を選択してエージェントを停止できます。送信が停止し、再アクティブ化すると再開します。

## リファレンス {#reference}

以下の表は、Decisioning Studio Goの各領域と関連する詳細をまとめたものです。

| 領域 | 詳細 |
|---|---|
| **チャネル** | メールのみ |
| **コンバージョン指標** | クリックのみ（ユーザーごとの日次ユニーククリック） |
| **パーソナライゼーションポイント** | 件名、CTA、ヒーロー画像（ベースクリエイティブごと） |
| **オーディエンス** | 1つのBrazeセグメント、必須のランダムコントロール（最低5%） |
| **頻度** | 単一選択（頻度の意思決定なし） |
| **テスト送信** | Brazeコンポーザー経由 |
| **レポート** | パフォーマンス、設定、エージェントの選好ビュー、および要素レベルの内訳 |
{: .reset-td-br-1 .reset-td-br-2 aria-label="Decisioning Studio Goの範囲" }

### 考慮事項 {#considerations}

- Content Blocksはパーソナライゼーションの置換ポイントとしてサポートされていません。
- 画像URLは手動で追加する必要があります。現在、メディアライブラリの統合はサポートされていません。
- セグメント選択以外のオーディエンスフィルターはサポートされていません。
- 本文、プリヘッダー、ヘッダーのパーソナライゼーションはまだ利用できません。

よくある質問については、[Decisioning Studio Go FAQ]({{site.baseurl}}/user_guide/brazeai/decisioning_studio/decisioning_studio_go/faq)を参照してください。
