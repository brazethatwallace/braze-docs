# メッセージング診断ダッシュボード {#messaging-diagnostics-dashboard}

> **メッセージング診断**ダッシュボードは、メッセージ送信結果の概要を提供し、メッセージング設定における傾向の把握や潜在的な問題の診断を可能にします。このダッシュボードは、キャンペーンやキャンバスからのメッセージが期待どおりに送信されなかった理由を理解するのに役立ちます。

{% alert important %}
**メッセージング診断**ダッシュボードは一般提供されています。この機能へのアクセスにご興味がある場合は、カスタマーサクセスマネージャーにお問い合わせください。
{% endalert %}

{% alert note %}
**メッセージング診断**ダッシュボードにアクセスするには、ワークスペースの「View Dashboard Reports」[ユーザー権限]({{site.baseurl}}/user_guide/administer/global/user_management/permissions)が必要です。
{% endalert %}

## 主要な概念 {#key-concepts}

### 送信済みと配信済み {#sent-and-delivered}

このダッシュボードは、Brazeが内部的にメッセージを処理した状況を報告するものであり、メッセージの最終的な配信ステータスを報告するものではないことを理解することが重要です。

このダッシュボードで「送信済み」と表示されたメッセージは、Brazeがそのメッセージを正常に処理し、送出したことを意味します。ほとんどのチャネルでは、Brazeが関連するサードパーティの送信パートナーにメッセージを引き渡したことを意味します。ただし、ユーザーのデバイスへの最終的な配信を保証するものではありません。

Brazeがメッセージを「送信」した後、最終的な配信は外部サービスに依存する場合があります。各チャネルの例を以下に示します。

| チャネル | 最終配信の例 |
| --- | --- |
| Content Cards | カードが送信され、閲覧可能な状態になりました。 |
| メール | Brazeがメッセージをメールサービスプロバイダー（ESP）に引き渡します。ESPが最終的な配信を担当します。たとえば、メールアドレスが無効であったり受信トレイがいっぱいの場合、ESPが「バウンス」を報告することがあります。 |
| アプリ内メッセージ | メッセージがユーザーに表示され、インプレッションが記録されました。 |
| LINE | メッセージが送信パートナーに正常に引き渡されました。 |
| プッシュ | Brazeがメッセージを適切なプッシュ通知サービス（iOSの場合はApple Push Notification service、Androidの場合はFirebase Cloud Messagingなど）に引き渡します。そのサービスがデバイスへの通知の最終配信を担当します。 |
| SMS/MMS/RCS | BrazeがメッセージをSMSゲートウェイ（Twilioなど）に引き渡します。そのゲートウェイがモバイルキャリアへの最終配信を担当します。 |
| webhook | webhookリクエストが正常に実行され、`2xx`レスポンスが返されました。 |
| WhatsApp | メッセージが送信パートナーに正常に引き渡されました。 |
{: .reset-td-br-1 .reset-td-br-2 aria-label="送信済みと配信済み" }

### データの鮮度 {#data-freshness}

このダッシュボードのデータが更新される頻度は、システム負荷に基づいて変動する場合があります。更新頻度は保証されていませんが、ほとんどの場合1時間未満である可能性が高いです。

## ダッシュボードの設定 {#configuring-the-dashboard}

診断ダッシュボードにアクセスするには、**Analytics** > **Dashboard Builder** に移動し、Brazeが作成したダッシュボードの一覧から **Messaging Diagnostics** を選択します。

ダッシュボードを実行してデータを表示するには、次の手順に従います。

1. ダッシュボードレポートのソースとして**キャンペーン**または**キャンバス**を選択します。
2. 1つ以上のキャンペーンまたはキャンバスを選択します。
3. **Run Dashboard** を選択して、選択したフィルターのデータを読み込みます。

## データの解釈 {#interpreting-the-data}

{% alert note %}
ダッシュボードには、直近7日間のデータのみが表示されます。すべてのタイムスタンプはワークスペースのタイムゾーンで表示されます。
{% endalert %}

### サマリータイル {#summary-tiles}

ページ上部には、選択した期間の主要なサマリータイルが表示されます。

- **送信済み:** Brazeが正常に処理して送信したメッセージの合計数。
  - **メール、SMS/MMS/RCS、WhatsApp、LINE、プッシュ:** メッセージが送信パートナーに正常に引き渡されました。
  - **Webhook:** Webhookリクエストが正常に実行され、`2xx`レスポンスが返されました。
  - **Content Cards:** カードが送信され、閲覧可能な状態になりました。
  - **アプリ内メッセージ:** メッセージがユーザーに表示されました。
- **未送信:** 中止されたメッセージの合計数。これには、キャンバスに入らなかったキャンバスオーディエンスメンバーや、ステップの失敗を経験したか、終了イベントの実行中に終了条件を満たしたためにキャンバスを退出したメンバーが含まれます。

### メッセージ結果の時系列推移 {#message-outcomes-over-time}

この時系列チャートは、メッセージが中止された理由やユーザーがキャンバスからドロップされた理由を時間単位で表示します。このチャートの結果ラベルは、正規化されたダッシュボードラベルであり、生のイベントペイロード値ではありません。このチャートには送信数は表示されません。

### メッセージ結果の詳細ログ {#message-outcomes-granular-log}

ダッシュボードには、選択したフィルターと期間に基づく個別のメッセージ結果の詳細テーブルが表示されます。このテーブルを使用して、タイムスタンプ、ユーザーID、キャンバスステップ、結果、詳細、チャネルなどの特定のレコードを確認できます。

テーブルをフィルタリングして特定のレコードに絞り込むことができます。

- **結果でフィルター:** 結果フィルターから結果を選択すると、その結果に一致する行のみが表示されます（例: `Frequency capped`や`User not eligible for channel`）。
- **ユーザーIDで検索:** 検索フィールドにユーザーIDを入力すると、そのユーザーの行が表示されます。

両方のフィルターを適用すると、選択した結果と入力したユーザーIDの両方に一致する行が返されます。

テーブルの行を選択すると、詳細パネルが開きます。詳細パネルにはその結果に関する追加のコンテキストが表示され、Ask Operatorが根本的な問題のトラブルシューティングに役立つ修正ガイダンスを提供します。

![メッセージング診断の詳細結果ログ。行が選択され、詳細パネルにアクセスできる状態。]({% image_buster /assets/img/messaging_diagnostics_dashboard_details_log.png %}){: style="max-width:45%;"} ![メッセージング診断の詳細パネルが展開され、結果のコンテキストと修正ガイダンスが表示されている状態。]({% image_buster /assets/img/messaging_diagnostics_dashboard_drawer_expanded.png %}){: style="max-width:45%;"}

{% alert note %}
チャネルフィルターは、特定のメッセージングチャネルに紐づく結果に適用されます。一部の結果はチャネルに依存しないため、チャネルフィルターを適用しても集計ビューに表示される場合があります。
{% endalert %}

### 中止結果 {#abort-outcomes}

以下の定義は、ダッシュボードに表示される中止結果を説明しています。結果はカテゴリ別にグループ化されており、調査中の結果を見つけやすくなっています。

{% alert note %}
メッセージング診断の中止結果は、人間が読みやすいダッシュボードラベルです。[Currentsメッセージエンゲージメントイベント]({{site.baseurl}}/user_guide/data/distribution/braze_currents/event_glossary/message_engagement_events)では、中止情報は`abort_type`や`abort_log`などのフィールドで表されます。これらのデータセットは異なる表現と処理パスを持つため、CurrentsとMessaging Diagnosticsの間でカウントや名称が異なる場合があります。
{% endalert %}

## よくある質問 {#frequently-asked-questions}

### 「事前チェック」の失敗とは何を意味しますか？ {#what-does-a-pre-check-failure-mean}

「事前チェック」とは、パイプラインステージの最初（メッセージのトリガーやキャンバスのメッセージステップの送信など）に実行される、高速でバンドルされた検証チェックのことです。最大速度を実現するための早期終了の仕組みと考えてください。ユーザーのプロファイルの詳細をすべて検証するなど、リソースを大量に消費する個別のチェックを多数実行する代わりに、Brazeは複数の基本的な検証を1つの「ファーストパス」にバンドルします。

ユーザーがこのバンドルされたチェックに失敗した場合、即座にドロップされます。このバンドルアプローチにより、Brazeは大量のメッセージを高速で処理でき、各メッセージの処理レイテンシーを削減することで、キャンペーンやキャンバスのパフォーマンスをより高速かつ安定させることができます。

### 「その他」の中止結果とは何を意味しますか？ {#what-does-an-other-abort-outcome-mean}

これらは、既存のダッシュボードカテゴリに該当しない中止です。「その他」の中止が大きな割合を占めている場合は、[Brazeサポート]({{site.baseurl}}/braze_support)に連絡して詳細なサポートを受けてください。

### _未送信_ と _送信済み_ の合計が予想されるオーディエンスサイズより少ないのはなぜですか？ {#why-is-the-sum-of-_not-sent_-and-_sent_-lower-than-my-expected-audience-size}

これはいくつかの理由で発生する可能性があります。

- **オーディエンス基準：** キャンペーンやキャンバスが開始された時点で、予想よりも少ないユーザーしかオーディエンス基準を満たしていなかった可能性があります（例えば、セグメントに含まれていなかった、または必要な属性を持っていなかったなど）。
- **処理中：** メッセージがまだ処理中の可能性があります。ユーザーがキャンバスの前のステップにまだいて、メッセージステップに到達していない場合があります。
- **データの鮮度：** ダッシュボードのデータは約15分ごとに更新されますが、これは保証されるものではありません。このキャンペーンやキャンバスの最新データがまだダッシュボードに反映されていない可能性があります。
- **エッジケース：** 現時点でこのダッシュボードに反映されていないエッジケースに遭遇している可能性がわずかにあります。その疑いがある場合は、[Brazeサポート]({{site.baseurl}}/user_guide/administer/personal/braze_support)に連絡してください。

### _未送信_ と _送信済み_ の合計がキャンペーンやキャンバスのオーディエンスより多いのはなぜですか？ {#why-is-the-sum-of-_not-sent_-and-_sent_-greater-than-the-audience-for-a-campaign-and-canvas}

これは以下の理由で発生する可能性があります。

- **マルチチャネルメッセージ：** キャンペーンやキャンバスステップが複数のチャネル（SMSやメールなど）で送信するように設定されていた場合です。1人のユーザーが、あるチャネル（メールなど）では「送信済み」の結果を受け取り、別のチャネル（「ユーザーがチャネルの対象外」など）では「中止」の結果を受け取ることがあります。この場合、その1人のユーザーはチャートで2回カウントされます。1回は「送信済み」として、もう1回は「中止」としてです。
  - **例：** iOSとAndroidの両方をターゲットにして、100人のユーザーにプッシュキャンペーンを送信します。あるユーザーがiOSデバイスのみを持っている場合、iOSプッシュは受信します（「送信済み」）が、Androidプッシュに対しては中止がトリガーされます（「ユーザーがチャネルの対象外」）。
- **複数のメッセージステップ（キャンバスのみ）：** キャンバスの特定のパスに複数のメッセージステップがある場合があります。このダッシュボードはすべての結果を集計するため、選択した期間内に複数のメッセージステップを通過した場合、1人のユーザーが複数回カウントされることがあります。
- **テストメッセージ：** テスト送信（ダッシュボードでカウントされます）により、合計カウントがオーディエンスサイズよりも大きくなっています。
