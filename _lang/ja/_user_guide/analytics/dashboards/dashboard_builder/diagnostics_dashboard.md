# メッセージング診断ダッシュボード {#messaging-diagnostics-dashboard}

> **メッセージング診断**ダッシュボードは、メッセージ送信結果の概要を提供し、メッセージング設定における傾向の把握や潜在的な問題の診断を可能にします。このダッシュボードは、キャンペーンやキャンバスからのメッセージが期待どおりに送信されなかった理由を理解するのに役立ちます。

{% alert important %}
**メッセージング診断**ダッシュボードは一般提供されています。この機能へのアクセスにご興味がある場合は、カスタマーサクセスマネージャーにお問い合わせください。
{% endalert %}

{% alert note %}
**メッセージング診断**ダッシュボードにアクセスするには、ワークスペースの「View Dashboard Reports」の[ユーザー権限]({{site.baseurl}}/user_guide/administer/global/user_management/permissions)が必要です。
{% endalert %}

## 主要概念 {#key-concepts}

### 送信済みと配信済み {#sent-and-delivered}

このダッシュボードは、Brazeがメッセージを内部的にどのように処理したかを報告するものであり、メッセージの最終的な配信ステータスを報告するものではないことを理解することが重要です。

このダッシュボードで「送信済み」と表示されたメッセージは、Brazeがメッセージの処理と発送に成功したことを意味します。ほとんどのチャネルでは、Brazeが関連するサードパーティの送信パートナーにメッセージを引き渡したことを意味します。ただし、ユーザーのデバイスへの最終的な配信を保証するものではありません。

Brazeがメッセージを「送信」した場合、最終的な配信は外部サービスに依存する場合があります。各チャネルの例を以下に示します。

| チャネル | 最終配信の例 |
| --- | --- |
| Content Cards | カードが送信され、閲覧可能な状態になりました。 |
| メール | Brazeがメッセージをメールサービスプロバイダー（ESP）に引き渡します。ESPが最終的な配信を担当します。例えば、メールアドレスが無効であったり、受信トレイがいっぱいであったりすると、ESPが「バウンス」を報告する場合があります。 |
| アプリ内メッセージ | メッセージがユーザーに表示され、インプレッションが記録されました。 |
| LINE | メッセージが送信パートナーに正常に引き渡されました。 |
| プッシュ | Brazeがメッセージを適切なプッシュ通知サービス（iOSの場合はApple Push Notification service、Androidの場合はFirebase Cloud Messagingなど）に引き渡します。そのサービスがデバイスへの通知の最終的な配信を担当します。 |
| SMS/MMS/RCS | BrazeがメッセージをSMSゲートウェイ（Twilioなど）に引き渡します。そのゲートウェイがモバイルキャリアへの最終的な配信を担当します。 |
| webhook | webhookリクエストが正常に行われ、`2xx`レスポンスが返されました。 |
| WhatsApp | メッセージが送信パートナーに正常に引き渡されました。 |
{: .reset-td-br-1 .reset-td-br-2 aria-label="送信済みと配信済み" }

### データの鮮度 {#data-freshness}

このダッシュボードのデータが更新される頻度は、システム負荷に基づいて変動する場合があります。更新頻度は保証されていませんが、ほとんどの場合、1時間未満で更新される可能性が高いです。

## ダッシュボードの設定 {#configuring-the-dashboard}

診断ダッシュボードにアクセスするには、**分析** > **ダッシュボードビルダー**に移動し、Brazeが作成したダッシュボードの一覧から**メッセージング診断**を選択します。

ダッシュボードを実行してデータを表示するには：

1. ダッシュボードレポートのソースとして**キャンペーン**または**キャンバス**を選択します。
2. 1つ以上のキャンペーンまたはキャンバスを選択します。
3. **ダッシュボードを実行**を選択して、選択したフィルターのデータを読み込みます。

## データの解釈 {#interpreting-the-data}

{% alert note %}
ダッシュボードには最大で過去7日間のデータのみが表示されます。すべてのタイムスタンプはワークスペースのタイムゾーンで表示されます。
{% endalert %}

### サマリータイル {#summary-tiles}

ページの上部には、選択した期間の主要なサマリータイルがあり、以下が表示されます。

- **送信済み:** Brazeが正常に処理し送信したメッセージの合計数。
  - **メール、SMS/MMS/RCS、WhatsApp、LINE、プッシュ:** メッセージが送信パートナーに正常に引き渡されました。
  - **Webhook:** Webhookリクエストが正常に実行され、`2xx`レスポンスが返されました。
  - **Content Cards:** カードが送信され、表示対象となりました。
  - **アプリ内メッセージ:** メッセージがユーザーに表示されました。
- **未送信:** 中止されたメッセージの合計数。これには、キャンバスに入らなかったキャンバスオーディエンスメンバーや、ステップの失敗を経験したり、離脱イベントの実行中に離脱条件を満たしたためにキャンバスを離脱したメンバーが含まれます。

### 時系列でのメッセージ結果 {#message-outcomes-over-time}

この時系列チャートは、メッセージが中止された理由やユーザーがキャンバスからドロップされた理由を時間単位で分類して表示します。このチャートの結果ラベルは正規化されたダッシュボードラベルであり、生のイベントペイロード値ではありません。このチャートには送信数は表示されません。

### メッセージ結果の詳細ログ {#message-outcomes-granular-log}

ダッシュボードには、選択したフィルターと期間における個々のメッセージ結果の詳細テーブルが表示されます。このテーブルを使用して、タイムスタンプ、ユーザーID、キャンバスステップ、結果、詳細、チャネルを含む特定のレコードを確認できます。

テーブルをフィルタリングして、特定のレコードに注目できます。

- **結果でフィルター:** 結果フィルターから結果を選択して、その結果のみの行を表示します（例: `Frequency capped`や`User not eligible for channel`）。
- **ユーザーIDで検索:** 検索フィールドにユーザーIDを入力して、その特定のユーザーの行を表示します。

両方のフィルターを適用すると、テーブルは選択した結果と入力したユーザーIDの両方に一致する行を返します。

テーブルの行を選択すると、詳細パネルが開きます。詳細パネルはその結果に関する追加のコンテキストを提供し、Ask Operatorは根本的な問題のトラブルシューティングに役立つ改善ガイダンスを提供します。

![選択した行と詳細パネルへのアクセスが表示されたメッセージング診断の詳細結果ログ]({% image_buster /assets/img/messaging_diagnostics_dashboard_details_log.png %}){: style="max-width:45%;"} ![結果のコンテキストと改善ガイダンスが展開されたメッセージング診断の詳細パネル]({% image_buster /assets/img/messaging_diagnostics_dashboard_drawer_expanded.png %}){: style="max-width:45%;"}

{% alert note %}
チャネルフィルターは、特定のメッセージングチャネルに関連付けられた結果に適用されます。一部の結果はチャネルに依存しないため、チャネルフィルターを適用しても集計ビューに表示されることがあります。
{% endalert %}

### 中止結果 {#abort-outcomes}

以下の定義は、ダッシュボードに表示される中止結果について説明しています。結果はカテゴリ別にグループ化されているため、調査対象の結果を見つけやすくなっています。

{% alert note %}
メッセージング診断の中止結果は、人間が読めるダッシュボードラベルです。[Currentsメッセージエンゲージメントイベント]({{site.baseurl}}/user_guide/data/distribution/braze_currents/event_glossary/message_engagement_events)では、中止情報は`abort_type`や`abort_log`などのフィールドで表されます。これらのデータセットは表現と処理パスが異なるため、CurrentsとMessaging Diagnosticsの間でカウントや命名が異なる場合があります。
{% endalert %}

#### コンテンツとレンダリング {#content-and-rendering}

| 中止結果 | 説明 |
| ---- | ---- |
| Content Cardの期限切れ | ユーザーが閲覧する前にContent Cardの有効期限が切れました。 |
| Content Cardが無効 | Content Cardにエラーがあり、ユーザーに送信されませんでした。一般的な理由は以下の通りです: {::nomarkdown}<ul><li>最大サイズ超過（2 KB）</li><li>有効期限が無効</li><li>メッセージに無効な文字が含まれている</li></ul>{:/} |
| Connected Contentの失敗 | Brazeはメッセージの送信を試みましたが、Connected Contentが最大リトライ回数（デフォルトは5回）に達した後に失敗しました。**注:** このカウントは、最大リトライ回数に達したために中止されたメッセージの数を表しており、Connected Contentリクエストの失敗の合計数ではありません。 |
| アプリ内メッセージのレンダリングタイムアウト | 複数回のリトライ後、Liquidをレンダリングできずタイムアウトしました。 |
| Liquidの中止 | [abort_message]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/liquid/aborting_messages) Liquidタグが呼び出されたため、送信がキャンセルされました。 |
| Liquidのレンダリングタイムアウト | Liquidテンプレートのレンダリングに時間がかかりすぎました。バナー、アプリ内メッセージ、メールで発生する可能性が最も高いです。 |
| Liquid構文エラー | Liquidテンプレートに解析エラーがあったため、メッセージがキャンセルされました。 |
| メディアURLの失敗 | メッセージ内のメディアURLをBrazeが処理できませんでした。URLがブロックされている、無効である、タイムアウトした、無効なHTTPステータスを返した、またはSSL検証に失敗した場合に発生する可能性があります。 |

| 中止結果 | 説明 |
| ---- | ---- |

| 72時間超のレート制限 | [配信速度レート制限]({{site.baseurl}}/user_guide/messaging/messaging_fundamentals/frequency_capping#delivery-speed-rate-limiting)により、メッセージが72時間以上スロットルされたため、送信が中止されました。 |

#### ユーザー資格とプロファイル {#user-eligibility-and-profile}

| 中止結果 | 説明 |
| ---- | ---- |
| 重複するユーザー識別子 | 一致する識別子（external ID、メールアドレス、電話番号など）を持つ複数のユーザーがこのメッセージを受信する資格がありました。同一ユーザーへの重複送信を防ぐため、このメッセージは中止されました。 |
| メッセージステップの事前チェックに失敗したユーザー | Brazeはキャンバスメッセージステップの完全な配信バリデーションの前に、オーディエンス資格、再資格、チャネル資格の基本的な事前チェックの初回パスを実行します。この結果は、ユーザーまたはメッセージがこれらのチェックのいずれかに失敗したため、そのステップでメッセージが中止されたことを意味します。 |
| トリガーメッセージの事前チェックに失敗したユーザー | Brazeはこのトリガーから送信するメッセージを作成する前に、オーディエンス資格、再資格、チャネル資格の基本的な事前チェックの初回パスを実行します。この結果は、ユーザーまたはメッセージがこれらのチェックのいずれかに失敗したため、メッセージが中止されたことを意味します。 |
| ユーザーが資格を喪失 | ユーザーは最初にターゲットオーディエンスに含まれていましたが、Brazeがメッセージを送信するかユーザーをキャンバスに入れる前に、オーディエンス条件に一致しなくなりました。ユーザーが最初にオーディエンス条件を満たしてからオーディエンスから外れるまでの時間は、以下の遅延に起因する可能性があります: {::nomarkdown}<ul><li>インテリジェントタイミング</li><li>サイレント時間帯</li><li>ローカルタイム</li><li>配信速度レート制限（キャンバスのエントリには適用されません）</li><li>メッセージングパイプラインの遅延</li></ul>{:/} |

| ユーザープロファイルが見つからない | ユーザーが存在したことがないか、Brazeに存在しなくなりました。一般的なケースは以下の通りです: {::nomarkdown}<ul><li>APIメッセージングを使用してユーザーをターゲットにしたが、Brazeにユーザーが存在しなかった。</li><li>メッセージが送信される前またはキャンバスステップが実行される前にユーザーが削除された。</li><li>メッセージが送信される前にユーザーが別のプロファイルに統合された。</li></ul>{:/} |

| プッシュ認証情報が無効 | このアプリの[プッシュ認証情報]({{site.baseurl}}/user_guide/channels/push/faqs#why-doesnt-an-opted-in-user-have-a-push-token)が見つからないか無効であるため、送信がキャンセルされました。**App Settings**で認証情報を更新してください。 |

| Webhookの失敗 | Webhookが失敗のレスポンスコード（非`2xx`）を受信しました。一般的なエラーコードとしては、`4XX`クライアントエラー、`5XX`サーバーエラーまたはタイムアウト、または`598 Host Unhealthy`やリクエストの一時停止があります。 |

## よくある質問 {#frequently-asked-questions}

### 「事前チェック」の失敗とはどういう意味ですか？ {#what-does-a-pre-check-failure-mean}

「事前チェック」とは、パイプラインステージの冒頭（メッセージのトリガーやキャンバスのメッセージステップの送信など）で実行される高速でバンドルされたバリデーションチェックを指します。最大速度を実現するための早期終了と考えてください。多くの個別のリソース集約型チェック（ユーザープロファイルのあらゆる詳細の検証など）を別々に実行する代わりに、Brazeは複数の基本的なバリデーションを1つの「ファーストパス」にバンドルします。

このバンドルされたチェックにユーザーが失敗した場合、即座にドロップされます。このバンドル方式により、Brazeは大量のメッセージを高速で処理でき、各メッセージの処理レイテンシーを削減することで、キャンペーンやキャンバスのパフォーマンスをより高速で安定したものにすることができます。

### 「その他」の中止結果とはどういう意味ですか？ {#what-does-an-other-abort-outcome-mean}

これは、既存のダッシュボードカテゴリに分類されない中止です。「その他」の中止の割合が大きいことに気付いた場合は、[Brazeサポート]({{site.baseurl}}/user_guide/administer/personal/braze_support)に連絡してさらなるサポートを受けてください。

### _未送信_ と _送信済み_ の合計が想定オーディエンスサイズよりも少ないのはなぜですか？ {#why-is-the-sum-of-_not-sent_-and-_sent_-lower-than-my-expected-audience-size}

これはいくつかの理由で発生する可能性があります。

- **オーディエンス条件:** キャンペーンやキャンバスが開始された時点で、予想よりも少ないユーザーしかオーディエンス条件を満たしていなかった可能性があります（たとえば、セグメントに含まれていなかった、または必要な属性を持っていなかったなど）。
- **処理中:** メッセージがまだ処理中の可能性があります。ユーザーがキャンバスの初期ステップにまだおり、メッセージステップに到達していない場合があります。
- **データの鮮度:** ダッシュボードのデータは約15分ごとに更新されますが、これは保証されるものではありません。このキャンペーンやキャンバスの最新データがまだダッシュボードに反映されていない可能性があります。
- **エッジケース:** 現時点でこのダッシュボードにキャプチャされていないエッジケースに遭遇している可能性がわずかにあります。この可能性が疑われる場合は、[Brazeサポート]({{site.baseurl}}/user_guide/administer/personal/braze_support)に連絡してください。

### _未送信_ と _送信済み_ の合計がキャンペーンやキャンバスのオーディエンスよりも多いのはなぜですか？ {#why-is-the-sum-of-_not-sent_-and-_sent_-greater-than-the-audience-for-a-campaign-and-canvas}

これは以下の理由で発生する可能性があります。

- **マルチチャネルメッセージ:** キャンペーンまたはキャンバスステップが複数のチャネル（SMSやメールなど）で送信するように設定されていた場合です。1人のユーザーが、あるチャネル（メールなど）では「送信済み」の結果を受け、別のチャネル（「ユーザーはチャネルの対象外」など）では「中止」の結果を受けることがあります。この場合、そのユーザーはチャートで2回カウントされます。1回は「送信済み」、もう1回は「中止」です。
  - **例:** 100人のユーザーにプッシュキャンペーンを送信し、iOSとAndroidの両方をターゲットにしているとします。あるユーザーがiOSデバイスのみを持っている場合、iOSプッシュは受信しますが（「送信済み」）、Androidプッシュの中止もトリガーされます（「ユーザーはチャネルの対象外」）。
- **複数のメッセージステップ（キャンバスのみ）:** キャンバスの特定のパスに複数のメッセージステップがある場合があります。このダッシュボードはすべての結果を集計するため、選択した期間内に複数のメッセージステップを通過した場合、1人のユーザーが複数回カウントされることがあります。
- **テストメッセージ:** テスト送信（ダッシュボードでカウントされます）により、合計カウントがオーディエンスサイズよりも大きくなっている場合があります。
