# アンインストール追跡 {#uninstall-tracking}

> この記事では、アプリのアンインストールの集計を時系列で表示し、傾向や異常を特定する方法と、キャンペーンレベルのアンインストールを追跡し、特定のキャンペーンがアプリのインストールを促進しているのか妨げているのかを判断する方法を紹介します。

Brazeのアンインストール追跡では、以下の詳細が提供されます。

1. アプリレベルの日次アンインストール統計情報：**ホーム**ページの時系列グラフに表示されます。
2. キャンペーンレベルのアンインストール統計情報：特定のキャンペーンの**キャンペーンの詳細**ページの時系列グラフに表示されます。この統計情報は、アンインストールしたキャンペーン受信者の日次数を示します。

{% alert note %}
Brazeダッシュボードでアンインストール追跡をオプトインする必要があります。この機能は、iOS、Android、Fire OSのアプリで利用できます。
{% endalert %}

## 仕組み {#how-it-works}

Brazeは、通常のプッシュキャンペーンからアンインストールに関する基本的な情報を自動的に収集します。ただし、異なるユーザーがプッシュキャンペーンを受信する頻度は異なる場合があるため、ユーザー間のアンインストールアクティビティをより正確に把握できるよう、アンインストール追跡を提供しています。

Brazeがアンインストールを検出すると、そのユーザーにアンインストール済みのタグが付けられます。キャンペーンで**アンインストールしていない**フィルターを使用すると、これらのタグ付きユーザーは除外されます。ユーザーがアプリを再インストールしても開かなかった場合、アンインストールタグはプロファイルに残ります。このタグは、ユーザーが再インストールしたアプリで新しいセッションを開始したときにのみ削除されます。つまり、再インストールしたものの一度もアプリを開かないユーザーは、引き続きアンインストール済みとして表示されます。

アンインストール追跡の使用方法について詳しくは、ブログ記事 [Uninstall Tracking: An Industry Look at its Strengths and Limitations](https://www.braze.com/blog/uninstall-tracking-an-industry-look-at-its-strengths-and-limitations/) をご覧ください。

## アンインストール追跡を有効にする {#turning-on-uninstall-tracking}

アンインストール追跡は、**設定**の**アプリ設定**ページで、追跡したいアプリごとに有効にできます。

アプリのアンインストール追跡を有効にすると、Brazeは24時間以内にセッションを記録していない、またはプッシュを受信していないユーザーに対して、毎晩バックグラウンドプッシュメッセージを送信します。

### 設定 {#configuration}

iOSアプリケーションのアンインストール追跡を設定するには、[ユーティリティメソッド]({{site.baseurl}}/developer_guide/analytics/tracking_uninstalls?sdktab=swift)を使用します。Androidアプリケーションの場合は、[`isUninstallTrackingPush()`](https://braze-inc.github.io/braze-android-sdk/kdoc/braze-android-sdk/com.braze.models.push/-braze-notification-payload/is-uninstall-tracking-push.html)を使用します。Brazeがアンインストールを検出すると、それがアンインストール追跡によるものであれ、通常のプッシュ通知キャンペーン配信によるものであれ、最も正確と推定されるアンインストール時刻をユーザープロファイルに記録します。この時刻は標準属性項目としてユーザープロファイルに保存され、奪還キャンペーン用のセグメントを定義するために使用できます。

## アンインストールによるセグメントのフィルタリング {#filtering-segments-by-uninstalls}

**アンインストール済み**フィルターは、指定した期間内にアプリをアンインストールしたユーザーを選択します。アンインストールの正確なタイミングを判断するのは難しいため、アンインストールフィルターには広めの期間を設定し、アンインストールしたすべてのユーザーがいずれかの時点でセグメントに含まれるようにすることをお勧めします。

アンインストールの日次統計は**ホーム**ページに表示されます。

![アンインストールセグメント。]({% image_buster /assets/img_archive/Uninstall_Segment.png %} "Uninstall Segment")

このグラフは、Brazeが提供する他の統計と同様に、アプリやセグメントごとに分類できます。**パフォーマンス概要**セクションで、日付範囲と、必要に応じてアプリを選択します。次に、**パフォーマンスの推移**グラフまでスクロールし、以下の操作を行います。

1. **統計の対象**ドロップダウンで、**アンインストール**を選択します。
2. **内訳**ドロップダウンで、**セグメント別**を選択します。
3. **内訳の値**ドロップダウンで、グラフに含めるセグメントを選択します。

{% alert note %}
アンインストール追跡が有効になっていないアプリは、ユーザーの一部（プッシュ通知の配信対象となったユーザー）のみのアンインストールを報告するため、日次のアンインストール合計数は表示されている値よりも高くなる可能性があります。
{% endalert %}

## キャンペーンのアンインストール追跡 {#uninstall-tracking-for-campaigns}

キャンペーンのアンインストール追跡では、特定のキャンペーンを受信した後、選択した期間内にアプリをアンインストールしたユーザーの数を表示します。このツールにより、キャンペーンが意図しないネガティブなユーザー行動を促進していないかについてのインサイトが得られ、キャンペーン全体の効果測定に役立ちます。

キャンペーンのアンインストール統計は、特定のキャンペーンの**キャンペーン分析**ページにあります。マルチチャネルキャンペーンおよび多変量キャンペーンの場合、アンインストールはそれぞれチャネル別およびバリアント別に分類できます。

![キャンペーンレベルのアンインストール追跡。]({% image_buster /assets/img_archive/campaign_level_uninstall_tracking.png %})

### 仕組み

Brazeは、ユーザーのデバイスに送信されたプッシュメッセージがFirebase Cloud Messaging（FCM）またはApple Push Notification Service（APNs）からアプリがインストールされていないというシグナルを返した場合に、アンインストールを追跡します。アプリのグローバルアンインストール追跡を有効にすると、Brazeはユーザーがアンインストールしたかどうかを検出するために、毎日サイレントプッシュメッセージを送信します。Brazeはこの「サイレント」プッシュをすべてのユーザーに送信します（ユーザーがアプリの設定でサイレントプッシュを無効にしている場合を除く）。このプッシュはユーザーには表示されません。Brazeがユーザーのアンインストールを検出した場合、以下の処理を行います。

* アプリの合計アンインストール数を1つ増加させます。
* 過去24時間以内にユーザーが正常に受信したすべてのキャンペーンのアンインストール数を1つ増加させます。
* ユーザーが24時間以内に3つのキャンペーンを受信した後にアンインストールした場合、3つのキャンペーンすべての「アンインストール」カウントを増加させます。

FCMおよびAPNsはアンインストール追跡に制限を設けています。Brazeは、FCMまたはAPNsからユーザーがアンインストールしたことが通知された場合にのみアンインストール数を増加させますが、これらのサードパーティシステムは任意のタイミングでアンインストールを通知する場合があります。アンインストール追跡は、正確な統計ではなく、方向性のあるトレンドを検出するために使用してください。

Brazeは、`DEVICE_UNREGISTERED`や`NotRegistered`など、FCMが登録トークンが無効であると報告した場合のFCMレスポンスを、トークン削除（アンインストール）レスポンスとして扱います。Brazeはその他のプッシュエラーを、トークンを削除せずにバウンスとして記録します。

アンインストール追跡の使用方法の詳細については、ブログ記事[Uninstall Tracking: An Industry Look at its Strengths and Limitations](https://www.braze.com/blog/uninstall-tracking-an-industry-look-at-its-strengths-and-limitations/)をご覧ください。

## トラブルシューティング {#troubleshooting}

### ユーザーのプロファイルがアンインストール済みとしてフラグ付けされるタイミングは？アンインストールタグがクリアされるタイミングは？ {#when-is-a-users-profile-flagged-as-uninstalled-when-is-the-uninstall-tag-cleared}

Brazeは、アプリがデバイス上に存在しなくなったことを検出した場合に、ユーザーをアンインストール済みとしてフラグ付けします（通常のプッシュおよびオプションのアンインストール追跡による検出については、[仕組み](#how-it-works)を参照してください）。ユーザーがアプリを再インストールした後も、**アプリを開いて新しいセッションを開始する**まで、アンインストールタグはプロファイルに残ることがあります。再インストールだけではタグはクリアされません。そのセッションが開始されるまで、アンインストール状態を使用するセグメントやフィルター（例：**アンインストールしていない**）では、引き続きそのユーザーをアンインストール済みとして扱います。

### 突然アンインストールが急増しているのはなぜですか？ {#why-am-i-suddenly-seeing-a-spike-in-uninstalls}

アプリのアンインストールが急増している場合、Firebase Cloud Messaging（FCM）やApple Push Notification Service（APNS）が古いトークンを異なる頻度で失効させていることが原因である可能性があります。

{% alert note %}
プライバシー上の理由から、Brazeのプッシュプロバイダーは不定期にトークンを失効させることがあり、特定の期間にアンインストール数が急増することがあります。<br><br>これらの変動を検証するには、アンインストール追跡をプッシュの直接開封率などのユーザーアクション指標と併せて監視してください。アンインストールが急増しているのにプッシュの直接開封が安定している場合、その急増はプロバイダーが古いトークンを失効させたことを反映している可能性が高く、実際のユーザー行動ではない場合があります。
{% endalert %}

### 特定のキャンペーンがアンインストールの原因かどうかを判断するにはどうすればよいですか？ {#how-do-i-determine-if-a-specific-campaign-caused-uninstalls}

アンインストールの急増が発生した時期と同じ頃にメッセージを送信したキャンペーンの分析を確認してください。特定のメッセージがアンインストールの増加と相関している場合、そのメッセージがユーザーのアンインストールに影響を与えている可能性があります。

セグメント別にアンインストールを表示するには：
1. ダッシュボードの**ホーム**ページに移動します。
2. **パフォーマンスの推移**セクションで、**統計対象**に**アンインストール**を、**内訳**に**セグメント別**を選択します。

[分析トラッキング]({{site.baseurl}}/user_guide/analytics/tracking/segment_analytics_tracking)が有効な離脱ユーザーを追跡するセグメントがある場合、そのアンインストールトレンドをアプリ全体のトレンドと比較してください。

### アンインストールが本物であることを確認するにはどうすればよいですか？ {#how-do-i-confirm-uninstalls-are-genuine}

APNsの場合、ユーザープロファイルで`BadDeviceToken`プッシュエラーを確認してください。このエラーがアンインストールの急増と同じ時間帯に大量に発生している場合、アンインストールは本物である可能性が高いです。`BadDeviceToken`はデバイスのプッシュトークンが無効になったことを示しており、これは通常アプリがアンインストールされた際に発生します。

### アプリのアンインストール数がAPNsの数値と異なるのはなぜですか？ {#why-are-the-number-of-app-uninstalls-different-from-whats-in-apns}

この差異は想定されるものです。

Appleは、プッシュトークンが無効になったことの報告を遅延させるためにランダム化されたスケジュールを使用しています。これは、ユーザーがアプリをアンインストールした後でも、APNsがしばらくの間プッシュ通知に対して成功レスポンスを返し続ける可能性があることを意味します。この遅延は意図的なもので、ユーザーのプライバシーを保護するために設計されています。APNsが無効なトークンに対して`410`ステータスを返すまで、バウンスや失敗は報告されません。

### アンインストール追跡はサイレントプッシュやバックグラウンドプッシュとどのように関連していますか？ {#how-does-uninstall-tracking-relate-to-silent-or-background-push}

アンインストールの検出には、可視的な通知として表示されない低優先度のバックグラウンドプッシュを使用することがあります。これらは標準的なメッセージング分析におけるキャンペーンの[**送信**]({{site.baseurl}}/user_guide/analytics/reports/campaign_analytics)とは別のものです。アンインストールのトレンドを分析する際は、アンインストールプッシュをマーケティング送信総数と直接比較するのではなく、アンインストールチャートをプッシュエンゲージメント指標と併せて確認してください。
