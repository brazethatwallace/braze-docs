# アプリ内メッセージのレポート {#iam-reporting}

> このリファレンス記事では、キャンペーンの詳細、メッセージのパフォーマンス、過去のパフォーマンスなど、アプリ内メッセージのレポートと分析について説明します。

{% multi_lang_include analytics/campaign_analytics.md channel="in-app message" %}

## アプリ内メッセージの指標 {#in-app-message-metrics}

ここでは、分析で確認できる主要なアプリ内メッセージの指標を紹介します。Brazeで使用されるすべての指標の定義については、[レポート指標用語集]({{site.baseurl}}/user_guide/analytics/metrics_glossary)を参照してください。

{% alert note %}
アプリ内メッセージの場合、このページではワークスペースのタイムゾーンにおけるカレンダー日の境界を使用してユニークインプレッションを定義しています。
{% endalert %}

| 用語 | 定義 |
| --- | --- |
| ユニークインプレッション | 実際にアプリ内メッセージを閲覧した人の合計数です。ユーザーがワークスペースのタイムゾーンにおける同じカレンダー日にメッセージを複数回受信した場合、その日にカウントされるユニークインプレッションは1回のみです。<br><br> **再適格性がオンの場合：** ユーザーが再度トリガーアクションを実行すると、ワークスペースのタイムゾーンにおける新しいカレンダー日にユニークインプレッションが再びインクリメントされます。アプリ内メッセージの場合、*ユニークインプレッション*は*ユニーク受信者*と等しくなります。どちらも新しいカレンダー日にインクリメントされるためです。 |
| 合計インプレッション | アプリ内メッセージが閲覧された回数です。メッセージが画面に表示されるとインプレッションが記録されます。ユーザーがメッセージを2回閲覧した場合、2回カウントされます。<br><br> **複数のデバイスがあり、再適格性がオフの場合：** ユーザーはアプリ内メッセージを1回のみ閲覧します。ユーザーが複数のデバイスを使用していても、最初にターゲットされたデバイスでのみ閲覧します。これは、プロファイルがデバイスを統合しており、ユーザーがデバイス間で1つのユーザーIDでログインしていることを前提としています。<br><br> **再適格性がオンの場合：** ユーザーがアプリ内メッセージを閲覧するたびにインプレッションが記録されます。<br><br> **注：** *合計インプレッション*は各閲覧をカウントします。*ユニーク受信者*は、ワークスペースのタイムゾーンにおけるカレンダー日の境界を使用して追跡される別の指標です。 |
| コンバージョン | コンバージョンのトラッキングは、ユーザーがアプリ内メッセージのインプレッションを記録した後に開始されます。ユーザーがアプリ内メッセージキャンペーンを受信して閲覧し、その後、定義されたコンバージョン期間内に特定のコンバージョンイベントを実行した場合、メッセージをクリックしたかどうかに関係なく、コンバージョンがカウントされます。<br><br> コンバージョンは、最後に受信したメッセージに帰属されます。再適格性が有効な場合、コンバージョンは定義されたコンバージョン期間内に発生した場合、最後に受信したアプリ内メッセージに割り当てられます。ただし、アプリ内メッセージにすでにコンバージョンが割り当てられている場合、そのメッセージに対して新しいコンバージョンを記録することはできません。これにより、各アプリ内メッセージの配信は1つのコンバージョンのみに関連付けられます。 |
| 合計コンバージョン | ユーザーがアプリ内メッセージキャンペーンを1回のみ閲覧した場合、その後コンバージョンイベントを複数回実行しても、カウントされるコンバージョンは1回のみです。ただし、再適格性がオンで、ユーザーがアプリ内メッセージキャンペーンを複数回閲覧した場合、ユーザーがアプリ内メッセージキャンペーンの新しいインスタンスのインプレッションを記録するたびに、*合計コンバージョン*は1回ずつ増加します。<br><br> たとえば、ユーザーがアプリ内メッセージを2回トリガーし、各インプレッション後にコンバージョンした場合（2回のコンバージョン）、*合計コンバージョン*は2増加します。ただし、インプレッションが1回のみで、その後2回のコンバージョンイベントがあった場合、記録されるコンバージョンは1回のみで、*合計コンバージョン*は1増加します。 |
| コンバージョン率 | コンバージョン率の計算には、1日のユニークインプレッション（*ユニークインプレッション*）の指標が使用されます。<br><br> コンバージョン率 = (1次コンバージョン) / (ユニークインプレッション) <br><br> アプリ内メッセージの場合、*ユニークインプレッション*はワークスペースのタイムゾーンにおけるカレンダー日ごとに1回のみカウントされます。ユーザーが目的のアクション（「コンバージョン」）を完了する回数は、同じカレンダー日内に増加する可能性があります。そのため、ユーザーが1日に複数回コンバージョンを完了した場合、*コンバージョン率*はそれに応じて増加しますが、*ユニークインプレッション*はそのカレンダー日に1回のみカウントされます。 |
{: .reset-td-br-1 .reset-td-br-2 aria-label="アプリ内メッセージの指標" }

{% alert note %}
A/Bテストでは、バリアントメッセージのレンダリングに時間がかかる場合（大きな画像やテンプレート化されたコネクテッドコンテンツなど）、コントロールグループの*ユニークインプレッション*がバリアントの*ユニークインプレッション*を上回ったり、コントロールの*合計インプレッション*がバリアントの*合計インプレッション*を上回ったりすることがあります。メッセージをトリガーしたがバリアントのレンダリングが完了する前に離脱したユーザーは、バリアントのインプレッションを記録しない場合がありますが、コントロールグループはメッセージをレンダリングせずにインプレッションを記録します。
{% endalert %}

## 再適格性でコンバージョンはどのようにインクリメントされますか？ {#how-do-conversions-increment-with-re-eligibility}

Brazeは各アプリ内メッセージの配信に対して1つのコンバージョンのみを割り当て、最後に受信したメッセージに帰属させます。

再適格性がオンの場合、新しい配信ごとに独自のコンバージョンを生成できます。たとえば、ユーザーが同じアプリ内メッセージを5回閲覧し、各インプレッション後にコンバージョンした場合、5回のコンバージョンがカウントされます。ユーザーがメッセージを1回のみ閲覧し、その後複数回コンバージョンした場合、カウントされるコンバージョンは1回のみです。

ユーザーが2日間にわたってアプリ内メッセージを閲覧し、3日目にコンバージョンした場合、Brazeは2日目のインプレッションに対してコンバージョンを記録します。キャンバスの場合、コンバージョンはステップごとではなくキャンバスエントリごとに追跡されます。ユーザーが同じエントリ中に複数のステップでコンバージョンしても、カウントされるコンバージョンは1回のみです。

{% tabs local %}
{% tab シナリオ 1 %}

*ユーザーが1日に同じアプリ内メッセージを5回受信し、同日に5回コンバージョンした場合。*

Sarahはショッピングアプリから、お気に入りのブランドの靴の期間限定セールに関するアプリ内メッセージを受信します。メッセージをクリックして靴を2足購入します。

数時間後、同じアプリ内メッセージを再度受信し、もう1足購入することにします。これが1日に合計5回発生し、Sarahはアプリ内メッセージをクリックするたびに5回の個別の購入を行います。

**結果：** Sarahのその日の*合計コンバージョン*と*合計インプレッション*はそれぞれ5ずつインクリメントされます。*ユニークインプレッション*はワークスペースのタイムゾーンにおけるカレンダー日の境界後にのみ再びインクリメントできるため、*ユニークインプレッション*は変わりません。これにより、その期間内の*コンバージョン率*が増加します。

{% alert note %}
このシナリオの各インプレッションとコンバージョンは、個別のSDKイベントとして処理されます。SDKがインプレッションとコンバージョンイベントをまとめてバッチ処理する場合、コンバージョン数が異なる場合があります。
{% endalert %}

{% endtab %}
{% tab シナリオ 2 %}

*ユーザーが1つのアプリ内メッセージを受信し、同日にコンバージョンした場合。*

Lenaは新しい学習コースに関するアプリ内メッセージを受信します。メッセージをクリックしてコースを開始します。アプリ内で、さらに4つのコースにも登録します。これはすべて、1つのメッセージを受信した後の同日に発生します。

**結果：** Lenaの*合計コンバージョン*と*合計インプレッション*はそれぞれ1ずつインクリメントされます。

{% endtab %}
{% tab シナリオ 3 %}

*ユーザーがアプリ内メッセージを受信し、翌日にコンバージョンした場合。*

TomはeコマースアプリのRegular顧客です。興味のある商品の期間限定割引を宣伝するアプリ内メッセージを受信します。Tomはメッセージをクリックしますが、すぐには購入しないことにします。翌日、Tomは割引を思い出して購入します。この購入は前日に受信したアプリ内メッセージに帰属されます。

**結果：** Tomの*合計コンバージョン*と*合計インプレッション*はそれぞれ1ずつインクリメントされます。

{% endtab %}
{% tab シナリオ 4 %}

*ユーザーがアプリ内メッセージを受信し、翌日に2回コンバージョンした場合。*

Alexは最近アーケードアプリをダウンロードしました。ある日、Alexは新しいゲームのレベルをクリアするよう促すアプリ内メッセージを受信します。Alexはメッセージをクリックしますが、気が散ってレベルをクリアしませんでした。翌日、Alexは同じゲームで2つのレベルをクリアします。

**結果：** レベルのクリアがコンバージョンイベントであるため、Alexは2日目に2回コンバージョンしました。ただし、受信したアプリ内メッセージは1つのみであるため、Alexの*合計コンバージョン*と*合計インプレッション*はそれぞれ1ずつインクリメントされます。

{% endtab %}
{% tab シナリオ 5 %}

*ユーザーが1日に同じアプリ内メッセージを2回受信し、翌日に2回コンバージョンした場合。*

Johnは忙しいビジネスパーソンで、お気に入りのレストランから食事を注文するためにデリバリーアプリを利用しています。通勤中にジオフェンスをトリガーし、近くのレストランを宣伝するアプリ内メッセージを受信します。帰宅時に、再適格性がオンであるため、同じメッセージを再度受信します。オファーは気に入りましたが、その日は注文しないことにします。

翌日、Johnはアプリを通じてランチとディナーを注文し、コンバージョンイベントを2回実行します。

**結果：** Johnの*合計コンバージョン*は1インクリメントされ、*合計インプレッション*は2インクリメントされます。再適格性がオンであるため、コンバージョンはJohnが受信した最後のアプリ内メッセージ（2回目のインプレッション）に割り当てられます。各アプリ内メッセージの配信に対してコンバージョンは1回のみ記録できます。
