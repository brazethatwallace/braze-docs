# アプリ内メッセージのレポート {#iam-reporting}

> このリファレンス記事では、キャンペーンの詳細、メッセージのパフォーマンス、過去のパフォーマンスなど、アプリ内メッセージのレポートと分析について説明します。

{% multi_lang_include analytics/campaign_analytics.md channel="in-app message" %}

## アプリ内メッセージの指標 {#in-app-message-metrics}

ここでは、分析で確認できる主要なアプリ内メッセージの指標を紹介します。Brazeで使用されるすべての指標の定義については、[レポート指標用語集]({{site.baseurl}}/user_guide/analytics/metrics_glossary)を参照してください。

{% alert note %}
アプリ内メッセージの場合、このページではワークスペースのタイムゾーンにおけるカレンダー日の境界を使用してユニークインプレッションを定義しています。
{% endalert %}

| 用語 | 定義 |
| --- | --- |
| ユニークインプレッション | 実際にアプリ内メッセージを閲覧した人の合計数です。ユーザーがワークスペースのタイムゾーンにおける同じカレンダー日に複数回メッセージを受信した場合でも、その日にカウントされるユニークインプレッションは1回のみです。<br><br> **再適格性がオンの場合：** ユーザーが再度トリガーアクションを実行すると、ワークスペースのタイムゾーンにおける新しいカレンダー日にユニークインプレッションが再びカウントされます。アプリ内メッセージの場合、*ユニークインプレッション*は*ユニーク受信者*と等しくなります。どちらも新しいカレンダー日にカウントが増加するためです。 |
| 合計インプレッション | アプリ内メッセージが閲覧された回数です。メッセージが画面に表示されたときにインプレッションが記録されます。ユーザーがメッセージを2回閲覧した場合、2回としてカウントされます。<br><br> **複数のデバイスがあり、再適格性がオフの場合：** ユーザーはアプリ内メッセージを1回のみ閲覧します。複数のデバイスを使用していても、最初にターゲットされたデバイスでのみ表示されます。これは、プロファイルにデバイスが統合されており、ユーザーが複数のデバイスで同じユーザーIDでログインしていることを前提としています。<br><br> **再適格性がオンの場合：** ユーザーがアプリ内メッセージを閲覧するたびにインプレッションが記録されます。<br><br> **注：** *合計インプレッション*は各閲覧をカウントします。*ユニーク受信者*は、ワークスペースのタイムゾーンにおけるカレンダー日の境界を使用して追跡される別の指標です。 |
| コンバージョン | コンバージョントラッキングは、ユーザーがアプリ内メッセージのインプレッションを記録した後に開始されます。ユーザーがアプリ内メッセージキャンペーンを受信して閲覧し、その後定義されたコンバージョンウィンドウ内に特定のコンバージョンイベントを実行した場合、メッセージをクリックしたかどうかに関係なくコンバージョンがカウントされます。<br><br> コンバージョンは最後に受信したメッセージに帰属します。再適格性が有効な場合、コンバージョンは定義されたコンバージョンウィンドウ内に発生した場合に限り、最後に受信したアプリ内メッセージに割り当てられます。ただし、アプリ内メッセージにすでにコンバージョンが割り当てられている場合、そのメッセージに対して新しいコンバージョンを記録することはできません。これにより、各アプリ内メッセージの配信が1つのコンバージョンのみに関連付けられます。 |
| 合計コンバージョン | ユーザーがアプリ内メッセージキャンペーンを1回のみ閲覧した場合、その後コンバージョンイベントを複数回実行しても、カウントされるコンバージョンは1回のみです。ただし、再適格性がオンで、ユーザーがアプリ内メッセージキャンペーンを複数回閲覧した場合、*合計コンバージョン*はユーザーがアプリ内メッセージキャンペーンの新しいインスタンスのインプレッションを記録するたびに1回ずつ増加します。<br><br> たとえば、ユーザーがアプリ内メッセージを2回トリガーし、各インプレッション後にコンバージョンした場合（2回のコンバージョン）、*合計コンバージョン*は2増加します。ただし、インプレッションが1回のみで、その後2回のコンバージョンイベントが発生した場合、記録されるコンバージョンは1回のみで、*合計コンバージョン*は1増加します。 |
| コンバージョン率 | コンバージョン率の計算には、1日あたりのユニークインプレッション（*ユニークインプレッション*）の指標が使用されます。<br><br> コンバージョン率 = (1次コンバージョン) / (ユニークインプレッション) <br><br> アプリ内メッセージの場合、*ユニークインプレッション*はワークスペースのタイムゾーンにおけるカレンダー日ごとに1回のみカウントされます。ユーザーが目的のアクション（「コンバージョン」）を完了する回数は、同じカレンダー日内に増加する可能性があります。そのため、ユーザーが1日に複数回コンバージョンを完了した場合、*コンバージョン率*はそれに応じて増加しますが、*ユニークインプレッション*はそのカレンダー日に1回のみカウントされます。 |
{: .reset-td-br-1 .reset-td-br-2 aria-label="アプリ内メッセージの指標" }

{% alert tip %}
ユーザーが同じカレンダー日にメッセージを複数回閲覧した場合、*合計インプレッション*は*ユニークインプレッション*を超えることがあります（上記の表の指標定義を参照）。インプレッション数が膨らんでいるユーザーを調査するには、**デバイス数**フィルターを**次の値より大きい** `1` に設定し、**キャンペーンからメッセージを受信**フィルターで特定のキャンペーンを指定したセグメントを作成してください。
{% endalert %}

### クリックトラッキング {#click-tracking}

Brazeは、アプリ内メッセージが画面に表示されたときにインプレッションを記録します。[従来のエディター]({{site.baseurl}}/user_guide/channels/in_app_messages/traditional)で作成されたアプリ内メッセージの場合、以下の表はクリックとしてカウントされるものを示しています。

| ユーザーアクション | クリック記録 |
|-------------|--------------|
| ボタンのないメッセージでユーザーがメッセージ本文をクリック | はい（ボディクリック） |
| ユーザーがボタンをクリック | はい（ボタンクリック） |
| ユーザーが閉じるボタン（X）をクリック | いいえ |
| ユーザーがメッセージの外側をタップまたはクリックして閉じる（有効な場合） | いいえ |
| メッセージ表示中にユーザーがアプリを閉じる | いいえ |
{: .reset-td-br-1 .reset-td-br-2 aria-label="クリックトラッキング" }

#### ユーザーアクション別のフルスクリーンメッセージ指標 {#fullscreen-metrics-by-user-action}

従来のエディターで作成された[フルスクリーン]({{site.baseurl}}/user_guide/channels/in_app_messages/message_types/fullscreen)アプリ内メッセージの場合、以下の表は一般的なユーザーアクションに対してBrazeが記録する内容を示しています。メッセージが画面に表示されたときにインプレッションが記録されます。

| ユーザーアクション | ボタン付きフルスクリーン | ボタンなしフルスクリーン |
| --- | --- | --- |
| ユーザーがアプリ内メッセージを閲覧し、何もクリックせずにアプリを閉じる | 1インプレッション | 1インプレッション |
| ユーザーがアプリ内メッセージを閲覧し、閉じるボタンをクリック | 1インプレッション | 1インプレッション |
| ユーザーがアプリ内メッセージを閲覧し、CTAボタンをクリック | 1ボタンクリックと1インプレッション | N/A |
| ユーザーがアプリ内メッセージを閲覧し、画面をタップするがボタンはタップしない | 1インプレッション<br><br>アプリ内メッセージをタップしてもメッセージは閉じません | 1ボディクリックと1インプレッション<br><br>アプリ内メッセージをタップするとメッセージが閉じるか、クリック時の動作がトリガーされます |
{: .reset-td-br-1 .reset-td-br-2 .reset-td-br-3 aria-label="ユーザーアクション別のフルスクリーンアプリ内メッセージ指標" }

{% alert note %}
[ドラッグ＆ドロップエディター]({{site.baseurl}}/user_guide/channels/in_app_messages/drag_and_drop)で作成されたアプリ内メッセージでは、ボディクリックは自動的に収集されません。ボディクリックを記録するには、**カスタムコード**ブロックを追加し、`brazeBridge.logClick()` を呼び出してください。詳細については、[ボタントラッキング]({{site.baseurl}}/user_guide/channels/in_app_messages/message_types/custom_html#button-tracking-improvements)および[JavaScriptブリッジ]({{site.baseurl}}/user_guide/channels/in_app_messages/message_types/custom_html#javascript-bridge)を参照してください。
{% endalert %}

ボディクリックとボタンクリックの定義については、[レポート指標用語集]({{site.baseurl}}/user_guide/analytics/metrics_glossary)を参照してください。

A/Bテストにおけるコントロールグループとバリアントのインプレッションの不均衡については、[コントロールグループとバリアントの差異]({{site.baseurl}}/user_guide/messaging/ab_testing/analytics#discrepancies-between-the-control-group-and-variant)を参照してください。

## 再適格性によるコンバージョンの増加の仕組み {#how-do-conversions-increment-with-re-eligibility}

Brazeは各アプリ内メッセージの配信に対して1つのコンバージョンのみを割り当て、最後に受信したメッセージに帰属させます。

再適格性がオンの場合、新しい配信ごとに独自のコンバージョンを生成できます。たとえば、ユーザーが同じアプリ内メッセージを5回表示し、各インプレッション後にコンバージョンした場合、5つのコンバージョンがカウントされます。ユーザーがメッセージを1回だけ表示し、その後複数回コンバージョンした場合、カウントされるコンバージョンは1つだけです。

ユーザーが2日間にわたってアプリ内メッセージを閲覧し、3日目にコンバージョンした場合、Brazeはそのコンバージョンを2日目のインプレッションに対して記録します。キャンバスの場合、コンバージョンはステップごとではなくキャンバスエントリごとにトラッキングされます。ユーザーが同じエントリ中に複数のステップでコンバージョンした場合でも、1つのコンバージョンとしてカウントされます。

{% tabs local %}
{% tab シナリオ 1 %}

*ユーザーが1日に同じアプリ内メッセージを5回受信し、同日に5回コンバージョンした場合。*

Sarahはショッピングアプリから、お気に入りのシューズブランドの期間限定セールに関するアプリ内メッセージを受信します。メッセージをクリックし、靴を2足購入します。

数時間後、同じアプリ内メッセージを再度受信し、もう1足購入することにします。これが1日に合計5回発生し、Sarahはアプリ内メッセージをクリックするたびに5回の個別の購入を行います。

**結果:** Sarahの*合計コンバージョン数*と*合計インプレッション数*はそれぞれその1日で5ずつ増加します。*ユニークインプレッション数*はワークスペースのタイムゾーンにおける暦日の境界を超えた後にのみ再度増加できるため、*ユニークインプレッション数*は変わりません。これにより、その期間内の*コンバージョン率*が上昇します。

{% alert note %}
このシナリオの各インプレッションとコンバージョンは、個別のSDKイベントとして処理されます。SDKがインプレッションとコンバージョンイベントをまとめてバッチ処理する場合、コンバージョン数が異なることがあります。
{% endalert %}

{% endtab %}
{% tab シナリオ 2 %}

*ユーザーが1つのアプリ内メッセージを受信し、同日にコンバージョンした場合。*

Lenaは新しい学習コースに関するアプリ内メッセージを受信します。メッセージをクリックしてコースを開始します。アプリ内で、さらに4つのコースにも登録します。これらはすべて、1つのメッセージを受信した後の同日に発生します。

**結果:** Lenaの*合計コンバージョン数*と*合計インプレッション数*はそれぞれ1ずつ増加します。

{% endtab %}
{% tab シナリオ 3 %}

*ユーザーがアプリ内メッセージを受信し、翌日にコンバージョンした場合。*

Tomはeコマースアプリの常連顧客です。興味のある商品の期間限定割引を宣伝するアプリ内メッセージを受信します。Tomはメッセージをクリックしますが、すぐには購入しないことにします。翌日、Tomは割引を思い出し、購入を行います。この購入は前日に受信したアプリ内メッセージに帰属されます。

**結果:** Tomの*合計コンバージョン数*と*合計インプレッション数*はそれぞれ1ずつ増加します。

{% endtab %}
{% tab シナリオ 4 %}

*ユーザーがアプリ内メッセージを受信し、翌日に2回コンバージョンした場合。*

Alexは最近アーケードアプリをダウンロードしました。ある日、Alexは新しいゲームのレベルをクリアするよう促すアプリ内メッセージを受信します。Alexはメッセージをクリックしますが、気が散ってレベルをクリアしませんでした。翌日、Alexは同じゲームで2つのレベルをクリアします。

**結果:** レベルのクリアがコンバージョンイベントであるため、Alexは2日目に2回コンバージョンしました。ただし、受信したアプリ内メッセージは1つだけであるため、Alexの*合計コンバージョン数*と*合計インプレッション数*はそれぞれ1ずつ増加します。

{% endtab %}
{% tab シナリオ 5 %}

*ユーザーが1日に同じアプリ内メッセージを2回受信し、翌日に2回コンバージョンした場合。*

Johnは多忙なビジネスパーソンで、お気に入りのレストランから食事を注文するためにデリバリーアプリを利用しています。通勤中にジオフェンスをトリガーし、近くのレストランを宣伝するアプリ内メッセージを受信します。帰宅時に、再適格性がオンになっているため、同じメッセージを再度受信します。オファーは気に入りましたが、その日は注文しないことにします。

翌日、Johnはアプリを通じてランチとディナーを注文し、コンバージョンイベントを2回実行します。

**結果:** Johnの*合計コンバージョン数*は1つ増加し、*合計インプレッション数*は2つ増加します。再適格性がオンになっているため、コンバージョンはJohnが受信した最新のアプリ内メッセージ（2回目のインプレッション）に割り当てられます。各アプリ内メッセージの配信に対してコンバージョンは1回のみ記録できます。
