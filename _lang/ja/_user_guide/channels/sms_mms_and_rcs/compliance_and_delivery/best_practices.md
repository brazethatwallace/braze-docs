# SMS、MMS、RCSのベストプラクティス {#best-practices-for-sms-mms-and-rcs}

> BrazeでのSMS、MMS、RCSのベストプラクティスについて、オプトアウト監視やトラフィックパンピングに関する推奨事項を含めて詳しく説明します。

## オプトアウト監視の推奨事項 {#opt-out-monitoring-recommendations}

通信のオプトアウトを求める受信者のリクエストに従うことは、法律で義務付けられています。SMSチャネルのオプトアウトリクエストに応じないと、罰金などのペナルティが科される可能性があり、訴訟につながることもあります。Brazeには、堅牢なSMSおよびMMSのオプトイン・オプトアウト管理を可能にする機能と、リクエストが正しく処理されることを支援する仕組みが備わっています。

当社との購読契約に基づき、お客様はサービスの利用において適用される法令を遵守する責任を単独で負います。したがって、SMSの設定を正しく構成することに細心の注意を払い、その設定を徹底的にテストし、オプトアウトのコンプライアンスを監視する措置を講じ、オプトアウトリクエストへの非準拠が確認された場合は速やかに対応されることを強くお勧めします。

BrazeでSMSおよびMMSのオプトインとオプトアウトを管理するための設定を行う際は、以下のリソース一覧を参照してください。
* [SMS購読グループ]({{site.baseurl}}/sms_rcs_subscription_groups): 購読グループとオプトイン・オプトアウトの方法およびステータス。
* [購読グループREST API]({{site.baseurl}}/api/endpoints/subscription_groups): メッセージへの直接返信以外のソースから受け取ったオプトインおよびオプトアウトの処理方法。
* [キーワード処理]({{site.baseurl}}/user_guide/channels/sms_mms_and_rcs/message_features_and_optimization/keyword_processing): Brazeがキーワードの処理と管理にどのようにアプローチするかの説明。
* [SMSダブルオプトイン]({{site.baseurl}}/user_guide/channels/sms_mms_and_rcs/message_features_and_optimization/keyword_processing/double_opt_in): SMSメッセージを受信する前に、ユーザーがオプトインの意思を明示的に確認する必要があります。SMSダブルオプトインは一部の国で必須とされているため、Brazeではこの設定を推奨しています。
* [SMSメッセージの送信]({{site.baseurl}}/user_guide/channels/sms_mms_and_rcs/message_setup/sms_sending): BrazeにおけるSMS送信の基本事項。購読グループの重要性、SMSセグメントとメッセージ本文の要件などについて説明します。

### 考慮事項 {#considerations}

SMSおよびMMSが複数のインスタンスにわたって設定されている場合、設定の誤りによりキャンペーンまたはキャンバスのオプトアウトが誤ったワークスペースに送信される可能性があります。

* Brazeにはこのようなケースを特定するための監視体制があります。この動作が検出された場合、Brazeはオプトアウトを正しいインスタンスにリダイレクトし、その期間中に発生したオプトアウトをバックフィルします。
* Brazeに設定されている各購読グループについてオプトアウトをテストされることを強くお勧めします。メッセージを開始する前にこの問題を特定する方が、問題が発覚した後に対処するよりもはるかに効果的です。

Brazeは、ユーザープロファイル（`user_id`）レベルと電話番号（`channel_id`）レベルの両方でSMS/MMSの購読を管理します。電話番号がオプトインまたはオプトアウトされると、その更新はその番号を共有するすべてのプロファイルに適用されます。エンドユーザーがある電話番号でオプトインした後に電話番号を変更した場合、新しい電話番号はそのユーザーの購読グループステータスを引き継ぎます。したがって、エンドユーザーがオプトアウトした後に新しい電話番号でアプリやWebサイトに再度アクセスした場合、不要なメッセージは受信しません。

## 電話番号リストの衛生管理に関する推奨事項 {#phone-number-list-hygiene-recommendations}

電話番号リストの衛生管理を維持することで、有効な同意データと到達可能性データを長期にわたって保持できます。Brazeは、コンプライアンスリスクの軽減、同意に基づくメッセージングの実践のサポート、および元のユーザーに属さなくなった可能性のある番号への送信の回避を目的として、一部の電話番号を無効としてマークします。

電話番号が無効としてマークされる一般的な理由については、[無効な電話番号の処理]({{site.baseurl}}/user_guide/channels/sms_mms_and_rcs/message_setup/user_phone_numbers#handling-invalid-phone-numbers)を参照してください。

無効な電話番号を削除するには、以下のワークフローを推奨します。

1. [`/sms/invalid_phone_numbers`エンドポイント]({{site.baseurl}}/api/endpoints/sms/get_query_invalid_numbers)を通じて、影響を受ける電話番号を特定します。
2. 無効化された電話番号、プロバイダーエラーにより無効とマークされた電話番号、フォーマットの問題により無効とマークされた電話番号（`invalid_format`、E.164形式でない番号など）を区別します。無効な電話番号APIの`reason`フィルターを使用して、カテゴリ別にクエリを実行してください。詳細については、[無効な電話番号の処理]({{site.baseurl}}/user_guide/channels/sms_mms_and_rcs/message_setup/user_phone_numbers#handling-invalid-phone-numbers)を参照してください。
3. 無効化された電話番号については、ユーザーに電話番号を再確認します。ユーザーが電話番号を確認した後、[`/sms/invalid_phone_numbers/remove`エンドポイント]({{site.baseurl}}/api/endpoints/sms/post_remove_invalid_numbers)を通じて、無効リストから電話番号を削除します。

## トラフィックポンピングに関する推奨事項 {#traffic-pumping-recommendations}

### トラフィックポンピングとは {#what-is-traffic-pumping}

トラフィックポンピングとは、悪意のある行為者がオンラインフォームを利用して大量のSMSメッセージ（オプトインメッセージやワンタイムパスワードなど）の送信をトリガーする不正行為です。悪意のある行為者はこれらのメッセージの送信先としてプレミアムレート電話番号を設定し、そのプレミアムレート番号が設定されている携帯キャリアからの収益分配を請求することで、不正な収益を得ます。

### トラフィックポンピングの見分け方 {#how-to-spot-traffic-pumping}

* この種の詐欺を支えるプレミアムレート番号は、必ずしもそうとは限りませんが、通常の送信対象地域以外の国で設定されていることが多いです。
* オンラインフォームからのメッセージ送信量の異常な急増は、トラフィックポンピングを示している可能性があります。
    * 不自然に多い数のメッセージが送信された場合に上限を設定し通知を受け取るために、[キャンペーンアラート]({{site.baseurl}}/user_guide/messaging/campaigns/manage_campaigns/campaign_alerts)を設定することをお勧めします。
* オンラインフォームが不完全な場合は、プログラムによるフォーム入力を示唆している可能性があります。
* オンラインフォームを構築する際は、フォームが完全に入力されていることを確認するルールを設定し、CAPTCHAなどのツールを使用してリスクを最小限に抑えることをお勧めします。

### トラフィックポンピングの影響 {#impact-of-traffic-pumping}

お客様は自身が送信するトラフィックの監視に責任を負い、アカウントを通じて送信されたすべてのSMSに対して請求されます。Brazeとお客様の間では、トラフィックポンピングを検知し防止するためにより適切な立場にあるのはお客様です。

## 多国間SMS送信 {#multi-country-sms-sending}

一部のブランドでは、異なる国の電話番号を持つユーザーグループにメッセージを送信したい場合があります。特定の国の電話番号にSMSメッセージを送信するには、同じ国のロングコードまたはショートコードを使用することがベストプラクティスです。実際、ショートコードは、そのショートコードが作成された国と同じ国の電話番号にのみSMSを送信できます。

この制限を克服するために、購読グループの[設定プロセス]({{site.baseurl}}/user_guide/channels/sms_mms_and_rcs/message_setup/subscription_groups)では、複数の異なる国のロングコードとショートコードを保持するようにグループを設定できます。設定が完了すると、キャンペーンの開始時にターゲットユーザーの電話番号と同じ国コードを持つ電話番号が自動的に使用されます。異なる国コードの電話番号を持つユーザーごとに個別のキャンペーンを作成する必要がないため、1つのキャンペーンを開始したり、1つのキャンバスコンポーネントを使用して関連するユーザーをターゲットにしたりできます。

![ターゲットユーザーの電話番号と同じ国コードを使用してSMSペイロードが送信されます。]({% image_buster /assets/img/sms/multi_country_subgroups.png %})

### 一般的な送信のベストプラクティス {#general-sending-best-practices}

1. **許可を得る。** ビジネスとしてSMSを使用する際の最も重要なルールの1つは、まず顧客から連絡する許可を得ることです。これを怠ると、ブランドイメージが損なわれ、高額な法的費用が発生する可能性があります。
2. **ユースケースに適した番号を選択する。** SMSメッセージを送受信できる電話番号には、ロングコード、ショートコード、英数字の送信者IDの3つの主要なタイプがあり、それぞれの機能と利用可能なリージョンは異なります。バニティコードの方がビジネスに適しているかどうかを事前に検討してください。
3. **タイミングに注意する。** 顧客は、直接自分に宛てられたメッセージに対してより反応しやすいことを覚えておいてください。受信者の名を使用したり、顧客の興味に合った会話調のタッチを加えるなど、少しのパーソナライゼーションが大きな効果をもたらします。
4. **双方向の会話に参加する。** SMSは顧客とのエンゲージメントに非常に効果的なチャネルであるため、メッセージへの返信を予測し、効果的に処理することが重要です。消費者の85%は、情報を受け取るだけでなく、ビジネスに返信したり会話に参加したりすることを望んでいます。
5. **効果を測定する。** 適切なタイミングで、最適な頻度で、最も効果的なコールトゥアクションを使用して顧客にリーチしていますか？適切なトラッキングツールを使用することで、ROIを証明する直接的かつ測定可能な指標を得ることができます。

## 大量送信 {#high-volume-sending}

大量送信を予定していますか？スムーズに送信するためのベストプラクティスをご紹介します。

- ターゲットオーディエンスのサイズに基づいて、キャンペーンまたはキャンバスの配信速度レート制限を必要に応じて調整してください。これにより、必要な送信量を達成し、SMSまたはRCSプロバイダーが想定し処理可能なレートでBrazeがメッセージを送信できるようになります。
- 160文字の制限を守り、特殊文字が2文字分としてカウントされることに注意してください（例：スラッシュ `\`、キャレット `^`、チルダ `~`）。

## サイレントアワーの推奨事項 {#quiet-hours-recommendations}

{% alert warning %}
**Brazeネイティブのサイレントアワーは、デバイスレベルの配信時刻を保証するものではありません。**メッセージが送信されると、キャリアに引き渡されます。キャリアがメッセージを受け入れた後、ユーザーのデバイスに配信される正確なタイミングについてBrazeはコントロールできません。<br><br>たとえば、メッセージが午後8時59分にキャリアに引き渡された場合、デバイスに届くのは午後9時02分になる場合があります。リスクを軽減するために、以下のLiquidベースのサイレントアワー方式を使用することをお勧めします。この方法では、メッセージが引き渡される前に、Brazeエンジンレベルで送信を抑制します。
{% endalert %}

### Brazeネイティブのサイレントアワー {#braze-native-quiet-hours}

SMSキャンペーンとキャンバス全体で、追加のスケジュール制御として[サイレントアワー]({{site.baseurl}}/user_guide/brazeai/intelligence_suite/intelligent_timing#quiet-hours)を有効にできます。コンプライアンスに敏感な送信の場合は、メッセージがキャリアに引き渡される前の主要な制御として、次のセクションのLiquidベースのセーフガードを使用してください。

### Content Blocksによる追加のセーフガード {#additional-safeguard-through-content-blocks}

コンテンツブロック内にLiquidベースのチェックを追加できます。これにより、ネイティブ設定と連携して動作する、信頼性の高いスケーラブルなセーフガードが提供されます。

#### 設定 {#setup}

SMSメッセージ本文の先頭に以下のスニペットを含めてください。この例では、ユーザーの[ローカルタイムゾーン]({{site.baseurl}}/user_guide/messaging/campaigns/faq#what-does-local-time-zone-delivery-offer)で午前9時〜午後9時の時間枠外に該当する場合に送信を中止します。

{% raw %}
```liquid
{% assign time = 'now' | time_zone: ${time_zone} %}
{% assign hour = time | date: '%H' | plus: 0 %}
{% if hour >= 21 or hour < 9 %}
  {% abort_message("Outside allowed time window") %}
{% endif %}
```
{% endraw %}

#### 考慮事項

- {% raw %}`time_zone: ${time_zone}`{% endraw %}により、[キャンペーンFAQ]({{site.baseurl}}/user_guide/messaging/campaigns/faq#what-does-local-time-zone-delivery-offer)で説明されているように、固定のグローバル時刻ではなく、各ユーザーのローカルタイムに基づいて時間枠が評価されます。
- {% raw %}`abort_message()`{% endraw %}で抑制されたメッセージは翌日に再スケジュールされず、キャンセルされます。
- {% raw %}デフォルトでは、中止されたメッセージは標準のキャンペーンレポートには表示されません。ただし、Liquidが`{% abort_message %}`で送信を中止すると、Brazeはメッセージアクティビティログにメッセージエラーとして記録します（デフォルトでは`{% abort_message %}`が呼び出されたと表示されます）。文字列を渡すと、その理由がログに表示されます。たとえば`{% abort_message('language was nil') %}`{% endraw %}のように表示されます。ダッシュボードでこれらの抑制を確認するには、[メッセージング診断ダッシュボード]({{site.baseurl}}/user_guide/analytics/dashboards/dashboard_builder/diagnostics_dashboard)へのアクセスについてカスタマーサクセスマネージャーにお問い合わせください。
