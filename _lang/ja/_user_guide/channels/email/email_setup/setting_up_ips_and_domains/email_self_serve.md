# メールセルフサービス {#email-self-serve}

> このページでは、Brazeで送信ドメインとトラッキングドメインを設定し、差出人ドメインとトラッキングリンクが同じサブドメインを共有するようにする方法について説明します。

## 前提条件 {#prerequisites}

セルフサービスメール設定を使用するには、以下の前提条件を満たす必要があります。

- オンボーディング中の新規顧客であること
- 「Edit Domain Settings」の会社レベル権限を持っていること
- IPプール、IPアドレス、および検証済みドメインを持っていること

## 考慮事項 {#considerations}

- 最低3レベルの送信サブドメインを計画してください。Brazeは委任されたドメイン（「marketing.example.com」など）の下にサブドメインを作成するため、送信ドメインは少なくとも3レベルの深さ（「e.marketing.example.com」など）が必要です。
- 送信ドメインは、所有するドメインの下位ドメインである必要があります。たとえば、「example.com」を所有している場合、サブドメインは「mail.example.com」とすることができ、送信アドレス「@mail.example.com」を使用できます。
- ドメイン制限が適用されます。トラッキングドメインの合計数は、契約内の検証済みドメイン数の2倍に制限されます。追加が必要な場合は、アカウントマネージャーにお問い合わせください。

## 設定 {#setup}

### ステップ1:送信ドメインを追加する {#step-1-add-a-sending-domain}

送信サブドメインは、メールの送信元アドレスです。受信者に表示される「差出人」アドレスを決定します。

1. **ドメイン**セクションで、**ドメインを追加**を選択します。
2. IPプールの**Mail from**フィールドと**送信ドメイン**フィールドに送信ドメインを追加します。
    - **Mail from**（エンベロープセンダーまたはリターンパス）アドレスは、バウンスを裏側で処理するものです。受信者にはメール上でこれは表示されません。たとえば、サブドメインとして「bounce」を使用し、カスタムMail fromメールを「bounce.mail.example.com」とすることができます。このサブドメインの使用は、DMARC SPFアライメントのベストプラクティスです。
    - **送信ドメイン**は、受信者が受信トレイで確認する差出人アドレスのドメインです。たとえば、差出人アドレスが「hello@e.mail.example.com」の場合、「e.mail.example.com」が送信ドメインです。
{: start="3"}
3. ドロップダウンから検証済みドメインを選択します。

送信ドメインは送信後に変更できません。Brazeは検証と認証のためのDNSレコードを作成し、DNS設定に追加します。送信ドメインを削除する必要がある場合は、[Brazeサポート]({{site.baseurl}}/user_guide/administer/personal/braze_support)にお問い合わせください。

### ステップ2:トラッキングドメインを追加する {#step-2-add-a-tracking-domain}

トラッキングドメインは、クリックトラッキングとブランディングの目的でメール内のリンクをラップするために使用されます。受信者がメール内のリンクにカーソルを合わせたりクリックしたりすると、このドメインが表示されます。適切なDNS委任のために、送信ドメインまたは検証済みドメインのサブドメインである必要があります。

1. トラッキングドメインのサブドメインとして使用する**検証済みドメイン**または**送信ドメイン**のどちらを使用するかを選択します。
    - トラッキングURLをブランドの一貫性のために送信ドメインと一致させたい場合は、**送信ドメイン**を選択します。
    - より短いトラッキングURLが必要な場合は、**検証済みドメイン**を選択します。

{: start="2"}
2. トラッキングサブドメインを入力します。これは前に選択したサブドメインの前に付加されます。

以下の例は、選択に基づいてメールでトラッキングドメインがどのように表示されるかを示しています。

|  | 選択 | トラッキングドメイン |
| --- | --- | ---|
| 検証済みドメイン | mail.example.com | links.mail.example.com |
| 送信ドメイン | marketing.mail.example.com | links.marketing.mail.example.com |
{: .reset-td-br-1 .reset-td-br-2 .reset-td-br-3 aria-label="選択別のトラッキングドメイン" }

{: start="3"}
3. ドロップダウンから使用する関連付けられた検証済みまたは送信サブドメインを選択します。
4. **送信**を選択します。送信ドメインとトラッキングドメインが**保留中**ステータスで表示されます。

送信ドメインのDNSレコードが伝播するまで5〜10分かかる場合があります。ドメインが使用可能になると、通知メールが届きます。トラッキングドメインのDNSレコードは伝播に最大24時間かかる場合がありますが、通常はそれより短い時間で完了します。送信サブドメインがトラッキングドメインより先に準備完了になる場合があります。

### ステップ3:ワークスペースを選択する {#step-3-select-workspaces}

ドメインにアクセスできるワークスペースを選択し、**確認**を選択します。新しいワークスペースが作成されたときに送信ドメインを自動的に追加するオプションも選択できます。

### ステップ4:ユニバーサルリンクを設定する（オプション） {#step-4-set-up-universal-links-optional}

ユニバーサルリンクを使用すると、メッセージ内のリンクがモバイルブラウザではなくモバイルアプリで直接開くようになります。Brazeは、トラッキングドメイン上のアソシエーションファイルを代わりにホストできます。

{% alert note %}
ユニバーサルリンクはトラッキングドメインごとに適用されます。同じファイル内容をドメイン間で共有できますが、各ドメインは独自のコピーをホストします。
{% endalert %}

1. **設定** > **会社設定** > **検証済みドメイン** > **ユニバーサルリンク**に移動します。
2. **ユニバーサルリンクを設定**を選択します。
3. ユニバーサルリンクセット名を入力します。
4. iOS設定をオンにし、AASAファイルを追加します。JSONが唯一の受け入れ可能なファイルタイプです。Brazeはファイルを読み取り、検出されたアプリIDとコンポーネントの数、および生成されたファイルのプレビューを表示します。
5. Android設定をオンにし、同じ方法でDigital Asset Linksファイルを追加します。Brazeはパッケージ名、SHA-256証明書フィンガープリント、ステートメント数、およびプレビューを表示します。
6. 各プレビューを確認して内容が正しいことを確認し、**次へ：トラッキングドメインを選択**を選択します。検証済みのトラッキングドメインのみが表示されます。1つのセットを複数のトラッキングドメインに適用できます。
7. セットがユニバーサルリンクページに、トラッキングドメイン、チャネル、iOSステータス、Androidステータス、作成日とともに表示されます。Brazeは各ドメインに対してAASAファイルが適切にホストされているかを確認し、結果をステータス列に報告します。

### ステップ5:メール送信をテストする {#step-5-test-your-email-sending}

送信ドメインとトラッキングドメインの両方が**使用可能**ステータスを表示したら、設定をテストします。

1. ワークスペースで、**設定** > **メール設定**に移動します。
2. **表示名アドレス**セクションに新しい送信ドメインが表示されていることを確認します。
3. 新しいドメインを使用した差出人アドレスを追加します（例：「hello@e.mail.example.com」）。
4. **保存**を選択します。
5. テストメールキャンペーンを作成し、自分自身に送信します。次の点を確認してください。
    - メールが正常に配信されたこと。
    - 差出人アドレスが正しいこと。
    - クリックトラッキングリンクがトラッキングドメインを使用していること。
    - ユニバーサルリンクが受信者のデバイスに基づいて期待どおりにアプリまたはWebサイトを開くこと。
    - メールヘッダーが正しく表示されること。

## 次のステップ {#next-steps}

送信者の検証が完了したら、メッセージが一貫して高い割合で宛先の受信トレイに届くように、BrazeはIPウォームアップを推奨します。この設定を完了した後、Brazeオンボーディングチームに相談して、ドメインと[IPウォームアップ]({{site.baseurl}}/user_guide/channels/email/email_setup/ip_warming)が正常に機能しているかを確認してください。

## トラブルシューティング {#troubleshooting}

### DNS伝播が予想より時間がかかっている {#dns-propagation-is-taking-longer-than-expected}

送信ドメインのレコードは通常5〜10分以内に伝播します。トラッキングドメインのレコードは、DNSプロバイダーのTTL設定によっては最大24時間かかる場合があります。伝播に時間がかかる場合は、まずNSレコードが正しく追加されていることを確認してから、Brazeサポートにお問い合わせください。

### 検証済みドメインを削除できない {#im-not-able-to-remove-a-verified-domain}

検証済みドメインは、適切にレビューされないと送信に影響を与える可能性があるため、ダッシュボードから直接削除することはできません。アカウントからドメインを削除するには、Brazeサポートにお問い合わせください。

### ユニバーサルリンクがアプリを開かない {#my-universal-links-arent-opening-the-app}

まず、ユニバーサルリンクページでiOSとAndroidのステータスを確認してください。ドメインが有効なファイルをホストしていない場合は、セットを開き、設定を修正して再度保存してください。ステータスに問題がない場合は、URLをブラウザのアドレスバーに貼り付けるのではなく、実際のデバイスでメール内のリンクからテストしていることを確認してください。

## よくある質問 {#frequently-asked-questions}

### BrazeはNS委任なしでSSL証明書を管理できますか？ {#can-braze-manage-my-ssl-certificate-without-ns-delegation}

検証済みドメインでは、BrazeへのDNS所有権委任のためにNS（ネームサーバー）レコードが必要です。{% multi_lang_include product_feedback_cta.md context="pain_point" channel="feature" feature="Braze-hosted SSL certificates without NS delegation" %}

### 代わりにルートドメインを委任できますか？ {#can-i-delegate-a-root-domain-instead}

検証済みドメインは主にサブドメインでの使用を目的として設計・推奨されています。セキュリティ上の理由から、ブランドのプライマリ親ドメインの委任は推奨しません。委任すると、そのドメインに対する可視性と制御を失うためです。親ドメインを委任する場合は、Braze以外で使用されていない親ドメインを使用してください。

### 検証済みドメインを送信ドメインとしても使用できないのはなぜですか？ {#why-cant-my-verified-domain-also-be-the-sending-domain}

Brazeは検証済みドメイン（通常は親ドメインのサブドメイン、`mail.example.com`）の下に送信サブドメインのみを作成できます。そのため、この場合の送信ドメインの最小深度は、通常の2レベルではなく3レベル（`e.mail.example.com`）になります。

### 設定後にNSレコードを変更するとどうなりますか？ {#what-happens-if-i-modify-any-of-my-ns-records-after-setup}

検証済みドメインはNSレコードが正常であることに完全に依存しています。NSレコードに変更を加えると、メールの送信とトラッキングが中断される可能性があります。

### digコマンドで4つのレコードすべてが表示されるので、NSレコードの1行だけを追加できますか？ {#can-i-add-only-one-of-four-ns-record-lines-since-my-dig-command-shows-all-four-records}

`dig`コマンドを使用して4つのNSレコードすべてが明示的に存在することを確認し、ダッシュボードでドメインが検証されてから設定完了としてください。
