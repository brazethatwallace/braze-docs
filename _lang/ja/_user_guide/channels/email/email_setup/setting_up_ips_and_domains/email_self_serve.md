# メールセルフサービス {#email-self-serve}

> このページでは、Brazeで送信ドメインとトラッキングドメインを設定し、差出人ドメインとトラッキングリンクが同じサブドメインを共有するようにする方法について説明します。

## 前提条件 {#prerequisites}

セルフサービスメール設定を使用するには、以下の前提条件を満たす必要があります。

- オンボーディング中の新規顧客であること
- 「Edit Domain Settings」の会社レベルの権限を持っていること
- IP プール、IP アドレス、および検証済みドメインを持っていること

## 注意事項 {#considerations}

- 最低3階層の送信サブドメインを計画してください。Brazeは委任されたドメインの下にサブドメインを作成するため（「marketing.example.com」など）、送信ドメインは少なくとも3階層の深さが必要です（「e.marketing.example.com」など）。
- 送信ドメインは、所有しているドメインの下位ドメインである必要があります。たとえば、「example.com」を所有している場合、サブドメインは「mail.example.com」となり、送信アドレス「@mail.example.com」を使用できます。
- ドメインの制限が適用されます。トラッキングドメインの合計数は、契約内の認証済みドメイン数の2倍に制限されています。追加が必要な場合は、アカウントマネージャーにお問い合わせください。

## 設定 {#setup}

### ステップ1:送信ドメインを追加する {#step-1-add-a-sending-domain}

送信サブドメインは、メールの送信元アドレスです。受信者に表示される「差出人」アドレスを決定します。

1. **Domains** セクションで、**Add domain** を選択します。
2. IP プールの **Mail from** フィールドと **Sending domain** フィールドに送信ドメインを追加します。
    - **Mail from**（エンベロープ送信者またはリターンパス）アドレスは、バウンスを裏で処理するものです。受信者にはメール上でこのアドレスは表示されません。たとえば、サブドメインに「bounce」を使用すると、カスタム Mail from メールは「bounce.mail.example.com」になります。このサブドメインを使用することは、DMARC SPF アラインメントのベストプラクティスです。
    - **Sending domain** は、受信者が受信トレイで確認する差出人アドレスのドメインです。たとえば、差出人アドレスが「hello@e.mail.example.com」の場合、「e.mail.example.com」が送信ドメインです。
{: start="3"}
3. ドロップダウンから検証済みドメインを選択します。

送信ドメインは、送信後に変更できません。Braze は検証と認証用の DNS レコードを作成し、DNS 設定に追加します。送信ドメインを削除する必要がある場合は、[Braze サポート]({{site.baseurl}}/user_guide/administer/personal/braze_support)にお問い合わせください。

### ステップ2:トラッキングドメインを追加する {#step-2-add-a-tracking-domain}

トラッキングドメインは、クリックトラッキングとブランディングの目的でメール内のリンクをラップするために使用されます。受信者がメール内のリンクにカーソルを合わせたりクリックしたりすると、このドメインが表示されます。トラッキングドメインは、適切な DNS 委任のために、送信ドメインまたは検証済みドメインのサブドメインである必要があります。

1. トラッキングドメインのサブドメインとして使用する **Verified domain** または **Sending domain** のどちらを使用するかを選択します。
    - トラッキング URL をブランドの一貫性のために送信ドメインと一致させたい場合は、**Sending domain** を選択します。
    - より短いトラッキング URL にしたい場合は、**Verified domain** を選択します。

{: start="2"}
2. トラッキングサブドメインを入力します。これは、前に選択したサブドメインの先頭に付加されます。

次の例は、選択内容に基づいてメール内でトラッキングドメインがどのように表示されるかを示しています。

|  | 選択 | トラッキングドメイン |
| --- | --- | ---|
| 検証済みドメイン | mail.example.com | links.mail.example.com |
| 送信ドメイン | marketing.mail.example.com | links.marketing.mail.example.com |
{: .reset-td-br-1 .reset-td-br-2 .reset-td-br-3 aria-label="選択別のトラッキングドメイン" }

{: start="3"}
3. ドロップダウンから、使用する関連付けられた検証済みまたは送信サブドメインを選択します。
4. **Submit** を選択します。送信ドメインとトラッキングドメインが **Pending** ステータスで表示されます。

送信ドメインの DNS レコードが伝播するまで 5～10 分かかる場合があります。ドメインが使用可能になると、通知メールが届きます。トラッキングドメインの DNS レコードは伝播に最大 24 時間かかることがありますが、通常はそれより短い時間で完了します。トラッキングドメインよりも先に送信サブドメインが準備完了になる場合があります。

### ステップ3:ワークスペースを選択する {#step-3-select-workspaces}

ドメインにアクセスできるワークスペースを選択し、**Confirm** を選択します。新しいワークスペースが作成されたときに送信ドメインを自動的に追加するオプションも選択できます。

### ステップ4:ユニバーサルリンクを設定する（オプション） {#step-4-set-up-universal-links-optional}

ユニバーサルリンクを使用すると、メッセージ内のリンクがモバイルブラウザではなくモバイルアプリで直接開くようになります。Braze は、トラッキングドメイン上でアソシエーションファイルを代わりにホストできます。

{% alert note %}
ユニバーサルリンクはトラッキングドメインごとに適用されます。同じファイル内容をドメイン間で共有できますが、各ドメインは独自のコピーをホストします。
{% endalert %}

1. **Settings** > **Company Settings** > **Verified Domains** > **Universal Links** に移動します。
2. **Set up universal links** を選択します。
3. ユニバーサルリンクセット名を入力します。
4. iOS 設定をオンにし、AASA ファイルを追加します。JSON のみが受け入れられるファイルタイプです。Braze がファイルを読み取り、検出されたアプリ ID とコンポーネントの数、および生成されたファイルのプレビューを表示します。
5. Android 設定をオンにし、同じ方法で Digital Asset Links ファイルを追加します。Braze はパッケージ名、SHA-256 証明書フィンガープリント、ステートメント数、およびプレビューを表示します。
6. 各プレビューを確認して内容が正しいことを確認し、**Next: Select tracking domains** を選択します。検証済みのトラッキングドメインのみが表示されます。1 つのセットを複数のトラッキングドメインに適用できます。
7. セットが、トラッキングドメイン、チャネル、iOS ステータス、Android ステータス、作成日とともにユニバーサルリンクページに表示されます。Braze は各ドメインで AASA ファイルが適切にホストされているかを確認し、結果をステータス列にレポートします。

### ステップ5:メール送信をテストする {#step-5-test-your-email-sending}

送信ドメインとトラッキングドメインの両方が **Ready for use** ステータスになったら、設定をテストします。

1. ワークスペースで、**Settings** > **Email Settings** に移動します。
2. **Display Name Address** セクションに新しい送信ドメインが表示されていることを確認します。
3. 新しいドメインを使用した差出人アドレスを追加します（例：「hello@e.mail.example.com」）。
4. **Save** を選択します。
5. テストメールキャンペーンを作成し、自分自身に送信します。次の点を確認してください。
    - メールが正常に配信されたこと。
    - 差出人アドレスが正しいこと。
    - クリックトラッキングリンクにトラッキングドメインが使用されていること。
    - ユニバーサルリンクが、受信者のデバイスに応じて、期待通りにアプリまたは Web サイトを開くこと。
    - メールヘッダーが正しく表示されていること。

## 次のステップ {#next-steps}

送信者認証が完了したら、メッセージが常に高い割合で宛先の受信トレイに届くよう、[IP ウォームアップ]({{site.baseurl}}/user_guide/channels/email/email_setup/ip_warming)を行うことをお勧めします。

この設定が完了したら、Brazeオンボーディングチームに相談して、ドメインとIP ウォームアップが正常に機能しているかどうかを確認してください。

## トラブルシューティング {#troubleshooting}

### DNS 伝播に予想以上に時間がかかる {#dns-propagation-is-taking-longer-than-expected}

送信ドメインのレコードは通常 5〜10 分以内に伝播します。トラッキングドメインのレコードは、DNS プロバイダーの TTL 設定によって最大 24 時間かかることがあります。伝播に時間がかかる場合は、まず NS レコードが正しく追加されていることを確認してから、Braze サポートに連絡してください。

### 検証済みドメインを削除できない {#im-not-able-to-remove-a-verified-domain}

検証済みドメインは、適切に確認しないと送信に支障をきたす可能性があるため、ダッシュボードから直接削除することはできません。アカウントからドメインを削除するには、Braze サポートに連絡してください。

### ユニバーサルリンクでアプリが開かない {#my-universal-links-arent-opening-the-app}

まず、ユニバーサルリンクページで iOS と Android のステータスを確認してください。ドメインが有効なファイルをホストしていない場合は、設定を開き、構成を修正して再度保存してください。ステータスに問題がない場合は、ブラウザのアドレスバーに URL を貼り付けるのではなく、実際のデバイスでメール内のリンクからテストしていることを確認してください。

## よくある質問 {#frequently-asked-questions}

### NS 委任なしで Braze に SSL 証明書を管理してもらうことはできますか？ {#can-braze-manage-my-ssl-certificate-without-ns-delegation}

検証済みドメインでは、DNS 所有権を Braze に委任するために NS（ネームサーバー）レコードが必要です。{% multi_lang_include product_feedback_cta.md context="pain_point" channel="feature" feature="Braze-hosted SSL certificates without NS delegation" %}

### 代わりにルートドメインを委任できますか？ {#can-i-delegate-a-root-domain-instead}

検証済みドメインは、主にサブドメインでの使用を想定して設計されており、推奨されています。ブランドのプライマリ親ドメインを委任すると、可視性とコントロールが失われるため、セキュリティ上の理由から推奨しません。親ドメインを委任する場合は、Braze 以外で使用されていない親ドメインを使用してください。

### 検証済みドメインを送信ドメインとしても使用できないのはなぜですか？ {#why-cant-my-verified-domain-also-be-the-sending-domain}

Braze は検証済みドメインの下に送信サブドメインを作成することしかできません。検証済みドメインは通常、親ドメインのサブドメイン（`mail.example.com`）です。そのため、この場合の送信ドメインの最小階層は、通常の 2 階層ではなく、3 階層（`e.mail.example.com`）になります。

### 設定後に NS レコードを変更するとどうなりますか？ {#what-happens-if-i-modify-any-of-my-ns-records-after-setup}

検証済みドメインは NS レコードが正しく保持されていることに完全に依存しています。NS レコードに変更を加えると、メールの送信やトラッキングが中断される可能性があります。

### dig コマンドで 4 つのレコードすべてが表示されるため、NS レコードを 1 行だけ追加すれば十分ですか？ {#can-i-add-only-one-of-four-ns-record-lines-since-my-dig-command-shows-all-four-records}

`dig` コマンドを使用して 4 つの NS レコードすべてが明示的に存在していることを確認し、ダッシュボードでドメインが検証されたことを確認してから、設定が完了したと判断してください。
