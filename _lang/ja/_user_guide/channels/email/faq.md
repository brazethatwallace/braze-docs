# よくある質問

> この記事では、メールに関するよくある質問への回答を提供します。

### メールが送信されたとき、複数のプロファイルが同じメールアドレスを持っている場合はどうなりますか？

一致するメールアドレスを持つ複数のユーザーがキャンペーンを受信するセグメントに含まれている場合、送信時にそのメールアドレスを持つランダムなユーザープロファイルが選択されます。これにより、メールは1回だけ送信され、重複が排除されるため、同じメールアドレスに複数回届くことはありません。

複数のプロファイルが同じメールアドレスを共有しており、1つのプロファイルが配信停止した場合、Braze はそのアドレスを持つ他のプロファイル（最大100件）を同じサブスクリプション状態に更新します。これは、配信停止やグローバルサブスクリプション状態、個別のサブスクリプショングループのステータスなどの変更に適用されます。

以下のシナリオでは、ユーザーがメールを2回受信したように見えることがあります。

- **キャンペーンまたはキャンバスの作成中にエラーが発生した場合：**ユーザーは文字通り同じ送信を2回受信するわけではありませんが、同じ件名の2通の別々のメールを受信する可能性があります。キャンペーンまたはキャンバスが複製された場合、画像や件名などのメール設定の詳細を確認してください。また、変更ログを参照して、キャンペーンまたはキャンバスが起動後に変更されたかどうかを確認できます。複製されたものは、ユーザーが受信した時点のオリジナルと同じ件名を持っている可能性があります。
- **複数のユーザープロファイルがメール転送を設定している場合：**ユーザーが特定のアプリで複数のアカウントを持っているが、1つのアカウントがメールを転送している場合、ユーザーは受信トレイごとに1回キャンペーンを受信します。メールが転送される受信トレイでは、メールが2回表示される可能性があります。メールが別のアカウントから転送されたことを示すプロバイダーは一部のみです。
- **受信者側のメール設定：**一部のクライアントは受信トレイを統合します（「ユニバーサル受信トレイ」）。同じキャンペーンが1つの受信トレイを共有する複数のアカウントをターゲットにしている場合、実際には2つの異なるプロファイルにメッセージが送信されたにもかかわらず、1人の人がキャンペーンを2回受信したように見えることがあります。受信者は、複数のアカウントが1つの受信トレイに統合されているかどうかを確認できます。

この重複排除は、ターゲットユーザーが同じディスパッチに含まれている場合に発生することに注意してください。トリガーキャンペーン（API トリガーキャンペーンを除く）およびキャンバスでは、一致するメールアドレスを持つ異なるユーザーが異なるタイミングでトリガーイベントを記録した場合、同じメールアドレスに複数回送信される可能性があります（再適格性により除外される期間内であっても）。例えば、ユーザー A とユーザー B がメールアドレス `johndoe@example.com` を共有しているが、プロファイルが異なるタイムゾーンにある場合、キャンペーンのトリガーイベントにユーザーのタイムゾーンでの送信が含まれていると、メールアドレス `johndoe@example.com` は2通のメールを受信します。

ユーザーはキャンバスのエントリ時にメールアドレスで重複排除されないため、レート制限されたエントリにより進行タイミングがわずかに異なる場合、キャンバスの最初のステップ以降では重複排除されない可能性があります。特定のメールアドレスに関連付けられたユーザーがメールを開封またはクリックすると、そのメールアドレスを共有するすべてのユーザープロファイルが、キャンペーンを開封またはクリックしたとしてマークされます。

#### 例外：API トリガーキャンペーン

API トリガーキャンペーンは、オーディエンスがどこで定義されているかに応じて、重複排除するか、重複を送信します。複数の詳細を受信するには、API コール内で異なる `user_ids` を使用して重複メールを個別にターゲットする必要があります。API トリガーキャンペーンには3つの可能なシナリオがあります。

- **シナリオ 1：ターゲットセグメント内の重複メール：**同じメールが、API トリガーキャンペーンのダッシュボードのオーディエンスフィルターでグループ化された複数のユーザープロファイルに表示される場合、プロファイルの1つだけがメールを受信します。
- **シナリオ 2：recipients オブジェクト内の異なる `user_ids` における重複メール：**同じメールが `recipients` オブジェクトで参照される複数の `external_user_id` 値内に表示される場合、メールは2回送信されます。
- **シナリオ 3：recipients オブジェクト内の重複 `user_ids` による重複メール：**同じユーザープロファイルを2回追加しようとした場合、プロファイルの1つだけがメールを受信します。

{% alert important %}
API コールを通じて API キャンペーン（API トリガーキャンペーンを除く）を送信し、同じメールアドレスを持つ複数のユーザーがセグメントオーディエンスに指定されている場合、コールにリストされた回数だけそのアドレスに送信されます。これは、API コールが意図的に構成されていると見なされるためです。
{% endalert %}

### ユーザーのメールアドレスが別のユーザーと共有されているアドレスに変更された場合、サブスクリプション状態はどうなりますか？

ユーザー A のメールアドレスを、既存のユーザー B が共有する別のメールアドレスに設定または更新した場合、**ユーザーがメールを更新したときに再サブスクライブする**設定がオンになっていない限り、ユーザー A はユーザー B から既に存在するサブスクリプション状態を継承します。

### 送信メール設定の更新は遡及的に適用されますか？

いいえ。送信メール設定に加えた更新は、既存の送信に遡及的に影響しません。例えば、メール設定でデフォルトの表示名を変更しても、アクティブなキャンペーンやキャンバスの既存のデフォルト表示名は自動的に置き換えられません。

### 「良い」メール配信率とはどのくらいですか？

一般的に、「理想的な数値」はメッセージの約98%が配信され、バウンス率が3%以下です。配信率がそれを下回る場合、通常は懸念の原因があります。

ただし、98%を超える率でも配信性の問題がある場合があります。例えば、すべてのバウンスが単一のドメインから発生している場合、それはそのプロバイダーとのレピュテーションの問題を示す明確なシグナルです。

さらに、メッセージが配信されてもスパムフォルダに入っている可能性があり、これは潜在的に深刻なレピュテーションの問題を示しています。配信されたメッセージの数だけでなく、開封率やクリック率も監視して、ユーザーが実際に受信トレイでメッセージを見ているかどうかを判断することが重要です。プロバイダーは通常すべてのスパムインスタンスを報告しないため、1%のスパム率でも懸念の原因となり、さらなる分析が必要になる可能性があります。

最後に、ビジネスや送信するメールの種類も配信に影響する可能性があります。例えば、主に[トランザクションメール]({{site.baseurl}}/api/api_campaigns/transactional_api_campaign)を送信している場合は、多くのマーケティングメッセージを送信している場合よりも良い率を期待できるはずです。

### メール配信指標が合計100%にならないのはなぜですか？

メール配信指標（配信、バウンス、スパム率）は、ソフトバウンスされた後、最大72時間のリトライ期間後に配信されなかったメールがあるため、合計100%にならない場合があります。

ソフトバウンスは、「メールボックスがいっぱい」「サーバーが一時的に利用不可」など、一時的または過渡的な問題によりバウンスされたメールです。ソフトバウンスされたメールが72時間後もまだ配信されない場合、このメールはキャンペーンの配信指標に計上されません。

### メールフィードバックループとは何ですか？

メールフィードバックループ（FBL）により、送信者は大量の苦情を受けるキャンペーンを特定することで、レピュテーションを監視できます。Gmail フィードバックループを実装する手順については、[Google のフィードバックループ](https://support.google.com/a/answer/6254652)の記事を参照してください。

### 開封トラッキングピクセルとは何ですか？

[開封トラッキングピクセル]({{site.baseurl}}/user_guide/administer/global/workspace_settings/email_preferences/#changing-location-of-tracking-pixel)は、送信者のメールクリックトラッキングドメインを利用してメールの開封イベントを追跡します。ピクセルはメールの HTML に追加される画像タグです。通常、body タグ内の最後の HTML 要素です。ユーザーがメールを読み込むと、ブランドトラッキングドメインから画像を取得するリクエストが行われ、開封イベントが記録されます。

### メールキャンペーンまたはキャンバスが停止された場合はどうなりますか？

ユーザーはキャンバスに入ることができなくなり、それ以上のメッセージは送信されません。

メールキャンペーンおよびキャンバスの場合、停止ボタンは即座に送信を停止するわけではありません。送信リクエストが送信されると、ユーザーへの配信を停止することはできず、多少の遅延が発生する場合があります。

キャンペーンまたはキャンバスが停止された後、Braze はそれ以上のリクエストを送信しませんが、ESP が処理中のリクエストを完了する間、分析が増加し続ける場合があります。

### メール分析で*合計クリック数*が*合計開封数*より多いのはなぜですか？

*合計開封数*はユーザーがメールを開封した回数のカウントであり、*合計クリック数*はユーザーが配信されたメール内でクリックした回数のカウントで、リンクのクリックなどあらゆる種類のクリックを含みます。以下のいずれかの理由により、開封数よりクリック数が多くなる場合があります。

- ユーザーが1回の開封内でメール本文を複数回クリックしている。
- ユーザーがスマートフォンのプレビューペイン内でメールリンクをクリックしている。この場合、Braze はこのメールをクリックされたが開封されていないとして記録します。
- ユーザーが以前プレビューしたメールを再度開封している。

### メールの開封数とクリック数がゼロなのはなぜですか？

トラッキングドメインの設定に問題がある場合、メールの開封数やクリック数が表示されないことがあります。これは以下のいずれかの理由による可能性があります。
- トラッキング URL が `https` ではなく `http` になっている SSL の問題がある。
- 開封イベント、クリックイベント、またはその両方のユーザーエージェント文字列が入力されていない CDN の問題がある。

### サーバークリックをトリガーする潜在的なリスクは何ですか？

過度に長いメッセージや感嘆符の多用など、メールメッセージの特定の要素がメールセキュリティの応答をトリガーする可能性があります。これらの応答はレポートや IP レピュテーションに影響を与え、ユーザーの配信停止につながる可能性があります。

これらの応答への対処方法のベストプラクティスについては、[クリック率の増加への対処]({{site.baseurl}}/user_guide/channels/email/reporting/)を参照してください。

### Braze は「配信停止」指標にカウントされる配信停止リンクを追跡できますか？

Braze は、メール内で以下の Liquid が使用されている場合に配信停止リンクを追跡します：{%raw%}`${set_user_to_unsubscribed_url}`{%endraw%}

### 配信停止数と配信停止リンクのクリック数が異なるのはなぜですか？

*配信停止数*がメール本文の配信停止リンクをクリックしたユーザー数より多い場合、list-unsubscribe ヘッダーのアクションがその差を説明していることが多いです。list-unsubscribe ヘッダーのクリックは*配信停止*としてカウントされますが、本文リンクの*クリック*としてはカウントされません。

本文の配信停止リンクの合計クリック数が*配信停止数*より多い場合、ユーザーがリンクを複数回クリックした可能性があります。

### メールに「ブラウザでこのメールを表示」リンクを追加できますか？

いいえ。Braze はこの機能を提供していません。これは、メールの大多数がモバイルデバイスや最新のメールクライアントで開封されており、画像やコンテンツを問題なくレンダリングするためです。

**回避策：**同じ結果を得るには、メールのコンテンツを外部のランディングページ（Web サイトなど）にホストし、メール本文の編集時に**リンク**ツールを使用して、作成中のメールキャンペーンからリンクすることができます。

### Braze はプレーンテキストの URL や「www.」テキストを自動的にリンクに変換しますか？

いいえ。Braze はメッセージをスキャンして、`www.` で始まるテキストや URL のように見えるプレーンテキストをハイパーリンクに変換することはありません。HTML アンカータグ（`<a href="...">`）で定義したリンクのみが、Braze の通常のレンダリングおよびリンク機能を通じて処理されます。

受信者がプレーンテキストをクリック可能なリンクとして表示している場合、その動作は通常、メールクライアント（Gmail、Outlook、Apple Mail など）によるものです。多くのクライアントは、メッセージが配信された後に URL のような文字列を検出し、受信者のデバイス上でリンクに変換します。Braze はその動作を制御できず、受信者側でオフにすることもできません。

予測可能なリンクの外観、トラッキング、スタイリングのために、プレーンテキストの URL ではなく明示的な `<a href>` タグを使用してください。

### メールセキュリティソフトウェアによってユーザーが自動的に配信停止されるのはなぜですか？

一部の企業向けメールセキュリティツール（Barracuda、Proofpoint などのサービス）は、受信メール内のすべての URL（配信停止リンクを含む）をプリフェッチまたはスキャンします。これにより、セキュリティツールがワンクリック list-unsubscribe リンクをたどった場合、意図しない配信停止が発生する可能性があります。

これを軽減するには：

- **受信者に送信ドメインの許可リストへの追加を推奨する：**影響を受ける受信者の IT チームと協力して、送信ドメインと Braze のトラッキングドメインをメールセキュリティの許可リストに追加してもらいます。
- **ユーザー設定センターを使用する：**直接の配信停止リンクの代わりに、配信停止アクションを確認するためにユーザーの操作を必要とする[ユーザー設定センター]({{site.baseurl}}/user_guide/channels/email/subscriptions/)を使用します。セキュリティスキャナーは通常、複数ステップのフォームを完了しません。
- **配信停止ログを確認する：**Currents の配信停止イベントデータの `User-Agent` ヘッダーと IP アドレスを確認して、自動スキャンと一致するパターン（複数の配信停止にわたる一貫した `User-Agent` ヘッダーなど）を特定します。

サーバーサイドスキャンがメール指標に与える影響の詳細については、[クリック率の増加への対処]({{site.baseurl}}/user_guide/channels/email/reporting/#handling-increases-in-click-rates)を参照してください。

### マシン開封率が予期せず変化したのはなぜですか？

[マシン開封]({{site.baseurl}}/user_guide/analytics/metrics_glossary/#machine-opens)は、Apple Mail Privacy Protection（MPP）などのメールセキュリティ機能によってトリガーされ、ユーザーが実際にメールを開封することなくメールコンテンツ（トラッキングピクセルを含む）をプリロードします。マシン開封率は以下に基づいて変動する可能性があります。

- Apple Mail やその他のプライバシー対応メールクライアントを使用しているオーディエンスの割合の変化。
- メールプロバイダーのプライバシー機能やボット検出動作の更新。
- オーディエンスのセグメンテーションやターゲティングの変更。

マシン開封率は、実際のエンゲージメントの信頼できる指標ではありません。メールパフォーマンスのより正確なビューを得るには、*その他の開封*（非マシン開封）と*ユニーククリック数*に注目してください。また、[メールパフォーマンスダッシュボード]({{site.baseurl}}/user_guide/analytics/dashboards/channel_performance/)を使用して、これらの指標を時系列で比較することもできます。

### Gmail でディープリンクが機能しないのはなぜですか？

Gmail はメールメッセージからすべての非 HTTP/HTTPS リンクを除去します。ディープリンクがカスタムスキーム（`myapp://path/to/content` など）を使用している場合、Gmail はそれを削除し、Gmail でメールを読んでいる受信者にはリンクが機能しません。これは Gmail の制限であり、Braze の制限ではありません。

これを回避するには：

- **Universal Links（iOS）または App Links（Android）を使用する。**これらは標準の `https://` URL を使用し、アプリがインストールされている場合はアプリを開き、そうでない場合は Web ページにフォールバックします。設定手順については、[Universal Links と App Links]({{site.baseurl}}/user_guide/channels/email/customize/universal_links_and_app_links/) を参照してください。
- **ディープリンクプロバイダーを使用する。**[Branch](https://www.branch.io/) などのサービスは、Gmail を含むメールクライアントと互換性のある HTTP 形式のディープリンクを生成します。
- **リダイレクトエンドポイントを設定する。**サーバー上にアプリのカスタムスキーム URL にリダイレクトする `https://` エンドポイントをホストします。メールクライアントは `https://` リンクを保持し、リダイレクトがアプリの起動を処理します。

### *ユニーク開封数*指標には*マシン開封*が含まれますか？

いいえ。*ユニーク開封数*は[その他の開封]({{site.baseurl}}/user_guide/analytics/metrics_glossary/#other-opens)のみをカウントし、マシン開封として識別されたメールは除外されます。*マシン開封*は個別に追跡されます。**キャンペーン分析**ビューおよび**レポートビルダー**で、両方の指標を独立して表示できます。

### メールの配信量が送信量と一致しないのはなぜですか？

メールが送信された後、受信者の受信トレイがいつ配信するかを決定します。メールボックスがいっぱいであったり、特定の IP からの ESP スロットリングなどの理由により、メッセージは数時間から数日間遅延する可能性があります。

遅延されたメッセージが送信日とは異なるカレンダー日に配信された場合、同じ日付範囲で*配信数*が*送信数*を超えることがあります。多くの遅延が1日に集中した場合、その範囲で*送信数*が*配信数*を超えることがあります。

### メールに配信停止リンクが含まれているのに、配信停止リンクを含めるよう警告が表示されるのはなぜですか？

この警告は、配信停止リンクを持たないキャンペーンから複製されたキャンペーンで表示され続けることがあります。これを解消するには：

- HTML メールの場合、**プレーンテキスト**タブに移動し、**HTML から再生成**を選択します。
- 複製後、バリアントを複製してから元のバリアントを削除します。元のバリアントを選択**しないでください**。選択すると警告が引き継がれる可能性があります。

### ユーザーがメールキャンペーンを受信しなかった理由は何ですか？

ユーザーがメールキャンペーンを受信しなかった理由には以下が含まれます。

- メールを受信する資格がなかった。
- メールアドレスが無効または存在しない。
- メッセージを見逃したか削除した可能性がある。
- メッセージがスパムフォルダに入っている可能性がある。

### Outlook で画像を最適化するにはどうすればよいですか？

Outlook は Microsoft Word スタイルのレンダリングを使用することが多く、画像の周りにボーダーが追加される場合があります。標準の条件付きコメントを使用して、Office クライアントで非表示になるようにコンテンツをラップできます。例：

```html
<!--[if !mso]><!-- -->
<span>Content hidden in Outlook desktop</span>
<!--<![endif]-->
```

### メールメッセージで SVG や WEBP 画像を使用できますか？

SVG 画像は Gmail Web や Gmail iOS ではレンダリングされません。WEBP はクライアント間で一貫してサポートされていません。代わりに、PNG や JPEG などの広くサポートされている形式を使用して、画像が確実にレンダリングされるようにしてください。

### メッセージ作成画面の一部で割り当てた Liquid 変数を別の部分で使用できますか？

いいえ。メールの各部分（件名、本文、ヘッダー、ボタンなど）は個別に生成されるため、1つのフィールドで割り当てた Liquid は別のフィールドでは使用できません。必要な各フィールドで変数を割り当ててください。

### メールテンプレートが見つかりません。どこにありますか？

**テンプレート** > **メールテンプレート**に移動してください。タイプ（HTML またはドラッグ＆ドロップ）でフィルタリングできます。

テンプレートを表示する権限があることを確認してください。[ユーザー権限]({{site.baseurl}}/user_guide/administer/global/user_management/permissions/)を参照してください。

### リレーメールやマスクメールのためにドメインを登録する必要がありますか？

[Apple のプライベートメールリレー]({{site.baseurl}}/user_guide/channels/email/best_practices/apple_mail/email_private_relay_apple_SSO/)では、バウンスを防ぐために Apple Developer Portal で送信ドメインを登録する必要があります。Google のシールドメールでは、手動でのドメイン登録や許可リスト登録プロセスは必要ありません。
