# よくある質問

> この記事では、メールに関するよくある質問に対する回答を提供します。

### メールが送信され、複数のプロファイルが同じメールアドレスを持っている場合はどうなりますか？

キャンペーンを受け取るセグメント内に、メールアドレスが一致するユーザーが複数いる場合、送信時にそのメールアドレスを持つランダムなユーザープロファイルが選択されます。この方法では、メールは一度だけ送信され、重複が排除されるため、同じメールアドレスに複数回送信されることはありません。

以下のシナリオでは、ユーザーがメールを 2 回受信したように見える場合があります。

- **キャンペーンまたはキャンバスの作成中にエラーが発生した場合：**ユーザーは文字通り同じ送信を 2 回受信するわけではありませんが、同じ件名の 2 通の別々のメールを受信する可能性があります。キャンペーンまたはキャンバスが複製された場合、画像や件名などのメール設定の詳細を確認してください。また、変更ログを参照して、キャンペーンまたはキャンバスが起動後に変更されたかどうかを確認することもできます。複製されたものは、ユーザーが受信した時点のオリジナルと同じ件名を共有している可能性があります。
- **複数のユーザープロファイルでメール転送が設定されている場合：**ユーザーが特定のアプリに複数のアカウントを持っていて、1 つのアカウントがメールを転送している場合、ユーザーは受信トレイごとに 1 回キャンペーンを受信します。メッセージが転送される受信トレイでは、メールが 2 回表示される場合があります。メールが別のアカウントから転送されたことを示すプロバイダーは一部に限られます。
- **受信者側のメール設定：**一部のクライアントは受信トレイを統合します（「ユニバーサル受信トレイ」）。同じキャンペーンが 1 つの受信トレイを共有する複数のアカウントをターゲットにしている場合、実際には 2 つの異なるプロファイルにメッセージが送信されたにもかかわらず、1 人がキャンペーンを 2 回受信したように見えることがあります。受信者は、複数のアカウントが 1 つの受信トレイに統合されているかどうかを確認できます。

この重複排除は、ターゲットのユーザーが同じディスパッチに含まれている場合に発生することに注意してください。トリガーキャンペーンでは、同じメールアドレスを持つ異なるユーザーが異なる時刻にトリガーイベントを記録した場合、（再適格性によりユーザーが除外される可能性がある期間内であっても）同じメールアドレスに複数回送信される可能性があります。キャンバスのエントリ時にメールによる重複排除は行われません。そのため、レート制限によるエントリのためにユーザーの進行速度がわずかに異なる場合、キャンバスの最初のステップ以降で重複排除が行われない可能性があります。あるメールアドレスに紐づけられたユーザーがメールを開封またはクリックすると、そのメールアドレスを共有するすべてのユーザープロファイルがキャンペーンを開封およびクリックしたとマークされます。

#### 例外：API トリガーキャンペーン

API トリガーキャンペーンは、オーディエンスがどこで定義されるかに応じて、重複排除または重複送信を行います。重複するメールが複数の詳細を受け取るためには、API 呼び出し内で個別の `user_ids` を使用して別々にターゲットにする必要があります。API トリガーキャンペーンで可能な 3 つのシナリオは次のとおりです。

- **シナリオ 1：ターゲットセグメント内の重複メール：**同じメールが API トリガーキャンペーンのダッシュボードのオーディエンスフィルターでグループ化された複数のユーザープロファイルに表示される場合、プロファイルのうち 1 つだけがメールを受信します。
- **シナリオ 2：受信者オブジェクト内の異なる `user_ids` の重複メール：**`recipients` オブジェクトで参照される複数の `external_user_id` 値に同じメールが含まれている場合、そのメールは 2 回送信されます。
- **シナリオ 3：受信者オブジェクト内の `user_ids` 重複によるメールの重複：**同じユーザープロファイルを 2 回追加しようとすると、プロファイルのうち 1 つだけがメールを受け取ります。

### 送信メール設定の更新は遡及的に適用されますか？

いいえ。送信メール設定を更新しても、既存の送信に遡って影響することはありません。例えば、メール設定でデフォルトの表示名を変更しても、アクティブなキャンペーンやキャンバスの既存のデフォルトの表示名は自動的に置き換えられません。 

### 「良好」なメール配信率とは？

通常、「マジックナンバー」は、バウンス率が 3％ を超えない状態でメッセージの約 98％ が配信されることです。配信率がそれ以下になると、通常は懸念の原因となります。

しかし、レートが 98％ を超えていても、配信到達性の問題が発生する可能性はあります。例えば、すべてのバウンスが特定のドメインから発生している場合、それはそのプロバイダーでの評判に問題があるという明確なシグナルです。

さらに、メッセージが配信されてもスパムに分類される可能性があり、潜在的に深刻な評判の問題を示しています。メッセージが配信されている数だけでなく、開封率やクリック率も監視して、ユーザーが実際に受信トレイでメッセージを見ているかどうかを確認することが重要です。プロバイダーは通常、すべてのスパムインスタンスを報告しないため、スパム率が 1％ でも懸念とさらなる分析の原因となる可能性があります。

最後に、ビジネスの内容と送信するメールの種類も配信に影響を与える可能性があります。例えば、主に[トランザクションメール]({{site.baseurl}}/api/api_campaigns/transactional_api_campaign)を送信する場合は、多くのマーケティングメッセージを送信する場合よりも良い率が期待できます。

### メール配信の指標の合計が 100％ にならないのはなぜですか？

メール配信指標（配信、バウンス、スパム率）は、ソフトバウンス後、最大 72 時間の再試行期間を経ても配信されないメールがあるため、合計が 100％ にならない場合があります。

ソフトバウンスは、「メールボックスがいっぱい」、「サーバーが一時的に利用できない」などの一時的または一過性の問題によりバウンスするメールです。ソフトバウンスしたメールが 72 時間後も配信されない場合、このメールはキャンペーン配信指標に含まれません。

### メールフィードバックループとは何ですか？

メールフィードバックループ（FBL）は、大量の苦情を受けたキャンペーンを特定することで、送信者が自身の評判を監視できるようにする仕組みです。Gmail のフィードバックループを実装する手順については、[Google's Feedback Loop](https://support.google.com/a/answer/6254652) の記事を参照してください。

### 開封トラッキングピクセルとは何ですか？

[開封トラッキングピクセル]({{site.baseurl}}/user_guide/administrative/app_settings/email_settings/#changing-location-of-tracking-pixel)は、送信者のメールクリックトラッキングドメインを活用して、メールの開封イベントを追跡します。ピクセルはメールの HTML に追加された画像タグです。通常、body タグ内の最後の HTML 要素です。ユーザーがメールを読み込むと、ブランド化されたトラッキングドメインから画像を取得するリクエストが送信され、開封イベントが記録されます。

### メールキャンペーンまたはキャンバスが停止された場合はどうなりますか？

ユーザーはキャンバスに入ることができず、これ以上メッセージは送信されません。

メールキャンペーンとキャンバスの場合、停止ボタンを押しても送信がすぐに停止するわけではありません。送信リクエストが送信されると、ユーザーへの配信を止めることはできず、多少の遅延が発生する場合があります。

Braze はキャンペーンまたはキャンバスが停止された後はそれ以上のリクエストを送信しませんが、ESP が処理中のリクエストを完了する間、分析データが増加し続ける場合があります。

### なぜメールの開封数よりもクリック数が多いのですか？

次のいずれかの理由で、クリック数が開封数より多くなることがあります：
- ユーザーが、単一の開封内でメールの本文を複数回クリックしている。
- ユーザーが、スマートフォンのプレビューペイン内のメールリンクをクリックしている。この場合、Braze はこのメールがクリックされたが開封されていないとして記録します。
- ユーザーが以前にプレビューしたメールを再度開いている。

### メールの開封やクリックがゼロなのはなぜですか？

トラッキングドメインに設定ミスがある場合、メール開封数やクリック数がゼロになる可能性があります。これは、次のいずれかが原因で発生することがあります：
- トラッキング URL が `https` ではなく `http` になっている SSL の問題がある。
- 開封イベント、クリックイベント、またはその両方でユーザーエージェント文字列が入力されない CDN の問題がある。

### サーバークリックをトリガーすることの潜在的なリスクは何ですか？

メールメッセージの特定の要素、例えば長すぎるメッセージや過剰な感嘆符などは、メールセキュリティの応答をトリガーする可能性があります。これらの応答は、レポート処理や IP の評判に影響を与え、ユーザーが配信停止する結果につながる可能性があります。

これらの応答への対処方法のベストプラクティスについては、[クリック率の増加への対応]({{site.baseurl}}/help/help_articles/email/open_rates/)を参照してください。

### Braze は「配信停止」指標にカウントされる配信停止リンクを追跡できますか？

Braze は、メール内で次の Liquid が使用されている場合、配信停止リンクを追跡します：{%raw%}`${set_user_to_unsubscribed_url}`{%endraw%}

### 配信停止数と配信停止リンクのクリック数が異なるのはなぜですか？

_配信停止_数がメール本文の配信停止リンクをクリックしたユーザー数より多い場合、list-unsubscribe ヘッダーのアクションがその差を説明していることがよくあります。list-unsubscribe ヘッダーのクリックは_配信停止_としてカウントされますが、本文リンクの_クリック_としてはカウントされません。

本文の配信停止リンクの合計クリック数が_配信停止_数より多い場合は、ユーザーがリンクを複数回クリックした可能性があります。

### 「このメールをブラウザで表示」リンクをメールに追加できますか？

いいえ、Braze はこの機能を提供していません。これは、ますます多くのメールがモバイルデバイスや最新のメールクライアントで開かれ、画像やコンテンツが問題なく表示されるためです。

**回避策：**同じ結果を達成するために、メールのコンテンツを外部のランディングページ（Web サイトなど）にホストし、メール本文を編集する際に**リンク**ツールを使用して、作成中のメールキャンペーンからリンクすることができます。

### なぜユーザーがメールセキュリティソフトウェアによって自動配信停止されるのですか？

一部の企業向けメールセキュリティツール（Barracuda、Proofpoint などのサービスを含む）は、受信メール内の全 URL（配信停止リンクを含む）を事前に取得またはスキャンします。セキュリティツールがワンクリックの list-unsubscribe リンクを辿ると、意図しない配信停止が発生する可能性があります。

これを軽減するには：

- **受信者に送信ドメインを許可リストに登録するよう推奨します：**影響を受けた受信者の IT チームと連携し、送信ドメインと Braze のトラッキングドメインをメールセキュリティの許可リストに追加してもらいます。
- **ユーザー設定センターを使用します：**直接的な配信停止リンクの代わりに、配信停止アクションを確認するためにユーザーの操作を必要とする[ユーザー設定センター]({{site.baseurl}}/user_guide/message_building_by_channel/email/preference_center/overview/)を使用します。セキュリティスキャナーは通常、複数ステップのフォームを完了しません。
- **配信停止ログを確認します：**Currents の配信停止イベントデータ内の `User-Agent` ヘッダーと IP アドレスを確認し、自動スキャンと一致するパターン（複数の配信停止で一貫した `User-Agent` ヘッダーなど）を特定します。

サーバーサイドスキャンがメール指標に与える影響の詳細については、[クリック率の増加への対応]({{site.baseurl}}/user_guide/message_building_by_channel/email/reporting_and_analytics/email_reporting/#handling-increases-in-click-rates)を参照してください。

### なぜ機械開封率が予期せず変化したのですか？

[機械開封]({{site.baseurl}}/user_guide/analytics/reporting/report_metrics/#machine-opens)は、Apple Mail のプライバシー保護（MPP）などのメールセキュリティ機能によってトリガーされます。この機能は、ユーザーが実際にメールを開封しなくても、メールのコンテンツ（トラッキングピクセルを含む）を事前に読み込みます。機械開封率は以下の要因によって変動します：

- Apple Mail やその他のプライバシー保護機能付きメールクライアントを利用するオーディエンスの割合の変化。
- メールプロバイダーのプライバシー機能やボット検出動作の更新。
- オーディエンスのセグメンテーションやターゲティングの変更。

機械開封率は実際のエンゲージメントを測る信頼できる指標ではありません。メールのパフォーマンスをより正確に把握するには、*その他の開封*（機械による開封ではないもの）と*ユニーククリック数*に注目してください。[メールパフォーマンスダッシュボード]({{site.baseurl}}/user_guide/analytics/dashboard/email_performance_dashboard/)を使用すれば、これらの指標を時系列で比較することもできます。

### *ユニーク開封*数には*機械開封*は含まれますか？

はい。*ユニーク開封*には*機械開封*が含まれます。**キャンペーン分析**ページと**レポートビルダー**では、両方の指標を確認できます。

### メールの配信数と送信数が一致しないのはなぜですか？

メールが送信された後、受信者の受信トレイが配信のタイミングを決定します。メールボックスがいっぱいである、特定の IP からの ESP スロットリングなどの理由で、メッセージが数時間から数日間遅延する場合があります。

遅延したメッセージが送信日とは異なるカレンダー日に配信された場合、同じ日付範囲で_配信数_が_送信数_を超えることがあります。多くの遅延メッセージが 1 日に集中して配信された場合、その範囲で_送信数_が_配信数_を超えることがあります。

### 配信停止リンクを含めるよう警告が表示されるのに、メールにはすでに含まれているのはなぜですか？

この警告は、配信停止リンクがなかったキャンペーンから複製されたキャンペーンで表示され続けることがあります。これを解消するには：

- HTML メールの場合、**プレーンテキスト**タブに移動し、**HTML から再生成**を選択します。
- 複製後、バリアントを複製してから、元のバリアントを削除します。元のバリアントを選択**しないでください**。選択すると、警告が引き継がれる可能性があります。

### ユーザーがメールキャンペーンを受信しなかった理由は何ですか？

ユーザーがメールキャンペーンを受信しなかった理由には、以下が含まれます：

- メールを受信する資格がなかった。
- メールアドレスが無効または存在しない。
- メッセージを見逃したか、削除した可能性がある。
- メッセージがスパムフォルダーに入っている可能性がある。

### Outlook で画像を最適化するにはどうすればよいですか？

Outlook は Microsoft Word スタイルのレンダリングを使用することが多く、画像の周囲にボーダーが追加される場合があります。標準の条件付きコメントを使用して、Office クライアントでコンテンツを非表示にするようにラップできます。例：

```html
<!--[if !mso]><!-- -->
<span>Content hidden in Outlook desktop</span>
<!--<![endif]-->
```

### メールメッセージで SVG や WEBP 画像を使用できますか？

SVG 画像は Gmail Web や Gmail iOS ではレンダリングされません。WEBP はクライアント間で一貫してサポートされていません。代わりに、PNG や JPEG などの広くサポートされている形式を使用して、画像が確実に表示されるようにしてください。

### メッセージ作成画面の一部で割り当てた Liquid 変数を別の部分で使用できますか？

いいえ。メールの各部分（件名、本文、ヘッダー、ボタンなど）は個別に生成されるため、あるフィールドで割り当てた Liquid は別のフィールドでは使用できません。必要な各フィールドで変数を割り当ててください。

### メールテンプレートが見つかりません。どこにありますか？

**テンプレート** > **メールテンプレート**に移動してください。タイプ（HTML またはドラッグ＆ドロップ）でフィルタリングできます。

テンプレートを表示する権限があることを確認してください。[ユーザー権限]({{site.baseurl}}/user_guide/administrative/app_settings/manage_your_braze_users/user_permissions/)を参照してください。
