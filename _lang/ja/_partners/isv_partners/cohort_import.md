# パートナーコホートインポート統合 {#partner-cohort-import-integration}

> パートナーコホートインポート統合機能により、パートナーはBrazeと統合して、パートナーのアプリケーション内で生成されたユーザーのコホートを送信できます。

## クラスターURL {#cluster-urls}

Brazeは、世界中の複数のクラスターでアプリケーションをホストしています。インポートエンドポイントのURLは、クライアントの会社インスタンスがホストされているクラスターによって異なります。

| US-03 | `https://rest.iad-03.braze.com` |
| US-04 | `https://rest.iad-04.braze.com` |
| US-05 | `https://rest.iad-05.braze.com` |

## エンドポイントURL {#endpoint-urls}

最上位のURLはクラスター固有であるだけでなく、各エンドポイントもパートナー固有です。たとえば、US01クラスターにインポートする場合、URLの形式は `https://rest.iad-01.braze.com/partners/[partner_name]/…` となります。ここで、`[partner_name]` は通常、パートナーのビジネス名です。各エンドポイントの詳細については、以降のセクションで説明します。

## 認証 {#authentication}

Brazeにコホートデータをインポートするには、2つの認証キーが必要です。

### パートナーAPIキー {#partner-api-key}

パートナーAPIキーにより、統合パートナーが識別され、リクエストがインポートに対して有効であると認証されます。このキーは、`partner_api_key` フィールドのリクエスト本文に含める必要があります。

パートナーのアプリケーションで統合を設定する際、クライアントにBrazeクラスターを指定するよう依頼してください。これにより、データのインポート時に使用するクラスターURLとパートナーAPIキーを統合側で認識できるようになります。

パートナーが統合開発を開始する前に、BrazeからパートナーAPIキーがパートナーに提供されます。一般的に、すべてのUSクラスターで有効な1つのキーと、EUクラスターで有効なもう1つのキーが提供されます。

### クライアントデータインポートキー {#client-data-import-key}

クライアントデータインポートキーは、コホートのインポート先となるクライアントワークスペースを識別します。このキーは、`client_secret` フィールドのリクエスト本文に含める必要があります。

このキーは、クライアントのダッシュボードにあるパートナーの統合設定で生成されます。パートナーのアプリケーションで統合を設定する際、クライアントにデータインポートキーを指定するよう依頼してください。これにより、データの送信先となるクライアントとワークスペースを統合側で認識できるようになります。

## APIエンドポイントの仕様 {#api-endpoint-specifications}

### コホート名エンドポイント {#cohort-name-endpoint}

コホート名エンドポイントを使用して、IDに基づいてコホートの名前を指定できます。このエンドポイントは、コホートが最初にBrazeにエクスポートされたとき、またはBrazeがすでに認識しているコホートの名前が変更されたときに呼び出す必要があります。

| フィールド | タイプ | 必須 | メモ |
| ----- | ---- | -------- | ----- |
| `partner_api_key` | 文字列 | はい | パートナー固有のAPIキー。パートナーからBrazeへのすべてのリクエストで使用されます。このキーはクラスター固有であるため（[パートナーAPIキー](#partner-api-key)を参照）、パートナーはコホートの書き込み先クラスターを把握している必要があります。 |
| `client_secret` | 文字列 | はい | コホートが属するクライアントのデータインポートキー。 |
| `cohort_id` | 文字列 | はい | コホートの識別子。この識別子は、指定したクライアントに対して一意である必要があります。 |
| `name` | 文字列 | はい | クライアントが指定したコホートの名前 |
| `created_at` | 文字列 | はい | ISO-8601形式のタイムスタンプ |
{: .reset-td-br-1 .reset-td-br-2 .reset-td-br-3  .reset-td-br-4 aria-label="Cohort name endpoint" }

#### リクエスト例: {#example-request}

`POST: https://rest.iad-01.braze.com/partners/[partner_name]/cohorts`
```
{
	"partner_api_key" : "123456-1234-1234-12345678",
	"client_secret" : "234567-2345-2345-23456789",
	"cohort_id" : "[some unique identifier generated by the partner]",
	"name" : "Name of the cohort that will appear in the Braze dashboard",
	"created_at" : "2021-01-21T19:20:30+05:00"
}
```

### ユーザーコホートエンドポイント {#user-cohort-endpoint}

ユーザーコホートエンドポイントでは、特定のコホートに追加または削除されたユーザーを指定できます。このエンドポイントは、コホートの更新時に呼び出す必要があります。コホートに新規に入ったユーザー、または最後の更新以降にコホートを離れたユーザーのみをBrazeに送信してください。

| フィールド | タイプ | 必須 | メモ |
| ----- | ---- | -------- | ----- |
| `partner_api_key` | 文字列 | はい | パートナー固有のAPIキー。パートナーからBrazeへのすべてのリクエストで使用されます。このキーはクラスター固有であるため（[パートナーAPIキー](#partner-api-key)を参照）、統合がコホートの書き込み先クラスターを認識している必要があります。 |
| `client_secret` | 文字列 | はい | コホートが属するクライアントのデータインポートキー。 |
| `cohort_id` | 文字列 | はい | コホートの識別子。識別子は指定されたクライアントに対して一意である必要があります。 |
| `cohort_changes` | オブジェクトの配列 | はい | オブジェクトには2つのフィールドを含めることができます。1つ目の `user_ids` は必須で、`external_ids`、`device_ids`、および `aliases` の配列を指定できます。各要素は、コホート内のステータスが変更されたユーザーのIDです。2つ目のフィールド `should_remove` はオプションのブール値で、このオブジェクト内のユーザーをコホートに追加するのではなく、コホートから削除するかどうかを示します。デフォルトはfalseです。1つのリクエストに含まれるユーザーIDの最大合計数は1,000です。<br/><br/>識別済みユーザーは、`external_id` または `alias` のどちらかで照合できます。匿名ユーザーは、`device_id` で照合できます。識別済みユーザーのデバイスIDを渡しても、Brazeはそのユーザーを追加または削除しません。識別済みユーザーにはexternal IDまたはエイリアスを使用する必要があります。 |
{: .reset-td-br-1 .reset-td-br-2 .reset-td-br-3  .reset-td-br-4 aria-label="User cohort endpoint" }

#### リクエスト例:

`POST: https://rest.iad-01.braze.com/partners/[partner_name]/cohorts/users`
```
{
	"partner_api_key" : "123456-1234-1234-12345678",
	"client_secret" : "234567-2345-2345-23456789",
	"cohort_id" : "[some unique identifier generated by the partner]",
	"cohort_changes" : [
	   {"user_ids": ["test_user_1", "test_user_2"]}
	]
}
```

## レート制限 {#rate-limiting}

ユーザーコホートエンドポイントでは1リクエストあたり最大1,000ユーザーIDという制限に加えて、これらのエンドポイントリクエストは1時間あたり250,000リクエストにレート制限されています。

## コホートフィルター {#cohort-filter}

Brazeは、ユーザーがパートナーコホートに含まれている場合に、ダッシュボードユーザーがターゲットオーディエンスにそれらのユーザーを含めるか除外できるフィルターを追加します。フィルターには、そのクライアントについてBrazeが認識しているすべてのコホート名のドロップダウンリストが表示されます。このフィルターは、パートナーとBrazeがこの統合での連携に同意しているクライアントにのみ表示されます。

## トラブルシューティング {#troubleshooting}

コホートインポートエンドポイントに固有のエラーコードとそのトラブルシューティング方法については、次の表を参照してください。

| エラーコード | 説明 |
| ----- | ---- |
| `400` | `cohort_id` は有効な文字列でなければなりません |
|  | `cohort_changes` は、キー `user_ids` および/または `device_ids` を持ち文字列の配列にマッピングされているオブジェクトの配列であるか、または `aliases` オブジェクトである必要があります |
|  | リクエストあたりの `user_ids`、`device_ids`、および `aliases` の許容数は1,000個です |
|  | `name` は空ではない文字列である必要があります |
|  | `created_at` は [ISO-8601](https://en.wikipedia.org/wiki/ISO_8601) 文字列として有効な時刻である必要があります |
| `401` | 不正なパートナーAPIキー |
|  | 不正なクライアントシークレット |
|  | クライアントシークレットを持つクライアントに対してパートナーが有効化されていません：**&#60;client secret&#62;** |
|  | 不正アクセス |
| `423` | リソースがロックされています |
{: .reset-td-br-1 .reset-td-br-2 aria-label="Troubleshooting" }

その他のトラブルシューティングについては、Braze APIの使用中に発生する可能性のあるさまざまなエラーとサーバー応答について説明している[エラーとレスポンス]({{site.baseurl}}/api/errors/)を参照してください。
