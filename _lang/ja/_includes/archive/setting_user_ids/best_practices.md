### 匿名ユーザー履歴の自動保存 {#automatic-preservation-of-anonymous-user-history}

| 識別コンテキスト | 保存の動作 |
| ---------------------- | -------------------------- |
| ユーザーが過去に識別されて**いない** | 識別時に匿名の履歴がユーザープロファイルに**統合されます**。 |
| ユーザーがアプリ内またはAPI経由で過去に識別**されている** | 識別時に匿名の履歴はユーザープロファイルに**統合されません**。 |
{: .reset-td-br-1 .reset-td-br-2 aria-label="Automatic preservation of anonymous user history" }

匿名ユーザーを識別した場合の詳細については、[識別済みユーザープロファイル]({{site.baseurl}}/user_guide/data_and_analytics/user_data_collection/user_profile_lifecycle/#identified-user-profiles)を参照してください。

### その他の注意事項とベストプラクティス {#additional-notes-and-best-practices}

以下の点に注意してください。

- アプリを複数のユーザーが使用する場合、各ユーザーにユニークな識別子を割り当てて追跡できます。
- ユーザー IDを設定した後、そのユーザーを匿名プロファイルに戻すことはできません。
- ユーザーがログアウトしたときにユーザー IDを変更しないでください。デバイスとユーザープロファイルが分離される可能性があります。
  - その結果、以前にログアウトしたユーザーを再エンゲージメントメッセージでターゲットにすることができなくなります。同じデバイスに複数のユーザーが存在することが予想されるものの、アプリがログアウト状態のときにそのうちの1人のみをターゲットにしたい場合は、ログアウト中にターゲットにするユーザー IDを個別に追跡し、アプリのログアウトプロセスの中でそのユーザー IDに切り替えることをお勧めします。デフォルトでは、最後にログインしたユーザーのみがアプリからプッシュ通知を受け取ります。
- 識別済みユーザーから別のユーザーへの切り替えは、比較的コストのかかる操作です。
  - ユーザー切り替えをリクエストすると、前のユーザーの現在のセッションは自動的に閉じられ、新しいセッションが開始されます。Brazeは、新しいユーザーに対してアプリ内メッセージやその他のBrazeリソースのデータ更新リクエストを自動的に行います。

{% alert tip %}
ユーザー IDとしてユニークな識別子のハッシュを使用する場合は、ハッシュ関数への入力を正規化していることを確認してください。例えば、メールアドレスのハッシュを使用する場合は、入力から先頭と末尾の空白を取り除き、ローカライゼーションを考慮していることを確認してください。
{% endalert %}
