# ユーザーアーカイブ {#user-archival}

> Brazeは毎週日曜日の東部標準時午前5時30分に、非アクティブユーザーと休眠ユーザーをBrazeサービスから削除するプロセスを実行します。なお、Brazeはワークスペースのユーザー数が250,000のしきい値に達しない限り、ユーザーをアーカイブしません。

このプロセスは、キャンペーンで到達可能なオーディエンスに関する正確な統計をBrazeが提供できるようにすることを目的としています。また、[GDPR][1]の2つの主要な概念に従って機能します。

1. 保存制限の原則—処理され保存された個人データは、必要な期間を超えて保存されるべきではありません。
2. 個人データを処理する正当な事業目的を有すること。

すなわち、処理され保存された個人データは必要以上の期間保存されるべきではなく、個人データは合法的な業務目的のためにのみ処理されるべきです。アーカイブされたユーザーは、GDPRに従って配信停止ステータスも削除されます。

{% alert important %}
アーカイブされたユーザーは永久に削除されます。<br><br>キャンバスを使って、[ユーザーアーカイブポリシーをカスタマイズ](#customizing-your-user-archival-policy)できます。顧客は、ユーザーが非アクティブか休眠状態かを完全にコントロールできます。キャンバスではこれを自動的に行う機能を提供しているため、一部またはすべての非アクティブユーザーや休眠ユーザーに対して、この機能を効果的にオフにすることができます。
{% endalert %}

## ユーザーアーカイブの定義 {#user-archival-definitions}

### アクティブユーザー {#active-users}

Brazeでは、特定の期間における「アクティブユーザー」を、モバイルアプリまたはWebサイトでセッションを記録したユーザー、更新されたユーザー、メッセージを送信されたユーザー、またはメッセージに対してインタラクションを行ったユーザーと定義しています。

新しいユーザーがログインしたときにユーザーIDを設定してユーザーを識別する場合、そのユーザーは別のアクティブユーザーとしてカウントされます。APIを通じて更新されたユーザーも、更新された期間のアクティブユーザーとしてカウントされます。

{% alert important %}
非アクティブユーザーと休眠ユーザーはどちらも、以下に記載されている理由でアーカイブから除外されない限り、アーカイブされます。
{% endalert %}

### 非アクティブユーザー {#inactive-users}

「非アクティブユーザー」とは、到達不能であり、離脱した可能性が高いユーザーです。非アクティブユーザーとは、以下のすべての条件を満たすユーザーを指します。

- メールを受信できない。例えば、メールアドレスを持っていない、またはすべてのメールリストから購読解除している。
- SMSを受信できない。例えば、有効な電話番号を持っていない、またはすべてのSMS購読グループから購読解除している。
- プッシュを受信できない。例えば、アプリをアンインストールした、またはプッシュ通知の許可を無効にしている。
- WhatsAppメッセージを受信できない。例えば、有効な電話番号を持っていない、またはすべてのWhatsApp購読グループから購読解除している。
- LINEメッセージを受信できない。例えば、LINE IDを持っていない、またはすべてのLINE購読グループから購読解除している。
- ワークスペース内のモバイルアプリの使用やWebサイトの訪問が6か月以上ない。
- ワークスペースからのメッセージの受信が6か月以上ない。
- 更新が6か月以上行われていない。

この場合、これらのユーザーにはメッセージを送信できず、ブランドとのエンゲージメントもありません。これらのユーザーは事実上離脱しています。

### 休眠ユーザー {#dormant-users}

「休眠ユーザー」とは、過去12か月間にアクティビティがなく、以下の条件を満たすユーザーです。

- ワークスペース内のモバイルアプリの使用やWebサイトの訪問が12か月以上ない。
- ワークスペースからのメッセージの受信が12か月以上ない。
- 更新が12か月以上行われていない。

## グローバルコントロールグループのユーザー {#global-control-group-users}

グローバルコントロールグループに含まれるユーザーは、非アクティブユーザーや休眠ユーザーの定義に該当する場合でも、アーカイブされることはありません。

### トリートメントサンプルグループ {#treatment-sample-group}

グローバルコントロールグループレポートのトリートメントサンプルグループのユーザーは、アーカイブの対象から除外されます。

## テストユーザー {#test-users}

テストユーザーは、非アクティブユーザーや休眠ユーザーの定義に該当する場合でも、アーカイブされることはありません。

## スパムブロック {#spam-blocking}

Brazeは、異常に大きくなった個別のユーザープロファイル（「ダミーユーザー」）をブロックします。これらは通常、不正なインテグレーションの結果として発生します。プロファイルが以下のいずれかのしきい値を超えると、ブロックされます。

| しきい値 | 説明 |
| --- | --- |
| 5,000,000を超えるセッション | 通常、1つの`external_id`を多数のユーザーで再利用していることが原因です。 |
| 20,000を超える固有のカスタムイベント名 | 通常、固定のイベント名セットを再利用せず、イベントごとに新しいイベント名を生成していることが原因です。 |
| 20,000を超える固有の購入商品名 | 通常、固定の商品IDセットを再利用せず、購入ごとに新しい`product_id`を生成していることが原因です。 |
{: .reset-td-br-1 .reset-td-br-2 aria-label="ダミーユーザーブロックのしきい値" }

プロファイルがブロックされると、Brazeはそのプロファイルへのすべての受信データ（SDKおよびREST APIの両方から）の取り込みを停止します。ブロックされた識別子を参照する[`/users/track`]({{site.baseurl}}/api/endpoints/user_data/post_user_track)へのリクエストは、エラー`"provided external_id is blacklisted and disallowed"`を返します。この文言はAPIレスポンスからそのまま引用したものです。また、Brazeはお客様のBrazeアカウントマネージャーに通知し、インテグレーションの問題についてお客様に連絡できるようにします。

正当なユーザーでこの問題が発生した場合は、Braze[サポート]({{site.baseurl}}/braze_support)にチケットを提出してください。

ダッシュボードのダミーユーザーを見つけるには、以下のステップを実行してください。

1. [セグメント]({{site.baseurl}}/user_guide/audience/segments/creating_a_segment)を作成します。
2. フィルター`Session Count`を選択し、`more than 5,000,000`に設定します。
3. セグメントをCSVでエクスポートします。

**Session Count**フィルターは、セッションベースのダミーユーザーのみを検出します。プロファイル上の固有のカスタムイベント名数や商品名数に対するセグメンテーションフィルターはないため、それらの理由でブロックされたプロファイルを特定するには、Brazeアカウントマネージャーにお問い合わせください。

必要に応じて、[`/users/delete`エンドポイント]({{site.baseurl}}/api/endpoints/user_data/post_user_delete)を使用してユーザーを削除できます。

## ユーザーアーカイブポリシーのカスタマイズ {#customizing-your-user-archival-policy}

Brazeはデータオーケストレーション機能を提供しており、ユーザーアーカイブポリシーをカスタマイズできます。キャンバスの[ユーザー更新]({{site.baseurl}}/user_update)コンポーネントを使用して、両方のメリットを兼ね備えたユーザーアーカイブポリシーを作成しましょう。

これにより、以下のことが可能になります。

- GDPRやプライバシーのベストプラクティスに準拠し、不要になったユーザープロファイルを削除できます。
- 正当なビジネス上の必要性があるユーザープロファイルを保持できます。

### ステップ {#steps}

1. ブランドのアーカイブ基準を満たし、保持したいユーザーをターゲットにします。たとえば、以下のようなユーザーを保持できます。
    - 最後にメッセージを受信したのが23週間以上前、またはメッセージを一度も受信していない<br>かつ<br>
    - 最後にアプリを使用したのが23週間以上前、またはアプリのセッション数がゼロ<br><br>
      ![最後にメッセージを受信したのが23週間以上前、キャンペーンまたはキャンバスステップからメッセージを受信したことがない、最後にアプリを使用したのが23週間以上前、アプリの使用回数がゼロのユーザーをターゲットにする設定。][2]<br><br>
2. 再適格性を6か月よりやや短い期間に設定します。<br><br>
      ![再適格性がオンになっており、再適格性ウィンドウが23週間に設定されたエントリコントロール。][3]<br><br>
3. ユーザー更新ステップを設定して、各プロファイルにイベントを追加します。<br><br>
      ![ユーザーのプロファイルに「do_not_archive」イベントを追加するユーザー更新ステップ。][4]
{% details ユーザー更新オブジェクトのサンプル %}

{% raw %}
```json
{
    "events": [
        {
            "name": "do_not_archive",
            "time": "{{ 'now' | time_zone: 'UTC' | date: '%Y-%m-%dT%H:%M:%SZ' }}"
        }
    ]
}
```
{% endraw %}
