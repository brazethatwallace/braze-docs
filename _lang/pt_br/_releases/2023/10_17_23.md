# Versão de 17 de outubro de 2023 {#october-17-2023-release}

## Cópia para espaços de trabalho {#copying-to-workspaces}

A [cópia de campanhas entre espaços de trabalho]({{site.baseurl}}/user_guide/messaging/governance/copy_across_workspaces) permite que você agilize a composição de mensagens começando com uma cópia de uma campanha em um espaço de trabalho diferente. Essa cópia permanecerá como rascunho até que você a edite e lance, ajudando a manter e desenvolver suas estratégias de envio de mensagens bem-sucedidas.

## Conectores de teste do Currents {#test-currents-connectors}

Os [conectores de teste do Currents]({{site.baseurl}}/user_guide/data_and_analytics/braze_currents/setting_up_currents#test-currents-connectors) são versões gratuitas dos nossos conectores existentes que podem ser usadas para testar e experimentar diferentes destinos. Os conectores de teste do Currents oferecem:

- Sem limite para o número de conectores de teste do Currents que você pode criar.
- Um máximo agregado de 10.000 eventos por período contínuo de 30 dias. Esse total de eventos é atualizado de hora em hora no dashboard.

## Feature Flags

Os [Feature Flags]({{site.baseurl}}/developer_guide/feature_flags) permitem ativar ou desativar remotamente funcionalidades para uma seleção específica ou aleatória de usuários. É importante ressaltar que eles permitem ativar e desativar um recurso em produção sem necessidade de implantação adicional de código ou atualizações na app store. Isso permite que você lance novos recursos com segurança e confiança.

## Experimentos com Feature Flag {#feature-flag-experiments}

Os [experimentos com Feature Flag]({{site.baseurl}}/developer_guide/feature_flags/experiments) permitem fazer testes A/B nas alterações dos seus aplicativos para otimizar as taxas de conversão. Os profissionais de marketing podem usar Feature Flags para determinar se um novo recurso afeta positiva ou negativamente as taxas de conversão, ou qual conjunto de propriedades do Feature Flag é o mais ideal.

## Mesclando perfis de usuário {#merging-user-profiles}

Se a sua pesquisa na página **Pesquisar usuários** retornar vários perfis de usuário, você poderá [mesclar perfis de usuário]({{site.baseurl}}/user_guide/engagement_tools/segments/user_profiles#merge-profiles) clicando no botão **Mesclar duplicatas**. Você pode selecionar qual perfil de usuário manter, o que significa que esse perfil será preservado e receberá os atributos do perfil mesclado.

## Dados de desempenho por segmento {#performance-data-by-segment}

Agora você pode usar os modelos de relatório do Criador de consultas para [detalhar os dados de desempenho]({{site.baseurl}}/user_guide/data_and_analytics/reporting/viewing_and_understanding_segment_data#performance-data-by-segment) por segmentos para Campaigns, Canvas, variantes e etapas.

## Atualização de perfis de usuário {#updating-user-profiles}

Agora é possível usar o [endpoint `/users/track`]({{site.baseurl}}/api/endpoints/user_data/post_user_track) para atualizar um perfil de usuário por número de telefone ou e-mail.

## Atualizações do SDK {#sdk-updates}

As seguintes atualizações do SDK foram lançadas. As atualizações com mudanças significativas estão listadas na seção de atualizações do SDK; todas as outras atualizações podem ser encontradas verificando os changelogs correspondentes do SDK.

- [Plug-in Swift do Braze Segment v2.1.0](https://github.com/braze-inc/braze-segment-swift/blob/main/CHANGELOG.md)
- [SDK da Web v4.10.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [SDK da Web v5.0.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
    - O retorno de chamada [`subscribeToFeatureFlagsUpdates()`](https://js.appboycdn.com/web-sdk/latest/doc/modules/braze.html#subscribetofeatureflagsupdates) agora sempre será chamado, independentemente do sucesso ou falha da atualização. Se houver uma falha no recebimento de atualizações, o retorno de chamada será chamado com os Feature Flags atualmente em cache.
    - O método [`getFeatureFlag()`](https://js.appboycdn.com/web-sdk/latest/doc/modules/braze.html#getfeatureflag) agora retorna nulo se o Feature Flag não existir ou se os Feature Flags estiverem desativados.
    - Removido o método `logContentCardsDisplayed()` que estava obsoleto desde a versão 4.0.4.
    - Removida a opção de inicialização obsoleta `enableHtmlInAppMessages`. Ela deve ser substituída pela opção `allowUserSuppliedJavascript`.
    - Removida a classe Banner, que já havia sido descontinuada na versão 4.9.0, em favor da classe [`ImageOnly`](https://js.appboycdn.com/web-sdk/latest/doc/classes/braze.imageonly.html).
    - Removido o nome da classe CSS `ab-banner` como parte da remoção da classe `Banner`. As personalizações de CSS devem direcionar a classe `ab-image-only`.
    - O SDK não gera mais erros de tempo de execução em nenhum lugar. Se os métodos da Braze forem chamados antes da inicialização, um aviso será registrado no console.
    - O SDK não adiciona mais os estilos padrão de mensagens no app da Braze às mensagens HTML personalizadas no app. Esses estilos eram usados anteriormente por tipos de mensagens no app legados.
- [Android SDK 29.0.0](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md)
    - Renomeou `BannerImageCard`, `BannerImageCardView` e `BannerImageContentCardView` para `ImageOnlyCard`, `ImageOnlyCardView` e `ImageOnlyContentCardView`.
    - Todos os estilos usados para cartões de banner foram atualizados para cartões somente de imagem. Todas as chaves com a palavra `banner` devem ser substituídas por `image_only`.
    - As informações sobre a marca do dispositivo agora são enviadas. Se você quiser bloquear isso, consulte Bloqueio da coleta de dados.
- [Flutter SDK 7.0.0](https://pub.dev/packages/braze_plugin/changelog)
    - Atualiza a ponte nativa do Android [do SDK da Braze para Android 26.1.1 para o 27.0.1](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#2701).
    - Adiciona suporte ao Gradle 8.
- [Swift SDK 7.0.0](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md)
    - A configuração `useUUIDAsDeviceId` agora está ativada por padrão.
        - Para saber mais sobre os impactos, consulte [Coleta de IDFV - Swift]({{site.baseurl}}/developer_guide/analytics/managing_data_collection/?sdktab=swift).
    - O tipo de cartão de conteúdo de banner e os elementos de interface do usuário correspondentes foram renomeados para `ImageOnly`. Todos os métodos e propriedades dos membros permanecem os mesmos.
        - `Braze.ContentCard.Banner` → `Braze.ContentCard.ImageOnly`
        - `BrazeContentCardUI.BannerCell` → `BrazeContentCardUI.ImageOnlyCell`
    - Refatora algumas lógicas de layout de texto na BrazeUI em uma nova classe Braze.ModalTextView.
    - Atualiza o comportamento dos métodos de Feature Flags.
        - `FeatureFlags.featureFlag(id:)` agora retorna nil para um ID que não existe.
        - `FeatureFlags.subscribeToUpdates(:)` disparará o retorno de chamada quando qualquer solicitação de atualização for concluída com sucesso ou falha.
            - O retorno de chamada também será disparado imediatamente após a inscrição inicial se houver dados armazenados em cache anteriormente.
- [AppboyKit iOS SDK 4.6.0](https://github.com/Appboy/appboy-ios-sdk/releases/tag/4.6.0)
    - Esta versão requer o Xcode `14.x`.
    - Elimina o suporte para iOS 9 e iOS 10.
    - Remove o suporte para os ativos desatualizados do `.framework` ao importar via Carthage em favor dos ativos modernos do `.xcframework`.
        - Use o comando `carthage update --use-xcframeworks` para importar o ativo apropriado da Braze.
        - Remove o suporte para `appboy_ios_sdk_full.json` em favor do uso de `appboy_ios_sdk.json`
