# Versão de 17 de outubro de 2023 {#october-17-2023-release}

## Copiando para espaços de trabalho {#copying-to-workspaces}

[Copiar Campaigns entre espaços de trabalho]({{site.baseurl}}/user_guide/messaging/governance/copy_across_workspaces) permite que você acelere a composição de mensagens começando com uma cópia de uma Campaign em um espaço de trabalho diferente. Essa cópia permanecerá como rascunho até que você a edite e lance, ajudando a manter e desenvolver suas estratégias de envio de mensagens bem-sucedidas.

## Testar conectores do Currents {#test-currents-connectors}

Os [conectores de teste do Currents]({{site.baseurl}}/user_guide/data_and_analytics/braze_currents/setting_up_currents#test-currents-connectors) são versões gratuitas dos nossos conectores existentes que podem ser usados para testes e para experimentar diferentes destinos. Os conectores de teste do Currents têm:

- Sem limite para o número de conectores de teste do Currents que você pode criar.
- Um máximo agregado de 10.000 eventos por período contínuo de 30 dias. Esse total de eventos é atualizado de hora em hora no dashboard.

## Feature Flags

As [Feature Flags]({{site.baseurl}}/developer_guide/feature_flags) permitem que você ative ou desative remotamente funcionalidades para uma seleção específica ou aleatória de usuários. O mais importante é que elas permitem ativar e desativar um recurso em produção sem a necessidade de implantação de código adicional ou atualizações na loja de apps. Isso permite que você lance novos recursos com segurança e confiança.

## Experimentos com Feature Flag {#feature-flag-experiments}

Os [experimentos com Feature Flag]({{site.baseurl}}/developer_guide/feature_flags/experiments) permitem que você faça testes A/B de alterações nos seus aplicativos para otimizar as taxas de conversão. Profissionais de marketing podem usar Feature Flags para determinar se um novo recurso impacta positiva ou negativamente as taxas de conversão, ou qual conjunto de propriedades de Feature Flag é o mais otimizado.

## Mesclando perfis de usuário {#merging-user-profiles}

Se a sua busca na página **Pesquisar Usuários** retornar vários perfis de usuário, você pode [mesclar perfis de usuário]({{site.baseurl}}/user_guide/audience/manage_audience/merge_duplicate_users) clicando no botão **Mesclar duplicatas**. Você pode selecionar qual perfil de usuário manter, o que significa que esse perfil será preservado e receberá os atributos do perfil mesclado.

## Dados de desempenho por Segment or segmento or segmento {#performance-data-by-segment}

Agora você pode usar modelos de relatório do Query Builder para [detalhar dados de desempenho]({{site.baseurl}}/user_guide/data_and_analytics/reporting/viewing_and_understanding_segment_data#performance-data-by-segment) por segmentos para Campaigns, Canvas, variantes e etapas.

## Atualizando perfis de usuário {#updating-user-profiles}

Agora você pode usar o [endpoint `/users/track`]({{site.baseurl}}/api/endpoints/user_data/post_user_track) para atualizar um perfil de usuário por número de telefone ou e-mail.

## Atualizações do SDK or kit de desenvolvimento de software {#sdk-updates}

As atualizações mais recentes do SDK or kit de desenvolvimento de software foram lançadas. Atualizações com mudanças significativas estão listadas na seção de atualizações do SDK or kit de desenvolvimento de software; todas as outras atualizações podem ser encontradas nos changelogs correspondentes do SDK or kit de desenvolvimento de software.

- [Braze Segment Swift Plugin v2.1.0](https://github.com/braze-inc/braze-segment-swift/blob/main/CHANGELOG.md)
- [Web SDK or kit de desenvolvimento de software v4.10.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [Web SDK or kit de desenvolvimento de software v5.0.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
    - O retorno de chamada [`subscribeToFeatureFlagsUpdates()`](https://js.appboycdn.com/web-sdk/latest/doc/modules/braze.html#subscribetofeatureflagsupdates) agora será sempre chamado, independentemente do sucesso/falha na atualização. Se houver uma falha no recebimento de atualizações, o retorno de chamada será acionado com as feature flags atualmente em cache.
    - O método [`getFeatureFlag()`](https://js.appboycdn.com/web-sdk/latest/doc/modules/braze.html#getfeatureflag) agora retorna null se a Feature Flag não existir ou se as feature flags estiverem desativadas.
    - Removido o método `logContentCardsDisplayed()` que havia sido descontinuado anteriormente na versão 4.0.4.
    - Removida a opção de inicialização descontinuada `enableHtmlInAppMessages`. Ela deve ser substituída pela opção `allowUserSuppliedJavascript`.
    - Removida a classe Banner que havia sido descontinuada na versão 4.9.0 em favor de [`ImageOnly`](https://js.appboycdn.com/web-sdk/latest/doc/classes/braze.imageonly.html).
    - Removido o nome de classe CSS `ab-banner` como parte da remoção da classe `Banner`. Personalizações CSS devem passar a usar a classe `ab-image-only`.
    - O SDK or kit de desenvolvimento de software não lança mais erros de tempo de execução em nenhum lugar. Se métodos da Braze forem chamados antes da inicialização, um alerta será registrado no console.
    - O SDK or kit de desenvolvimento de software não adiciona mais estilos padrão de In-App Messages da Braze a mensagens no app HTML personalizadas. Esses estilos eram usados anteriormente por tipos legados de mensagens no app.
- [Android SDK or kit de desenvolvimento de software 29.0.0](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md)
    - `BannerImageCard`, `BannerImageCardView` e `BannerImageContentCardView` foram renomeados para `ImageOnlyCard`, `ImageOnlyCardView` e `ImageOnlyContentCardView`.
    - Todos os estilos usados para Banner Cards foram atualizados para Image Only Cards. Todas as chaves com a palavra `banner` devem ser substituídas por `image_only`.
    - Informações da marca do dispositivo agora são enviadas. Se você quiser bloquear isso, consulte Bloqueio de coleta de dados.
- [Flutter SDK or kit de desenvolvimento de software 7.0.0](https://pub.dev/packages/braze_plugin/changelog)
    - Atualiza a bridge nativa do Android [do Braze Android SDK or kit de desenvolvimento de software 26.1.1 para 27.0.1](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#2701).
    - Adiciona suporte para Gradle 8.
- [Swift SDK or kit de desenvolvimento de software 7.0.0](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md)
    - A configuração `useUUIDAsDeviceId` agora está ativada por padrão.
        - Para mais detalhes sobre os impactos, consulte [Coleta de IDFV - Swift]({{site.baseurl}}/developer_guide/analytics/managing_data_collection/?sdktab=swift).
    - O tipo de cartão de conteúdo Banner e os elementos de UI correspondentes foram renomeados para `ImageOnly`. Todos os métodos e propriedades dos membros permanecem os mesmos.
        - `Braze.ContentCard.Banner` → `Braze.ContentCard.ImageOnly`
        - `BrazeContentCardUI.BannerCell` → `BrazeContentCardUI.ImageOnlyCell`
    - Refatora parte da lógica de layout de texto no BrazeUI em uma nova classe Braze.ModalTextView.
    - Atualiza o comportamento dos métodos de Feature Flags.
        - `FeatureFlags.featureFlag(id:)` agora retorna nil para um ID que não existe.
        - `FeatureFlags.subscribeToUpdates(:)` acionará o retorno de chamada quando qualquer solicitação de atualização for concluída com sucesso ou falha.
            - O retorno de chamada também será acionado imediatamente após a inscrição inicial, caso existam dados previamente armazenados em cache.
- [AppboyKit iOS SDK or kit de desenvolvimento de software 4.6.0](https://github.com/Appboy/appboy-ios-sdk/releases/tag/4.6.0)
    - Esta versão requer Xcode `14.x`.
    - Encerra o suporte para iOS 9 e iOS 10.
    - Remove o suporte para os ativos `.framework` desatualizados ao importar via Carthage em favor dos ativos `.xcframework` modernos.
        - Use o comando `carthage update --use-xcframeworks` para importar o ativo apropriado da Braze.
        - Remove o suporte para `appboy_ios_sdk_full.json` em favor do uso de `appboy_ios_sdk.json`
