# Lançamento em 14 de novembro de 2023 {#november-14-2023-release}

## Introdução à Braze {#getting-started-with-braze}

Boas notícias! Estamos apresentando duas seções de Introdução feitas especificamente para nossos [profissionais de marketing]({{site.baseurl}}/user_guide/get_started) e [desenvolvedores]({{site.baseurl}}/developer_guide/getting_started). Essas seções são projetadas para ajudar você a começar rapidamente a usar a Braze, fornecendo todas as ferramentas e orientações necessárias. Mergulhe e comece a explorar.

## Nova instância do dashboard da Braze {#new-braze-dashboard-instance}

A Braze gerencia várias instâncias diferentes para nosso dashboard e endpoints REST. Adicionamos uma nova instância de dashboard `US-07`. Para saber mais, consulte a [visão geral da API]({{site.baseurl}}/api/basics).

## Canais robustos {#robust-channels}

### Modelos personalizados de arrastar e soltar para mensagens no app {#custom-drag-and-drop-templates-for-in-app-messages}

{% multi_lang_include release_type.md release="General availability" %}

Agora você pode usar [modelos personalizados de arrastar e soltar para mensagens no app]({{site.baseurl}}/user_guide/channels/in_app_messages/drag_and_drop) para começar a criar sua mensagem no app no editor de arrastar e soltar.

### Aceitação dupla de SMS {#sms-double-opt-in}

{% multi_lang_include release_type.md release="General availability" %}

[A aceitação dupla de SMS]({{site.baseurl}}/user_guide/channels/sms_mms_and_rcs/message_features_and_optimization/keyword_processing/double_opt_in) permite que você exija que os usuários confirmem explicitamente sua intenção de aceitação antes que possam receber mensagens SMS. Isso ajuda você a direcionar seu foco para usuários que provavelmente estão engajados ou já estão engajados com SMS.

### Taxa de abertura real estimada para relatórios de e-mail {#estimated-real-open-rate-for-email-reporting}

{% multi_lang_include release_type.md release="General availability" %}

[A taxa de abertura real estimada]({{site.baseurl}}/user_guide/message_building_by_channel/email/reporting_and_analytics/email_reporting#estimated-real-open-rate) usa um modelo analítico proprietário criado pela Braze para reconstruir uma estimativa da taxa de abertura única da Campaign como se aberturas de máquina não existissem. A Braze usa dados de cliques de cada Campaign para inferir a taxa na qual humanos reais abriram a mensagem. Isso compensa vários mecanismos de abertura de máquina, incluindo o MPP da Apple.

### Jornadas personalizadas para Canvas {#personalized-paths-for-canvas}

{% multi_lang_include release_type.md release="Beta" %}

Com as [Jornadas personalizadas]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/experiment_step/personalized_paths), você pode personalizar jornadas inteiras no Canvas para usuários individuais com base na probabilidade de conversão, de forma semelhante às variantes personalizadas em Campaigns. Use jornadas personalizadas com uma etapa de jornada experimental para manter uma parte dos usuários em um grupo de postergação enquanto a Braze testa as jornadas restantes entre si.

{% multi_lang_include release_type.md release="General availability" %}

Agora você pode bloquear até 10 atributos ou eventos personalizados por vez. Para saber mais, consulte [Gerenciamento de eventos e atributos personalizados]({{site.baseurl}}/user_guide/data/activation/custom_data/managing_custom_data).

### Novo artigo de ajuda: links universais e links de app {#new-help-article-universal-links-and-app-links}

Os links universais da Apple e os links de app do Android são mecanismos criados para proporcionar uma transição perfeita entre o conteúdo da web e os aplicativos móveis. Embora os links universais sejam específicos para iOS, os links de app do Android servem ao mesmo propósito para aplicativos Android.

Saiba mais sobre esse tópico em nosso artigo dedicado [Links universais e links de app]({{site.baseurl}}/user_guide/channels/email/customize/universal_links_and_app_links).

## Novas parcerias da Braze {#new-braze-partnerships}

### Olo – Extensões de canal {#olo-channel-extensions}

A integração da Braze com o [Olo]({{site.baseurl}}/partners/ecommerce/ordering_payments_subscription/olo) permite que você atualize perfis de usuário na Braze para mantê-los consistentes com os perfis de usuário do Olo. Você também pode enviar as mensagens certas pela Braze com base nos eventos do Olo.

### Typeform – Plataforma de dados do cliente {#typeform-customer-data-platform}

A integração da Braze com o [Typeform]({{site.baseurl}}/partners/additional_channels_and_extensions/extensions/surveys/typeform) permite que você atualize perfis de usuários na Braze com dados coletados a partir das respostas do Typeform, dispare envio de mensagens na Braze com base no engajamento do usuário com um typeform e personalize o envio de mensagens da Braze com base nas respostas do usuário no Typeform.

## Atualizações do SDK {#sdk-updates}

As seguintes atualizações do SDK foram lançadas. As atualizações com mudanças significativas estão listadas abaixo; todas as outras atualizações podem ser encontradas verificando os changelogs correspondentes do SDK.

- [Web SDK v4.10.1](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [Web SDK v5.0.1](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [Android SDK 29.0.1](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md)
- [Swift SDK 7.1.0-7.2.0](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md)
    - `Braze.Configuration.DeviceProperty.pushDisplayOptions` foi descontinuado. Fornecer este valor não tem mais efeito.
- [React Native SDK 8.0.0-8.1.0](https://github.com/braze-inc/braze-react-native-sdk/blob/master/CHANGELOG.md)
    - Atualiza a ponte nativa do Android do SDK da Braze para Android 27.0.1 para 29.0.0.
    - Atualiza a ponte nativa do iOS do SDK Swift da Braze 6.6.0 para 7.0.0.
    - Renomeia o tipo de Content Cards `Banner` para ImageOnly:
        - de `BannerContentCard` para `ImageOnlyContentCard`
        - de `ContentCardTypes.BANNER` para `ContentCardTypes.IMAGE_ONLY`
    - No Android, se os arquivos XML no seu projeto contiverem a palavra `banner` para Content Cards, ela deve ser substituída por `image_only`.
    - `Braze.getFeatureFlag(id)` agora retornará `null` se a Feature Flag não existir.
    - `Braze.Events.FEATURE_FLAGS_UPDATED` só será disparado quando uma solicitação de atualização for concluída com êxito ou com falha, e na inscrição inicial, se houver dados em cache anteriores da sessão atual.
