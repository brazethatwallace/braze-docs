## Flexibilidade de dados {#data-flexibility}

### Notificações de volta ao estoque para catálogos {#back-in-stock-notifications-for-catalogs}

{% multi_lang_include release_type.md release="Early access" %}

Usando uma combinação de [notificações de volta ao estoque]({{site.baseurl}}/user_guide/data/activation/catalogs/catalog_triggers/back_in_stock_notifications) por meio de catálogos e um Canvas, você pode notificar os clientes quando um item estiver disponível novamente. Sempre que um cliente realiza um evento personalizado selecionado, ele pode ser inscrito automaticamente para receber uma notificação quando o item for reabastecido.

### Segmentos de catálogo {#catalog-segments}

{% multi_lang_include release_type.md release="Early access" %}

[Segmentos de catálogo]({{site.baseurl}}/user_guide/audience/segments/segment_extension/sql_segments/catalog_segments) são um público de usuários com base em dados de catálogo em extensões de segmento SQL. Essas extensões de segmento SQL podem ser referenciadas em um segmento e, em seguida, direcionadas por Campaigns e Canvas. Os segmentos de catálogo usam SQL para unir dados de catálogos e dados de eventos personalizados ou compras. Para isso, você deve ter um campo identificador comum em seus catálogos e em seus eventos personalizados ou compras.

### Migração para a API do Firebase Cloud Messaging {#migrating-to-the-firebase-cloud-messaging-api}

{% multi_lang_include release_type.md release="Early access" %}

Saiba [como migrar]({{site.baseurl}}/developer_guide/push_notifications/?sdktab=android) da API Cloud Messaging do Google, que está obsoleta, para a API Firebase Cloud Messaging (FCM), que conta com suporte total.

## Atualizações do SDK {#sdk-updates}

As seguintes atualizações do SDK foram lançadas. As alterações que causam quebra de compatibilidade estão listadas na seção de atualizações do SDK; todas as outras atualizações podem ser encontradas nos changelogs correspondentes do SDK.

- [Swift SDK 7.5.0](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md)
    - Adiciona manifestos de privacidade para `BrazeKit` e `BrazeLocation` para descrever as políticas de coleta de dados da Braze. Para mais detalhes, consulte a [documentação](https://developer.apple.com/documentation/bundleresources/privacy_manifest_files/describing_data_use_in_privacy_manifests) da Apple sobre manifestos de privacidade. Mais configurações para gerenciar suas práticas de coleta de dados serão disponibilizadas em uma versão futura.
    - Corrige um problema com as assinaturas de código dos XCFrameworks introduzido na versão 7.1.0.
- [Web SDK v5.1.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [Unity SDK 5.0.0](https://github.com/braze-inc/braze-unity-sdk/blob/master/CHANGELOG.md)
    - Atualização da ponte nativa do iOS do Braze Swift SDK 6.1.0 para o 7.4.0.
        - O link do repositório do iOS agora aponta para os XCFrameworks dinâmicos pré-construídos deste [repositório](https://github.com/braze-inc/braze-swift-sdk-prebuilt-dynamic).
    - Atualização da ponte nativa do Android do Braze Android SDK 27.0.1 para o 29.0.1.
    - `AppboyBinding.GetFeatureFlag(string id)` agora retornará `null` se a Feature Flag não existir.
    - `FEATURE_FLAGS_UPDATED` só será disparado quando uma solicitação de atualização for concluída com sucesso ou falha, e na inscrição inicial, se houver dados em cache anteriores da sessão atual.
