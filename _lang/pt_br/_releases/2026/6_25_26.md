# Versão de 25 de junho de 2026 {#june-25-2026-release}

## Dados e relatórios {#data-reporting}

### Atualização do nome da métrica para Content Cards e Banners {#metric-name-update-for-content-cards-and-banners}

A métrica _Unique Recipients_ foi renomeada para _Unique Daily Impressions_ para Content Cards e Banners. _Unique Daily Impressions_ refere-se ao número recebido da Braze e é baseada no `user_id`. As impressões diárias únicas são contadas no nível da Campaign ou da etapa do Canvas. Para mais detalhes, consulte o [Glossário de métricas]({{site.baseurl}}/user_guide/analytics/metrics_glossary).

### Exclusão de usuários {#user-deletion}

{% multi_lang_include release_type.md release="General availability" %}

A [exclusão de usuários]({{site.baseurl}}/user_guide/audience/manage_audience/user_profiles/delete_users) permite gerenciar seu banco de dados removendo perfis que não são mais necessários, foram criados por engano ou precisam ser excluídos por conformidade (como GDPR ou CCPA).

### Exclusões de pontos de dados {#data-point-exclusions}

{% multi_lang_include release_type.md release="General availability" %}

Os [eventos recomendados de eCommerce]({{site.baseurl}}/user_guide/data/activation/events/recommended_events/ecommerce_events) não contam mais como pontos de dados faturáveis. Você pode adotar os eventos de eCommerce da Braze (`ecommerce.product_viewed`, `ecommerce.cart_updated`, `ecommerce.checkout_started`, `ecommerce.order_placed`, `ecommerce.order_cancelled`, `ecommerce.order_refunded`) sem consumo de pontos de dados.

### Guia Histórico de eventos {#event-history-tab}

{% multi_lang_include release_type.md release="General availability" %}

A guia **Histórico de eventos** nos [perfis de usuário]({{site.baseurl}}/user_guide/audience/manage_audience/user_profiles) lista os eventos personalizados e as compras do usuário nos últimos 30 dias (até os 100 mais recentes). Use-a para confirmar se uma integração de SDK ou API está enviando eventos conforme esperado, depurar por que um usuário entrou (ou não) em uma Campaign ou Canvas disparada por evento, ou investigar uma escalação de suporte sobre um usuário específico.

### O Centro de entregabilidade exibe dados do Microsoft SNDS para clientes do Amazon SES {#deliverability-center-surfaces-microsoft-snds-data-for-amazon-ses-customers}

Para espaços de trabalho que enviam e-mail pelo Amazon SES, o [Centro de entregabilidade]({{site.baseurl}}/deliverability_center) exibe métricas do Microsoft SNDS para seus IPs de envio dedicados. A Braze preenche retroativamente até 90 dias de dados históricos do SNDS quando esse recurso é ativado para o seu espaço de trabalho.

## BrazeAI<sup>TM</sup>

### Assistentes BrazeAI unificados no Operator {#unified-brazeai-assistants-in-operator}

Os assistentes BrazeAI independentes encontrados em todo o dashboard foram unificados no [BrazeAI Operator]({{site.baseurl}}/user_guide/brazeai/operator), estabelecendo o Operator como o assistente de IA único para assistência de IA generativa voltada ao profissional de marketing em todo o dashboard. Os seguintes assistentes agora passam pelo Operator:

- AI Liquid Agent
- AI Copywriter
- AI HTML Email Template agent
- AI Image generator
- Content QA with AI
- AI Copilot for Data Transformations

Os pontos de entrada existentes permanecem onde cada botão de assistente legado costumava estar. Em vez de abrir um assistente independente, esses pontos de entrada agora abrem o painel do Operator com prompts dinâmicos pré-configurados para a sua tarefa. Esses pontos de entrada fornecem uma rota direta para o Operator, para que você possa usar essas funcionalidades sem ajustar seus fluxos de trabalho existentes.

### Suporte do Operator para criação e edição de Campaigns {#operator-support-for-campaign-creation-and-editing}

O [Operator]({{site.baseurl}}/user_guide/brazeai/operator) agora pode criar e editar Campaigns inteiras, não apenas redigir mensagens. A partir de um único prompt em linguagem natural ou briefing de Campaign, o Operator constrói uma Campaign pronta para revisão de ponta a ponta — redigindo a mensagem, programando a entrega, direcionando um público e atribuindo eventos de conversão — e depois resume o que construiu na etapa de revisão. Anteriormente, o Operator podia redigir a mensagem (uma das cinco etapas de criação de Campaign); agora ele tem visibilidade e controle sobre as etapas restantes de Programar, Direcionar, Atribuir e Revisar.

Essa funcionalidade está disponível na página **Campaigns** ou de dentro de qualquer Campaign existente. Como resultado, o Operator pode:

- Responder a prompts como "Quero enviar aos nossos usuários inativos uma notificação por push com um código promocional de 20% de desconto na próxima vez que abrirem o app ou registrarem um evento personalizado que cancele a inscrição deles".
- Auxiliar você em cada etapa individual do assistente de Campaign, com visibilidade total do que você está trabalhando e a capacidade de alterar as entradas do formulário na página.
- Navegar até a etapa correta no assistente para começar a agir, seja a partir de uma Campaign aberta ou da página **Campaigns**.

### Suporte do Operator para Content Blocks {#operator-support-for-content-blocks}

O [Operator]({{site.baseurl}}/user_guide/brazeai/operator) agora pode criar e editar [Content Blocks]({{site.baseurl}}/user_guide/messaging/design_and_edit/content_blocks) — os trechos reutilizáveis que você cria uma vez e referencia em várias mensagens — diretamente a partir de um prompt em linguagem natural. Na página **Content Blocks**, peça ao Operator para criar um novo Content Block do zero ou editar um existente, e o Operator gera ou atualiza o conteúdo para sua revisão.

### Modelos do Agent Console criados com o Operator {#agent-console-templates-built-with-operator}

Ao criar um agente no **Agent Console**, você pode optar por criar um agente personalizado ou selecionar uma opção em **Create an agent with Operator** para usar o BrazeAI Operator e aplicar um modelo inicial. O Operator pode pré-configurar instruções, campos de saída e contexto para os seguintes modelos iniciais do Agent Console.

Para mais detalhes, consulte [Criar agentes personalizados]({{site.baseurl}}/user_guide/brazeai/agents/creating_agents#agent-templates-built-with-operator).

### Melhorias no Agent Console {#agent-console-enhancements}

Você pode fazer o seguinte no [Agent Console]({{site.baseurl}}/user_guide/brazeai/agents):

- Configurar casos de uso pré-definidos com o Operator pelo menu suspenso do botão **Create agent**.
- Duplicar agentes existentes a partir da lista de agentes.
- Salvar agentes como rascunhos durante a criação e concluir as configurações depois.
- Definir valores de saída de fallback para agentes do Canvas para evitar que variáveis de saída sejam definidas como nulas se o agente apresentar erro.
- Definir campos de entrada obrigatórios para um campo agêntico de catálogo, para que o agente não seja executado se o valor de um campo de entrada obrigatório estiver vazio ou ausente.
- Reexecutar um agente para todas as células vazias de uma coluna agêntica para preencher valores ausentes sem reexecutar a coluna inteira.

### Editar uma etapa do Otimizador de Conteúdo já lançada {#edit-a-launched-content-optimizer-step}

{% multi_lang_include release_type.md release="Beta" %}

Depois que seu Canvas for lançado, agora você pode [atualizar uma etapa do Otimizador de Conteúdo]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/content_optimizer_step#edit-a-launched-step) para:

- Adicionar novas variantes a qualquer componente existente, manualmente ou usando sugestões geradas por IA, até o limite de cinco variantes por componente.
- Desativar variantes para parar de enviá-las aos usuários.
- Reativar variantes previamente desativadas, desde que isso mantenha o componente dentro do limite de cinco variantes.

## Canais e pontos de contato {#channels-touchpoints}

### Dispensas de usuários para Banners {#user-dismissals-for-banners}

{% multi_lang_include release_type.md release="General availability" %}

Você pode permitir que os usuários dispensem manualmente um Banner selecionando **Banner can be dismissed** ao configurar o comportamento de dispensa. Essa opção é útil em cenários em que você deseja promover uma venda por tempo limitado para todos os usuários do app, mas permitir que eles dispensem a mensagem se não estiverem interessados.

Consulte [Configurar comportamento de dispensa]({{site.baseurl}}/user_guide/channels/banners/create_a_banner#dismiss-behavior) para detalhes sobre como ativar a dispensa e personalizar o botão de dispensar.

### Rastreamento de cliques personalizado para Banners {#custom-click-tracking-for-banners}

{% multi_lang_include release_type.md release="General availability" %}

Para um rastreamento de cliques mais granular para Banners, você pode [atribuir um identificador personalizado]({{site.baseurl}}/user_guide/channels/banners/create_a_banner#step-32-define-on-click-behavior-optional) a cada elemento interativo usando o campo **Identifier for Reporting** no painel de propriedades.

### Reelegibilidade para Banners {#re-eligibility-for-banners}

Quando a reelegibilidade está ativada para Campaigns de Banner, os usuários que dispensarem um Banner podem se tornar elegíveis novamente após um período de espera configurável que começa na dispensa. Se a reelegibilidade não estiver ativada, os usuários que dispensaram permanecem inelegíveis. Para configurar a reelegibilidade, consulte [Configurar reelegibilidade]({{site.baseurl}}/user_guide/channels/banners/create_a_banner#re-eligibility). Observe que as etapas de Banner no Canvas usam as configurações de reentrada do Canvas.

### Testes A/B de Quick Push {#quick-push-ab-testing}

{% multi_lang_include release_type.md release="General availability" %}

Os testes A/B de Quick Push agora suportam Campaigns de push multiplataforma e etapas do Canvas por meio de grupos de variantes, para que você possa testar variações de mensagens alinhadas para iOS e Android em um único fluxo de trabalho. Para mais informações, consulte [Mensagens push multiplataforma]({{site.baseurl}}/user_guide/channels/push/create_a_push_message/multiple_platform_push#use-cases).

### Seleção de variante BrazeAI<sup>TM</sup> {#brazeai-variant-selection}

{% multi_lang_include release_type.md release="Early access" %}

A Seleção de variante BrazeAI<sup>TM</sup> é ativada automaticamente quando você adiciona múltiplas variantes de push, aplica padrões de experimento recomendados e otimiza em direção à variante de melhor desempenho para melhorar o engajamento. Você pode desativá-la se precisar enviar imediatamente. Para mais informações, consulte [Seleção de variante BrazeAI<sup>TM</sup>]({{site.baseurl}}/user_guide/brazeai/intelligence_suite/variant_selection).

### Resultados de envio de teste do WhatsApp {#whatsapp-test-send-results}

Após enviar uma mensagem de teste do WhatsApp, você pode visualizar um [relatório de entrega detalhado]({{site.baseurl}}/user_guide/channels/whatsapp/create_a_whatsapp_message#step-4-view-test-send-results) diretamente no criador de mensagens. Isso ajuda a confirmar que sua mensagem chegou ao destinatário pretendido e a solucionar falhas antes do lançamento.

## Parcerias {#partnerships}

### Convercus - Dados e análise de dados - Fidelidade {#convercus-data-and-analytics-loyalty}

A [Convercus]({{site.baseurl}}/partners/data_and_analytics/loyalty/convercus) é uma plataforma SaaS de fidelidade e cupons que ajuda marcas e varejistas a aumentar a frequência de clientes, o valor do carrinho e as taxas de recompra por meio de programas de fidelidade omnicanal e campanhas de cupons personalizadas.

### Copy Pastd - Orquestração de mensagens - Modelos {#copy-pastd-message-orchestration-templates}

O [Copy Pastd]({{site.baseurl}}/partners/copy_pastd) Building Blocks é um construtor de e-mail de arrastar e soltar que envia Content Blocks com Liquid e modelos completos diretamente para o seu espaço de trabalho da Braze. Crie uma vez, sincronize com a Braze e reutilize os mesmos componentes em Campaigns, Canvas e fluxos disparados sem reconstruir HTML a cada vez.

### Databricks Mosaic - Provedores de modelos de IA {#databricks-mosaic-ai-model-providers}

O [Databricks Mosaic]({{site.baseurl}}/partners/databricks_mosaic) é a plataforma unificada da Databricks para construir, implantar e gerenciar modelos de IA e machine learning em escala na Databricks Data Intelligence Platform.

### DinMo - Dados e análise de dados - ETL reverso {#dinmo-data-and-analytics-reverse-etl}

O [DinMo]({{site.baseurl}}/partners/dinmo) é uma plataforma de dados do cliente (CDP) composável que conecta seu data warehouse na nuvem à Braze por meio de ETL reverso (Extract, Transform, Load). As equipes de marketing podem criar segmentos de público a partir de dados do warehouse, sincronizar atributos e eventos de usuários na Braze e manter os status de inscrição atualizados sem uploads de CSV ou suporte de engenharia.

### EmailShepherd - Orquestração de mensagens - Modelos {#emailshepherd-message-orchestration-templates}

O [EmailShepherd]({{site.baseurl}}/partners/emailshepherd) é uma plataforma agêntica de criação de e-mail construída sobre o seu Email Design System que permite que toda a sua equipe de marketing — e agentes de IA — produza e-mails prontos para produção e alinhados à marca sem gargalos. A integração com a Braze publica e-mails aprovados diretamente no seu espaço de trabalho da Braze, para que os profissionais de marketing possam escalar a produção de e-mails na Braze sem sacrificar a consistência da marca.

### Talkable - Personalização de mensagens - Indicações {#talkable-message-personalization-referrals}

A [Talkable]({{site.baseurl}}/partners/talkable) ajuda marcas de consumo a transformar clientes satisfeitos em um canal de indicação escalável. Com a integração com a Braze, os opt-ins de e-mail de marketing capturados em campanhas de indicação da Talkable fluem para a Braze em tempo real, fornecendo à sua equipe o consentimento, o contexto e os dados de campanha necessários para dar boas-vindas, segmentar e engajar cada novo defensor e amigo.

## SDK

### Atualizações com mudanças significativas do SDK {#sdk-breaking-updates}

As seguintes atualizações do SDK foram lançadas. As mudanças significativas estão listadas abaixo; todas as outras atualizações podem ser encontradas nos changelogs correspondentes do SDK.

- [Swift SDK 14.2.0](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md)
- [Android SDK 42.3.0](https://github.com/braze-inc/braze-android-sdk/releases/tag/v42.3.0)
    - `BannerView`: Os campos `BannerDismissSnapshot` passados para `onDismissCallback` agora são não nulos. Se o SDK não conseguir resolver `placementId`, `stableKey` ou `trackingId`, o retorno de chamada é ignorado e um aviso é registrado.
- [Web SDK 6.8.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
    - Adiciona suporte para novos métodos de eventos de eCommerce.
- [Swift SDK 14.2.1](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md#1421)
- [Swift SDK 15.0.0](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md)
    - Banners: `onDismiss` agora recebe `Braze/BannerDismissalEvent` em vez de `Braze/Banner`.
    - Eleva a versão do Xcode para 26.0 (17A324).
    - Eleva o alvo mínimo de implantação do Mac Catalyst de iOS 13 (macOS 10.15 Catalina) para iOS 16 (macOS 13 Ventura).
        - Usuários do Mac Catalyst no macOS 12 Monterey ou anterior não são mais suportados.
    - Remove a capacidade de controlar se o SDK impede a exibição de mensagens no app para diferentes usuários em certos casos extremos.
        - Remove a opção de configurar por meio de `Braze.Configuration.preventInAppMessageDisplayForDifferentUser`.
        - O SDK agora sempre se comportará como se essa opção de configuração estivesse definida como true.
    - Atualiza o init de `Braze.WebViewBridge.ScriptMessageHandler` e `Braze.WebViewBridge.SchemeHandler` para ter o parâmetro `channel` não opcional.
- [Android SDK 42.3.1](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#4231)
    - Adiciona suporte para novos métodos de eventos de eCommerce.
    - Adiciona métodos de dispensa de Banner para implementações de UI personalizadas.
    - Inclui correções de bugs de mensagens no app em HTML.
- [Swift SDK 15.0.1](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md#1501)
- [React Native 21.0.0](https://www.npmjs.com/package/@braze/react-native-sdk/v/21.0.0)
    - Atualiza as vinculações de versão nativa do Swift e Android SDK.
    - Atualiza as vinculações de versão nativa do Swift SDK [de Braze Swift SDK 14.0.4 para 15.0.1](https://github.com/braze-inc/braze-swift-sdk/compare/14.0.4...15.0.1#diff-06572a96a58dc510037d5efa622f9bec8519bc1beab13c9f251e97e657a9d4ed).
    - Corrige o JSDoc de Content Cards.
        - Eleva a versão do Xcode para 26.0 (17A324).
- [Swift SDK 15.1.0](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md)
    - Adiciona suporte para novos métodos de eventos de eCommerce.
    - Adiciona métodos de dispensa de Banner para implementações de UI personalizadas.
    - Adiciona implementações de exemplo para construir UI personalizada com Banners.
    - Adiciona observabilidade de Live Activities de passagem, permitindo que erros e eventos de atualização sejam rastreados com mais precisão e granularidade.
    - Adiciona getters assíncronos baseados em retorno de chamada para Content Cards e descontinua getters mais antigos.
