# Veröffentlichung am 27. Mai 2025 {#may-27-2025-release}

## Flexibilität der Daten {#data-flexibility}

### Kopieren von Canvases über Workspaces hinweg {#copying-canvases-across-workspaces}

{% multi_lang_include release_type.md release="General availability" %}

Sie können Canvases jetzt über Workspaces hinweg kopieren. Auf diese Weise können Sie mit dem Verfassen von Nachrichten beginnen, indem Sie mit einer Kopie eines Canvas in einem anderen Workspace starten. Weitere Informationen darüber, was kopiert wird, finden Sie unter [Kopieren von Campaigns und Canvases über Workspaces hinweg]({{site.baseurl}}/copying_to_workspaces/).

### Messaging-Regeln für den Genehmigungs-Workflow {#messaging-rules-for-approval-workflow}

{% multi_lang_include release_type.md release="General availability" %}

Verwenden Sie [Messaging-Regeln]({{site.baseurl}}/user_guide/messaging/governance/approvals/messaging_rules/) in Ihrem Genehmigungs-Workflow, um die Anzahl der erreichbaren Nutzer:innen zu begrenzen, bevor eine zusätzliche Genehmigung erforderlich ist – so können Sie Ihre Campaigns und Canvases überprüfen, bevor Sie eine größere Zielgruppe ansprechen.

### Entity-Relationship-Diagramme für Snowflake und Braze {#entity-relationship-diagrams-for-snowflake-and-braze}

Zu Beginn dieses Jahres haben wir Entity-Relationship-Tabellen für Daten erstellt, die zwischen Snowflake und Braze geteilt werden. Diesen Monat haben wir [neue interaktive Diagramme]({{site.baseurl}}/partners/data_and_analytics/data_warehouses/snowflake/entity_relationships/) hinzugefügt, in denen Sie die Details der einzelnen Tabellen schwenken, greifen und zoomen können. So erhalten Sie eine bessere Vorstellung davon, wie Ihre Daten mit Braze interagieren.

## Kreativität entfesseln {#unlocking-creativity}

### Empfohlene Ereignisse {#recommended-events}

{% multi_lang_include release_type.md release="Early access" %}

[Empfohlene Ereignisse]({{site.baseurl}}/user_guide/data/activation/events/recommended_events/) sind den häufigsten E-Commerce-Anwendungsfällen zugeordnet. Durch die Verwendung empfohlener Ereignisse können Sie vorgefertigte Canvas-Templates, Berichts-Dashboards, die an den Kundenlebenszyklus angepasst sind, und vieles mehr freischalten.

## Robuste Kanäle {#robust-channels}

### Banner-Kanal {#banners-channel}

{% multi_lang_include release_type.md release="General availability" %}

Mit [Bannern]({{site.baseurl}}/user_guide/channels/banners/) können Sie personalisierte Nachrichten für Ihre Nutzer:innen erstellen und gleichzeitig die Reichweite Ihrer anderen Kanäle wie E-Mail oder Push-Benachrichtigungen erweitern. Sie können Banner direkt in Ihre App oder Website einbetten, wodurch Sie Nutzer:innen durch ein natürliches Erlebnis ansprechen können.

### Rich Communication Services (RCS)-Kanal {#rich-communication-services-rcs-channel}

{% multi_lang_include release_type.md release="General availability" %}

[Rich Communication Services (RCS)]({{site.baseurl}}/user_guide/channels/sms_mms_and_rcs/) erweitern die traditionelle SMS, indem sie Marken ermöglichen, Nachrichten zuzustellen, die nicht nur informativ, sondern auch deutlich ansprechender sind. RCS wird jetzt sowohl auf Android als auch auf iOS unterstützt und bringt Features wie hochwertige Medien, interaktive Buttons und gebrandete Absenderprofile direkt in die vorinstallierten Messaging-Apps der Nutzer:innen – der Download einer separaten App entfällt.

### Seite „Push-Einstellungen“ {#push-settings-page}

{% multi_lang_include release_type.md release="General availability" %}

Auf der Seite [**Push-Einstellungen**]({{site.baseurl}}/user_guide/administer/global/workspace_settings/push_settings/) können Sie die wichtigsten Einstellungen für Ihre Push-Benachrichtigungen konfigurieren, darunter die Push-Time-to-Live (TTL) und die Standard-FCM-Priorität für Android-Campaigns. Mit diesen Einstellungen können Sie die Zustellung und Effektivität Ihrer Push-Benachrichtigungen optimieren und so ein besseres Erlebnis für Ihre Nutzer:innen gewährleisten.

### Aktionscodes für In-App-Nachricht-Campaigns {#promotion-codes-for-in-app-message-campaigns}

{% multi_lang_include release_type.md release="Early access" %}

Sie können [Aktionscodes]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/sources/promotion_codes/) in In-App-Nachricht-Campaigns verwenden, indem Sie ein [Snippet mit einer Aktionscode-Liste]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/sources/promotion_codes/#creating-a-promotion-code-list) in den Nachrichtentext Ihrer In-App-Nachricht-Campaign einfügen.

### Umgang mit Webhook-Fehlern und Rate-Limiting {#handling-webhook-errors-and-rate-limiting}

[Über Webhooks]({{site.baseurl}}/user_guide/message_building_by_channel/webhooks/understanding_webhooks/#webhook-error-handling-and-rate-limiting) enthält einen neuen Abschnitt, der beschreibt, wie Braze mit Webhook-Fehlern und Rate-Limiting umgeht.

### Lokalisierungen für In-App-Nachrichten {#in-app-message-locales}

Nachdem Sie Ihrem Workspace [Lokalisierungen hinzugefügt haben]({{site.baseurl}}/locales_in_messages/), können Sie Nutzer:innen in verschiedenen Sprachen innerhalb einer einzigen In-App-Nachricht ansprechen.

### Amazon SES als Anbieter für den E-Mail-Versand (ESP) {#amazon-ses-as-an-email-sending-provider-esp}

Sie können jetzt Amazon SES als ESP verwenden, ähnlich wie Sie SendGrid und SparkPost verwenden würden. Siehe [SSL bei Braze]({{site.baseurl}}/user_guide/message_building_by_channel/email/email_setup/ssl/#what-is-a-cdn-and-why-do-i-need-it) und [Universal Links und App Links]({{site.baseurl}}/user_guide/message_building_by_channel/email/universal_links/#turning-off-click-tracking-on-a-link-to-link-basis) für die Feinheiten der SSL-Einrichtung und des Klick-Trackings auf Link-zu-Link-Basis.

## Neue Braze-Partnerschaften {#new-braze-partnerships}

### Eagle Eye – Loyalität {#eagle-eye-loyalty}

Die bidirektionale Integration von Braze und [Eagle Eye]({{site.baseurl}}/partners/eagle_eye/) ermöglicht es Ihnen, Treue- und Aktionsdaten direkt in Braze zu aktivieren, sodass Marketer das Customer-Engagement anhand von Echtzeitdaten wie Punkteständen, Aktionen und Belohnungsaktivitäten personalisieren können.

### Eppo – A/B-Tests {#eppo-ab-testing}

Die Integration von Braze und [Eppo]({{site.baseurl}}/partners/eppo/) ermöglicht es Ihnen, A/B-Tests in Braze einzurichten und die Ergebnisse in Eppo zu analysieren, um Insights zu gewinnen und die Performance von Nachrichten mit langfristigen Geschäftsmetriken wie Umsatz oder Bindung zu verknüpfen.

### Mention Me – Empfehlungen {#mention-me-referrals}

Gemeinsam können [Mention Me](https://www.mention-me.com/) und Braze Ihr Tor zur Gewinnung von Premium-Kund:innen und zur Förderung einer unerschütterlichen Markentreue sein. Durch die nahtlose Integration von First-Party-Empfehlungsdaten in Braze können Sie hoch personalisierte Omnichannel-Erlebnisse liefern, die auf Ihre Markenfans zugeschnitten sind. Weitere Informationen finden Sie unter [Technologie-Partner: Mention Me]({{site.baseurl}}/partners/mention_me/).

### Shopify – E-Commerce {#shopify-ecommerce}

[Verbinden Sie mehrere Shopify-Shop-Domains]({{site.baseurl}}/shopify_connecting_multiple_stores/) mit einem einzigen Workspace, um einen ganzheitlichen Überblick über Ihre Kund:innen in allen Märkten zu erhalten. Erstellen und starten Sie Automatisierungsprogramme und Journeys in einem einzigen Workspace, ohne doppelte Arbeit in den regionalen Shops.

Wir haben unseren Artikel [Barrierefreie Nachrichten in Braze erstellen]({{site.baseurl}}/user_guide/messaging/messaging_fundamentals/accessibility/) mit klarerer, präziserer Anleitung zum Erstellen barrierefreier Nachrichten aktualisiert. ## SDK-Updates

Die folgenden SDK-Updates wurden veröffentlicht. Wichtige Updates sind unten aufgeführt; alle weiteren Updates finden Sie in den entsprechenden SDK-Changelogs.

- [Android SDK 36.0.0](https://pub.dev/packages/braze_plugin/changelog)
    - Diese Version macht die Erhöhung der Mindestversion des Android SDK von Braze von API 21 auf API 25 rückgängig, die in 34.0.0 eingeführt wurde. Damit kann das SDK wieder in Apps kompiliert werden, die bereits ab API 21 unterstützen. Bitte beachten Sie, dass wir zwar die Kompilierbarkeit wieder einführen, aber keine formale Unterstützung für < API 25 bieten und nicht garantieren können, dass das SDK auf Geräten mit diesen Versionen wie vorgesehen funktioniert.
    - Wenn Ihre App diese Versionen unterstützt, sollten Sie:
        - Überprüfen, ob Ihre Integration des SDK auf physischen Geräten (nicht nur Emulatoren) für diese API-Versionen wie vorgesehen funktioniert.
        - Wenn Sie das erwartete Verhalten nicht überprüfen können, müssen Sie entweder [disableSDK](https://braze-inc.github.io/braze-android-sdk/kdoc/braze-android-sdk/com.braze/-braze/-companion/disable-sdk.html) aufrufen oder das SDK auf diesen Versionen nicht initialisieren. Andernfalls kann es auf den Geräten Ihrer Endnutzer:innen zu unbeabsichtigten Nebeneffekten oder einer verminderten Performance kommen.
    - Ein Problem wurde behoben, bei dem In-App-Nachrichten einen Lesezugriff auf den Hauptthread verursachten.
    `BrazeInAppMessageManager.displayInAppMessage` ist jetzt eine Kotlin-Suspend-Funktion.
        - Wenn Sie diese Funktion nicht direkt aufrufen, müssen Sie keine Änderungen vornehmen.
    - AndroidX Compose BOM wurde auf 2025.04.01 aktualisiert, um Updates in den Jetpack Compose APIs zu verarbeiten.
- [React Native SDK 15.0.0](https://github.com/braze-inc/braze-react-native-sdk/blob/master/CHANGELOG.md)
    - Aktualisiert die native Android-Bridge von Braze Android SDK 35.0.0 auf 36.0.0.
    - Aktualisiert die nativen iOS-Versionsbindungen von Braze Swift SDK 11.9.0 auf 12.0.0.
    - Aktualisiert die Einheitsdarstellung von PushNotificationEvent.timestamp auf Millisekunden unter iOS.
        - Zuvor wurde dieser Wert unter iOS in Sekunden angegeben. Dies entspricht nun der bestehenden Android-Implementierung.
- [Web SDK 5.9.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [Flutter SDK 14.0.0 5.9.0](https://pub.dev/packages/braze_plugin/changelog)
    - Diese Version macht die Erhöhung der Mindestversion des Android SDK von Braze von API 21 auf API 25 rückgängig, die in 34.0.0 eingeführt wurde. Damit kann das SDK wieder in Apps kompiliert werden, die bereits ab API 21 unterstützen. Wir werden jedoch keine formale Unterstützung für < API 25 wieder einführen. Lesen Sie [hier](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#3600) mehr.
    - Aktualisiert die native Android-Bridge von Braze Android SDK 35.0.0 auf 36.0.0.
    - Aktualisiert die native iOS-Bridge von Braze Swift SDK 11.9.0 auf 12.0.0.
