# Veröffentlichung am 27. Mai 2025 {#may-27-2025-release}

## Datenflexibilität {#data-flexibility}

### Canvases über Workspaces hinweg kopieren {#copying-canvases-across-workspaces}

{% multi_lang_include release_type.md release="General availability" %}

Sie können jetzt Canvases über Workspaces hinweg kopieren. So können Sie Ihre Nachrichtengestaltung beschleunigen, indem Sie mit einer Kopie eines Canvas aus einem anderen Workspace beginnen. Weitere Informationen darüber, was kopiert wird, finden Sie unter [Campaigns und Canvases über Workspaces hinweg kopieren]({{site.baseurl}}/copying_to_workspaces).

### Messaging-Regeln für Genehmigungsworkflows {#messaging-rules-for-approval-workflow}

{% multi_lang_include release_type.md release="General availability" %}

Verwenden Sie [Messaging-Regeln]({{site.baseurl}}/user_guide/messaging/governance/approvals/messaging_rules) in Ihrem Genehmigungsworkflow, um die Anzahl der erreichbaren Nutzer:innen zu begrenzen, bevor eine zusätzliche Genehmigung erforderlich ist – so können Sie Ihre Campaigns und Canvases überprüfen, bevor Sie eine größere Zielgruppe ansprechen.

### Entity-Relationship-Diagramme für Snowflake und Braze {#entity-relationship-diagrams-for-snowflake-and-braze}

Anfang dieses Jahres haben wir Entity-Relationship-Tabellen für die zwischen Snowflake und Braze geteilten Daten erstellt. Diesen Monat haben wir [neue interaktive Diagramme]({{site.baseurl}}/partners/data_and_analytics/data_warehouses/snowflake/entity_relationships) hinzugefügt, in denen Sie schwenken, greifen und in die Details jeder Tabelle hineinzoomen können, um ein besseres Verständnis davon zu bekommen, wie Ihre Daten mit Braze interagieren.

## Kreativität freisetzen {#unlocking-creativity}

### Empfohlene Ereignisse {#recommended-events}

{% multi_lang_include release_type.md release="Early access" %}

[Empfohlene Ereignisse]({{site.baseurl}}/user_guide/data/activation/events/recommended_events) decken die häufigsten E-Commerce-Anwendungsfälle ab. Durch die Verwendung empfohlener Ereignisse erhalten Sie Zugang zu vorgefertigten Canvas-Templates, Reporting-Dashboards, die den Kundenlebenszyklus abbilden, und mehr.

## Robuste Kanäle {#robust-channels}

### Banner-Kanal {#banners-channel}

{% multi_lang_include release_type.md release="General availability" %}

Mit [Banner]({{site.baseurl}}/user_guide/channels/banners) können Sie personalisierte Nachrichten für Ihre Nutzer:innen erstellen und gleichzeitig die Reichweite Ihrer anderen Kanäle wie E-Mail oder Push-Benachrichtigungen erweitern. Sie können Banner direkt in Ihre App oder Website einbetten, sodass Sie Nutzer:innen über ein Erlebnis ansprechen, das sich natürlich anfühlt.

### Rich Communication Services (RCS)-Kanal {#rich-communication-services-rcs-channel}

{% multi_lang_include release_type.md release="General availability" %}

[Rich Communication Services (RCS)]({{site.baseurl}}/user_guide/channels/sms_mms_and_rcs) erweitert herkömmliche SMS, indem Marken Nachrichten senden können, die nicht nur informativ, sondern auch wesentlich ansprechender sind. RCS wird jetzt sowohl auf Android als auch auf iOS unterstützt und bietet Features wie hochwertige Medien, interaktive Buttons und gebrandete Absenderprofile direkt in den vorinstallierten Messaging-Apps der Nutzer:innen – ohne dass eine separate App heruntergeladen werden muss.

### Seite „Push-Einstellungen“ {#push-settings-page}

{% multi_lang_include release_type.md release="General availability" %}

Verwenden Sie die Seite [**Push-Einstellungen**]({{site.baseurl}}/user_guide/administer/global/workspace_settings/push_settings), um wichtige Einstellungen für Ihre Push-Benachrichtigungen zu konfigurieren, darunter Push TTL (TTL) und die Standard-FCM-Priorität für Android-Campaigns. Diese Einstellungen helfen dabei, die Zustellung und Effektivität Ihrer Push-Benachrichtigungen zu optimieren und ein besseres Erlebnis für Ihre Nutzer:innen sicherzustellen.

### Aktionscodes für In-App-Nachrichten-Campaigns {#promotion-codes-for-in-app-message-campaigns}

{% multi_lang_include release_type.md release="Early access" %}

Sie können [Aktionscodes]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/sources/promotion_codes) in In-App-Nachrichten-Campaigns verwenden, indem Sie ein [Aktionscode-Listen-Snippet]({{site.baseurl}}/user_guide/messaging/design_and_edit/personalize/sources/promotion_codes/create#create) in den Nachrichtentext Ihrer In-App-Nachrichten-Campaign einfügen.

### Behandlung von Webhook-Fehlern und Rate-Limiting {#handling-webhook-errors-and-rate-limiting}

[Über Webhooks]({{site.baseurl}}/user_guide/message_building_by_channel/webhooks/understanding_webhooks#webhook-error-handling-and-rate-limiting) enthält einen neuen Abschnitt, der beschreibt, wie Braze Webhook-Fehler und Rate-Limiting behandelt.

### Lokalisierungen für In-App-Nachrichten {#in-app-message-locales}

Nachdem Sie [Lokalisierungen]({{site.baseurl}}/locales_in_messages) zu Ihrem Workspace hinzugefügt haben, können Sie Nutzer:innen in verschiedenen Sprachen innerhalb einer einzigen In-App-Nachricht ansprechen.

### Amazon SES als E-Mail-Versandanbieter (E-Mail-Anbieter) {#amazon-ses-as-an-email-sending-provider-esp}

Sie können Amazon SES jetzt als E-Mail-Anbieter verwenden, ähnlich wie Sie SendGrid und SparkPost verwenden würden. Weitere Informationen zu Besonderheiten bei der SSL-Einrichtung und dem Klick, der-Tracking auf Link-Ebene finden Sie unter [SSL bei Braze]({{site.baseurl}}/user_guide/channels/email/email_setup/ssl#what-is-a-cdn-and-why-do-i-need-it) und [Universal Links und App Links]({{site.baseurl}}/user_guide/channels/email/customize/universal_links_and_app_links#turning-off-click-tracking-on-a-link-to-link-basis).

## Neue Braze-Partnerschaften {#new-braze-partnerships}

### Eagle Eye – Kundenbindung {#eagle-eye-loyalty}

Die bidirektionale Integration von Braze und [Eagle Eye]({{site.baseurl}}/partners/eagle_eye) ermöglicht es Ihnen, Kundenbindungs- und Aktionsdaten direkt in Braze zu aktivieren, sodass Marketer das Customer-Engagement mithilfe von Echtzeitdaten wie Punkteständen, Aktionen und Prämienaktivitäten personalisieren können.

### Eppo – A/B-Tests {#eppo-ab-testing}

Die Integration von Braze und [Eppo]({{site.baseurl}}/partners/eppo) ermöglicht es Ihnen, A/B-Tests in Braze einzurichten und die Ergebnisse in Eppo zu analysieren, um Insights zu gewinnen und die Nachrichten-Performance mit langfristigen Geschäftsmetriken wie Umsatz oder Bindung zu verknüpfen.

### Mention Me – Empfehlungen {#mention-me-referrals}

Gemeinsam können [Mention Me](https://www.mention-me.com/) und Braze Ihr Tor zu Premium-Kund:innen und nachhaltiger Markentreue sein. Durch die nahtlose Integration von First-Party-Empfehlungsdaten in Braze können Sie hochpersonalisierte Omnichannel-Erlebnisse bereitstellen, die auf Ihre Markenfans zugeschnitten sind. Informationen zum Einstieg finden Sie unter [Technologie-Partner: Mention Me]({{site.baseurl}}/partners/mention_me).

### Shopify – E-Commerce {#shopify-ecommerce}

[Verbinden Sie mehrere Shopify-Shop-Domains]({{site.baseurl}}/shopify_connecting_multiple_stores) mit einem einzelnen Workspace, um eine ganzheitliche Sicht auf Ihre Kund:innen über alle Märkte hinweg zu erhalten. Erstellen und starten Sie Automatisierungsprogramme und Journeys in einem einzigen Workspace, ohne Aufwände über regionale Shops hinweg duplizieren zu müssen.

## Sonstiges {#other}

### Aktualisierung von „Barrierefreie Nachrichten in Braze erstellen“ {#update-to-building-accessible-messages-in-braze}

Wir haben unseren Artikel [Barrierefreie Nachrichten in Braze erstellen]({{site.baseurl}}/user_guide/messaging/messaging_fundamentals/accessibility) mit klareren, praxisnäheren Anleitungen zur Erstellung barrierefreier Nachrichten aktualisiert. Dieses Update ist Teil unserer umfassenderen Initiative zur Unterstützung barrierefreier Messaging-Erlebnisse in Braze. Wir wissen, dass Barrierefreiheit ein Thema ist, das sich ständig weiterentwickelt, und wir werden unsere Erkenntnisse weiterhin teilen.

## SDK-Updates

Die neuesten SDK-Updates wurden veröffentlicht. Wichtige Änderungen sind im Abschnitt SDK-Updates aufgeführt; alle weiteren Updates finden Sie in den entsprechenden SDK-Changelogs.

- [Android SDK 36.0.0](https://pub.dev/packages/braze_plugin/changelog)
    - Dieses Release macht die Erhöhung der Mindest-Android-SDK-Version des Braze Android SDK von API 21 auf API 25, die in Version 34.0.0 eingeführt wurde, rückgängig. Dadurch kann das SDK wieder in Apps kompiliert werden, die bereits ab API 21 unterstützt werden. Bitte beachten Sie, dass wir zwar die Möglichkeit zur Kompilierung wieder einführen, jedoch keine formelle Unterstützung für < API 25 wieder aufnehmen und nicht garantieren können, dass das SDK auf Geräten mit diesen Versionen wie vorgesehen funktioniert.
    - Wenn Ihre App diese Versionen unterstützt, sollten Sie:
        - Ihre SDK-Integration auf physischen Geräten (nicht nur Emulatoren) für diese API-Versionen validieren.
        - Falls Sie das erwartete Verhalten nicht validieren können, müssen Sie entweder [disableSDK](https://braze-inc.github.io/braze-android-sdk/kdoc/braze-android-sdk/com.braze/-braze/-companion/disable-sdk.html) aufrufen oder das SDK auf diesen Versionen nicht initialisieren. Andernfalls können unbeabsichtigte Nebeneffekte oder eine beeinträchtigte Performance auf den Geräten Ihrer Endnutzer:innen auftreten.
    - Ein Problem wurde behoben, bei dem In-App-Nachrichten einen Lesevorgang auf dem Main-Thread verursachten.
    `BrazeInAppMessageManager.displayInAppMessage` ist jetzt eine Kotlin-Suspend-Funktion.
        - Wenn Sie diese Funktion nicht direkt aufrufen, müssen Sie keine Änderungen vornehmen.
    - AndroidX Compose BOM wurde auf 2025.04.01 aktualisiert, um Änderungen in den Jetpack Compose APIs zu berücksichtigen.
- [React Native SDK 15.0.0](https://github.com/braze-inc/braze-react-native-sdk/blob/master/CHANGELOG.md)
    - Aktualisiert die native Android-Bridge von Braze Android SDK 35.0.0 auf 36.0.0.
    - Aktualisiert die nativen iOS-Versionsbindungen von Braze Swift SDK 11.9.0 auf 12.0.0.
    - Aktualisiert die Einheitendarstellung von PushNotificationEvent.timestamp auf Millisekunden unter iOS.
        - Zuvor wurde dieser Wert unter iOS in Sekunden dargestellt. Dies stimmt nun mit der bestehenden Android-Implementierung überein.
- [Web SDK 5.9.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [Flutter SDK 14.0.0 5.9.0](https://pub.dev/packages/braze_plugin/changelog)
    - Dieses Release macht die Erhöhung der Mindest-Android-SDK-Version des Braze Android SDK von API 21 auf API 25, die in Version 34.0.0 eingeführt wurde, rückgängig. Dadurch kann das SDK wieder in Apps kompiliert werden, die bereits ab API 21 unterstützt werden. Wir nehmen jedoch keine formelle Unterstützung für < API 25 wieder auf. Lesen Sie den [Braze Android SDK Changelog-Eintrag](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#3600).
    - Aktualisiert die native Android-Bridge von Braze Android SDK 35.0.0 auf 36.0.0.
    - Aktualisiert die native iOS-Bridge von Braze Swift SDK 11.9.0 auf 12.0.0.
