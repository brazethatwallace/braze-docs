# Veröffentlichung am 19. August 2025 {#august-19-2025-release}

## Standardisierung der Zeitzonenkonsistenz für Canvas Context {#time-zone-consistency-standardization-to-canvas-context}

{% multi_lang_include release_type.md release="Early access" %}

Wenn Sie am [Early Access für den Canvas-Context-Schritt]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/context) teilnehmen, werden alle Zeitstempel mit einem Datum-/Uhrzeit-Typ aus Trigger-Event-Eigenschaften in aktionsbasierten Canvases immer auf [UTC](https://en.wikipedia.org/wiki/Coordinated_Universal_Time) normalisiert. Weitere Informationen hierzu finden Sie unter [Standardisierung der Zeitzonenkonsistenz]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/context#time-zone-consistency-standardization).

## Datenflexibilität {#data-flexibility}

### Self-Service-benutzerdefinierte Domains {#self-serve-custom-domains}

{% multi_lang_include release_type.md release="General access" %}

[Self-Service-benutzerdefinierte Domains]({{site.baseurl}}/user_guide/channels/sms_mms_and_rcs/message_features_and_optimization/custom_domains) ermöglichen es Ihnen, Ihre eigenen benutzerdefinierten Domains für SMS, RCS und WhatsApp direkt über Ihr Braze-Dashboard zu konfigurieren und zu verwalten. Sie können ganz einfach bis zu 10 benutzerdefinierte Domains an einem Ort hinzufügen, überwachen und verwalten.

### Segment-Funnel-Statistiken {#segment-funnel-statistics}

Wählen Sie [Funnel-Statistiken anzeigen]({{site.baseurl}}/user_guide/engagement_tools/segments/creating_a_segment#viewing-funnel-statistics) aus, um die Statistiken für diese Filtergruppe anzuzeigen und zu sehen, wie sich jeder hinzugefügte Filter auf Ihre Segment-Statistiken auswirkt. Sie sehen eine geschätzte Anzahl und einen Prozentsatz der Nutzer:innen, die bis zu diesem Punkt von allen Filtern angesprochen werden. Nachdem die Statistiken für eine Filtergruppe angezeigt wurden, werden sie automatisch aktualisiert, wenn Sie die Filter ändern.

### Neue Antwortfelder für den Endpunkt `/campaigns/details` für Push-Benachrichtigungen {#new-response-fields-for-campaignsdetails-endpoint-for-push-notifications}

Die `messages`-Antwort für Push-Benachrichtigungen enthält jetzt zwei neue Felder:

- `image_url`: Eine Bild-URL für ein Android-Benachrichtigungsbild, ein iOS-Benachrichtigungsbild oder ein Web-Push-Symbol-Bild.
- `large_image_url`: Eine Web-Benachrichtigungsbild-URL für Android Chrome und Windows Web-Push-Aktionen.

### PII-Felder definieren {#defining-pii-fields}

Das Auswählen und [Definieren bestimmter Felder als PII-Felder]({{site.baseurl}}/user_guide/administer/global/admin_settings/security_settings#view-pii) wirkt sich nur darauf aus, was Nutzer:innen im Braze-Dashboard sehen können, und hat keinen Einfluss darauf, wie die Endnutzer:innen-Daten in solchen PII-Feldern behandelt werden.

Wenden Sie sich an Ihr Rechtsteam, um die Einstellungen Ihres Dashboards mit den für Ihr Unternehmen geltenden Datenschutzvorschriften und -richtlinien abzustimmen, einschließlich derjenigen in Bezug auf die [Datenspeicherung]({{site.baseurl}}/api/data_retention).

### Einen Download-Link des Berichts-Builders teilen {#sharing-a-report-builder-download-link}

Sie können [einen Dashboard-Link]({{site.baseurl}}/user_guide/analytics/reporting/report_builder#sharing-a-report) zum Bericht teilen, indem Sie **Teilen** und dann **Einen Link teilen** oder **Eine E-Mail senden oder planen** auswählen.

## Kreativität freisetzen {#unlocking-creativity}

### Benutzerdefinierte Head-Tags für Drag-and-Drop-E-Mails {#custom-head-tags-for-drag-and-drop-emails}

Verwenden Sie `<head>`-Tags, um CSS und Metadaten in Ihrer E-Mail-Nachricht hinzuzufügen. Sie können diese Tags beispielsweise verwenden, um ein Stylesheet oder ein Favicon hinzuzufügen. Liquid wird in `<head>`-Tags unterstützt.

### Best Practices für Fuzzy-Opt-out {#fuzzy-out-out-best-practices}

Wir haben einen [Abschnitt mit Best Practices]({{site.baseurl}}) hinzugefügt, der Ihnen hilft, Ihre Fuzzy-Opt-out-Nachricht durchdacht zu konfigurieren und ein klares, regelkonformes und positives Erlebnis für Ihre Abonnent:innen zu schaffen.

### WhatsApp Flows

{% multi_lang_include release_type.md release="Early access" %}

[WhatsApp Flows]({{site.baseurl}}/whatsapp_flows) ist eine Erweiterung des bestehenden WhatsApp-Kanals, mit der Sie interaktive und dynamische Messaging-Erlebnisse erstellen können.

### Eingehende WhatsApp-Produktfragen {#whatsapp-inbound-product-questions}

Nutzer:innen können auf Ihre Produkt- oder Katalognachricht mit [Produktfragen]({{site.baseurl}}/user_guide/message_building_by_channel/whatsapp/whatsapp_campaign/product_messages#receiving-inbound-product-questions) antworten. Diese treffen als eingehende Nachrichten ein, die dann mit einem Aktionspfad sortiert werden können.

Darüber hinaus extrahiert Braze die Produkt-ID und die Katalog-ID aus diesen Fragen. Wenn Sie also Antworten automatisieren oder Fragen an ein anderes Team (z. B. den Kundensupport) weiterleiten möchten, können Sie diese Details einbeziehen.

## SDK-Updates

Die neuesten SDK-Updates wurden veröffentlicht. Wichtige Änderungen sind im Abschnitt „SDK-Updates“ aufgeführt; alle weiteren Updates finden Sie in den entsprechenden SDK-Changelogs.

- [Swift SDK 13.0.0](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md)
    - Erweitert die Funktionalität von `BrazeSDKAuthDelegate.braze(_:sdkAuthenticationFailedWithError:)`, sodass diese auch bei „Optional“-Authentifizierungsfehlern ausgelöst wird.
        - Die Delegate-Methode `BrazeSDKAuthDelegate.braze(_:sdkAuthenticationFailedWithError:)` wird nun sowohl bei „Required“- als auch bei „Optional“-Authentifizierungsfehlern ausgelöst.
        - Wenn Sie nur „Required“-SDK-Authentifizierungsfehler behandeln möchten, fügen Sie in Ihrer Implementierung dieser Delegate-Methode eine Prüfung hinzu, die sicherstellt, dass `BrazeSDKAuthError.optional` „false“ ist.
    - Behebt die Verwendung von `Braze.Configuration.sdkAuthentication`, damit diese bei Aktivierung wirksam wird.
        - Zuvor wurde der Wert dieser Konfiguration vom SDK nicht verarbeitet, und das Token wurde immer an Anfragen angehängt, sofern es vorhanden war.
        - Jetzt hängt das SDK das SDK-Authentifizierungstoken nur dann an ausgehende Netzwerkanfragen an, wenn diese Konfiguration aktiviert ist.
    - Die Setter für alle Eigenschaften von `Braze.FeatureFlag` und alle Eigenschaften von `Braze.Banner` wurden auf `private` gesetzt. Die Eigenschaften dieser Klassen sind jetzt schreibgeschützt.
    - Entfernt die Eigenschaft `Braze.Banner.id`, die in Version `11.4.0` als veraltet markiert wurde.
        - Verwenden Sie stattdessen `Braze.Banner.trackingId`, um die Campaign-Tracking-ID eines Banners auszulesen.
- [React Native SDK 16.0.0](https://github.com/braze-inc/braze-react-native-sdk/blob/master/CHANGELOG.md)
    - Aktualisiert die nativen Android-SDK-Versionsbindungen von [Braze Android SDK 36.0.0 auf 37.0.0](https://github.com/braze-inc/braze-android-sdk/compare/v36.0.0...v37.0.0#diff-06572a96a58dc510037d5efa622f9bec8519bc1beab13c9f251e97e657a9d4ed).
    - Aktualisiert die nativen Swift-SDK-Versionsbindungen von [Braze Swift SDK 12.0.0 auf 13.0.0](https://github.com/braze-inc/braze-swift-sdk/compare/12.0.0...13.0.0#diff-06572a96a58dc510037d5efa622f9bec8519bc1beab13c9f251e97e657a9d4ed).
        - Das `sdkAuthenticationError`-Ereignis wird nun sowohl bei „Required“- als auch bei „Optional“-Authentifizierungsfehlern ausgelöst.
- [Xamarin SDK 7.0.0](https://github.com/braze-inc/braze-xamarin-sdk/blob/7.0.0/CHANGELOG.md)
    - Unterstützung für .NET 9.0 für die iOS- und Android-Bindungen hinzugefügt.
        - Damit entfällt die Unterstützung für .NET 8.0.
        - Dies erfordert eine [Mindestversion von iOS 12.2](https://learn.microsoft.com/en-us/dotnet/maui/whats-new/dotnet-9?view=net-maui-9.0).
    - Die Android-Bindung wurde von [Braze Android 32.0.0 auf 37.0.0](https://github.com/braze-inc/braze-android-sdk/compare/v32.0.0...v37.0.0#diff-06572a96a58dc510037d5efa622f9bec8519bc1beab13c9f251e97e657a9d4ed) aktualisiert.
    - Die iOS-Bindung wurde von [Braze Swift SDK 10.0.0 auf 12.1.0](https://github.com/braze-inc/braze-swift-sdk/compare/10.0.0...12.1.0#diff-06572a96a58dc510037d5efa622f9bec8519bc1beab13c9f251e97e657a9d4ed) aktualisiert.
    - Dieses Release enthält APIs für das Banner-Feature, wird aber derzeit von diesem SDK nicht vollständig unterstützt. Wenn Sie Banner in Ihrer .NET-MAUI-App verwenden möchten, wenden Sie sich an Ihre:n Customer-Support-Manager:in, bevor Sie die Integration in Ihre Anwendung vornehmen.
- [Cordova SDK 13.0.0](https://github.com/braze-inc/braze-cordova-sdk/blob/master/CHANGELOG.md#1300)
    - Die interne iOS-Implementierung der Methode `enableSdk` wurde aktualisiert und verwendet nun `setEnabled`: anstelle von `_requestEnableSDKOnNextAppRun`, das im Swift SDK als veraltet markiert wurde.
    - Der Aufruf dieser Methode erfordert keinen Neustart der App mehr, um wirksam zu werden. Das SDK wird nun aktiviert, sobald diese Methode ausgeführt wird.
    - Die native Android-Bridge wurde von [Braze Android SDK `36.0.0` auf `37.0.0`](https://github.com/braze-inc/braze-android-sdk/compare/v36.0.0...v37.0.0#diff-06572a96a58dc510037d5efa622f9bec8519bc1beab13c9f251e97e657a9d4ed) aktualisiert.
