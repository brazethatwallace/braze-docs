# Veröffentlichung am 22. Juli 2025 {#july-22-2025-release}

## Export von Sicherheitsereignissen mit Amazon S3 {#security-events-export-with-amazon-s3}

Sie können [Sicherheitsereignisse automatisch nach Amazon S3 exportieren]({{site.baseurl}}/user_guide/administer/global/admin_settings/security_settings/security_export_s3), einem Cloud-Speicheranbieter, mit einem täglichen Job, der um Mitternacht UTC ausgeführt wird. Nach der Einrichtung müssen Sie Sicherheitsereignisse nicht mehr manuell aus dem Dashboard exportieren.

## Datenflexibilität {#data-flexibility}

### CSV-Import

{% multi_lang_include release_type.md release="General availability" %}

Sie können den CSV-Import verwenden, um Nutzer:innen-Attribute und angepasste Events in Braze zu erfassen und zu aktualisieren, z. B. `first_name`, `last_destination_searched` und `trip_booked`. Informationen zu den ersten Schritten finden Sie unter [CSV-Import]({{site.baseurl}}/user_guide/audience/manage_audience/import_users/csv_import).

### API-Nutzungswarnungen {#api-usage-alerts}

{% multi_lang_include release_type.md release="General availability" %}

API-Nutzungswarnungen bieten wichtige Einblicke in Ihre API-Nutzung und ermöglichen es Ihnen, unerwarteten Datenverkehr proaktiv zu erkennen. Durch die Einrichtung dieser Warnungen zur Überwachung wichtiger API-Anfragevolumen können Sie Echtzeit-Benachrichtigungen erhalten und Probleme beheben, bevor sie sich auf Ihre Marketing-Campaigns auswirken.

### Workspace-API-Rate-Limits

Mit Workspace-API-Rate-Limits können Sie eine maximale Anzahl von API-Anfragen festlegen, die ein Workspace an einen bestimmten Ingestion-Endpunkt senden kann, z. B. `/users/track` oder SDK-Daten. Sie können Rate-Limits auch auf eine Gruppe von Workspaces anwenden, sodass das Limit über alle Workspaces in dieser Gruppe hinweg geteilt wird.

### Standard-Zeitraum für Campaign Analytics {#default-time-range-for-campaign-analytics}

Standardmäßig zeigt der Zeitraum für [**Campaign Analytics**]({{site.baseurl}}/user_guide/analytics/reports/campaign_analytics) die letzten 90 Tage ab dem aktuellen Zeitpunkt an. Das bedeutet: Wenn die Campaign vor mehr als 90 Tagen gestartet wurde, werden die Analytics für den angegebenen Zeitraum als „0“ angezeigt. Um alle Analytics für ältere Campaigns anzuzeigen, passen Sie den Berichtszeitraum an.

### Aktualisiertes Verhalten für den Canvas-Experimentpfad-Schritt {#updated-behavior-for-canvas-experiment-paths-step}

Wenn Ihr Canvas einen aktiven oder laufenden Gewinnerpfad oder personalisierten Pfad als [Experiment]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/experiment_step) hat und Sie den aktiven Canvas aktualisieren – unabhängig davon, ob Sie den Experimentpfad-Schritt selbst aktualisieren –, wird das laufende Experiment beendet und der Experimentschritt bestimmt keinen Gewinnerpfad oder personalisierte Pfade. Um das Experiment neu zu starten, können Sie den bestehenden Experimentpfad trennen und einen neuen starten oder den Canvas duplizieren und einen neuen Canvas starten. Andernfalls durchlaufen Nutzer:innen den Experimentpfad so, als ob keine Optimierungsmethode ausgewählt worden wäre.

Weitere Informationen finden Sie unter [Canvases nach dem Start bearbeiten]({{site.baseurl}}/post-launch_edits).

### Schnelleres Rate-Limit für den `/users/export/ids`-Endpunkt {#faster-rate-limit-available-for-usersexportids-endpoint}

Sie können auch das [Rate-Limit für den /users/export/ids-Endpunkt]({{site.baseurl}}/api/endpoints/export/user_data/post_users_identifier#rate-limit) auf 40 Anfragen pro Sekunde erhöhen, indem Sie die folgenden Anforderungen erfüllen:

- Ihr Workspace hat das Standard-Rate-Limit (250 Anfragen pro Minute) aktiviert. Wenden Sie sich an Ihren Braze Account Manager, wenn Sie Hilfe beim Entfernen eines bereits bestehenden Rate-Limits benötigen.
- Ihre Anfrage enthält den Parameter fields_to_export, um alle Felder aufzulisten, die Sie erhalten möchten.

## Kreativität freisetzen {#unlocking-creativity}

### Landing-Pages

Sie können Ihre Landing-Page [responsiv an die Größe des Geräts der Nutzer:innen anpassen]({{site.baseurl}}/user_guide/messaging/landing_pages/create_landing_pages#step-3-customize-the-page), indem Sie Spalten auf kleineren Bildschirmen vertikal stapeln. Aktivieren Sie dazu eine Spalte in der Zeile, die responsiv sein soll, und schalten Sie dann **Vertically stack on smaller screens** im Abschnitt **Customize columns** ein.

## Robuste Kanäle {#robust-channels}

### Bot-Filterung für E-Mails {#bot-filtering-for-emails}

{% multi_lang_include release_type.md release="General availability" %}

Richten Sie die Bot-Filterung in Ihren [E-Mail-Einstellungen]({{site.baseurl}}/user_guide/administer/global/workspace_settings/email_preferences) ein, um alle verdächtigen Maschinen- oder Bot-Klicks auszuschließen. Ein „Bot-Klick“ in einer E-Mail bezeichnet einen Klick auf Hyperlinks innerhalb einer E-Mail, der von einem automatisierten Programm generiert wird. Durch das Filtern dieser Bot-Klicks können Sie gezielt Nachrichten an engagierte Empfänger:innen auslösen und zustellen.

### Drag-and-Drop-Produktblöcke {#drag-and-drop-product-blocks}

{% multi_lang_include release_type.md release="Early access" %}

Der [Drag-and-Drop-Editor]({{site.baseurl}}/dnd_product_blocks) ermöglicht es Ihnen, Produktblöcke schnell hinzuzufügen und zu konfigurieren, um Ihre Produkte nahtlos in Ihren Nachrichten zu präsentieren – ohne angepassten Liquid-Code erstellen zu müssen. Das Drag-and-Drop-Produktblock-Feature ist derzeit nur für E-Mail verfügbar.

### Span-Text für Landing-Pages und In-App-Nachrichten {#span-text-for-landing-pages-and-in-app-messages}

Mit Span-Text können Sie bestimmte Styles auf Textblöcke anwenden, ohne angepassten Code für Ihre [Landing-Pages]({{site.baseurl}}/user_guide/engagement_tools/landing_pages/creating_pages#step-3-customize-the-page) und [In-App-Nachrichten]({{site.baseurl}}/user_guide/channels/in_app_messages/customize/style_settings#blocks) zu benötigen. Markieren Sie dazu den Text, den Sie stylen möchten, und wählen Sie dann **Wrap with span for style** aus.

### Anzeigenklick zu WhatsApp {#ad-click-to-whatsapp}

[Ads That Click to WhatsApp]({{site.baseurl}}/whatsapp_use_cases) sind eine effiziente Möglichkeit, sowohl neue als auch bestehende Kund:innen über Meta-Anzeigen auf Facebook, Instagram oder anderen Plattformen zu erreichen. Nutzen Sie diese Anzeigen, um Ihre Produkte und Dienste zu bewerben und gleichzeitig Nutzer:innen auf Ihre WhatsApp-Präsenz aufmerksam zu machen.

## Neue Braze-Partnerschaften {#new-braze-partnerships}

### Shopify Visitory API — E-Commerce {#shopify-visitory-api-ecommerce}

Braze erfasst Besucherinformationen wie E-Mail-Adressen und Telefonnummern über In-Browser-Nachrichten. Diese Informationen werden dann an Shopify gesendet. Diese Daten helfen Händlern, Besucher:innen ihres Shops zu erkennen und ein personalisierteres Einkaufserlebnis zu schaffen.

### Okendo — E-Commerce {#okendo-ecommerce}

Die Integration von Braze und [Okendo]({{site.baseurl}}/partners/okendo) funktioniert über mehrere Produkte auf der Okendo-Plattform hinweg, darunter Reviews, Loyalty, Referrals, Surveys und Quizzes. Okendo sendet angepasste Events und Nutzerattribute an Braze, die zur Personalisierung und zum Triggern von Nachrichten verwendet werden können.

### Lemnisk — Customer Data Platform (CDP) {#lemnisk-customer-data-platform}

Die Integration von Braze und [Lemnisk]({{site.baseurl}}/partners/lemnisk) ermöglicht es Marken und Unternehmen, das volle Potenzial von Braze auszuschöpfen, indem Lemnisk als CDP-gestützte Intelligenzschicht fungiert, die Nutzerdaten plattformübergreifend in Echtzeit vereinheitlicht und die gesammelten Informationen und Verhaltensweisen der Nutzer:innen in Echtzeit an Braze sendet.

## SDK-Updates

Die neuesten SDK-Updates wurden veröffentlicht. Wichtige Änderungen sind im Abschnitt SDK-Updates aufgeführt; alle weiteren Updates finden Sie in den entsprechenden SDK-Changelogs.

- [Web SDK 6.0.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
    - Die Eigenschaft `Banner.html` sowie die Methoden `logBannerClick` und `logBannerImpressions` wurden entfernt. Verwenden Sie stattdessen [`insertBanner`](https://js.appboycdn.com/web-sdk/latest/doc/modules/braze.html#insertbanner), das Impression- und Klick-Tracking automatisch verwaltet.
    - Die Unterstützung für das veraltete News Feed-Feature wurde entfernt. Dies umfasst die Entfernung der Feed-Klasse und der zugehörigen Methoden.
    - Die Felder „created“ und „categories“, die von veralteten News Feed-Cards verwendet wurden, wurden aus den Unterklassen von [`Card`](https://js.appboycdn.com/web-sdk/latest/doc/classes/braze.card.html) entfernt.
    - Das Feld „linkText“ wurde ebenfalls aus der [`ImageOnly`](https://js.appboycdn.com/web-sdk/latest/doc/classes/braze.imageonly.html)-Card-Unterklasse und deren Konstruktor entfernt.
    - Definitionen wurden präzisiert und Typen aktualisiert, um zu verdeutlichen, dass bestimmte SDK-Methoden explizit „undefined“ zurückgeben, wenn das SDK nicht initialisiert ist. Damit stimmen die Typisierungen mit dem tatsächlichen Laufzeitverhalten überein. Dies kann neue TypeScript-Fehler in Projekten verursachen, die auf die vorherigen (unvollständigen) Typisierungen angewiesen waren.
    - Die Bilder von In-App-Nachrichten mit `cropType` `CENTER_CROP` (z. B. standardmäßig `FullScreenMessage`) werden nun über ein `<img>`-Tag statt eines `<span>`-Tags gerendert, um die Barrierefreiheit zu verbessern. Dies kann bestehende CSS-Anpassungen für die Klasse `.ab-center-cropped-img` oder deren Kindelemente beeinträchtigen.
- [Cordova SDK 13.0.0](https://github.com/braze-inc/braze-cordova-sdk/blob/master/CHANGELOG.md#1300)
    - Die interne iOS-Implementierung der Methode `enableSdk` wurde aktualisiert und verwendet nun „setEnabled:“ anstelle von `_requestEnableSDKOnNextAppRun`, das im Swift SDK als veraltet markiert wurde.
        - Der Aufruf dieser Methode erfordert keinen Neustart der App mehr, damit die Änderung wirksam wird. Das SDK wird nun aktiviert, sobald diese Methode ausgeführt wird.
    - Die native Android-Bridge wurde [von Braze Android SDK 36.0.0 auf 37.0.0](https://github.com/braze-inc/braze-android-sdk/compare/v36.0.0...v37.0.0#diff-06572a96a58dc510037d5efa622f9bec8519bc1beab13c9f251e97e657a9d4ed) aktualisiert.
- [Android SDK 37.0.0](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md)
- [Swift SDK 12.0.1–12.1.0](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md)
