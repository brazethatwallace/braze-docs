# Release vom 17. Oktober 2023 {#october-17-2023-release}

## In andere Workspaces kopieren {#copying-to-workspaces}

[Das Kopieren von Campaigns über einen Workspace hinweg]({{site.baseurl}}/user_guide/messaging/governance/copy_across_workspaces) ermöglicht Ihnen einen schnellen Einstieg in die Nachrichtenerstellung, indem Sie mit einer Kopie einer Campaign in einem anderen Workspace beginnen. Diese Kopie bleibt als Entwurf erhalten, bis Sie sie bearbeiten und starten, sodass Sie Ihre erfolgreichen Messaging-Strategien beibehalten und darauf aufbauen können.

## Currents-Konnektoren testen {#test-currents-connectors}

[Currents-Konnektoren testen]({{site.baseurl}}/user_guide/data_and_analytics/braze_currents/setting_up_currents#test-currents-connectors) sind kostenlose Versionen unserer bestehenden Konnektoren, die zum Testen und Ausprobieren verschiedener Ziele verwendet werden können. Test-Currents haben:

- Keine Begrenzung der Anzahl an Test-Currents-Konnektoren, die Sie erstellen können.
- Ein aggregiertes Maximum von 10.000 Ereignissen pro rollendem 30-Tage-Zeitraum. Diese Ereignis-Gesamtzahl wird stündlich im Dashboard aktualisiert.

## Feature-Flags

Mit [Feature-Flags]({{site.baseurl}}/developer_guide/feature_flags) können Sie Funktionen für eine bestimmte oder zufällige Auswahl von Nutzer:innen remote aktivieren oder deaktivieren. Besonders wichtig ist, dass Sie ein Feature in der Produktionsumgebung ein- und ausschalten können, ohne zusätzliche Code-Deployments oder App-Store-Updates durchführen zu müssen. So können Sie neue Features sicher und mit Zuversicht ausrollen.

## Feature-Flag-Experimente {#feature-flag-experiments}

[Feature-Flag-Experimente]({{site.baseurl}}/developer_guide/feature_flags/experiments) ermöglichen es Ihnen, Änderungen an Ihren Anwendungen per A/B-Test zu überprüfen und die Konversionsraten zu optimieren. Marketer können Feature-Flags nutzen, um festzustellen, ob ein neues Feature die Konversionsraten positiv oder negativ beeinflusst oder welche Kombination von Feature-Flag-Eigenschaften am optimalsten ist.

## Zusammenführen von Nutzerprofilen {#merging-user-profiles}

Wenn Ihre Suche auf der Seite **Nutzer:innen suchen** mehrere Nutzerprofile ergibt, können Sie [Nutzerprofile zusammenführen]({{site.baseurl}}/user_guide/audience/manage_audience/merge_duplicate_users), indem Sie auf den Button **Merge duplicates** klicken. Sie können auswählen, welches Kundenprofil beibehalten werden soll – dieses Profil bleibt bestehen und erhält die Attribute aus dem zusammengeführten Profil.

## Performance-Daten nach Segment {#performance-data-by-segment}

Sie können jetzt Report-Templates im Query Builder verwenden, um [Performance-Daten nach Segmenten aufzuschlüsseln]({{site.baseurl}}/user_guide/data_and_analytics/reporting/viewing_and_understanding_segment_data#performance-data-by-segment) – für Campaigns, Canvas, Varianten und Schritte.

## Aktualisieren von Nutzerprofilen {#updating-user-profiles}

Sie können jetzt den [`/users/track`-Endpunkt]({{site.baseurl}}/api/endpoints/user_data/post_user_track) verwenden, um ein Kundenprofil per Telefonnummer oder E-Mail zu aktualisieren.

## SDK-Updates

Die neuesten SDK-Updates wurden veröffentlicht. Wichtige Änderungen sind im Abschnitt „SDK-Updates“ aufgeführt; alle weiteren Updates finden Sie in den entsprechenden SDK-Changelogs.

- [Braze Segment Swift Plugin v2.1.0](https://github.com/braze-inc/braze-segment-swift/blob/main/CHANGELOG.md)
- [Web SDK v4.10.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [Web SDK v5.0.0](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
    - Der [`subscribeToFeatureFlagsUpdates()`](https://js.appboycdn.com/web-sdk/latest/doc/modules/braze.html#subscribetofeatureflagsupdates)-Callback wird jetzt immer aufgerufen, unabhängig davon, ob die Aktualisierung erfolgreich war oder fehlgeschlagen ist. Bei einem Fehler beim Empfang von Updates wird der Callback mit den aktuell zwischengespeicherten Feature-Flags aufgerufen.
    - Die [`getFeatureFlag()`](https://js.appboycdn.com/web-sdk/latest/doc/modules/braze.html#getfeatureflag)-Methode gibt jetzt null zurück, wenn das Feature-Flag nicht existiert oder Feature-Flags deaktiviert sind.
    - Die zuvor in Version 4.0.4 als veraltet markierte Methode `logContentCardsDisplayed()` wurde entfernt.
    - Die veraltete Initialisierungsoption `enableHtmlInAppMessages` wurde entfernt. Sie sollte stattdessen durch die Option `allowUserSuppliedJavascript` ersetzt werden.
    - Die in Version 4.9.0 als veraltet markierte Banner-Klasse wurde zugunsten von [`ImageOnly`](https://js.appboycdn.com/web-sdk/latest/doc/classes/braze.imageonly.html) entfernt.
    - Der CSS-Klassenname `ab-banner` wurde im Rahmen der Entfernung der `Banner`-Klasse entfernt. CSS-Anpassungen sollten stattdessen die Klasse `ab-image-only` verwenden.
    - Das SDK wirft nirgendwo mehr Laufzeitfehler. Wenn Braze-Methoden vor der Initialisierung aufgerufen werden, wird stattdessen eine Warnung in der Konsole protokolliert.
    - Das SDK fügt benutzerdefinierten HTML-In-App-Nachrichten keine standardmäßigen Braze-In-App-Nachrichtenstile mehr hinzu. Diese Stile wurden zuvor von älteren In-App-Nachrichtentypen verwendet.
- [Android SDK 29.0.0](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md)
    - `BannerImageCard`, `BannerImageCardView` und `BannerImageContentCardView` wurden in `ImageOnlyCard`, `ImageOnlyCardView` und `ImageOnlyContentCardView` umbenannt.
    - Alle für Banner Cards verwendeten Stile wurden auf Image Only Cards aktualisiert. Alle Schlüssel mit dem Wort `banner` sollten durch `image_only` ersetzt werden.
    - Geräte-Markeninformationen werden jetzt gesendet. Wenn Sie dies blockieren möchten, lesen Sie den Abschnitt zur Blockierung der Datenerfassung.
- [Flutter SDK 7.0.0](https://pub.dev/packages/braze_plugin/changelog)
    - Aktualisiert die native Android-Bridge [von Braze Android SDK 26.1.1 auf 27.0.1](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md#2701).
    - Fügt Unterstützung für Gradle 8 hinzu.
- [Swift SDK 7.0.0](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md)
    - Die Konfiguration `useUUIDAsDeviceId` ist jetzt standardmäßig aktiviert.
        - Weitere Details zu den Auswirkungen finden Sie unter [IDFV erfassen – Swift]({{site.baseurl}}/developer_guide/analytics/managing_data_collection/?sdktab=swift).
    - Der Content-Card-Typ „Banner“ und die zugehörigen UI-Elemente wurden in `ImageOnly` umbenannt. Alle Methoden und Eigenschaften bleiben gleich.
        - `Braze.ContentCard.Banner` → `Braze.ContentCard.ImageOnly`
        - `BrazeContentCardUI.BannerCell` → `BrazeContentCardUI.ImageOnlyCell`
    - Überarbeitet Teile der Text-Layout-Logik in BrazeUI in eine neue Klasse Braze.ModalTextView.
    - Aktualisiert das Verhalten der Feature-Flag-Methoden.
        - `FeatureFlags.featureFlag(id:)` gibt jetzt nil zurück, wenn eine ID nicht existiert.
        - `FeatureFlags.subscribeToUpdates(:)` löst den Callback aus, wenn eine Aktualisierungsanfrage erfolgreich abgeschlossen wird oder fehlschlägt.
            - Der Callback wird auch sofort bei der erstmaligen Registrierung ausgelöst, wenn zuvor zwischengespeicherte Daten vorhanden sind.
- [AppboyKit iOS SDK 4.6.0](https://github.com/Appboy/appboy-ios-sdk/releases/tag/4.6.0)
    - Dieses Release erfordert Xcode `14.x`.
    - Die Unterstützung für iOS 9 und iOS 10 wurde eingestellt.
    - Die Unterstützung für die veralteten `.framework`-Assets beim Import über Carthage wurde zugunsten der modernen `.xcframework`-Assets entfernt.
        - Verwenden Sie den Befehl `carthage update --use-xcframeworks`, um das entsprechende Braze-Asset zu importieren.
        - Die Unterstützung für `appboy_ios_sdk_full.json` wurde zugunsten von `appboy_ios_sdk.json` entfernt.
