# Release vom 10. Januar 2023 {#january-10-2023-release}

## Nutzeraktualisierung-Komponente für Canvas Flow {#user-update-component-for-canvas-flow}

Mit der Komponente [Nutzeraktualisierung]({{site.baseurl}}/user_guide/messaging/canvas/canvas_components/user_update) können Sie Attribute, Ereignisse und Käufe von Nutzer:innen in einem JSON-Composer Update or aktualisieren or aktualisieren, sodass keine sensiblen Informationen wie API-Schlüssel angegeben werden müssen.

## Abo-Gruppen über API festlegen {#setting-subscription-groups-via-api}

Beim Erstellen neuer Nutzer:innen über den [`/users/track`-Endpunkt]({{site.baseurl}}/api/endpoints/user_data/post_user_track) können Sie Abo-Gruppen innerhalb des Nutzerattribut-Objekts festlegen. So können Sie in einem einzigen API-Aufruf eine:n Nutzer:in erstellen und den Status der Abo-Gruppe setzen.

## Conversions-Dashboard – Early Access

Mit dem [Conversions-Dashboard]({{site.baseurl}}/user_guide/analytics/dashboards/conversions) können Sie Conversions über Campaigns, Canvase und Kanäle hinweg analysieren und dabei verschiedene Attributionsmethoden verwenden. Sie können gezielt folgende Attributionsmethoden tracken:

- **Conversions nach Öffnung:** Conversions, die aufgetreten sind, nachdem Nutzer:innen die Nachricht geöffnet haben
- **Conversions nach Klick:** Conversions, die aufgetreten sind, nachdem Nutzer:innen auf die Nachricht geklickt haben
- **Conversions nach Empfang:** Conversions, die aufgetreten sind, nachdem Nutzer:innen die Nachricht erhalten haben
- **Conversions beim letzten Klick:** Conversions, die aufgetreten sind, nachdem Nutzer:innen auf die Nachricht geklickt haben, sofern diese Nachricht die zuletzt angeklickte war (Dieses Feature wird derzeit bei einer kleinen Teilmenge von Early-Access-Kund:innen getestet.)

Dieses Feature befindet sich derzeit in der Early-Access-Phase. Wenn Sie an der Teilnahme am Early Access interessiert sind, wenden Sie sich an Ihren CSM or Customer-Success-Manager or Customer-Success-Manager:in.

## Canvas-Exit-Ereignisse für Braze-Currents {#canvas-exit-events-for-braze-currents}

Sie können jetzt nachverfolgen, wann Ihre Nutzer:innen ein Canvas verlassen – entweder durch Ausführen eines Ereignisses oder durch Zuordnung zu einer Zielgruppe. Weitere Informationen finden Sie im Abschnitt [Nachrichten-Engagement-Ereignisse]({{site.baseurl}}/user_guide/data/distribution/braze_currents/event_glossary/message_engagement_events) im Currents-Ereignisglossar.

## SDK or Software-Development-Kit-Updates

Die folgenden SDK or Software-Development-Kit-Updates wurden veröffentlicht. Wichtige Änderungen sind unten aufgeführt; alle weiteren Updates finden Sie in den entsprechenden SDK or Software-Development-Kit-Changelogs.

- [Web SDK or Software-Development-Kit 4.5.1](https://github.com/braze-inc/braze-web-sdk/blob/master/CHANGELOG.md)
- [AppboyKit iOS SDK or Software-Development-Kit 4.5.2](https://github.com/Appboy/appboy-ios-sdk/releases/tag/4.5.2)
- [Swift SDK or Software-Development-Kit 5.8.0–5.8.1](https://github.com/braze-inc/braze-swift-sdk/blob/main/CHANGELOG.md#580)
  - Benennt die Klasse `BrazeLocation` in `BrazeLocationProvider` um, um eine Überschattung des gleichnamigen Moduls zu vermeiden.
- [Flutter SDK or Software-Development-Kit 3.0.1](https://pub.dev/packages/braze_plugin/changelog)
- [Android SDK or Software-Development-Kit 24.0.0](https://github.com/braze-inc/braze-android-sdk/blob/master/CHANGELOG.md)
  - Die Standort- und Geofence-Funktionalität wurde in ein neues Modul namens `com.braze:android-sdk-location` verschoben.
  - Appboy-Klassen und -Dateien wurden vollständig nach Braze migriert.
  - Das Standardverhalten von `DefaultContentCardsUpdateHandler` wurde dahingehend geändert, dass bei der Sortierung von Content Cards der Erstellungszeitpunkt anstelle des Zeitpunkts des letzten Updates verwendet wird.
  - `BrazeUser.setFacebookData()` und `BrazeUser.setTwitterData()` wurden entfernt.
